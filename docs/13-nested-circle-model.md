# 모든 음악을 서클로 표현하는 모델

> 후속 사용자 결정: 앨범→곡·악장→섹션→음악 서클까지 확장하며, 확대 후 정밀 편집도 같은 캔버스에서 직접 수행한다. 아래의 ‘사각 창에서 정밀 편집’과 ‘재귀 송폼은 후속’ 제안은 [앨범 전체 작업 공간](14-album-circle-implementation.md)으로 대체됐다. 이 문서는 섹션 내부 그래프의 설계 기록으로 유지한다.

날짜: 2026-09-07 · 설계 revision: 1 · 현재 앱: 0.7.1

**섹션은 내부에 오디오·MIDI·이펙터 등의 서클과 연결을 담는 원형 그룹이다.** 곡 구성과 섹션 내부의 음악 구성을 같은 캔버스에서 다룬다.

이 문서는 최신 제품 방향이다. 아래의 사용자 확정 사항과 이를 실현하기 위한 설계 제안을 구분한다. 0.7.1 앱에는 이 중첩 모델이 아직 구현되어 있지 않다. 이전 문서의 트랙 중심 섹션 편집, 별도 사운드 보기, 정리용 frame만으로 그룹을 설명하던 부분은 이 문서의 목표 모델로 갱신한다. 기존 구현 기록은 당시 동작의 근거로 남긴다.

## 사용자 확정 사항

- 송라이터와 편곡자가 곡의 구성을 설계하는 macOS 앱이며 제품명은 써클러(circlr)다.
- 음악 구성 요소를 서클로 표현한다. 섹션 자체가 그룹이며 그 안에 오디오·MIDI·이펙터 서클이 들어가고 노드로 연결된다.
- 하나의 넓은 프리폼 캔버스가 기본 작업 공간이다. 그리드·정렬·그룹을 지원하며 좌우·아래 고정 창으로 화면을 나누지 않는다.
- 섹션 테두리로 길이와 마디·박을 표현한다. 글로벌과 개별 서클의 tempo·scale·박자를 모두 지원한다. BeatGrid와 실제 RhythmPattern은 별도 설정이다.
- 정밀 MIDI·오디오 편집은 필요할 때 여는 사각 창을 사용한다. 기본 외관은 다크 모드이며 휠 위/아래로 확대/축소한다.
- 메인 창 닫기는 최소화다. 별도 편집 창 닫기와 앱 종료는 각각의 동작을 유지한다.

## 서클의 종류와 역할 — 설계 제안

| 서클 | 담는 내용 | 연결과 시간 |
|---|---|---|
| 섹션 | 이름·길이·설정·내부 서클 그래프 | 다음 섹션으로 진행; 전체 내부 구성을 반복 |
| 오디오 | 원본 미디어 참조·재생 구간·take | audio 출력; 시작·길이·반복·tempo 추종 정책 |
| MIDI | note·controller·take | MIDI 출력; 시작·길이·반복·로컬 음악 기준 |
| 악기 | MIDI를 소리로 만드는 instrument 설정 | MIDI 입력 → audio 출력 |
| 이펙터 | effect와 parameter·automation 참조 | 지원하는 신호 입출력; 독립된 마디 길이를 꾸며내지 않음 |
| 믹스/출력 | 여러 audio 입력의 합산·레벨·출력 경계 | audio 입력 → 섹션 출력 또는 명시한 상위 bus |
| 전환 | 앞뒤 섹션에 대한 시간 범위·대상·처리 참조 | 송폼 연결 사이에서 within/insert/overlap을 표현 |

악기·믹스/출력·전환을 별도의 서클로 노출하는 것은 연결을 명확히 하기 위한 제안이다. 오디오·MIDI·이펙터를 포함한 섹션 그룹은 사용자 확정 사항이다. 버튼·입력칸·메뉴·파형 편집 창까지 원형으로 바꾸는 것으로 해석하지 않는다.

하나의 오디오 서클은 한 재생 구간, 하나의 MIDI 서클은 한 phrase를 기본 단위로 제안한다. 여러 take는 같은 서클에 보관하고 활성 take를 선택한다. 여러 clip을 담는 상위 음악 그룹과 임의 깊이의 재귀 중첩은 별도 확장 설계다. 우선 **곡 → 섹션 그룹 → 음악 서클**의 관계를 완성한다.

예를 들어 벌스 그룹 안에는 다음 두 경로를 함께 둘 수 있다. 이는 개념 설명이며 앱에 자동으로 채우는 기본 곡이 아니다.

```text
MIDI 서클 → 악기 서클 → 이펙터 서클 ─┐
                                   ├→ 믹스/출력 서클
오디오 서클 → 이펙터 서클 ──────────┘
```

MIDI와 오디오는 서로 다른 신호다. MIDI 서클을 audio 전용 effect에 직접 연결하지 않는다. MIDI effect가 필요하면 해당 종류와 포트를 명시한다. source를 연결하지 않은 섹션은 음악 구성용 빈 그룹으로 보존하며 임의의 음원을 넣지 않는다.

## 한 캔버스에서 작업하는 방식 — UX 제안

| 상황 | 같은 캔버스에서의 동작 | 편집 창 |
|---|---|---|
| 전체 송폼 설계 | 섹션 그룹의 이름·마디·반복·다음 연결을 우선 표시 | 자동으로 열지 않음 |
| 섹션 내부 보기 | 휠 확대에 따라 내부 서클과 연결의 상세도를 높임 | 자동으로 열지 않음 |
| 섹션 더블클릭 | 해당 그룹이 잘 보이도록 카메라를 이동·확대 | 이전 위치와 배율을 복귀 지점으로 보관 |
| 내부 음악 만들기 | 그룹 안의 생성 메뉴로 종류를 고르거나 오디오를 가져옴 | 입력/녹음 등 필요한 작업에만 사용 |
| 음악 서클 이동·연결 | 부모 안에서 자유 배치·정렬하고 typed port로 연결 | 캔버스 조작을 계속 허용 |
| MIDI·오디오 더블클릭 | 선택한 음악 서클을 편집 대상으로 지정 | note 또는 waveform/clip의 정밀 편집 |
| 이펙터 편집 | 대상 서클과 경로를 계속 표시 | parameter 또는 실제 plugin 편집기 |
| 전체로 돌아가기 | 부모 선택/전체 맞추기; 편집 창이 없을 때 Esc로 직전 초점 복귀 | 열린 편집 창의 Esc는 먼저 그 창만 닫음 |

섹션 안으로 들어가는 것은 캔버스의 다른 페이지를 여는 동작이 아니다. 주변 섹션과 외부 연결을 유지하고, 확대할수록 해당 그룹 내부가 읽히게 한다. 일정 배율을 오갈 때 노드가 반복해서 나타났다 사라지지 않도록 상세도 전환에 여유 구간을 둔다. 정확한 임계 배율과 움직임은 native 사용성 검증으로 결정한다.

접힌 그룹에도 내부 서클의 작은 구성 요약을 남긴다. 섹션 경계는 그룹을 둘러싸는 큰 원이며, 펼쳤을 때 이름·길이 등은 경계 쪽에 배치해 자식 그래프를 가리지 않는다. 시간 눈금·반복 링·선택 테두리·입출력 포트는 역할을 구분한다. 작은 화면에서는 눈금을 줄이되 섹션 길이와 반복 숫자는 유지한다.

그룹 크기를 바꾸거나 자식 서클을 끌어도 음악 길이와 시작 시점은 변하지 않는다. 일반 drag로 경계를 지나갔다고 부모가 바뀌지 않는다. `다른 섹션으로 옮기기`처럼 명시적인 동작으로만 소속·상속·연결 변경을 수행하고, 완료 전 영향을 표시한다. 그룹 이동은 자식의 상대 좌표와 연결을 보존하고 한 번의 undo로 되돌린다.

사각 편집 창은 선택한 음악 서클의 정밀 편집에 사용한다. 섹션의 전체 구성과 routing을 알아보기 위해 이 창을 반드시 열어야 하는 구조를 피한다. 필요하면 관련 MIDI와 오디오를 공통 시간축으로 함께 보여 줄 수 있으며, 기존의 탭 없는 편집 원칙을 유지한다. 단순 캔버스 선택은 창을 강제로 앞으로 가져오지 않는다.

## 포함 관계와 연결 관계

세 관계는 화면에 함께 나타나도 데이터에서는 분리한다.

| 관계 | 의미 | 예 |
|---|---|---|
| 포함 | 무엇이 어느 섹션의 음악인가 | 벌스 그룹이 MIDI·악기·이펙터를 소유 |
| 진행 | 어느 구간을 언제 재생하는가 | 벌스 → 전환 → 후렴 |
| 신호 | 어떤 연주를 어디서 처리하는가 | MIDI → 악기 → delay → 출력 |

MIDI → 악기 → delay는 세 서클을 차례로 재생한다는 뜻이 아니다. MIDI의 event 시간에 맞춰 연결된 처리 경로가 동작한다. 섹션 진행선을 바꾸면 곡 순서가 바뀌고, 내부 audio 선을 바꾸면 소리가 바뀐다. 종류 이름·포트 표시·방향·선 표현을 함께 사용하고 색 하나에 의존하지 않는다.

첫 설계에서 신호 그래프는 검증 가능한 비순환 경로로 제한한다. feedback은 명시적 delay와 안정성 정책을 갖춘 후 별도로 지원한다. 맞지 않는 포트, 사라진 대상, 순환 연결은 저장·재생 준비 시 진단하고 연결 동작에서도 안내한다.

섹션 경계를 넘는 audio 연결은 노출한 섹션 포트나 명명된 공유 bus를 통한다. 임의의 다른 섹션 내부 노드를 직접 참조하지 않는 것을 기본안으로 삼는다. 그룹을 접어도 외부 연결이 무엇을 가리키는지 유지하고, 대상 이름으로 내부 경로를 찾을 수 있어야 한다.

기존 `CanvasGroup`은 정리용 묶음이며 새 **섹션 그룹**과 다르다. 기존 묶음을 섹션으로 자동 변환하지 않는다. 시각 정리용 묶음의 표현과 명칭은 사용성 검토 후 결정하되, 음악 그룹으로 오인되는 사각 frame을 기본 제품 언어로 삼지 않는다.

## 길이·반복·개별 음악 설정

섹션 바깥 링은 섹션 한 회의 시간이다. 오디오·MIDI의 링은 각각의 재생 구간이며 부모 링과 길이가 같을 필요가 없다. 예를 들어 8마디 벌스 안에서 2마디 MIDI 리프를 4회 재생하고 3마디째에 오디오를 시작할 수 있다. 캔버스 좌표와 연결선 각도로 시간을 암묵적으로 정하지 않는다. 시작·길이·반복을 음악 속성으로 저장한다.

섹션의 `총 2회`는 그 안의 배치·연주·처리 경로를 두 번 실행한다. 자식 MIDI의 `총 4회`는 섹션 한 회 안에서의 반복이다. 보이는 서클이나 plugin state를 반복 횟수만큼 복사하지 않는다. 회차별 playback occurrence와 저장된 원본을 구분한다.

설정별 해석 순서는 다음을 제안한다.

```text
글로벌 기본값 → 섹션 원본 설정 → 이번 섹션 사용의 override
            → 내부 서클의 원본 설정 → 이번 사용에서 해당 서클의 override
```

각 항목에 `부모 따름 / 글로벌 직접 따름 / 개별`을 둔다. MIDI만 개별 scale을 사용하고 audio는 부모 tempo를 따르는 식으로 조합할 수 있다. effect는 의미 있는 tempo 동기 항목을 소비하며, scale·meter가 실제 처리에 쓰이지 않는다면 불필요한 입력칸을 만들지 않는다.

자식이 독립 tempo를 가지면 해당 로컬 박을 공통 sample 시간으로 변환한다. 시작점은 부모 시간으로, 자식 연주 길이는 자식 시간으로 해석하는 안을 제안한다. 예: 120 BPM·4/4 부모의 3마디째는 4초 뒤이고, 여기서 시작하는 60 BPM·4/4 한 마디 MIDI는 4초간 재생한다. 단순한 눈금 변경으로 기존 audio가 자동 변속되지는 않는다. audio에는 `부모 tempo 추종 / 개별 tempo 추종 / 원속도`와 source tempo·warp 준비가 필요하다.

자식 길이가 부모 끝을 넘는 경우를 숨기지 않는다. 기본안은 섹션 끝에서 새 event 발생을 멈추고 note release/effect tail은 명시된 경계 정책에 따르는 것이다. 음악 본문을 계속 들려주려면 섹션 길이를 늘리거나 pickup/overhang을 지정한다. 독립 tempo 반복, 녹음, tempo-synced plugin이 함께 동작하는 정확한 경계 정책은 engine 검증이 필요한 미결 사항이다.

BeatGrid는 입력·눈금 기준이며 소리를 생성하지 않는다. 상속한 RhythmPattern은 섹션 안의 패턴 연주 서클로 추적 가능하게 표시하는 안을 제안한다. 모든 자식 서클이 같은 글로벌 pattern을 중복 재생하지 않는다. 패턴 해석은 섹션 수준에서 한 번 이루어지고 실제 출력을 명시적 경로에 연결한다. 추가 레이어는 사용자가 만든 별도 음악 서클이다. scale 변경은 기존 MIDI pitch와 녹음 pitch를 자동으로 바꾸지 않는다.

## 기본 아키텍처 — 목표 모델

하나의 화면이라고 모델까지 한 종류의 무타입 그래프로 합치지 않는다. 포함 관계, 송폼 실행, MIDI/audio 처리를 구분한 채 하나의 캔버스가 함께 표현한다. 아래 타입 이름은 구현 예약이 아닌 책임 설명이다.

| 구성 | 책임 |
|---|---|
| `SectionDefinition` | 섹션 길이·설정·`SectionGraph` 원본 |
| `SectionUse` | 곡에서의 사용 위치·반복·이번 사용의 노드/연결 override |
| `SectionGraph` | stable ID를 가진 음악 서클·typed port·내부 신호 edge·노출 port |
| `CircleNode` | 역할별 payload 참조·설정·연주 구간; 좌표와 분리 |
| `ProcessorResource` | instrument/effect 설정·state와 공유 정책; 화면 노드 ID와 실제 실행 instance 구분 |
| `NodeLayout` | 부모 기준 좌표·크기·접힘·카메라 초점, 음악 revision과 분리 |
| `ContextResolver` | 글로벌·부모·자식의 필드별 유효 값과 출처 계산 |
| `GraphValidator` | 포트 호환성·scope·누락 참조·cycle·출력 경로 검사 |
| `ArrangementCompiler` | 순서·반복·전환을 절대 시간 occurrence로 전개 |
| `SectionGraphCompiler` | 각 occurrence 내부 event clock·processor 경로·출력 계획 생성 |
| `ExecutionPlan` | renderer가 실행할 불변 계획; 캔버스 좌표에 의존하지 않음 |
| `EditorTarget` | 프로젝트·섹션 사용·자식 node ID·편집 범위; 창과 선택의 대상 일치 유지 |

실행 흐름은 `Project snapshot → 설정 해석·그래프 검증 → 송폼 occurrence → 내부 신호 계획 → render/playback/export`다. 녹음은 선택한 오디오 또는 MIDI 서클에 take를 추가한다. 복구·undo·저장은 캔버스와 사각 편집 창이 같은 문서를 사용한다.

같은 instrument를 여러 섹션에서 쓰는 요구는 유지한다. 각 서클은 공유 자원을 참조할 수도, 명시적으로 독립 설정을 가질 수도 있다. 그림상 악기 서클을 다시 썼다는 이유만으로 plugin 실행 instance를 공유하거나 매번 새로 만들지 않는다. 서로 다른 동시 tempo, effect tail, automation, plugin host transport를 고려해 instance 공유 범위를 결정한다. 이 공유 정책과 외부 plugin 격리는 후속 기술 결정이다.

`다시 사용`은 내부 그래프 원본을 공유한다. `이번 사용만 편집`은 node·edge의 stable ID 기준으로 추가/수정/삭제 override를 만들고, `원본 분리`는 현재 유효 그래프를 새 ID로 복사한다. 변경된 노드를 참조하는 edge·automation·editor target도 함께 갱신한다. 원본에서 삭제된 노드에 사용별 edge가 남으면 조용히 다른 노드에 재연결하지 않고 충돌을 표시한다.

## 현재 코드와의 차이·전환 순서

현재 코드의 `Section.lanes`는 `Lane.notes`와 `Lane.audio`를 담고, `Track.instrument`가 악기를 정한다. `SectionUse.effects`는 목록이며 프로젝트에 별도 `SignalGraph`가 있다. 섹션 내부 서클 그래프를 담는 타입과 편집기가 아직 없다. 원형 아이콘만 추가해 해결되는 변경이 아니다.

| 단계 | 구체적인 대상 | 완료 근거 |
|---|---|---|
| 1. 저장·도메인 | `Sources/CirclrCore/Model.swift`, `ProjectStore.swift`와 관련 core 테스트 | versioned migration, stable ID, 원본/사용별 변형, round-trip |
| 2. 시간·신호 계획 | core compiler와 `Sources/CirclrAudio/Renderer.swift` | 내부 routing·반복·tempo·effect scope 결과 확인 |
| 3. 같은 캔버스의 중첩 | `Sources/CirclrApp/CanvasView.swift`, `CanvasState.swift`, `AppStore.swift` | 부모/자식 좌표·hit·선택·포트·zoom·undo·저장 |
| 4. 정밀 편집 연결 | `EditorWindow.swift`, `CircleWorkspace.swift`, `UnifiedSectionView.swift`와 MIDI/audio 편집기 | node ID별 편집 대상·창 닫기·focus·선택 변경 |
| 5. 실행 검증 | core/audio 테스트, 별도 QA 곡, native macOS 앱 | 이전 곡 보존·실제 편집·재생·export 회귀 |

기존 package의 `schemaVersion`은 1이다. 새로운 schema 번호와 migration을 정의한 뒤 원본 package를 보존하고 새 사본에서 검증한다. 기존 lane의 note 묶음과 각각의 audio clip을 음악 서클로 대응시키며 원본 asset·take·시작 위치·변형 정보를 보존한다. 이 문서 작성으로 기존 사용자 곡을 변환하지 않는다.

특히 현재 renderer는 각 트랙의 섹션 연주에 `SectionUse.effects`를 적용한 뒤 프로젝트 사운드 graph로 보낸다. 이를 새 섹션 출력의 단일 effect로 옮기면 distortion/compressor 같은 nonlinear 처리 결과가 달라질 수 있다. migration은 기존 적용 위치를 그대로 보존하는 경로를 만들고, 공유 effect로 합치는 변경은 별도의 음악 편집으로 취급한다. 기존 글로벌 bus와 plugin state도 함께 대응해야 한다.

## 인수 시나리오 — 아직 실행하지 않음

1. 빈 벌스 그룹 안에 MIDI·악기·오디오·이펙터·출력 서클을 만들고 두 연주 경로를 연결한다. 모든 요소가 실제 객체로 저장되며 내부 구성을 보기 위해 편집 창을 열 필요가 없다.
2. 그룹 이동·접기·확대·정렬 후 event 시간·소리·연결은 그대로다. 잘못된 부모로 끌어 지나가도 소속이 바뀌지 않는다.
3. MIDI 서클 더블클릭으로 사각 편집 창을 열어 note를 바꾼다. 다른 MIDI/오디오 서클 선택 뒤 이전 대상의 지연 작업이 새 대상에 적용되지 않는다. 닫으면 같은 캔버스 위치로 돌아온다.
4. 8마디 섹션 안의 2마디 리프 총 4회, 섹션 총 2회에서 리프가 총 8번 실행된다. 재사용한 후렴 하나의 note/edge만 바꾸고 다른 후렴과 원본이 유지되는지 확인한다.
5. 120 BPM 부모 안의 60 BPM 자식, 개별 7/8 자식, 글로벌 pattern 한 개를 함께 사용한다. 시작 시각과 길이를 sample 기준으로 확인하며 pattern 중복·자동 pitch 변경이 없다.
6. audio 입력과 MIDI 출력을 잘못 연결하거나 feedback을 만들 때 정확한 포트/경로를 설명한다. 연결선의 길이·곡률은 처리 결과에 영향을 주지 않는다.
7. 이전 곡을 보존한 사본에서 migration·undo·저장/재열기를 확인한다. deterministic native effect 경로는 파형 비교, 실제 AU는 재현 가능한 별도 청취/상태 확인으로 검증한다.
8. 휠 확대/축소와 섹션 안팎 이동이 자연스럽고, 사각 편집 창·메인 창 최소화·실제 종료의 동작이 유지된다. native 화면 검증과 실제 오디오 검증 결과를 각각 기록한다.
