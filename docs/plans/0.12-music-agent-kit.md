# 0.12 음악 에이전트 키트 실행 계획

- Owner: development-lead → skill author / Python integration → QA (단일 실행 슬롯, 순차 수행).
- Outcome: `$circlr-studio`로 음악 작업을 조율하고 8종의 전문 Codex custom agent를 호출할 수 있는 프로젝트 설치 및 앱 번들.
- Paths: `Resources/Codex/`, `scripts/build-agent-kit.py`, `mcp/server.py`, `mcp/test_server.py`, `qa/test_agent_kit.py`, `scripts/package-app.py`, `Resources/Info.plist`, `README.md`, `CHANGELOG.md`, `docs/24-music-agent-kit.md`, `docs/20-codex-account-console-plan.md`.
- Runtime install: 이 저장소의 `.agents/skills/circlr-studio`, `.codex/agents/circlr-*.toml`, `.codex/config.toml`의 전용 MCP 설정. 기존 파일은 관리된 버전과 일치할 때만 갱신. 사용자 전역 설정/인증/모델은 변경하지 않는다.
- Contract: artist 의도가 최우선; specialist는 담당 파트와 읽은 revision에 대한 편집안을 제출; main session이 단일 writer. MCP 읽기 전용 adapter는 쓰기·재생·정지·focus를 실제로 차단한다. 이는 시스템 전체 권한 격리를 대체하지 않는다.
- Role scope: producer, arranger, performer, beatmaker, topliner, sound-designer, mixing-engineer, mastering-engineer. 전문 자료는 필요할 때만 읽고, 코드 이름만으로 청취 또는 음악적 완성도를 주장하지 않는다.
- Acceptance: 형식 검증, installer 최초/재실행/갱신/사용자 수정 충돌·롤백, 읽기 전용 우회호출 거부, 실제 Codex skills/list 검색, app resource hash와 codesign 검증.
- Assumptions: Codex 0.149.1의 standalone agent TOML; 모델·effort·동시성은 사용자 runtime을 따른다. 설치 도구는 Python 3.11+; 기존 MCP는 Python 3.9+ stdlib. 앱 내 로그인/LLM 대화는 기존 후속 계획으로 남긴다.
- Git: 기존 전체 untracked 파일을 보존하며 요청 범위만 작성. commit/push 없음.
- Sources: 사용자가 제시한 OpenAI latest-model, 공식 Codex skills/subagents 문서, 로컬 App Server schema, Berklee 역할 설명을 대조. 외부 배포·유료 음악 생성 없이 오프라인 검증.
