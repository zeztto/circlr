상태: **RELEASED_WITH_QA_WAIVER**. 2026-09-11 사용자가 한글 IME 및 남은 native QA를 유예하고 build160 정식 게시를 승인했다. 실제 QA 실행 결과는 보존하며 모든 gate PASS로 처리하지 않는다. 사용자가 공개 전환을 확인하고 코드 MIT·데모 별도 조건을 선택했다. 출고 패키지는 라이선스 고지를 추가한 build161이다. 시작 기준: `codex/daw-integration`의 build152 및 검증 기록 commit `4abf43c`. 계획 도입 commit `7a1ba7f`에서 구현 브랜치를 생성했다. 목표 앱 버전은 0.30.0, 출고 후보는 메뉴 대비 수정·컬러 데모 v5·라이선스 고지를 포함한 build161이다. 높은 콘솔의 페달 수치 가림·Tab 자동 노출을 수정하고 재검증했다.

## 결과와 범위

사용자가 새 곡에 섹션을 만들고 드럼/신스 MIDI와 오디오를 배치한 뒤, 효과와 automation을 적용하고 송폼을 바꾸며 실제 재생·바운스·저장/재열기까지 수행한다. 작업은 기존 단일 다크 캔버스에서 이어져야 한다.

포함: 기존 제작 기능의 연속 사용 중 발견되는 데이터·범위·입력·가시성·파일/재생 오류, 키보드 포커스, 명확한 대기/실패/취소, 현재 schema 호환, 검증된 실제 패키지.

후속 범위: 새 악기 엔진의 대규모 재설계, 녹음 기능 확장, 새로운 일반 CC/plugin automation, 앱 내 계정 대화, 아티스트 catalog, 발매 수준 데모 완성. 기존 녹음/영상 기능에 회귀를 만들지 않아야 하지만 그 전체 품질 인증은 0.40/0.90의 필수 조건이다.

## 설계 불변 조건

- 서클은 시간 궤도이며 화면 배치 변경이 노트 시간·연결 의미를 임의로 바꾸지 않는다. 새로운 고정 좌우·하단 편집 패널을 추가하지 않는다.
- 이번 use·섹션 원본·공유 패턴을 명시한다. GUI·키보드·MCP가 같은 편집/Undo 계약을 사용한다.
- 수치·이름 초안과 IME 입력을 늦은 포커스가 가져가지 않는다. 파일 읽기 대기는 완료/실패와 구분하고 취소 후 입력 가능한 상태를 회복한다.
- 기존 노트·원본 오디오·라이선스 자산을 보존한다. 저장 schema는 불필요하게 올리지 않는다.
- 물리 I/O를 차단한 QA와 실제 재생을 구분한다. 장치 검증을 실행할 수 없으면 출고 gate가 열린 상태로 남는다.

## 검증 명령과 증거 기록

[공통 QA 명령](README.md)을 사용한다. 수정한 Audio test class의 이름/필터와 물리 I/O 여부를 실행 전에 이곳에 추가한다. 최종 후보 build에서 Core·MCP와 영향받는 Audio 회귀, 위 native matrix를 실행한다. 전체 테스트 반복 횟수를 완료 기준으로 삼지 않는다.

증거 행은 `Q ID | build/commit 또는 candidate SHA | 실행 환경 | 명령/조작 | 예상/실제 | PASS/FAIL/NOT_RUN | 증거 위치`로 기록한다. 로그는 민감정보를 제거하고 재현 가능한 요약은 commit한다. 큰 WAV·QA 앱·스크린샷 묶음은 로컬에 보관한다. 실패를 수정한 경우 최초 실패와 재검사 범위를 모두 남긴다.

실행 근거는 [0.30.0 후보 QA 기록](0.30.0-qa.md)에 모은다. 부분 검증은 전체 gate PASS가 아니다.

## 위험과 대응

- 기존 HAL 대기의 원인은 미확정이다. 장치·프로세스·timeout 기록으로 원인을 좁히고, 사용자 앱을 변경하지 않는 진단부터 시작한다. 원인 확인 전 엔진 전면 재작성으로 범위를 넓히지 않는다.
- 공통 포커스 변경은 IME·수치 draft 회귀 위험이 있다. 대상 identity와 async 요청 수명을 함께 검증한다.
- 공유 패턴과 use 변형은 데이터 누수 위험이 있다. 정상 대상과 비대상 모두 비교한다.
- package-app은 dist 앱을 바꾼다. release checkout과 사용자 앱 경로를 먼저 구분하고 이전 앱/프로젝트 백업을 보존한다.
- 필수 결함은 이 버전에서 해결한다. 새 기능은 다음 버전으로 보내며 일정 때문에 완료 기준을 낮추지 않는다.

## 검토·릴리스 기록

계획 독립 검토: release_process_audit PASS. 승인 전 QA와 승인 후 원격 tag 확인이 순환하던 지적을 수정했고, 후보 패키지 준비→QA/검토→문서/commit/tag/push 순서의 재검토를 통과했다. 링크·소유 경로·작업 8개·필수 QA 10개와 diff 검사를 통과했다.

제품 구현 독립 검토: build155 범위에서 release_process_audit PASS. 비동기 MIDI 읽기 동안 라이브러리 접근 권한이 해제되는 지적을 수정하고 재검토했다. build157의 높은 콘솔 결함 수정도 소스 재검토 PASS, native Tab·오류 표시·Escape 복구를 확인했다.

출고 결정: 미승인. 실제 후보 버전/build·artifact SHA·호환·백업/복구·필수 QA를 확인한 뒤 리드가 APPROVED로 기록한다.

출고 후 필수 확인: R30-08에서 원격 release branch와 annotated tag의 peeled SHA가 승인 commit과 일치하는지 확인한다. 한·영 릴리스 노트, 검증된 ZIP·SHA256SUMS를 GitHub Release에 등록하고 URL, `isDraft=false`, `isPrerelease=true`, 내려받은 자산의 hash를 검증한다. 이는 승인 전 Q10과 분리된 RELEASED gate다. [등록 절차](README.md)를 따른다.

원격 릴리스: 없음. 필수 QA가 남아 있으므로 현재 build157에는 tag나 GitHub Release를 만들지 않는다. 계획을 문서 commit/push한 것은 0.30.0 완료나 tag 발행이 아니다. 릴리스 태그 예정: `v0.30.0`.

## 현재 후보 배포 — preview.1

사용자의 현재 버전 병합·등록 요청에 따라 build158을 `main`에 통합하고 `v0.30.0-preview.1` GitHub prerelease로 배포한다. [한영 배포 노트](0.30.0-preview.1-notes.md)를 따른다. 필수 QA 표와 IN_PROGRESS 상태는 유지하며 정식 `v0.30.0` 또는 R30-08 완료를 뜻하지 않는다.

### Preview 게시 확인

상태: **PREVIEW_PUBLISHED**. [GitHub Release](https://github.com/zeztto/circlr/releases/tag/v0.30.0-preview.1), `isDraft=false`, `isPrerelease=true`. 태그가 가리키는 main 병합 commit은 `08fbaf61eb580898d89abd12219138e62d47f44d`다. 한·영 노트와 Apple Silicon ZIP·SHA256SUMS 2개 자산 등록을 확인했다.

GitHub에서 ZIP과 SHA256SUMS를 다시 내려받아 첨부 checksum 및 로컬 ZIP과 모두 일치함을 확인했다: `a1ba71af234c1299d10946d3ad8f90e2639575a5469ab7cfa029aebf473cf20b`. 현재 마일스톤은 여전히 IN_PROGRESS다. 이 게시 확인 기록은 배포 소스 이후의 문서 갱신이며 태그를 이동하지 않는다.
