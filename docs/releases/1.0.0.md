# 1.0.0 — AI와 함께 곡을 완성하는 DAW 기준판

상태: PLANNED · 기준: [0.80 개발 후보](0.80.0.md), [0.90 안정화 계획](0.90.0.md) · 최신 정식판: `v0.70.0`. 날짜나 버전 숫자만으로 출고하지 않는다. 1.0의 성공은 실제 앱에서 음악을 만들고, 듣고, 되돌리고, 저장·출력하는 동선과 본인 Codex 계정의 AI 작업을 끝까지 검증한 결과다.

## 전제와 제품 경계

- 0.80의 짧은 한 곡 제작·재생·녹화와 0.90의 반복·장시간·복구 gate를 통과한 동일 계열 소스를 사용한다. 한 장치의 무음 자동 테스트는 청취나 다른 장치 호환성을 증명하지 않는다.
- AI는 송폼과 MIDI·오디오·악기·효과·오토메이션·바운스를 **실제 circlr 프로젝트의 typed 작업**으로 수행한다. 자연어 응답만으로 편집 성공이라고 보고하지 않는다. 기존 외부 MCP와 수동 DAW는 AI 연결 여부와 무관하게 동작한다.
- 사용자는 자신의 Codex/ChatGPT 계정으로 앱 안의 콘솔에서 대화하고 진행·승인·중단을 확인할 수 있어야 한다. OpenAI API key나 별도 API 과금 계정을 이 요구의 대체물로 취급하지 않는다.
- [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)는 현재 `codex app-server` 명령을 experimental이며 production 미지원이라고 명시한다. [OpenAI의 제품 통합 안내](https://developers.openai.com/blog/codex-as-a-platform)는 지속 대화·이벤트·승인이 필요한 앱의 통합 경로로 App Server를 제시한다. 두 사실을 함께 적용해 내부 codec·gateway는 준비하되 지원·배포 조건을 확인하기 전에는 계정 UI를 공개하지 않는다. 상세 설계는 [계정 콘솔 계획](../20-codex-account-console-plan.md)을 따른다.
- [Codex SDK 문서](https://learn.chatgpt.com/docs/codex-sdk)의 Python SDK는 stable 배포본과 고정된 CLI runtime을 제공하지만 내부에서 App Server를 제어한다. 이 패키지의 안정판 표기를 App Server 기반 앱의 production 지원 근거로 사용하지 않는다. G0에서 통합·재배포 조건을 별도로 판정한다.
- 공식 [CLI 명령 표](https://learn.chatgpt.com/docs/developer-commands)에서 stable인 `codex exec`는 [비대화형 작업·JSONL·재개](https://learn.chatgpt.com/docs/non-interactive-mode)를 지원한다. 사용자 설치 CLI로 짧은 범위 제한 작업을 내부 시험할 수 있지만, 중간 승인·steering을 포함한 완전한 인앱 대화나 CLI 재배포 권한을 입증하지 않는다. R100-03~05의 완료 조건을 낮추지 않는다.

0.80 build225는 앱이 선택한 section/lane/track에 한정된 내부 `TrustedAgentIngress`를 직접 소유한다. 실제 socket에서 MIDI 편집→사용자 Undo→nonzero bounce, 완료/STOP/만료·문서 교체 정리를 통합 시험했다. 이는 R100-04의 **부분적인 앱 내부 준비**일 뿐이다. 공개 기능의 필수 후속 검증은 앱이 시작한 전용 MCP helper의 프로세스 신원, capability의 모델·shell·환경변수 비노출, 매 turn 새 helper/channel 보장, 재생 중 STOP의 transport 보존, WAV 게시 중단과 실제 계정 turn의 중단·재시작 경합이다. 기존 외부 MCP socket을 신뢰된 Codex 경로로 재사용하지 않는다. [계정 콘솔 구현 계획](../20-codex-account-console-plan.md) · [build225 QA](../../qa/0.80-build225-ai.md).

build232는 콘솔에 현재 내부 trusted turn의 소유 job이 보일 경우 `AI 중단`을 job만 취소하는 동작과 분리했다. 통합 테스트는 lease 철회·socket 폐쇄·늦은 bounce/apply 차단과 일반 공개 job 취소의 독립성을 확인한다. 현재 앱 UI에서 사용자 계정으로 trusted turn을 시작하는 연결은 여전히 없고, 재생 중 AI 중단의 실제 오디오 보존도 확인해야 한다. [build232 QA](../../qa/0.80-build232.md).

Codex CLI 0.149.1의 [build210 당시 앱 밖 개발 smoke](../../qa/0.80-build210-codex-smoke.md)는 ChatGPT 로그인 조회와 명시적 호환 모델의 한 turn 완료를 확인했다. 당시 전역 기본 모델은 이 CLI보다 새 런타임을 요구해 실패했다. 모델·런타임 협상, 앱 안의 콘솔 스트림, 음악 도구의 turn별 권한, 배포와 계정 격리는 아직 검증되지 않았다. build211 내부 보안 리뷰로 child 환경 설정을 필수로 바꾸고, 관리형 세션의 승인 cwd·읽기 전용 thread ID 결합을 추가했지만 앱 연결·계정 격리의 운영 검증은 여전히 남는다.

[QA232 외부 모델→MCP→격리 실제 앱](../../qa/0.80-qa232-model-native.md)은 ChatGPT 로그인 CLI가 네 MIDI note의 단일 batch 편집·Undo·재적용·저장/재열기·70초 nonzero WAV까지 수행한 범위에서 성공했다. 이는 앱 내부의 계정 대화·권한 부여 경로가 아니다. `snapshot`/`inspect` 전체 구조를 모델에 반복 전달한 두 시도는 큰 token 사용량을 기록했다. R100-05 전에 선택 use/lane과 revision·필요 필드만 돌려주는 범위 선택형 읽기, 응답 크기 상한, tool 결과 요약을 설계하고 실제 prompt/token 계측으로 검증한다. 정확한 모델 ID도 QA trace에서 노출되지 않아 후속 실행에서는 명시적으로 고정해야 한다.

## AI 인수 시나리오

1. 사용자가 QA 사본의 Chorus를 선택해 자신의 계정으로 “후렴 베이스를 간단하게 편곡하고 들려줘”라고 요청한다. 콘솔은 실제 tool/job/Undo 상태를 보여준다. 변경 전후 MIDI·프로젝트 revision·렌더 PCM이 달라지고, 사용자가 되돌리면 원상 복원된다.
2. 렌더 WAV의 임시 파일에 PCM이 쓰이는 동안 AI turn을 중단한다. 재생 중인 음악은 계속되고, 추가 파일 게시·문서 수정은 없다. 이미 완료한 편집은 남아 명시적 Undo가 가능하다. 새 turn에서는 사용자의 새 허용으로 작업을 재개한다.
3. 대화 중 다른 프로젝트를 열거나 녹음을 시작한다. 이전 프로젝트의 늦은 tool 결과가 새 문서·media를 변경하지 않는다. 같은 request 재전송과 연결 재시작에서도 중복 바운스가 생기지 않는다.
4. 네트워크·인증·한도 실패 시 입력 초안을 보존하고 수동 편집·재생을 계속한다. 모델로 전송된 실제 payload에서 불필요한 절대 경로·인증정보·원본 sample을 찾지 못해야 한다.

각 시나리오는 protocol fixture, 격리 native 앱, 실제 계정 응답, 음악/파일 검사와 물리 청취를 구분해 보고한다. AI 서비스 응답과 비용이 발생하는 실제 계정 검증은 짧은 QA 범위에서 수행한다. 내부 codec 테스트나 기존 외부 MCP의 PASS만으로 R100-03~05를 완료 처리하지 않는다.

## 버전 운영

0.80/0.90의 미해결 DAW gate를 1.0으로 이름만 옮기지 않는다. 작은 결함은 해당 정식 버전 출고 후 patch로 수정할 수 있으며 관련 QA를 다시 통과해야 한다. 1.0 후보도 [릴리스 규약](README.md)의 계획→구현→실제 QA→독립 검토→문서·스크린샷→commit/tag/Release→원격 검증 순서를 따른다. G0나 핵심 작업이 막히면 내부 작업을 계속하되 정식 태그와 비동작 계정 UI는 내지 않는다.
