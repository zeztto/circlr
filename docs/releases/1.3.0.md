# 1.3 · 보존·복구와 기본 조작 신뢰성

상태: PLANNED · 기준: 1.2.0/build253 · 구현/QA/build 미착수

[2.0까지 상세 계획](2.0-development-plan.md)의 첫 실행 버전이다. 새로운 recovery 시스템을 전면 작성하는 일이 아니라, 기존 저장·복구·미디어 동선을 실제로 재현해 확인된 결손을 고치는 작업이다.

## 목표·제외 범위

편집·저장·재생 중 문제가 나도 마지막 유효 작품을 보존하고 사용자가 복구할 수 있어야 한다. 계정 없이 동작하며, 다음 버전의 녹음 시간을 안전하게 기록할 수 있는 기반을 확정한다.

제외: overdub/count-in 구현, artist catalog, AU 지연 보정, 영상 최적화, 새 음색 확장. 이 영역에서 데이터 손상이나 기존 기능의 심각한 회귀를 발견하면 즉시 차단 결함으로 분리한다.

### 최초 planning gate

1. 현재 main과1.2 source/tag, 작업 중인 checkout·파일 상태를 확인한다. 보호할 사용자 원본을 식별하고 격리 사본을 만든다.
2. 기존 테스트를 읽고 같은 계약을 반복 검증하는 테스트를 새로 만들지 않는다. 실패 재현·경계 조건을 추가한다.
3. QA20건을 아래 matrix에서 구체적인 파일/예상결과로 확정한다. 실제 source 결함이 없으면 ‘신규 기능 구현’이 아니라 검증 완료로 기록한다.
4. 새로운 파일/schema가 필요하면 migration·실패 복구·rollback을 먼저 문서화한다. 스키마 변경이 불필요하면1.2 형식을 유지한다.
5. 버전 시작 branch는 최신main의 `release/1.3.0`이다. 이 계획 작성 단계에서는 branch와 후보 build를 만들지 않는다.

## 필수 재현 matrix

| 묶음 | 조건 | PASS의 의미 |
|---|---|---|
| 저장 무결성 | 저장 전/쓰기 중/원자 교체 전후 강제 종료 | 마지막 완전본 또는 완전한 새 본으로 열린다. 중간 상태를 성공본으로 쓰지 않음 |
| 파일 시스템 | 공간 부족, 쓰기 권한 없음, 외장 media 분리 | dirty 유지, 원본 hash 유지, 다시 시도 가능한 이유 표시 |
| recovery 소유 | 동일 복구 위치를 쓰는 두 QA process | 다른 process의 복구 자료를 덮어쓰거나 지우지 않음 |
| media 매칭 | 파일 이동, 같은 이름 다른 내용, 대소문자/Unicode 이름, 중복 asset | 잘못된 source 자동 연결0건; 사용자가 고른 후보를 검사하고 변경 범위 표시 |
| portable copy | asset 누락, 복사 중 취소, 목적지 충돌, 충분한 공간 | 원본 무변경; 성공본만 완전한 project로 열림 |
| 편집 이력 | clipboard/섹션 재사용/automation/오디오편집 후 Undo/Redo·저장 | musical values와 참조가 예상과 일치 |
| 작업 경계 | 렌더/loop 준비 중 Stop·문서 전환·앱 종료 | 늦은 commit·엉뚱한 문서 수정·helper 잔류0건 |
| native 입력 | 한글 조합 중 ⌘S/⌘Z/⌘C/V,700pt·가로, keyboard-only | 텍스트와 노트 명령이 섞이지 않고 핵심 동작 수행 |

권한 취소나 공간 부족은 사용자 디스크를 채우거나 권한을 광범위하게 바꾸어 재현하지 않는다. 격리 QA 경로·fault injection·제한된 테스트 볼륨을 우선한다. 실제 앱의 파일 선택·오류·복구 UI 검증은 별도로 수행한다.

## 검사 명령과 결과 보존

아래는 앞으로 실행할 명령이다. 아직 PASS 결과가 아니다.

```sh
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter CirclrCoreTests
# 관련 App/Audio test class는 소유 범위와 실제 발견 결함을 기준으로 qa/1.3-plan.md에 고정한다.
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Tests -p 'test_mcp_*.py'
./scripts/build-app.sh
codesign --verify --deep --strict 'dist/써클러.app'
git diff --check
```

버전 전체 통합 검사는 최종 후보에서 한 번 수행하고, 수정이 있으면 영향 범위만 재검증한다. `qa/evidence/r130-*.json`에 기준 build/source·조건·실제 결과·원본/결과 hash·미검증을 남긴다. raw 로그와 QA 음악 파일은 공개 소스에 자동 포함하지 않는다.

## 사용자 검수와 마감

사용자 조작이 필요하기 전까지 자동·MCP·허용된 격리 앱 검증을 완료한다. 한글 IME와 실제 복구 경험에 사용자가 필요하면 테스트 파일·행동 순서·기대 결과를 하나의 검수 묶음으로 제공한다. 실제 IME를 확인하지 못하면 자동 입력 성공으로 대체하지 않는다.

출고 조건: 정의한20개 이상 장애 시나리오, cold reopen, media 재연결/portable copy, 변경된 컨트롤의 native 입력, 독립 리뷰 차단 결함0, 문서·최신 스크린샷, main/tag/정식Release와 원격 asset 확인. 목표를 일부 달성했다고 버전 숫자만 올리지 않는다.

수정 범위가 예상보다 크면1.3 필수 사용자 결과를 다시 정리하고 나머지를1.4 이후 backlog에 넣는다. 단, 데이터 손상·권한 결함이나1.3 필수 복구 실패를 그대로 두고 완료 처리할 수는 없다.
