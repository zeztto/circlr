# 0.80.0 — 읽기 쉬운 궤도와 핵심 제작 안정화

상태: IN_PROGRESS · 기준 `v0.70.0` (`055ad3259b2f07adb5c1405373934f893fe983bb`) · 구현 브랜치 `release/0.80.0` · 현재 개발 후보 0.80.0/build211. 이 문서는 착수 범위이며 출시나 기능 완성을 뜻하지 않는다.

0.70.0은 사용자의 지시에 따라 열린 native QA를 공개한 채 정식 출시했다. 이는 0.80의 PASS 증거가 아니며 반복 검증에서 회귀를 별도로 판정한다.

## 이번 버전의 사용자 작업

사용자는 곡을 축소해 전체 궤도를 볼 때 신호 경로의 존재와 선택된 경로를 쉽게 구분하고, 확대하면 정확한 포트/연결 정보를 다시 볼 수 있어야 한다. 가로·세로 창 모두 상단 주요 조작과 녹화 상태를 알아볼 수 있어야 한다. 먼저 한 곡의 재생·녹화·편집·저장·바운스를 실제 앱에서 끝까지 마쳐야 한다. 본인 Codex 계정으로 앱 안에서 대화하는 원래 구상은 유지하지만, 공식 production 지원 경로가 확인될 때까지 공개 0.80 출고 범위에서 분리한다. 기존 MCP·하단 작업 로그 콘솔은 유지한다.

2026-09-23 사용자 목표 변경에 따라 버전 숫자보다 핵심 기능의 실제 동작과 UI 품질을 우선한다. [0.90 안정화 계획](0.90.0.md)은 이 짧은 제작 경로를 장시간·반복·고밀도 상황까지 확장한다. 0.80.x는 0.80.0 출고 전에는 사용하지 않는다.

## UI 인수 기준

- **정보 우선순위:** 선택·hover·연결 드래그 중인 경로 > 현재 재생 신호의 이동 표식 > 그 밖의 활성 경로 > 비활성 경로다. 고밀도 재생에서 활성 케이블이 많더라도 모든 케이블 몸체가 동시에 선택 경로만큼 밝아지지 않아야 한다. 선택을 풀면 원래 우선순위로 돌아가며 데이터와 포트 hit 영역은 그대로 둔다.
- **줌·상태 매트릭스:** 확대에서는 전체 포트 이름·방향·케이블을, 중간 배율에서는 선택/hover 라벨과 음악 흐름을, 개요에서는 방향 점과 주요 경로를 먼저 읽는다. 정지/재생/감상/녹화 네 상태에서 같은 음악 경로를 가리키며 감상 모드와 MP4에는 편집 UI를 끌어오지 않는다.
- **상단 상태:** 700pt에서는 기본 재생·중단, 녹화, 감상, 서클 추가가 화면 안에 남아야 한다. 녹화 준비/진행/저장 중에는 진행 상태가 구별되고 저장 성공·실패는 기존 실제 결과에 근거해 표시한다. 녹화와 감상 버튼은 나란히 배치하고 좁은 창에서도 축소된 조작의 접근성 이름을 유지한다.
- 첫 후보의 줌 표현은 `zoom≥0.90`에서 전체 연결/포트, `0.55–0.90`에서 비관련 선·화살표의 점진적 약화, 약 `zoom≤0.64`에서 비관련 포트의 작은 IN/OUT 점과 포커스 라벨만 표시한다. 이 값은 native 사용성 결과에 따라 조정할 수 있으며 음악 모델이나 연결의 존재를 바꾸지 않는다.
- 축소/중간/확대 세 단계에서 연결 종류·방향을 잃지 않으면서 선택 경로가 가장 잘 보인다. 선을 모두 숨겨 곡 구조를 속이지 않는다.
- 선택·hover·연결 드래그·재생 시그널·감상 모드와 화면 녹화에서 표현이 일치한다. MIDI/오디오/flow/sidechain 의미, 8방향 IN/OUT, 클릭 영역, Undo, 저장 후 재열기는 유지한다.
- 700·900·1280pt 경계와 넓은 가로/세로 창에서 주요 transport·녹화·감상 버튼이 겹치지 않는다. 키보드·VoiceOver가 시각적 단순화 때문에 사라지지 않는다.
- 비교 스크린샷은 같은 데모/밀도/카메라·최종 후보 build에서 얻고 `docs/images/README.md`에 출처를 기록한다. 가독성 평가는 UI 관찰이며 실제 FPS 증거와 구분한다.

## Codex 계정 콘솔 G0 확인 · 2026-09-23

공식 [App Server](https://learn.chatgpt.com/docs/app-server) 문서는 제품 내 대화·스트림·승인 통합 경로로 stdio JSONL을 설명하지만, **`codex app-server` 명령과 WebSocket transport가 experimental이며 production workloads에 지원되지 않는다**고 명시한다. 비실험 메서드만 사용해도 명령 자체의 지원 상태는 바뀌지 않는다. [기능 성숙도](https://learn.chatgpt.com/docs/feature-maturity) 기준과 함께 공개 앱의 계정 콘솔 배포 gate를 **NO-GO**로 둔다. 앱에는 로그인 버튼이나 성공하지 않는 대화 UI를 추가하지 않는다. 기존 MCP·작업 로그 콘솔은 유지한다.

개발용 계약은 `initialize`/`initialized` → `account/read` 및 관리형 ChatGPT 로그인 → `thread/start|resume` → `turn/start` → item/turn 이벤트 → `turn/interrupt`와 서버 발신 승인 응답이다. `experimentalApi`는 끄고, 음악 편집은 circlr MCP gateway의 별도 lease/revision 검사로 제한한다. 이는 구현 완료나 계정 로그인 QA 결과가 아니다. [인증](https://learn.chatgpt.com/docs/auth)은 `keyring` 저장을 설명하지만 `CODEX_HOME`별 Keychain 격리를 보장하지 않는다. [소스 공개](https://learn.chatgpt.com/docs/open-source) 역시 선택한 바이너리의 재배포·서명·공증 검증을 대신하지 않는다.

G0 재개 조건은 공식 production 지원 경로의 확인, 고정할 runtime/schema/hash/라이선스, macOS credential 격리, 깨끗한 Mac의 앱 단독 설치·로그인·스트림·STOP·승인·MCP·서명 검증이다. 사용자의 핵심 기능 우선 지시에 따라 **계정 대화를 공개 0.80 범위에서 분리**했다. 이는 계정 기능의 완료나 G0 통과가 아니며, 본 버전의 오디오·영상·제작 QA가 끝나야 출고할 수 있다.
