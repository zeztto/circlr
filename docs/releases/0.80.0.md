## 이번 버전의 사용자 작업

사용자는 곡을 축소해 전체 궤도를 볼 때 신호 경로의 존재와 선택된 경로를 쉽게 구분하고, 확대하면 정확한 포트/연결 정보를 다시 볼 수 있어야 한다. 가로·세로 창 모두 상단 주요 조작과 녹화 상태를 알아볼 수 있어야 한다. 같은 캔버스의 하단 콘솔에서는 본인 Codex 계정으로 음악 작업을 요청하고, 진행 상황과 실제 변경을 확인하고, 음악 재생과 독립적으로 AI 작업을 멈출 수 있어야 한다. 단, AI 계정 기능은 공식 계약·배포·보안 gate가 먼저 닫힐 때에만 사용자 기능으로 노출한다.

## UI 인수 기준

- 첫 후보의 줌 표현은 `zoom≥0.90`에서 전체 연결/포트, `0.55–0.90`에서 비관련 선·화살표의 점진적 약화, 약 `zoom≤0.64`에서 비관련 포트의 작은 IN/OUT 점과 포커스 라벨만 표시한다. 이 값은 native 사용성 결과에 따라 조정할 수 있으며 음악 모델이나 연결의 존재를 바꾸지 않는다.
- 축소/중간/확대 세 단계에서 연결 종류·방향을 잃지 않으면서 선택 경로가 가장 잘 보인다. 선을 모두 숨겨 곡 구조를 속이지 않는다.
- 선택·hover·연결 드래그·재생 시그널·감상 모드와 화면 녹화에서 표현이 일치한다. MIDI/오디오/flow/sidechain 의미, 8방향 IN/OUT, 클릭 영역, Undo, 저장 후 재열기는 유지한다.
- 700·900·1280pt 경계와 넓은 가로/세로 창에서 주요 transport·녹화·감상 버튼이 겹치지 않는다. 키보드·VoiceOver가 시각적 단순화 때문에 사라지지 않는다.
- 비교 스크린샷은 같은 데모/밀도/카메라·최종 후보 build에서 얻고 `docs/images/README.md`에 출처를 기록한다. 가독성 평가는 UI 관찰이며 실제 FPS 증거와 구분한다.

## build181 첫 UI slice · 2026-09-23

`AlbumCanvas.swift`에서 축소할수록 비선택 연결선/화살표가 점진적으로 옅어지도록 했다. 선택·hover한 경로와 포트는 강조하고, 비포커스 포트는 작은 점으로 표시하면서 **OUT 채움 / IN 빈 점**을 유지한다. 개요 라벨 배치는 포커스 포트만 요청해 숨긴 라벨이 공간을 예약하지 않는다. 연결선 자체와 포트 hit geometry, AX 케이블/포트 목록은 기존 경로를 유지한다. 재생 시 활성 연결의 신호 시각화는 유지한다.

- 코드 검토자가 포커스 라벨을 가리는 숨은 요청과 IN/OUT 동일 점 두 결함을 찾아 수정했다. 수정 뒤 `git diff --check`와 최종 release 빌드·ad-hoc 서명, 독립 QA 앱 0.80.0/build181 준비를 통과했다.
- 독립 재검토는 두 결함의 수정과 기존 hit/AX 경계 보존을 확인했고 새 고신뢰 P1/P2를 찾지 못했다. 포트 표시의 개요 단계 전환은 연속 줌 native 감각 조정 항목이다.
- 첫 수정 전 시작한 전체 Swift 테스트는 **1007개 실행·3개 skip·실패0**이었다. 검토 수정 뒤 최종 소스를 다시 컴파일한 `CanvasLabelLayoutTests`·`CirclePortPresentationTests` **12개 실패0**이었다. 이 둘이 새 `AlbumCanvas` 표시 로직을 직접 픽셀 검증하지는 않는다.
- 최종 QA 앱에서 f0r h3r를 열고 곡 궤도 진입, 두 단계 축소, 케이블 AX 선택을 확인했다. 선택된 케이블과 IN/OUT이 선명해지고 다른 선은 남으면서 옅어졌다. 재생 시작 후 Scarlett 6i6 USB 출력 장치를 앱이 확인했고 팔로우가 고밀도 섹션으로 이동했으며 Stop으로 끝났다. **실제 청취는 미확인**이다. 실행 앱은 종료했고 테스트용 프로젝트는 출고 자산이 아니다.
- 고밀도 섹션의 재생 화면은 여전히 조밀하다. 여러 활성 신호 경로·라벨·포커스 카메라의 결합을 후속 R80-01/02 조정과 native QA에 남긴다. 이번 관찰은 실제 compositor FPS 개선이나 모든 줌 단계·키보드·VoiceOver·감상 모드 완료 증거가 아니다.
