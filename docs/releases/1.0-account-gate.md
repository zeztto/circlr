# 1.0 계정 연결 경로 재검증 · 2026-09-30

상태: 조사 완료 · R100-03 미통과 · 실제 인증/모델 호출 없음.

설치된 Codex CLI는 `0.149.1`이며 `app-server --help`는 experimental로 표시한다. [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)도 app-server command와 WebSocket transport가 production workload 지원 대상이 아니라고 명시한다. 이 제한을 WebSocket만의 제약으로 해석하지 않는다. 기존 내부 codec과 gateway의 테스트는 배포 지원의 근거가 아니다.

별도로 [Sign in with ChatGPT의 OSS/local 앱 문서](https://developers.openai.com/siwc/token-sharing-open-source)는 OAuth로 사용자 ChatGPT 플랜의 사용량을 활용하는 Responses API 경로를 안내한다. 따라서 Responses 사용이 반드시 별도 API key·별도 과금을 요구한다고 일반화하지 않는다. [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)의 preview 표기만으로 모든 SIWC production 사용이 금지됐다고 단정하지도 않는다. 직접 Responses OAuth 경로의 production 적합성과 적용 약관은 추가 확인이 필요하다.

[SIWC App Server 연결 안내](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)는 앱의 token 갱신 책임과 child runtime 재시작·thread resume 경로를 제시한다. 이 안내만으로 위 App Server 지원 제한이 해제된 것은 아니다. 설치 npm package의 Apache-2.0 표기와 [공식 Open Source 목록](https://learn.chatgpt.com/docs/open-source)은 출처 근거이며 선택한 배포물의 NOTICE·종속 바이너리 검증은 별도다.

## 다음 구현 계약

- 계정 provider와 음악 편집 권한을 분리한다. 관리형 Codex 계정과 SIWC OAuth는 서로 다른 provider로 취급한다.
- token refresh 및 runtime restart 시 기존 RunLease를 철회하고 generation을 교체한다. thread resume이 과거 쓰기 권한까지 복원해서는 안 된다.
- 현재 `CirclrCodex`의 조회·turn/interrupt 코어를 앱 로그인 UI 완료로 표시하지 않는다. App target 연결, login/logout, refresh, resume, 인증 실패 시 수동 제작 유지가 필요하다.
- credential을 일반 환경 변수 allowlist에 단순 추가하지 않는다. 명시적 child 전달·로그 비노출·계정 격리를 별도 검토한다.
- 공개 계정 UI와 정식 출고는 R100-03 지원/인증/배포 및 R100-04 보안 검증 후 결정한다. App Server의 현재 제약을 영구 불가로 보지 않고, 직접 Responses OAuth 대안도 같은 기준으로 검토한다.

## 직접 SIWC provider · CONDITIONAL-GO

후속 조사에서는 App Server를 동봉하지 않는 **OAuth → Responses → 로컬 typed 도구** 경로를 우선 구현 대상으로 선정했다. 실제 계정·region·workspace eligibility는 미검증이며 이는 출시 승인과 구분한다.

[Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)에 따라 시스템 브라우저와 `127.0.0.1` loopback callback을 사용한다. 첫 등록의 `dynamic_agent_client`와 이후 callback에서 발급된 client ID를 구별하고 설치별 host ID를 유지한다. 매 인증마다 새 state/nonce와 PKCE S256을 사용한다. token 교환에는 발급된 client ID와 동일 redirect URI를 사용한다. client secret이나 별도 partner API key는 필요하지 않다. direct usage scope를 확인한 뒤 모델 호출을 허용한다.

[ID token 검증](https://developers.openai.com/siwc/website)은 JWKS 서명·issuer·audience·expiry·nonce 검증을 요구한다. JWT payload decoding만으로 로그인 성공으로 판단하지 않는다. [계정 수명](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)은 issuer/client ID/검증된 sub를 기준으로 분리한다. refresh는 직렬화하고 회전된 token을 원자적으로 교체한다. 로그아웃 시 진행 요청과 lease를 중단하고 remote revocation을 시도한 뒤 로컬 credential을 제거한다. 일시적 오프라인은 credential 삭제 사유가 아니다. macOS Keychain 저장 경로는 구현·보안 검증 대상으로 둔다.

[Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference)의 OAuth model 목록에서 표시 가능한 모델과 실제 요청 slug를 사용한다. Responses 요청은 `store:false`, `stream:true`, 배열 input이며 HTTP 대화 history는 앱이 관리한다. SSE text 수신만으로 성공 처리하지 않고 `response.completed`를 확인한다. Preview에서 hosted MCP는 지원되지 않으므로 앱 내부 function dispatcher가 기존 trusted 명령과 RunLease를 검사하도록 연결한다. [도구 제약](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations).

구현 순서는 (1) OAuth 상태·credential 경계와 검증 라이브러리 선정, (2) SSE/도구 호출과 중단·generation 검사, (3) 앱 콘솔 연결, (4) 실제 계정 인증·갱신·로그아웃·오프라인·음악 편집 시나리오다. 미지원 계정과 admission 오류를 별도로 처리하며, 과금·사용량과 ChatGPT 플랜 표시는 [UI 지침](https://developers.openai.com/siwc/ui-ux-guidelines)을 따른다. [오류 복구](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery)의 재동의·재시도 조건도 검사한다. 자동으로 API key 방식으로 전환하지 않는다.

## 구현 파일 경계 · 2026-09-30

- `Sources/CirclrCodex/SIWCAuth*.swift`: PKCE·callback·token/refresh·ID token 검증·Keychain. Foundation URLSession과 OS 암호화 기능을 사용하며 인증정보를 오류·로그에 넣지 않는다.
- `Sources/CirclrCodex/SIWCResponses*.swift`: OAuth 모델 목록과 Responses 요청·SSE·function 호출 이벤트. UTF-8/chunk 경계와 응답 크기를 제한하고 종료 전 또는 중단된 도구를 실행하지 않는다.
- `Sources/CirclrApp/ChatGPTAccount*.swift`: loopback listener와 앱의 계정 수명. browser open 전에 listener가 준비돼야 하며 timeout·취소·logout 후 늦은 callback은 credential을 복원하지 못한다.
- `Package.swift`: 앱에서 `CirclrCodex`를 참조한다. 공개 콘솔 조작은 실제 provider와 RunLease dispatcher의 통합 후 연결한다.
- 각 구현자는 같은 prefix의 관련 테스트를 소유한다. 빌드 슬롯은 순차 사용하고 최종 인증/입력 diff는 독립 보안 검토 후 commit한다. 실제 로그인·추론은 자동 fixture 검증과 구분한다.

첫 통합의 수용 조건은 테스트용 임의 계정 표시가 아니라, 검증된 credential만 사용한 요청, 취소 후 늦은 요청/결과 거부, 제한된 함수 dispatch, 인증 실패 중에도 기존 수동 음악 작업 유지다. Keychain 실패를 평문 저장으로 우회하지 않는다. 인증 토큰은 프로젝트·복구 파일·activity history에 직렬화하지 않는다.

## 첫 provider 구현 검증 범위

인증·Responses·계정 coordinator는 내부 모듈로 구현했다. [관련 QA](../../qa/1.0-account-provider.md)를 따른다. 공개 로그인 버튼이나 대화 도구 loop가 연결된 상태는 아니며 실제 계정 성공을 주장하지 않는다. 다음 통합은 모델 목록·대화 입력·완료된 function 호출을 기존 RunLease gateway에 연결하는 것이다. 계정 무효화 callback은 음악 편집 권한과 진행 요청을 동기적으로 중단하도록 앱에 연결해야 한다.

공식 [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference)는 `earliest_refresh_at` 필드를 명시하지만 조회한 문서에는 반환 형식이 명확하지 않았다. 구현은 검증한 Unix seconds 또는 RFC3339를 수용하고 갱신 하한을 지킨다. 이는 호환 가정이며 실제 서버 반환형을 확인한 근거가 아니다. 미확인 형식·live refresh는 R100-03에 남는다.
