# 0.90.0 — 핵심 음악 제작과 비주얼라이저 신뢰성

상태: PLANNED · 기준: [0.80.0 build242 출고](0.80.0.md) · 최신 정식판: `v0.80.0`. 이 문서는 0.90 완료나 출고 승인이 아니다. 버전 숫자는 작업 순서이고, 실제 재생·제작·저장·영상 결과가 완료 기준이다.

## 범위 결정

사용자는 0.90까지 개발하되 핵심 기능의 실제 동작과 UI 개선을 버전 숫자보다 우선한다. 0.80에서는 짧은 실사용 제작 경로와 외부 Codex→MCP 편집을 확인했고, 0.90에서는 같은 경로의 반복·장시간·고밀도·오류 복구를 보증한다. 사용자의 0.80 마감 결정에 따라 [build242 실제 영상](../../qa/0.80-build242-performance.md)의 **70.000ms 단일 PTS gap(사전 최대 66.67ms 기준 FAIL)**을 우선순위가 낮은 이월 결함으로 취급한다. 실패를 통과로 바꾸거나 기준을 완화하지 않고 0.90에서 수정·실측한다. 기존 아티스트 프로필·작품 catalog·자산 백업 목표는 [아티스트 설계](../21-artist-universe.md)에 보존하고 음악 제작 gate 통과 뒤 착수한다. Codex 계정 대화는 공식 production 지원 경로를 확인할 때까지 [G0](0.80.0.md) 밖에 두며 기존 typed MCP와 작업 로그는 유지한다.

## 작업과 인수 증거

| ID | 사용자 결과 | 최소 인수 증거 |
|---|---|---|
| R90-01 | 앱을 열어 재생·정지·재시도를 반복해도 출력이 멈추지 않는다 | 최종 패키지의 동일 빌드를 cold start하고 명시적 내장 출력에서 반복 Play/Stop/자연 종료와 실제 청취를 확인한다. 연결된 구형 Scarlett은 timeout·장치 변경·실패 후 내장 출력 재시도의 안전성으로 평가하며 정상 출력 자체를 필수로 삼지 않는다. helper trace의 시작/정리와 시스템 기본 설정 불변을 별도 기록 |
| R90-02 | 곡과 섹션을 루프로 끊김 없이 듣고 재생 위치를 믿을 수 있다 | 100회 offline 경계의 sample 수·위상·tail·누적 drift 검사에 더해 실제 장치의 곡/섹션 경계 청취. 전환·루프 해제·Stop 뒤 잔음·재시작과 카메라 팔로우의 재생 위치 대조 |
| R90-03 | 비주얼라이저를 1080p/30fps 영상으로 안전하게 저장한다 | build242의 599.979초·17,989 decoded 프레임 중 **106.340→106.410초 70.000ms gap 1곳**을 재현·원인 분리·수정한다. 고밀도·섹션 전환·루프가 있는 새 고정 후보의 1920×1080 10분 MP4를 반복 측정해 decoded PTS 최대 **≤66.67ms**, 중복·누락, 시작/중간/끝 A/V offset 1프레임 이내를 확인한다. AAC 연속성과 별도로 실제 플레이어의 중간·끝 지각적 동기 및 물리 청취를 확인한다. 취소·디스크 실패·최소화/복원과 임시 파일 정리도 검증한다 |
| R90-04 | 한 곡을 편집·보존·되돌리고 실제 결과물로 출력한다 | 격리 QA 곡에서 섹션 이동, MIDI/step, 오디오 take trim/split/fade, 효과/automation, Undo/Redo → 저장·앱 종료·재열기 → 바운스/WAV/stems. manifest·media hash와 원본 데모 불변, 출력 길이·nonzero PCM·별도 청취를 확인 |
| R90-05 | 넓고 좁은 가로·세로 화면에서 궤도 작업과 감상이 편하다 | 700/900/1280pt, 가로·세로, 3 zoom × 정지/재생/감상/녹화에서 같은 곡·카메라로 화면 비교. 선택 cable·현재 섹션·8방향 IN/OUT의 시각/키보드/AX, hit/Undo 불변. 앱 PID에 귀속된 실제 compositor-present FPS를 계측하거나 OS 제약과 대체 검증 범위를 분리 기록한다. 내부 callback Hz·MP4 FPS를 표시 FPS라고 부르지 않는다 |
| R90-06 | 설치한 앱이 검증한 앱과 같다 | 전체 회귀·독립 코드/QA 검토, 한영 README·스크린샷·CHANGELOG·노트, 앱/동봉 helpers/데모/kit 서명·버전 일치, ZIP 재압축/재다운로드 SHA 검증. 미해결 필수 gate가 있으면 tag/Release 보류 |
| R90-07 | 앱 전용 입력을 반복 사용하고 장치 장애에서도 take를 지킨다 | 0.80에서 확인한 CalDigit 선택→take→저장·재열기·WAV를 여러 cold start·권한 상태에서 재현한다. 장치 timeout·분리/재연결 중 부분 CAF와 기존 문서 보존, worker PID·파일 정리, 사용자에게 보이는 재선택/재시도와 실제 입력 레벨·청취를 검증한다. 시스템 기본 Scarlett 변경이나 Scarlett 정상 녹음은 필수로 삼지 않는다 |
| R90-08 | 한국어 입력과 키보드·대형 목록 탐색이 실제 Mac에서 일관된다 | 실제 한글 IME 조합·확정·취소 후 검색/이름 편집, `Fn+Space`의 OS 전달 여부와 앱 단축키 충돌, 5만 항목 미디어 목록의 열기·필터·Tab 이동 지연을 고정 후보의 작은/큰 가로·세로 창에서 측정한다. 키보드/AX 포커스·재생 상태·미확정 입력의 보존을 확인한다. build241에서 검증한 기본 Tab/Shift+Tab/Esc와 Space/⌥Space 통과를 이 세 열린 항목의 PASS로 소급하지 않는다 |

각 항목은 자동 테스트, 고립된 native QA 앱, 실제 장치/파일, 배포물의 증거를 구분한다. mock·offline PCM·타이머 callback 통과는 물리 청취나 실제 표시 FPS의 대용이 아니다. 장치 의존 결함이 재현되지 않을 때는 무조건 timeout 연장이나 자동 재시도를 제품 정책으로 넣지 않고 stage trace·재현 조건을 먼저 남긴다. 0.80.x는 0.80.0 정식 출고 뒤 발견한 좁은 결함만 수정하고 동일한 관련 gate를 다시 통과한 경우에 사용한다.

build235 당시 입력 선택은 미지원이었지만 이 설명은 현재 구현 상태가 아니다. build238은 앱 전용 AUHAL worker에 UID 선택을 연결했고, build239 실제 CalDigit 입력에서 7.285초 nonzero CAF가 프로젝트 저장·완전 종료·재열기·24-bit WAV까지 유지됐다. 신호 피크는 약 0.00058로 매우 낮아 녹음 음질·물리 청취의 합격 증거는 아니다. Mac Studio에는 확인된 내장 마이크가 없고 시스템 기본 Scarlett 입출력은 변경하지 않았다. R90-07은 [입력 지속성 QA](../../qa/0.80-build239-input-persistence-native.md)의 제한된 성공을 반복·권한·hotplug·음질·복구 조건으로 확장한다.

build236은 가상 CoreMIDI packet의 host timestamp를 녹음 시점에 사용하고 정지 직전 이벤트 회수를 보강했다. DAW 리뷰의 입력 source별 running status 혼합·분할 메시지 시각 P2/P3를 수정·재검토했지만 물리 MIDI 장치의 연결·분리·재연결과 실제 take는 확인하지 않았다. 기존 hotplug P2는 별도 장치 QA로 남긴다. Stem 폴더의 STOP/게시 순서는 파일 테스트로 고정했으나 대형 GUI stems를 실제 앱에서 중단하는 동선·메모리·청취 검사는 R90-04에 남는다. 이 두 수정은 R90-07의 선택 입력 UID·오디오 PCM/TCC나 crash 중 private 파일 정리를 대체하지 않는다. [build236 QA](../../qa/0.80-build236.md).

build236 콘솔의 과거 로그 고정·미확인 수는 상태 테스트 단계다. R90-05에서는 500행 절단과 높은 빈도의 AI 작업 로그를 실제 40pt/좁은 창에 재현해 휠·키보드·VoiceOver의 읽기 위치, `최신 로그` 복귀, 입력 지연과 재생 compositor FPS를 함께 측정한다.

## 다음 작업 경계

0.80의 [출고 gate](../../qa/0.80-release-gates.md)는 build242의 **10분 영상 최대 70.000ms PTS gap FAIL**, 실제 compositor-present FPS·물리 청취/지각적 A/V 동기, 실제 한글 IME·`Fn+Space`·5만 항목 목록 지연을 구분해 기록한다. 사용자 결정에 따른 0.80의 이월은 해당 검증의 PASS가 아니다. 0.90은 0.80의 제한된 한 번 성공을 반복·고밀도·장치 장애·실제 표시/청감 조건으로 넓힌다. 0.90 완료나 아티스트 catalog 완료는 그 증거가 나온 뒤에만 주장한다. 사용자 앱 교체, tag, 공개 Release의 실제 상태는 각 버전의 출고 기록에서 확인한다.
