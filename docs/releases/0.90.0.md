# 0.90.0 — 핵심 음악 제작과 비주얼라이저 신뢰성

상태: RELEASED_WITH_DEFERRED_QA · 0.90.0/build243 · 사용자 지시에 따른 비필수 범위 이월 · 구현 브랜치: `release/0.90.0` · 기준: [0.80.0 build242 출고](0.80.0.md) · 최신 정식판: `v0.90.0` · [원격 출고 검증](../../qa/0.90-release-verification.md). 최초 전체 계획의 미완료 항목은 최종 마감 범위에 따라 이월한다. 버전 숫자는 작업 순서이고, 실제 재생·제작·저장·영상 결과가 완료 기준이다.

## 범위 결정

사용자는 0.90까지 개발하되 핵심 기능의 실제 동작과 UI 개선을 버전 숫자보다 우선한다. 0.80에서는 짧은 실사용 제작 경로와 외부 Codex→MCP 편집을 확인했고, 0.90에서는 같은 경로의 반복·장시간·고밀도·오류 복구를 검증한다. 사용자의 0.80 마감 결정에 따라 [build242 실제 영상](../../qa/0.80-build242-performance.md)의 **70.000ms 단일 PTS gap(사전 최대 66.67ms 기준 FAIL)**을 우선순위가 낮은 이월 결함으로 취급한다. 실패를 통과로 바꾸거나 기준을 완화하지 않고 0.90에서 수정·실측한다. 기존 아티스트 프로필·작품 catalog·자산 백업 목표는 [아티스트 설계](../21-artist-universe.md)에 보존하고 음악 제작 gate 통과 뒤 착수한다. Codex 계정 대화는 공식 production 지원 경로를 확인할 때까지 [G0](0.80.0.md) 밖에 두며 기존 typed MCP와 작업 로그는 유지한다.

build235 당시 입력 선택은 미지원이었지만 이 설명은 현재 구현 상태가 아니다. build238은 앱 전용 AUHAL worker에 UID 선택을 연결했고, build239 실제 CalDigit 입력에서 7.285초 nonzero CAF가 프로젝트 저장·완전 종료·재열기·24-bit WAV까지 유지됐다. 신호 피크는 약 0.00058로 매우 낮아 녹음 음질·물리 청취의 합격 증거는 아니다. Mac Studio에는 확인된 내장 마이크가 없고 시스템 기본 Scarlett 입출력은 변경하지 않았다. R90-07은 [입력 지속성 QA](../../qa/0.80-build239-input-persistence-native.md)의 제한된 성공을 반복·권한·hotplug·음질·복구 조건으로 확장한다.

build236은 가상 CoreMIDI packet의 host timestamp를 녹음 시점에 사용하고 정지 직전 이벤트 회수를 보강했다. DAW 리뷰의 입력 source별 running status 혼합·분할 메시지 시각 P2/P3를 수정·재검토했지만 물리 MIDI 장치의 연결·분리·재연결과 실제 take는 확인하지 않았다. 기존 hotplug P2는 별도 장치 QA로 남긴다. Stem 폴더의 STOP/게시 순서는 파일 테스트로 고정했으나 대형 GUI stems를 실제 앱에서 중단하는 동선·메모리·청취 검사는 R90-04에 남는다. 이 두 수정은 R90-07의 선택 입력 UID·오디오 PCM/TCC나 crash 중 private 파일 정리를 대체하지 않는다. [build236 QA](../../qa/0.80-build236.md).

build236 콘솔의 과거 로그 고정·미확인 수는 상태 테스트 단계다. R90-05에서는 500행 절단과 높은 빈도의 AI 작업 로그를 실제 40pt/좁은 창에 재현해 휠·키보드·VoiceOver의 읽기 위치, `최신 로그` 복귀, 입력 지연과 재생 compositor FPS를 함께 측정한다.

## 다음 작업 경계

0.80의 [출고 gate](../../qa/0.80-release-gates.md)는 build242의 **10분 영상 최대 70.000ms PTS gap FAIL**, 실제 compositor-present FPS·물리 청취/지각적 A/V 동기, 실제 한글 IME·`Fn+Space`·5만 항목 목록 지연을 구분해 기록한다. 사용자 결정에 따른 0.80의 이월은 해당 검증의 PASS가 아니다. 0.90은 0.80의 제한된 한 번 성공을 반복·고밀도·장치 장애·실제 표시/청감 조건으로 넓힌다. 0.90 완료나 아티스트 catalog 완료는 그 증거가 나온 뒤에만 주장한다. 사용자 앱 교체, tag, 공개 Release의 실제 상태는 각 버전의 출고 기록에서 확인한다.

**첫 실행 slice:** DAW core와 편집 UI를 각각 읽기 전용 감사해 높은 확신의 재현 결함부터 고친다. 소유 경로와 집중 테스트는 `qa/0.90-build243-plan.md`에 고정한다. AI 범위는 현재 외부 Codex→MCP의 실제 편집 계약을 보존하며, 인앱 계정 대화 G0는 1.0에서 공식 지원 조건을 재확인한다. 본 점검에서는 과거 OpenAI 지원 상태를 현재 사실로 재검증하지 않았다.

검증은 변경된 계약의 집중 회귀부터 실행한다. 전체 테스트·패키징·긴 native 녹화는 의미 있는 후보가 동결될 때 통합하고, 같은 상태를 반복 계측하지 않는다. native/청취가 필요한 결과는 자동 테스트로 대체하지 않는다. 사용자가 실제 검수할 때는 남은 장치·음질·IME 항목을 하나의 목록으로 모은다.

## 2026-09-30 범위 축소 결정

사용자는 필수 문제가 아니라면 현 작업을 마감하고 후속 버전으로 넘기도록 지시했다. MIDI hotplug와 live CC64/pitch bend 누락은 v0.80.0에도 있는 기존 제한이며 이번 작업에서 생긴 회귀가 아니다. MIDI inspector 키보드 진입은 편의 개선이다. 이 항목들을 이유로 이미 출고된 0.80을 다시 열거나 반복적인 toolchain 우회 검증을 진행하지 않는다. hotplug·표현 녹음은 후속 DAW 개발 backlog, inspector 진입·대형 viewport 최적화는 후속 UI backlog로 보존한다.

이번 0.90 착수 감사는 종료한다. 검증되지 않은 UI 변경은 배포 소스에서 분리하고, 0.90 완료·패키지 생성·Release 게시를 주장하지 않는다. 최신 정식판은 v0.80.0이다. 다음 구현은 위 표 전체를 한 번에 필수로 확대하지 않고, 사용자 음악 제작을 막는 결함과 데이터 보존부터 작은 범위로 선정한다. 실행 결과와 이월 상태는 [착수 기록](../../qa/0.90-build243-plan.md)에 남긴다.

## 2026-09-30 재생 경계 정확도

Xcode 라이선스 차단은 해소됐으며 기본 Swift 6.4로 실제 XCTest를 실행했다. 이월한 MIDI hotplug/inspector 기능은 다시 열지 않았다. 기존 전체 회귀는 1,340개 중 실패 0개이며, 초기 skip 26개 중 11개 helper process 테스트는 명시적 실행 경로를 지정해 모두 통과했다. 남은 15개 native/장치 검사는 자동 PASS로 간주하지 않는다.

R90-02의 100회 offline 반복 검증을 보강한 결과 정확한 샘플 경계 26곳에서 반복 횟수가 한 회 적게 계산되는 결함을 재현했다. PCM 샘플 누락·중복이나 잔향 소실은 이 테스트에서 재현되지 않았다. `PlaybackLoopPCM.iteration`의 극소 부동소수점 오차만 보정하며, 재생 위치 보간·PCM·스케줄러는 유지한다. [현재 검증 기록](../../qa/0.90-loop-boundary.md). 이는 R90-02의 offline 부분이며 물리 청취와 전체 0.90 마일스톤의 완료 증거가 아니다. README 화면·버전/build·패키지·Release는 최종 후보 검증 시 함께 갱신한다.
