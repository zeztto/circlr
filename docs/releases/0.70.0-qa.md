## 일반 재생 · 녹화 꺼짐

`qa/measure-canvas-playback.py`는 재생이 시작된 뒤 두 MCP snapshot의 `frameCount` 차이를 벽시계 간격으로 나눈다. build170의 구간은 재생14.38–29.78초, build171은10.26–25.60초였다. 둘 다 첫 섹션 내다.

| 항목 | build170 | build171 초기 후보 | build172 현재 후보 |
|---|---:|---:|---:|
| 구간 길이 | 15.385초 | 15.356초 | 15.364초 |
| 시각 업데이트 콜백 | 235 / 15.27Hz | 854 / 55.61Hz | **873 / 56.82Hz** |
| 화면 `draw` 콜백 | 계측 없음 | 833 / 54.25Hz | **865 / 56.30Hz** |
| `draw` 비용 p50 / p95 / p99 | 계측 없음 | 8.48 / 10.46 / 10.93ms | 8.59 / 10.62 / 11.15ms |
| `updatePlaybackFrame` 비용 p50 / p95 / p99 | 계측 없음 | 0.87 / 0.98 / 1.03ms | 0.87 / 1.00 / 1.06ms |

build172 구간은 재생16.34–31.70초이며 역시 첫 섹션 안이다. 비용 백분위수는 **최근600 콜백** 버퍼이므로 위 15초 구간의 정확한 통계로 읽으면 안 된다. 최대 호출 간격은 앱 실행 전체의 누적값이고 비활성 시간도 포함한다. `frameCount`는 화면 표시 프레임 수가 아니라 시각 업데이트 타이머 횟수다. 실제 compositor FPS는 미측정이다. build170의 10초 `sample`에서 주 스레드 `AlbumCanvasView.draw → drawReadableLabels → isVisible → labelContext → HierarchyScene.contextBounds` 반복이 확인되었고, 이것이 이번 캐시 변경의 근거다. 이 수치만으로 실제 FPS가3.72배 올랐다고 주장하지 않는다.

독립 코드 리뷰는 캐시 경로의 동작 회귀를 찾지 못했지만, 별도 QA 리뷰에서 **선택된 포트가 라벨 배치 전에 핸들을 캐시하는 경우**를 발견했다. build171은 이 시나리오에서 새 라벨과 포트 겹침을 허용할 수 있다. 포트 캐시를 라벨 배치 직후 비우는 수정은 build172에 적용했다. 독립 재검토에서 캐시 무효화 순서를 확인했고, 실제 UI에서 포트를 선택한 화면을 육안 확인했다. 장시간·여러 라벨 배치는 추가 검증한다.

## 녹화 동시 실행 · 실패

build171에서 같은 캔버스로 내장 곡을 녹화했다. 10.232초 구간(재생75.02–85.31초, 섹션 전환 포함)의 콜백은 시각 업데이트346 / 33.81Hz, 화면 `draw`269 / 26.29Hz, 영상 `draw`320 / 31.27Hz였다. UI의 최종 결과는173.49초 MP4, 2995프레임, 누락221프레임이다.

`qa/inspect-movie-timing.swift`가 AVAssetReader의 H.264 sample PTS를 표시 순서로 정렬해 검사한 값: 영상 sample2999개, 평균17.32fps, PTS 간격 p50 63.33ms / p95 85ms / p99 95ms, 66.67ms 초과 간격512개, 최대 간격320ms. 오디오 첫 PTS0초, 첫 영상 PTS0.363초다. `videoDuplicatePTS=1`은 **동일 타임스탬프**만 뜻한다. 영상 내용이 중복된 프레임은 이 검사로 찾지 못한다. UI의2995와 파일2999 sample 차이도 조사 대상이다. MP4의 실제 플레이어 시청·청취 및 AV offset 정밀 검증은 미수행이다. 이 결과는 녹화 gate FAIL이다.

## 검사 및 다음 gate

- release 앱 패키징과 ad-hoc `codesign --verify --deep --strict` 통과, 격리 앱의 버전/빌드와 데모 동일 입력 검증.
- Swift 전체 테스트 **1007개 실행, 3개 skip, 실패0**; `CanvasFrameTiming` 독립 테스트 PASS; `git diff --check` PASS.
- build172에서 선택 포트/라벨 화면과 첫 섹션 정상 재생 콜백을 재검증했다. 섹션 경계와 고밀도 장면은 추가 검증한다.
- 실제 표시 FPS, 가로/세로·팔로우 구도·보기 모드·저밀도/고밀도·최소화/복원, 녹화 캡처/인코드 분리 계측과 1080p30 영상 프레임/내용 중복/AV 동기, 실제 시청·청취가 릴리스 필수다.

정식 릴리스는 이 gate가 충족되기 전까지 금지한다. 상세 범위는 [0.70.0 계획](0.70.0.md)과 [로드맵](roadmap.md)에 있다.
