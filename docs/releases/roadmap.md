## 0.40.0 우선 요구사항 — 루프·시작 화면·녹화·감상 모드

상태: **RELEASED / 0.40.0 build162**. 아래 항목은0.40의 원래 인수 기준이며 삭제하지 않는다. 코드·자동/offline 검증 결과는 [버전 기록](0.40.0.md)과 [최종 QA](0.40.0-final-qa.md)를 따른다. 실제 GUI·입출력 청취·장시간 프레임 실측·IME 항목은 사용자가 이번 버전에서 USER_WAIVED로 지정했다.


English: 0.40.0 prioritizes gapless looping of the current song or section and a launch screen offering New Song, Load Template and Load Demo. It also prioritizes diagnosing and fixing reported screen-recording stutter, with frame-pacing and audio/video synchronization checks. A text-free viewing mode will show circle and signal flow during playback and recording. Playback follow will offer song, section and explicitly pinned circle targets, with separate camera framing controls. The implementation now includes these controls and four bundled demos. Native GUI/listening/FPS/IME QA was explicitly waived for0.40. Further musical refinement of f0r h3r remains in0.60.0.

### R40-01 · 전체 곡 / 섹션 루프 재생

**사용자 결과:** 전체 곡 또는 선택한 섹션을 정지할 때까지 반복해서 듣는다. 곡의 편곡 자체에 저장된 반복 횟수와 transport의 루프 청취를 구분한다.

- 상단 재생 영역에서 루프 켜기/끄기와 `현재 곡 전체` / `선택 섹션` 범위를 선택한다. 대상 이름·마디 범위·현재 반복 위치를 보여주고, 단축키·명령 검색·MCP에서도 같은 상태를 조회·조작한다.
- 곡 전체는 현재 곡의 활성 편곡에 있는 섹션 순서·반복·전환을 포함한다. 섹션은 현재 선택한 **use**의 길이·음악 설정·변형을 사용한다. 다른 곡이나 같은 원본의 모든 use를 함께 재생하는 뜻이 아니다.
- 선택 변경만으로 실행 중인 루프 대상을 바꾸지 않는다. 범위 변경을 명시하면 다음 루프 경계에서 적용하며, 빈 곡·삭제된 대상·유효하지 않은 범위는 재생하지 않고 원인을 표시한다. 루프 해제는 현재 반복 끝에서 종료하며 명시적 Stop은 즉시 정지한다.
- 루프 경계마다 파일을 다시 읽거나 전체 렌더·장치 연결을 재시작하지 않는다. 연속 오디오 clock/scheduling으로 불필요한 공백·중복·시간 누적 오차 없이 재생한다. 구현 방식은 현재 PCM 준비 구조와 실제 장치 측정을 토대로 정한다.
- 효과 잔향은 다음 반복과 이어지도록 처리하며 export용 tail을 매번 붙여 루프 주기를 늘리지 않는다. 경계의 note-off·페달·지속음·automation 시작값을 정의해 hanging note와 값 누수를 막는다. 클릭 방지 처리는 명시적인 경계 정책으로 정하고 원본 파일·노트·어택을 임의로 수정하지 않는다.
- 글로벌/섹션별 템포·박자와 프로젝트 반복은 실행 계획에 반영한다. 재생 포커스·팔로우와 궤도 위치는 실제 오디오 위치를 따른다. 루프 청취 설정 때문에 WAV export가 무한 반복되거나 송폼이 바뀌지 않는다.

**완료 기준:** 짧은 섹션 100회 offline 경계 검사와 실제 장치에서 곡/섹션 각각 연속 청취를 수행한다. 예상 sample 수·위치·반복 횟수와 실제 결과를 비교하고 공백·중복·경계 클릭·누적 drift·잔향·지속음 종료를 확인한다. 전체 곡↔섹션 전환, 루프 해제, Stop/재시작, 빈 대상·편집/삭제·장치 실패 뒤 재사용, GUI/MCP 동일 상태도 검증한다. offline 검사만으로 가청 성공을 선언하지 않는다.

### R40-02 · 앱 시작 화면

**사용자 결과:** 프로젝트를 지정하지 않고 앱을 열면 같은 메인 창에서 **새 곡 / 템플릿 불러오기 / 데모곡 불러오기**를 선택한다. 문서를 연 뒤에는 하나의 캔버스로 이어지며 고정 사이드 패널을 추가하지 않는다.

- `새 곡`: 이름과 기본 템포·박자·스케일을 정하고 빈 곡을 만든다. 기본값으로 바로 시작할 수 있으며 앨범을 먼저 이해하도록 강요하지 않는다.
- `템플릿 불러오기`: 이름·트랙/악기 구성·템포/박자/스케일을 확인하고 선택한다. 실제로 로드되는 템플릿만 표시한다.
- `데모곡 불러오기`: 데모 이름·스타일·편성·필요 음원을 확인한 뒤 편집 가능한 새 프로젝트로 연다. 로드만으로 소리를 자동 재생하지 않는다.
- 기존 작업은 별도 `프로젝트 열기` 동작으로 계속 연다. Finder 파일 열기·`--open`·세션 복구 요청이 있으면 그 요청을 우선 처리하며 시작 화면이 늦게 나타나 문서를 덮어쓰지 않는다.
- 키보드만으로 선택·확정·취소할 수 있다. 불러오는 동안 진행/오류·재시도·취소를 표시한다. 파일/음원 누락·권한 거부·취소 후에도 시작 화면 또는 원래 작업으로 돌아온다.

**완료 기준:** 새 실행의 세 진입 경로, 기존 파일 직접 열기, 복구 우선순위, 키보드/작은 창, 로드 실패·취소 후 늦은 문서 교체 방지, 저장·종료·재열기를 실제 앱에서 확인한다. 시작 화면에서 프로젝트가 열릴 때까지 비동작 버튼이나 빈 화면이 없어야 한다.

### R40-03 · 템플릿·데모 자산과 녹음 통합

- 0.30 build160의 데모 로더가 만드는 작업 사본의 수명을 관리한다. 현재 세션·복구 데이터·사용자 저장에서 참조하지 않는 소유 사본만 안전하게 정리하며, 편집 중인 미디어를 삭제하지 않는다.

- 템플릿과 데모는 새 project ID 및 쓰기 가능한 작업 사본으로 연다. 번들 원본은 불변이며 편집·저장·Undo가 다음 사용자의 템플릿/데모를 바꾸지 않는다. 미디어 참조·버전/schema 호환을 검증한다.
- 내장 악기로 실제 실행 가능한 템플릿과 재배포 권리가 확인된 데모만 포함한다. 사용자 계정·Splice 로그인·유료 플러그인 없이 로드 가능해야 한다. QA fixture를 제품 데모로 바꾸거나 완료되지 않은 항목을 메뉴에 노출하지 않는다.
- 0.40.0 데모 로더는 검증된 편집용 곡을 사용한다. **발매 수준 f0r h3r 완성·사용자 음악 검토는 기존 0.60.0 범위**이며, 그때 데모 콘텐츠를 갱신한다. 로더 완성과 음악적 완성도를 구분한다.
- 기존 녹음·테이크 편집 QA에 루프 재생과 녹음의 상태 충돌·Stop·복구를 추가한다. 무한 overdub, 루프별 comping, 임의 구간 A/B 루프는 이번 요청의 필수 범위로 자동 확장하지 않는다.

**완료 기준:** 새 환경에서 템플릿/데모 로드→편집→저장→재열기, 원본 checksum 보존, 자산 누락/마이그레이션 처리, 배포 ZIP의 재배포 권리 기록을 확인한다. 0.40.0의 기존 실제 녹음·테이크·원본 보존 조건도 함께 통과해야 한다.

### R40-04 · 화면 녹화 프레임 끊김 개선

**상태: 소프트웨어 캡처·인코딩 병목 보완 / 실제 native FPS 미측정.** 화면 녹화가 제대로 작동하지 않고 프레임이 심하게 끊긴다는 피드백을 기록한다. 실행 build·장치·해상도·FPS·저장된 영상의 상태는 아직 확인하지 않았으며, 특정 renderer나 encoder가 원인이라고 단정하지 않는다.

**사용자 결과:** 재생 비주얼라이저를 매끄러운 영상으로 녹화하고, 내보낸 MP4에서도 궤도·노드 시그널·팔로우 움직임과 음악이 일치한다. 기존 녹화 결함을 0.90.0의 멀티미디어 확장까지 미루지 않는다.

- **재현·측정:** 녹화하지 않는 재생, 녹화 중 앱 화면, 저장된 MP4를 비교한다. UI 렌더·캡처·픽셀 변환·인코딩·디스크 기록별 시간과 queue 깊이, 실제 frame timestamp·누락/반복 프레임·CPU/GPU·메모리를 기록한다. 평균 FPS만으로 끊김을 판정하지 않는다.
- **처리 분리:** UI 및 오디오 realtime 경로에서 무거운 캡처/인코딩/파일 쓰기가 대기하지 않도록 병목을 줄인다. 재사용 가능한 buffer와 제한된 queue를 검토하며 메모리를 무한히 늘려 성능 문제를 숨기지 않는다. 구체 기술은 측정 후 결정한다.
- **시간 기준:** 실제 오디오 clock을 기준으로 프레임 시각과 카메라·시그널 위치를 맞춘다. 늦은 timer 호출로 시간을 누적 계산하거나, 같은 프레임을 반복해 파일의 명목 FPS만 맞춘 것을 개선으로 간주하지 않는다.
- **상태·실패 처리:** 요청 FPS·해상도와 지원 가능한 녹화 조건을 명확히 한다. 처리량 부족·프레임 누락을 탐지해 안내하며 품질을 몰래 낮추지 않는다. 정지·취소·인코더 오류·디스크 부족 시 오디오를 불필요하게 막지 않고 파일 마무리/복구 결과를 알린다.
- **루프 연계:** 곡·섹션 루프 경계에서도 녹화 timestamp는 단조 증가한다. 반복 횟수에 따라 영상 길이가 맞고 오디오가 빠지거나 중복되지 않는다. Stop은 끝 프레임·음원·효과 tail의 포함 정책에 따라 안전하게 마무리한다.

**초기 검증 목표(실측 결과 아님):** 지원 대상 Apple Silicon Mac에서 1080p/30fps를 기본 기준으로 정하고, 섹션 전환·시그널·팔로우가 움직이는 실제 프로젝트를 10분 녹화한다. 프레임 처리 시간 p95/p99, frame 간격과 최대 정지 구간, 누락/중복률, 시작/중간/끝 AV offset을 수치로 남긴다. 정상 지원 조건에서 의도하지 않은 누락·중복 0, 연속 프레임 사이 표시 공백은 목표 주기의 2배 이하, AV offset은 1프레임 이내를 수용 목표로 삼는다. 지원 장치와 측정 방법은 착수 계획에 고정하며 달성하지 못하면 통과로 바꾸지 않는다.

**완료 기준:** 위 수치 검사와 함께 저장 MP4를 별도 플레이어에서 끝까지 보고 들어 프레임 끊김·음성 누락·누적 동기 오차가 없음을 확인한다. 작은/큰 창, 낮은/높은 노드 밀도, 카메라 이동, 루프 경계, 창 가림·최소화, 정지·취소·재시작·오류 복구를 검증한다. 오디오 자체와 편집 반응성의 회귀도 확인한다. 60fps·4K 및 광범위 장시간/멀티미디어 출력은 0.90.0에서 지원 범위를 확장하며 기본 녹화 결함의 해결 조건을 대신하지 않는다.

### R40-05 · 텍스트 없는 감상 모드

**상태: PLANNED / 미구현.** 재생 중 서클의 궤도·연결·시그널 흐름에 집중할 수 있도록 화면 텍스트를 모두 숨긴다. 기존 단일 캔버스에 표시 모드를 추가하며 음악 데이터는 바꾸지 않는다.

- **숨김 범위:** 서클/곡/섹션/트랙 이름, IN/OUT 글자, 마디·박·시간·수치 눈금, 템포·스케일·반복 횟수, 로고/버전 텍스트, breadcrumb, 편집 도구의 문구·필드, 콘솔·로그·상태 문구를 포함한다. 숨긴 라벨의 배경판도 제거한다. hover tooltip·비필수 알림이 텍스트를 다시 노출하지 않게 한다.
- **남기는 표현:** 서클·궤도·색상·연결선·방향 화살표·시그널 움직임과 재생 위치 표시를 유지한다. 글자를 지우기 위해 원이나 연결 자체를 없애지 않는다. 재생 팔로우와 화면 확대·이동은 계속 사용할 수 있다.
- **조작·복귀:** 명령 검색/표시 메뉴와 전용 토글 단축키로 진입하며, 키는 구현 시 기존 단축키와 충돌하지 않게 확정한다. `Esc`는 상위 서클 이동보다 감상 모드 종료를 우선한다. 재생/정지 단축키와 텍스트 없는 복귀 아이콘을 제공하고, 자동 숨김 컨트롤은 포인터 이동으로 다시 드러나게 한다. 감상 중에는 우발적인 노트/노드 편집을 막는다.
- **편집 상태 보존:** 진입 전에 미확정 이름·수치/IME 초안을 기존 보호 규칙으로 처리한다. 잘못된 초안을 숨긴 채 모드로 들어가지 않는다. 종료하면 원래 편집 대상·선택·콘솔 상태를 복원하고 사용자가 감상 중 바꾼 카메라 위치는 유지한다. 저장된 프로젝트 이름·음악·연결·Undo 이력은 변경하지 않는다.
- **전체 화면·접근성:** 창 모드에서는 앱 콘텐츠의 텍스트를 숨기고, 전체 화면 감상에서는 앱 제목줄도 노출되지 않게 한다. macOS 시스템 메뉴·권한 창까지 임의로 변경하지 않는다. 눈에 보이는 라벨을 숨겨도 재생/정지·복귀 컨트롤의 접근성 이름과 키보드 접근은 유지한다. 동작 줄이기 설정을 존중한다.
- **녹화 연계:** 활성화된 감상 모드는 화면 녹화에도 동일하게 적용한다. 감상 모드로 녹화를 시작하면 첫 프레임부터 이름·콘솔·버전 등의 텍스트가 섞이지 않아야 한다. 모드 전환으로 오디오가 재시작되거나 루프/영상 시간이 초기화되지 않는다. 중요한 오류는 감상 모드를 종료하고 명확히 안내하며 숨긴 상태로 방치하지 않는다.

**완료 기준:** 텍스트가 많은 프로젝트에서 앱 화면과 실제 저장 MP4의 시작·루프/섹션 경계·팔로우·hover·끝 프레임을 확인해 모드 활성 구간에 텍스트가 남지 않는지 검사한다. 재생 중 반복 토글·Stop·Esc·전체 화면·키보드/접근성·오류 복구와 초안 보호를 확인한다. 모드 전후 음악 데이터/Undo 불변, 카메라/선택 복귀, 오디오 연속성 및 R40-04 프레임/AV 동기 목표를 함께 충족해야 한다.

### R40-06 · 재생 팔로우 대상과 화면 범위 선택

**상태: PLANNED / 미구현.** 사용자가 감상하려는 계층과 화면 범위를 직접 선택한다. 현재 재생되는 음악 범위(R40-01)와 카메라가 따라갈 대상은 서로 독립된 설정이다.

| 팔로우 대상 | 화면 동작 |
|---|---|
| 현재 곡 서클 | 곡의 전체 구조를 보며 진행한다. 섹션이 바뀌어도 곡 화면을 유지하고, 앨범 재생에서 다음 곡으로 넘어갈 때만 그 곡으로 이동한다. |
| 현재 섹션 서클 | 실제 재생 중인 섹션 use를 따라간다. 섹션 전환 시 다음 섹션으로 이동하며 같은 섹션의 루프 경계에서는 불필요하게 다시 줌하지 않는다. |
| 지정 서클 | 사용자가 명시적으로 고른 MIDI·오디오·악기·이펙터·그룹 등의 서클을 고정 대상으로 삼는다. 일반 편집 선택이 바뀌어도 고정 대상을 바꾸지 않는다. 해당 서클이 재생에 참여하지 않는 구간에는 마지막 구도를 유지한다. |
| 팔로우 끄기 | 현재 카메라 위치를 유지하고 자유롭게 탐색한다. 음악은 계속 재생한다. |

- **구도 설정:** 대상 선택과 별도로 `대상 전체 맞춤` / `현재 배율 유지`를 제공한다. 전체 맞춤에는 내부 서클과 여백을 포함하고 콘솔·창 크기를 고려한다. 섹션 내부의 신호량이나 노트 변화 때문에 매 프레임 확대율을 바꾸지 않는다.
- **전환:** 기본값은 현재 섹션 팔로우로 유지한다. 대상 변경을 확정하면 실제 playback clock의 현재 곡/섹션으로 부드럽게 이동한다. 이동 중 다음 전환이 오면 이전 카메라 요청을 버리고 최신 대상만 따른다. 곡/섹션의 반복, 로컬 템포와 다음 곡 전환에서도 실제 재생 위치를 기준으로 삼는다.
- **섹션 전환 연출:** 현재 섹션 팔로우에서 다른 섹션 use로 넘어갈 때 `짧은 줌아웃 → 다음 섹션으로 이동 → 목표 구도로 줌인`을 하나의 연속 카메라 곡선으로 표현한다. 순간적인 화면 점프나 줌 단계의 정지 없이 연결 방향과 다음 목적지를 자연스럽게 보여준다. 재생 경계에서 시작하며 음악을 늦추거나 전환을 위해 미리 다음 섹션을 재생하지 않는다.
- **연출 설정:** `끄기 / 은은하게 / 강조`를 제공하며 기본 제안은 `은은하게`다. 초기 조정안은 전체 450~700ms, 현재/목표 중 더 넓은 구도보다 약 10~20% 추가 줌아웃이며 실제 앱에서 조정·확정한다. 먼 섹션 때문에 캔버스 전체가 점처럼 보이지 않도록 최대 줌아웃을 제한한다. `현재 배율 유지`는 전환 중의 일시 줌을 허용하되 도착 시 원래 배율로 돌아간다는 뜻으로 명시한다. 연출 끄기는 줌 변화를 없애고 기존 이동을 유지한다.
- **적용 경계:** 곡 전체 팔로우·지정 서클·팔로우 끄기에는 섹션 전환 줌을 적용하지 않는다. 같은 use의 루프 경계에는 반복하지 않으며, 다른 use라도 화면 위치와 목표 구도가 같으면 생략한다. 짧은 섹션이 연속되면 시간을 줄이거나 효과를 생략해 줌 펌핑을 방지한다. 전환 도중 새 대상이 오면 현재 보이는 카메라 상태에서 최신 대상으로 이어가고, 사용자 휠/드래그·Stop·팔로우 해제 시 즉시 취소하여 이전 애니메이션이 뒤늦게 화면을 되돌리지 않게 한다.
- **접근성·영상:** macOS 동작 줄이기에서는 확대/축소 연출을 비활성화하고 최소 이동으로 대상을 표시한다. 화면과 녹화는 동일한 시간 기반 카메라 경로를 사용하며 frame 수에 비례해 속도가 달라지지 않게 한다. R40-04 프레임/AV 동기 목표를 유지하고 연출 때문에 텍스트·도구 패널을 자동 노출하지 않는다.
- **일시 중지·재개:** 사용자가 휠·드래그·선택·편집으로 화면을 조작하면 팔로우를 일시 중지하되 선택한 대상 종류·고정 서클·구도 설정은 유지한다. `팔로우 재개`는 그 설정으로 현재 위치를 따라간다. `끄기`와 `일시 중지`는 서로 다른 상태로 표시한다.
- **대상 식별:** 곡 ID·편곡 ID·use ID·node/group ID로 구분해 동일한 섹션 원본을 재사용해도 다른 인스턴스로 잘못 이동하지 않는다. 고정 서클 삭제·편곡 교체 등으로 대상을 찾을 수 없으면 팔로우를 일시 중지하고 재선택을 안내한다. 임의의 다른 서클로 대체하지 않는다.
- **데이터·조작:** 상단 팔로우 메뉴·명령 검색·키보드·MCP에서 같은 설정과 실행 상태를 다룬다. 카메라 이동이 음악 편집 선택·송폼·노트·Undo·오디오 출력을 변경하지 않아야 한다. 대상/구도 선호는 프로젝트 작업공간 설정으로 보존하되 파일을 여는 것만으로 재생하거나 카메라를 계속 움직이지 않는다.
- **감상·녹화:** 텍스트 숨김 모드에서도 선택한 팔로우와 단축키가 유지된다. 설정을 바꾸기 위해 숨긴 텍스트를 녹화 프레임에 자동 노출하지 않는다. 녹화 영상의 카메라 이동에도 같은 대상·구도·실제 재생 시간을 적용하며 R40-04 프레임/AV 동기 조건을 유지한다.

**완료 기준:** 여러 곡과 재사용 섹션이 있는 프로젝트에서 곡/섹션/고정 서클/끄기를 비교하고, 화면에 보이는 대상 ID와 실제 재생 위치를 대조한다. 섹션·곡·루프 경계, 빠른 대상 전환, 삭제된 고정 대상, 배율 유지/전체 맞춤, 수동 탐색 후 재개, 저장/재열기, 감상 모드·실제 녹화, GUI/MCP 상태 일치를 확인한다. 카메라 튐·뒤늦은 이전 대상 복귀·음악 데이터/출력 변경이 없어야 한다.

**전환 연출 QA:** 가까운/먼 섹션, 다른 크기의 서클, 빠른 템포·짧은 섹션, 동일 위치의 다른 use, 루프, 전환 중 수동 조작·Stop·대상 삭제를 확인한다. 설정별 도착 배율·최대 줌아웃·취소 후 카메라 불변과 동작 줄이기를 검증한다. 실제 MP4에서 전환 시작/끝·누락 프레임·AV 동기를 확인하며 음악 데이터·재생 위치는 바뀌지 않아야 한다.

Intensity, stable arrival framing, interruption handling and reduced-motion support are planned; playback and recording must remain synchronized. ### R40-07 · 공개 MIDI·스템 기반 데모 3~5곡

**상태: RESEARCHED / PLANNED, 미탑재.** 0.40.0 시작 화면에 최소 3곡·목표 4곡의 편집 가능한 데모를 제공한다. Satie·Grieg·Debussy의 Public Domain MIDI와 Lithium의 CC0 stems를 우선 검토한다. [후보·공식 라이선스·편곡·QA 계획](demo-library-plan.md)에 출처와 미검증 범위를 기록했다.

- 먼저 Gymnopédie 한 곡을 편곡·실제 청취 검토한 뒤 확대한다. 곡→섹션→MIDI/오디오/악기/FX 계층, 공유 반복과 변형, 섹션 재배치, 바운스를 각각 학습할 수 있게 만든다.
- R40-02/03의 로더·원본 보존과 R40-01/04/05/06의 루프·녹화·감상·팔로우 QA를 실제 데모로 연결한다. 원본 MIDI를 그대로 넣거나 QA fixture를 데모로 이름만 바꾸지 않는다.
- 파일별 권리·출처·checksum, 내장 음색 권리, 실제 청취·오프라인 로드·편집·재열기·WAV/stem 출력·패키지 성능 검증을 탑재 gate로 삼는다.

## 의존성과 범위 관리

0.30의 기본 재생이 막히면 0.40의 녹음·0.60의 음악 품질을 완료 처리하지 않는다. MCP 기반 자동 편집은 기존 기능을 계속 사용할 수 있지만 계정 대화의 완료는 0.70에 속한다. 아티스트·멀티미디어 설계는 보존하되 음악 제작 기준판보다 먼저 확장하지 않는다.

0.30은 UI 미세 조정만 묶은 버전이 아니다. 파일/범위/Undo와 실제 재생을 포함한 한 곡의 결과가 출고 조건이다. 0.40 이후에도 단순히 기존 기능 이름을 나열해 버전을 올리지 않고 그 버전에서 새로 보장할 동작과 증거를 정의한다.

기존 상세 설계의 출발점:

- [전체 기술 과제](../138-current-development-plan.md): realtime clock·PDC, comping/time warp, backend 계약. 큰 엔진 재설계가 필요하면 원인·범위·검증을 별도 명시한다.
- [기본 DAW](../31-daw-basics-plan.md), [계정 콘솔](../20-codex-account-console-plan.md), [음악 역할](../24-music-agent-kit.md).
- [Splice](../27-splice-licensing-and-integration.md), [아티스트](../21-artist-universe.md). 외부 API·라이선스는 착수 시 현재 공식 조건을 확인한다.
