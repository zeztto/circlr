## 0.40.0 우선 요구사항 — 루프와 시작 화면

상태: **PLANNED / 미구현**. 0.30.0의 기본 재생 안정화를 전제로 다음 버전에 반영한다. 기존 0.40.0 녹음 범위는 보존하되 **R40-01 → R40-02 → R40-03 → 기존 녹음 통합 QA** 순으로 진행한다. 착수 시 버전 실행 계획에서 파일 소유·의존성과 아래 기준을 동결한다. 이번 로드맵 변경으로 현재 앱이 기능을 지원하게 되는 것은 아니다.

English: 0.40.0 prioritizes gapless looping of the current song or section and a launch screen offering New Song, Load Template and Load Demo. These are planned features; 0.60.0 will upgrade the bundled demo to the reviewed f0r h3r production.

### R40-01 · 전체 곡 / 섹션 루프 재생

**사용자 결과:** 전체 곡 또는 선택한 섹션을 정지할 때까지 반복해서 듣는다. 곡의 편곡 자체에 저장된 반복 횟수와 transport의 루프 청취를 구분한다.

- 상단 재생 영역에서 루프 켜기/끄기와 `현재 곡 전체` / `선택 섹션` 범위를 선택한다. 대상 이름·마디 범위·현재 반복 위치를 보여주고, 단축키·명령 검색·MCP에서도 같은 상태를 조회·조작한다.
- 곡 전체는 현재 곡의 활성 편곡에 있는 섹션 순서·반복·전환을 포함한다. 섹션은 현재 선택한 **use**의 길이·음악 설정·변형을 사용한다. 다른 곡이나 같은 원본의 모든 use를 함께 재생하는 뜻이 아니다.
- 선택 변경만으로 실행 중인 루프 대상을 바꾸지 않는다. 범위 변경을 명시하면 다음 루프 경계에서 적용하며, 빈 곡·삭제된 대상·유효하지 않은 범위는 재생하지 않고 원인을 표시한다. 루프 해제는 현재 반복 끝에서 종료하며 명시적 Stop은 즉시 정지한다.
- 루프 경계마다 파일을 다시 읽거나 전체 렌더·장치 연결을 재시작하지 않는다. 연속 오디오 clock/scheduling으로 불필요한 공백·중복·시간 누적 오차 없이 재생한다. 구현 방식은 현재 PCM 준비 구조와 실제 장치 측정을 토대로 정한다.
- 효과 잔향은 다음 반복과 이어지도록 처리하며 export용 tail을 매번 붙여 루프 주기를 늘리지 않는다. 경계의 note-off·페달·지속음·automation 시작값을 정의해 hanging note와 값 누수를 막는다. 클릭 방지 처리는 명시적인 경계 정책으로 정하고 원본 파일·노트·어택을 임의로 수정하지 않는다.
- 글로벌/섹션별 템포·박자와 프로젝트 반복은 실행 계획에 반영한다. 재생 포커스·팔로우와 궤도 위치는 실제 오디오 위치를 따른다. 루프 청취 설정 때문에 WAV export가 무한 반복되거나 송폼이 바뀌지 않는다.

**완료 기준:** 짧은 섹션 100회 offline 경계 검사와 실제 장치에서 곡/섹션 각각 연속 청취를 수행한다. 예상 sample 수·위치·반복 횟수와 실제 결과를 비교하고 공백·중복·경계 클릭·누적 drift·잔향·지속음 종료를 확인한다. 전체 곡↔섹션 전환, 루프 해제, Stop/재시작, 빈 대상·편집/삭제·장치 실패 뒤 재사용, GUI/MCP 동일 상태도 검증한다. offline 검사만으로 가청 성공을 선언하지 않는다.

### R40-02 · 앱 시작 화면

**사용자 결과:** 프로젝트를 지정하지 않고 앱을 열면 같은 메인 창에서 **새 곡 / 템플릿 불러오기 / 데모곡 불러오기**를 선택한다. 문서를 연 뒤에는 하나의 캔버스로 이어지며 고정 사이드 패널을 추가하지 않는다.

- `새 곡`: 이름과 기본 템포·박자·스케일을 정하고 빈 곡을 만든다. 기본값으로 바로 시작할 수 있으며 앨범을 먼저 이해하도록 강요하지 않는다.
- `템플릿 불러오기`: 이름·트랙/악기 구성·템포/박자/스케일을 확인하고 선택한다. 실제로 로드되는 템플릿만 표시한다.
- `데모곡 불러오기`: 데모 이름·스타일·편성·필요 음원을 확인한 뒤 편집 가능한 새 프로젝트로 연다. 로드만으로 소리를 자동 재생하지 않는다.
- 기존 작업은 별도 `프로젝트 열기` 동작으로 계속 연다. Finder 파일 열기·`--open`·세션 복구 요청이 있으면 그 요청을 우선 처리하며 시작 화면이 늦게 나타나 문서를 덮어쓰지 않는다.
- 키보드만으로 선택·확정·취소할 수 있다. 불러오는 동안 진행/오류·재시도·취소를 표시한다. 파일/음원 누락·권한 거부·취소 후에도 시작 화면 또는 원래 작업으로 돌아온다.

**완료 기준:** 새 실행의 세 진입 경로, 기존 파일 직접 열기, 복구 우선순위, 키보드/작은 창, 로드 실패·취소 후 늦은 문서 교체 방지, 저장·종료·재열기를 실제 앱에서 확인한다. 시작 화면에서 프로젝트가 열릴 때까지 비동작 버튼이나 빈 화면이 없어야 한다.

### R40-03 · 템플릿·데모 자산과 녹음 통합

- 템플릿과 데모는 새 project ID 및 쓰기 가능한 작업 사본으로 연다. 번들 원본은 불변이며 편집·저장·Undo가 다음 사용자의 템플릿/데모를 바꾸지 않는다. 미디어 참조·버전/schema 호환을 검증한다.
- 내장 악기로 실제 실행 가능한 템플릿과 재배포 권리가 확인된 데모만 포함한다. 사용자 계정·Splice 로그인·유료 플러그인 없이 로드 가능해야 한다. QA fixture를 제품 데모로 바꾸거나 완료되지 않은 항목을 메뉴에 노출하지 않는다.
- 0.40.0 데모 로더는 검증된 편집용 곡을 사용한다. **발매 수준 f0r h3r 완성·사용자 음악 검토는 기존 0.60.0 범위**이며, 그때 데모 콘텐츠를 갱신한다. 로더 완성과 음악적 완성도를 구분한다.
- 기존 녹음·테이크 편집 QA에 루프 재생과 녹음의 상태 충돌·Stop·복구를 추가한다. 무한 overdub, 루프별 comping, 임의 구간 A/B 루프는 이번 요청의 필수 범위로 자동 확장하지 않는다.

**완료 기준:** 새 환경에서 템플릿/데모 로드→편집→저장→재열기, 원본 checksum 보존, 자산 누락/마이그레이션 처리, 배포 ZIP의 재배포 권리 기록을 확인한다. 0.40.0의 기존 실제 녹음·테이크·원본 보존 조건도 함께 통과해야 한다.

## 의존성과 범위 관리

0.30의 기본 재생이 막히면 0.40의 녹음·0.60의 음악 품질을 완료 처리하지 않는다. MCP 기반 자동 편집은 기존 기능을 계속 사용할 수 있지만 계정 대화의 완료는 0.70에 속한다. 아티스트·멀티미디어 설계는 보존하되 음악 제작 기준판보다 먼저 확장하지 않는다.

0.30은 UI 미세 조정만 묶은 버전이 아니다. 파일/범위/Undo와 실제 재생을 포함한 한 곡의 결과가 출고 조건이다. 0.40 이후에도 단순히 기존 기능 이름을 나열해 버전을 올리지 않고 그 버전에서 새로 보장할 동작과 증거를 정의한다.

기존 상세 설계의 출발점:

- [전체 기술 과제](../138-current-development-plan.md): realtime clock·PDC, comping/time warp, backend 계약. 큰 엔진 재설계가 필요하면 원인·범위·검증을 별도 명시한다.
- [기본 DAW](../31-daw-basics-plan.md), [계정 콘솔](../20-codex-account-console-plan.md), [음악 역할](../24-music-agent-kit.md).
- [Splice](../27-splice-licensing-and-integration.md), [아티스트](../21-artist-universe.md). 외부 API·라이선스는 착수 시 현재 공식 조건을 확인한다.
