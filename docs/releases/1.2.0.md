# 1.2 · 반복 제작과 송폼 편집

상태: RELEASED_WITH_KNOWN_LIMITS · **1.2.0/build253** · source `ca00aa0` · [정식 Release](https://github.com/zeztto/circlr/releases/tag/v1.2.0) · [출고 검증](../../qa/1.2-release-verification.md)

## 사용자 작업의 변화

기준 버전에서는 MIDI 구절을 다른 서클로 옮길 수 없었고, 편집 커서부터 듣기 위해 재생 시작 위치를 지정할 수 없었다. 루프 중 편집은 다음 재생까지 지연됐으며 섹션 재사용은 재생 경로와 분리됐다. build253은 아래 네 작업을 구현하고 실제 앱에서 검증했다. 1.1 계정 연결 소스는 보존하지만 OpenAI 호출은 사용자 요청으로 보류한다.

## build253 구현과 검증

- **MIDI 구절 전송:** 선택 노트의 상대 박·길이·음높이·세기를 보존하여 다른 섹션·트랙에 붙여넣는다. 새 note ID를 발급하며 copy/cut/paste는 텍스트 입력과 분리한다. 실제 키보드 copy/cut·Undo/Redo와 다른 트랙 전송, 저장 후 cold open을 확인했다.
- **커서 재생:** 선택 섹션의 편집 커서에서 `⌥⌘Return`으로 듣는다. 실제 앱의 10박 커서가 5.00초로 계산되고 Mac Studio 출력 worker가 그 위치에서 시작했다. 기존 일반 재생 동작은 유지한다.
- **루프 수정 반영:** 현재 PCM을 유지하면서 바뀐 음악을 준비하고 다음 예약 가능한 루프 경계에 교체한다. build253 실제 worker에서 revision 12·13 반영과 CAF PCM hash 변경을 확인했다. CAF staging 중 Undo 경합은 commit gate로 수정했고 관련 38개 테스트와 독립 재검토를 통과했다.
- **재사용 삽입:** 섹션 우클릭 또는 명령 검색의 ‘이 섹션 뒤에 재사용’으로 새 use를 재생 경로에 넣는다. 공유 원본·반복·local override는 유지한다. 기존 outgoing 전환은 재사용 use 뒤로 옮기고 두 use 사이에는 중립 연결을 만든다. 분기·순환·유효하지 않은 전환은 무변경 거부한다. 기존 자유 배치 재사용은 유지한다.
- **계정 없는 제작:** 기본 배포에서 계정 로그인·AI 대화 UI를 숨기며 로컬 MCP·명령 콘솔은 유지한다. 저장된 AI 모드 설정도 명령 콘솔로 안전하게 표시한다.

실제 바운스 서클과 WAV 출력 완료도 확인했다. 상세 증거와 빌드별 경계는 [제작 흐름 QA](../../qa/1.2-production-workflow.md)를 따른다. PCM·worker·파일 검증은 물리 스피커 청취 합격을 의미하지 않는다.

## 남은 출고 작업

최종 후보의 통합 회귀·패키지·최신 화면/문서 대조와 main 병합·tag·한영 Release·ZIP/SHA256 게시·원격 재다운로드를 완료했다. 범위별 증거는 [출고 기록](../../qa/1.2-release-verification.md)에 있다. 개별 기능 검증 결과를 미검증 장치·청취·영상 품질로 확대하지 않는다.

## 실행과 계약

Development lead가 통합과 출고를 소유한다. clipboard, playback, section arrangement를 겹치지 않는 경로로 분담한다. AppStore.swift 수정은 playback 담당만 맡고 다른 기능은 extension에서 기존 mutate/setLane/history를 사용한다. 공용 toolbar 충돌은 root가 조정한다. 새 파일 포맷/프로젝트 schema 변경은 피하고 필요하면 명시적 migration 검증을 추가한다. 작업 전에 구현 담당은 세부 계약을 보고하며 모호한 음악 시간·반복·transition 처리는 임의로 숨기지 않는다.

검증은 변경별 Swift tests(각 담당의 고유 scratch 경로), 배포형 `./scripts/build-app.sh`, 격리 source-built QA 앱과 실제 앱의 기존 MCP/콘솔을 사용한다. native UI는 Computer Use로만 조작한다. source/unit PASS를 청취·compositor·실기기 PASS로 대체하지 않는다.

## 통합 제작 시나리오

새 곡에 두 섹션을 만든다. 첫 섹션의 드럼/신스 구절을 선택해 두 번째로 옮기고 원본/새 IDs/상대 박을 비교한다. 후반 커서부터 재생한다. 섹션 루프 중 노트를 추가·제거하고 다음 준비된 경계의 실제 PCM 변화와 transport 연속성을 확인한다. 첫 섹션 뒤에 섹션을 재사용해 재생 순서를 검증하고 Undo/Redo한다. 바운스 WAV를 확인하고 저장·cold reopen 후 음악 데이터와 송폼을 대조한다. 700pt/가로 창에서 핵심 버튼·키보드 동선을 확인한다. 실제 개선 전/후 조작 차이와 FAIL/OPEN을 기록한다.

## 범위 경계

OpenAI 서비스의 빈 응답은 해결된 것으로 선언하지 않는다. 미검증 계정 경로는 아래 bundle gate로 기본 배포에서 비활성화한다. 반주와 동기화된 MIDI/audio overdub·count-in/metronome, 장시간 영상70ms FAIL, 물리 장치/청취·전체 IME/VoiceOver matrix는 별도 작업으로 남긴다. 사용자 최신 지시 없이 기존 미검증을 일괄 PASS 또는 유예로 바꾸지 않는다.

build253은 1.2 검증 후보이며 정식판과 구분한다. 정식 완료는 main/tag/한영 GitHub Release/ZIP·SHA256 원격 검증까지이며 현재 이 문서는 출고 선언이 아니다.

## 출고 기능 노출 결정

계정 대화는 `CirclrAccountChatEnabled` 명시적 bundle 설정이 있어야 노출하며 기본 배포에서는 꺼둔다. 외부 Codex→로컬 MCP와 명령 콘솔은 유지한다. 보류 기능에 coming-soon 표식을 붙여 제품 기능처럼 노출하지 않는다. 1.1 구현과 테스트는 소스에 남아 있으며 실서비스 검증을 재개할 때 별도 QA 앱에서만 활성화할 수 있다. 1.2 핵심 제작 흐름은 계정 없이 검증한다.

## 출고 후보 승인 (게시 전 기록)

build253의 실제 구절 전송·커서 재생·루프 PCM 교체·송폼 재사용·바운스·cold reopen과700pt UI를 확인했다. Core736/Python39 회귀와 집중 App/Audio 테스트를 통과했다. 독립 리뷰의 경합 수정 및 문서 정정을 마쳤다. ZIP68파일 복원·서명·시작을 검사했다. main/tag/Release 원격 검증은 다음 출고 gate이며 아직 이 문서로 성공을 선언하지 않는다.
