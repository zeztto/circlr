# 0.50.0 — 펼쳐지는 궤도와 화면 비율 대응

상태: RELEASED. 기준 v0.40.0/build162. 브랜치 release/0.50.0. 최종 후보 build166. [검증 결과와 제한](0.50.0-qa.md).

## 사용자 결정

- 서클은 자식을 담는 원형 상자가 아니라 시간 궤도다. 시간 서클은 궤도 위 또는 바깥의 앵커 연결로 펼친다. 악기·이펙트는 궤도 밖 신호 흐름에 배치한다.
- 가로/세로 디스플레이에서 상단 조작이 겹치지 않도록 한다. 하나의 큰 캔버스와 dark mode를 유지한다.
- 이번0.50은 화면 구조·반응형 UI를 우선 출시한다. 기존 표현·믹스 안정화는 후속 backlog에 보존한다(사용자 선택).
- macOS Gatekeeper 경고/그래도 열기 절차를 Apple 공식 문서에 근거해 KO/EN으로 안내한다.
- 0.40 native QA 유예는 이 버전에 자동 적용하지 않는다. 이번 변경의 실제 UI·가로/세로 화면·선택·pan/zoom·재생 follow를 검증하고 수행하지 못한 항목은 구분한다.

## UX 및 아키텍처 계약

1. 소속/시간/신호/화면 위치를 구별한다. Project hierarchy와 compiler 결과, CircleAddress/port IDs는 유지한다.
2. 궤도 모드에서 자손 수납을 위한 부모 radius 확대와 재귀0.3배 축소를 제거한다. 시간 궤도의 radius와 화면 내용 bounds는 별개다. legacy freeform의 저장 배치와 동작은 보존한다.
3. timed source의 시작시각을 owner 궤도상의 정확한 anchor로 표현한다. 충돌하는 동시 시작 source는 바깥에 펼치고 anchor와 연결한다. processor는 해당 흐름의 바깥에 놓는다. 시각 배치 이동으로 음악 시작시각을 바꾸지 않는다.
4. ring 내부 빈 공간에서는 pan/context create가 가능하다. 시간 편집 handle·port·작은 원의 선택은 명확히 구별한다. 그룹은 소속을 바꾸는 경우와 시각적 묶음을 구별하며 그룹 전후 음악/시간 anchor를 보존한다.
5. focus/follow는 parent radius가 아닌 context와 필요한 주변 노드 bounds를 기준으로 한다. 확대/축소로 관련 계층을 드러내고, 무관한 모든 자손을 한꺼번에 표시하지 않는다.
6. 상단 chrome은 window의 실제 사용 가능 폭으로 배치한다. 넓으면 단일 행, 좁으면 핵심 재생/중단과 곡 정보·보조 조작을 나눈 행 또는 overflow로 제공한다. 문서/이름은 줄임 처리하며 Space·추가·메뉴 접근을 보존한다. 고정 사이드/하단 작업창은 새로 만들지 않는다.
