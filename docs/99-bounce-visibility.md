# 바운스 대상·연결 상태와 수정 동선

상태: build85 Core28개·AudioRouterAudio15개·최종 compact Release40.86초 및 아래 native 검증 확인. QA checker 최종 대조 통과. [QA](../qa/bounce-visibility-review.md).

## 확인한 문제

build84 실제 앱에서 같은 트랙의 원본 오디오는 연결하고 복제본은 경로 밖에 둔 상태로 복제본을 편집하면 바운스가 활성화되지만 현재 서클이 제외된다는 안내가 없었다. 입력 없는 출력의 바운스는 비활성화되며 거절 이유가 help에만 있었다. 이를 build85 상태 표시·연결 복구 검증의 기준으로 삼았다.

## 사용자 동선

- 기존 `StudioRouteBar` 중앙 공간에 짧은 상태 원인과 복구 동작을 표시한다. 새 세로 행·별도 패널·추가 화면 깊이를 만들지 않고 파형의 편집 높이를 보존한다.
- 실행을 막는 원인을 inline으로 읽을 수 있게 한다. 비활성 버튼의 help만으로 원인을 전달하지 않는다.
- 트랙의 바운스가 가능해도 현재 편집 서클이 해당 경로 밖이라면 제외 상태를 명시한다. 트랙 전체의 실행 가능성과 현재 서클의 포함 여부를 구분한다.
- 연결을 수정해야 할 때 활성 출력의 연결 보기 동작으로 수정 대상에 이동한다. 명령 검색에서도 같은 복구 동작에 접근한다.

## 계산 계약

Core의 typed assessment가 바운스 대상·실행 문제·현재 서클의 경로 포함 여부를 제공하고 UI가 이를 표시한다. 포트 연결을 따라 판단하며 router와 sidechain을 고려한다. 단순히 같은 트랙에 속한다는 이유만으로 현재 서클이 바운스에 포함된다고 판단하지 않는다.

안내와 실제 바운스의 판단이 어긋나지 않도록 기존 실행 검증과 일치시킨다. 연결 보기와 명령 검색은 의도한 출력 대상을 사용하며 기존 편곡·음악을 변경하지 않는다. 원본·이번 사용, Undo·저장과 프로젝트 전환의 기존 경계를 유지한다.

이 표시는 연결·대상 판정이다. 음원 유효성·실제 재생 시간·출력 성공·청취 품질을 보장하지 않는다. 사용자 앱과 기존 오디오 출고 조건을 유지한다.

## 검증 기준

1. build84에서 재현한 경로 밖 복제본과 입력 없는 출력에 inline 상태가 표시된다.
2. 연결된 현재 서클, 경로 밖 서클, router·sidechain을 포함하는 대표 경로에서 Core 판정과 실제 바운스 대상을 대조한다.
3. 작은 창·긴 이름에서도 상태와 복구 동작을 확인하고 명령 검색에서 같은 출력 연결로 이동한다.
4. 연결 수정 뒤 상태가 갱신되며 기존 편집·바운스·Undo·저장/재열기의 음악 보존을 확인한다.
5. 최종 Release와 native 결과를 기록한 뒤 수정 범위의 검증 완료를 판단한다.

## 중간 검증과 수정 경계

Core28개와 AudioRouterAudio15개를 통과했다 (`.build/bounce-visibility-audio-tests.log`). 독립 bus·cross-matrix의 실제 PCM 결과와 assessment의 main/outside 판정을 대조했다. typed assessment는 읽기 전용이며 이 근거를 실제 장치 출력 성공으로 해석하지 않는다.

초기 build85 Release72.90초 후 실제 UI에서 오류→출력 IN 직행→그룹 main return 연결 복구를 확인했다. 추가 상태 행이 파형 높이를85에서45로 줄이는 회귀를 발견했다. 최종 compact 후보에서 새 행을 제거하고 기존 `StudioRouteBar` 한 줄에 통합해 파형 공간을 복원했다. 초기 후보의 일부 통과를 최종 결과와 구분한다.
