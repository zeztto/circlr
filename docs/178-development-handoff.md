# build151 개발 현황과 실사용 인수인계

후속 운영: 이후 사용자의 요청으로 [버전 단위 개발 프로세스](releases/README.md)를 도입했다. 아래 운영 방침·우선순위는 당시 기록이며 현재 착수/완료 기준은 [0.30.0 계획](releases/0.30.0.md)을 따른다.

기준일: 2026-09-11. 코드 기준: `codex/daw-integration`의 `e0bead767323ed991abff61bd43f5615fea20a8a` (0.20.0 build151). 이 문서는 기존 구현·검증 기록을 정리한 것이며 새로운 테스트나 청취 결과가 아니다.

현재 운영 방침은 **기능 확장을 일단 멈추고 실제 사용에서 발견한 문제를 작은 단위로 수정**하는 것이다. 아래 업데이트는 우선순위와 완료 조건이며 자동 실행 지시나 확정 일정이 아니다. 상세 설계는 [현행 개발 계획](138-current-development-plan.md)을 참고한다.

## 실행 앱과 소스 구분

- 최신 소스는 비공개 저장소 `zeztto/circlr`의 `codex/daw-integration` 브랜치에 있다. 다른 브랜치나 기존 설치 앱을 build151로 가정하지 않는다.
- build151 Release 빌드·패키징과 별도 QA 앱 검증을 수행했다. 사용자가 실행하던 기존 앱은 교체하지 않았다.
- QA 앱은 물리 입출력을 막는 helper stub을 사용했다. 실제 제작용 앱이나 오디오 성능 검증 결과로 사용하지 않는다.
- 문제 제보 전 실행 중인 앱의 버전·build·경로를 기록한다. 실사용 패키지 교체가 필요하면 해당 바이너리와 자산·프로젝트 호환을 확인하는 별도 배포 작업으로 처리한다.
- 레포의 소스·문서·테스트·아이콘·직접 작성 MIDI와, 로컬 음악 프로젝트·라이선스 오디오·QA 산출물·인증정보는 구분한다. 후자는 이번 문서 업데이트에도 포함하지 않는다.

실제 확인한 페달 흐름: 열기만 할 때 불변 → raw 63→64 → 잘못된 128 입력과 모드 이동 차단 → 같은 beat 이벤트 개별 선택 → MCP 범위 밖 이벤트 추가와 이전 선택 해제 → 전체 해제와 nil no-op → Undo/Redo → 설정/가져오기 취소 복귀 → 저장·재시작. 최종 선택 index 5와 표시 범위 80 beats를 보존했다.

미실행 항목: 공유/원본의 실제 native 페달 변경, 초기 channel 변경, 외부 변경 뒤 stale draft 입력, 같은 beat 이벤트 3개의 연속 native 입력, 물리 I/O. 페달 첫 진입·재열기 포커스는 outer canvas로 관측되었다.

## 실사용에서 먼저 확인할 체크리스트

아래는 **미실행 체크리스트**다. 체크는 해당 앱 build에서 실제 성공한 뒤에만 한다. 원본 곡 대신 복사본으로 시작하고 한 곡의 연속 작업을 우선한다.

| ID | 사용자 작업 | 기대 결과 / 기록할 문제 |
|---|---|---|
| U01 | 실행 앱 버전 확인, 곡 복사본 열기 | build·프로젝트 경로가 명확하고 기존 자산이 정상 연결됨 |
| U02 | 빈 곳 우클릭으로 섹션/MIDI/오디오 구성, 이동·정렬·연결 | 메뉴 발견 가능, 궤도·그룹 의미 유지, IN/OUT 대상 명확 |
| U03 | 휠 확대·축소, 작은 창과 높은 콘솔에서 편집 | 필요한 수치·선택·버튼 가시성, 편집 스크롤과 캔버스 줌 충돌 없음 |
| U04 | 드럼·신스 스텝 → 노트 → 벤드 → 페달 이동 | 대상과 scope 유지, 키보드 입력 위치가 보임, 의도치 않은 음표 생성 없음 |
| U05 | Tab/Shift-Tab·방향키·Return·Escape·Undo/Redo 사용 | 잘못된 입력은 명확히 표시되고 유효 입력만 한 번 적용됨 |
| U06 | 이번 use/섹션 원본/공유 패턴을 각각 수정 | 변경 범위가 예상과 같고 다른 사용처가 뜻밖에 바뀌지 않음 |
| U07 | MIDI·오디오 파일 가져오기, 취소·미지원 파일·권한 대기 | 대상·오류·대기가 보이며 취소 후 이전 편집으로 복귀 |
| U08 | 오디오 자르기·fade·gain/pan, 효과·신스 automation | 파형과 수치·곡선·실제 결과 일치, Undo로 원래 상태 복구 |
| U09 | 섹션·편곡 왕복 후 저장, 종료/재열기 | 음악·자산·선택·모드 복원, 앱 닫기 동작도 의도대로 확인 |
| U10 | 바운스 → 결과 확인 → 원본 복원 | 범위·tail·템포·표현 데이터 일치, 원본 유실 없음 |
| U11 | 한국어 이름 입력, 긴 이름·중복 이름·키보드 탐색 | IME 정상 입력, 정확한 대상 식별, 포커스가 화면 밖으로 사라지지 않음 |
| U12 | MCP 편집·충돌 요청·STOP·재연결 | GUI와 같은 변경, stale 요청 거절, STOP 이후 늦은 변경 없음 |

실제 오디오 점검은 별도로 수행한다. 내장 신스→sampler→AU 순서로 음 시작/해제·반복·정지·잔향을 듣고, 녹음 WAV 재열기와 영상의 시작/끝 동기를 확인한다. 장치 이름·sample rate·buffer·실행 build를 기록하고 오류 발생 시 장치 설정을 무작정 변경하지 말고 재현 조건부터 남긴다. 이 문서 작성에서는 장치나 재생을 조작하지 않았다.

## 수정 작업의 QA·비용 운영

1. 사용자 제보 한 건의 재현 조건과 기대 동작을 먼저 확정한다. 독립적인 큰 작업이 없으면 새 에이전트를 늘리지 않는다.
2. 관련 파일과 변경 범위를 제한한다. 문서만 바뀌면 링크·diff 검사로 마무리한다.
3. 동작 수정은 해당 계약의 테스트와 실제 재현 동선부터 확인한다. 공통 저장·엔진·입력 경로에 영향이 있거나 새 실패가 있을 때 회귀 범위를 넓힌다.
4. 소스 검사, CPU/fixture, native UI, 물리 오디오, 패키징 결과를 따로 보고한다. skip·실패·재검사·미실행을 숨기지 않는다.
5. README/CHANGELOG와 해당 기록을 업데이트하고 승인된 소스 범위만 commit/push한다. 변경 없이는 같은 전체 검사·화면 촬영을 반복하지 않는다.
6. 실사용 앱 배포는 소스 push와 구분한다. 배포 대상 build, 기존 앱·프로젝트 보존, 재열기 결과를 확인한다.
