# 작업 흐름과 화면 구조

> 설계 기준 문서. 0.4.0에서 실행 가능한 범위는 [프로토타입 계약](08-prototype-contract.md)과 [검증 기록](09-prototype-verification.md)을 따른다. 이 문서의 장기 동작 전체가 구현됐다는 뜻은 아니다.

기초 버전: 0.3 · UX 갱신: 2026-09-07 · 소유 역할: ui-ux-designer · 상태: 상호작용 제안

최신 작업 흐름은 [중첩 서클 모델](13-nested-circle-model.md)을 따른다. 현재 0.7.1 구현과 목표 UX는 구분한다.

## 기본 화면의 정보 구조

```text
상단    곡 이름 · 편곡안 A/B · 재생/정지/녹음 · 글로벌 tempo/scale/박자 · 리듬 기준/패턴 · 전체 길이
캔버스  섹션 그룹과 내부 오디오·MIDI·악기·이펙터 서클, 그리드·정렬·연결
선택    해당 서클 가까이에서 여는 설정·생성 메뉴, 부모/이번 사용/원본 편집 범위
보조    필요할 때 여는 사각 note·파형·plugin 편집 창
```

좌우·아래에 고정 창을 만들지 않는다. 이 구조는 정보 우선순위를 설명하며 완성된 화면이 아니다. 메뉴·단축키·파일 열기/저장·창 동작은 Mac 사용 흐름을 따른다.

중앙의 기본 작업은 자유 배치·연결·그룹 편집이다. **현재 편곡안**을 기본으로 보여주며 미연결 아이디어도 캔버스에 보관할 수 있다. 다른 편곡안 전체를 동시에 겹쳐 그리지 않는다. A/B 비교에서는 변경된 구간과 길이 차이를 함께 확인한다. zoom out은 전체 구조, zoom in은 선택한 원과 전환에 집중한다.

그리드 표시와 snap은 별도로 켜고 끈다. 수평/수직 중심 정렬·간격 정돈·그룹 이동/접기/해제를 제공하며 음악 내용과 경로를 유지한다. 같은 작업 공간에서 송폼·사운드 연결을 선택적으로 펼친다. 상세 계약은 [프리폼 캔버스와 음악 설정](07-canvas-and-musical-context.md)에 둔다.

## 원 하나에 표시할 정보

| 위치 | 표시 | 규칙 |
|---|---|---|
| 중심 | `후렴 2` | 사용자 지정 이름, 한글·영문 음악 용어 허용 |
| 중심 아래 | `8마디 · 총 2회` | 반복 수는 추가 횟수가 아닌 전체 재생 횟수 |
| 테두리 | 섹션 길이를 마디·박으로 나눈 링과 playhead | 한 바퀴 = 섹션 한 회; 반복마다 시작으로 복귀 |
| 중앙/선택 시 | 유효 tempo·scale·박자와 글로벌/개별 출처 | 개별 지정 항목을 우선 표시 |
| 보조 상태 | `원본 공유`, `이번 사용 변형` | 상세 패널에서 어느 원본과 연결됐는지 확인 |
| 재생 시 | `2/2회`, `다음: 브리지` | 선택 상태와 재생 상태를 별개로 표시 |

선택 outline과 음악 시간 링을 구분한다. 큰 눈금은 마디, 작은 눈금은 박 분할을 나타내며 7/8의 강세 묶음은 별도 표시한다. 링의 위치 선택은 transport seek와 구분한다. 악기 수는 필요할 때 보조로 보여준다. 원의 크기·화면 좌표·연결선 길이는 음악 시간을 바꾸지 않는다. 색만으로 상태나 포트 종류를 구분하지 않는다.

## 생성에서 첫 편곡까지

1. 빈 프로젝트에서 `섹션 만들기`로 이름과 길이를 지정한다. 기본 길이 8마디는 변경 가능한 제안이다.
2. 같은 캔버스에서 섹션 그룹을 확대하고 오디오·MIDI·악기·이펙터 서클을 생성·연결한다. 녹음·import는 대상 음악 서클에 담고 note·파형 정밀 편집만 사각 창으로 연다. 빈 섹션은 의도한 구조로 보존한다.
3. 각 서클의 tempo·scale·박자·리듬 기준을 부모 상속 또는 개별 설정으로 지정한다. 축소해 다른 섹션을 만들고 진행 포트로 다음 섹션을 연결한다. 내부 audio/MIDI 포트와 진행 포트를 구분한다.
4. 시작 섹션과 끝을 정하고 재생한다. 전체 흐름 띠에서 실제 길이와 순서를 확인한다.
5. 같은 섹션을 다시 쓰거나 일부만 변형하고, 편곡안을 복제해 다른 구조를 비교한다.
6. 선택한 편곡안을 stereo/stem으로 내보낸다. 끝이나 분기가 미정이면 필요한 결정을 표시한다.

빈 섹션도 구조 구상에 사용할 수 있다. 내보내기 전 무음 구간임을 명시하고 사용자가 의도한 쉼이라면 허용한다. 임의의 음악을 채우지 않는다.

## 이동과 연결

| 행동 | 의미 | 즉시 보여줄 피드백 |
|---|---|---|
| 원을 일반 drag | 화면 배치·그리드 정렬 | 선 위를 지나가도 기존 연결과 순서 유지 |
| 삽입 모드에서 원을 연결선 위에 drag | 그 지점으로 사용 위치 이동 | 삽입 지점·새 연결·새 순서를 미리 표시 |
| 섹션 목록에서 연결선으로 drag | 기존 원본의 새 사용 위치 생성 | `후렴 A를 다시 사용` |
| 출력 포트에서 다른 원 입력으로 drag | 진행 경로 연결 | 연결 가능한 입력과 방향 표시 |
| `앞으로 이동`·`뒤로 이동` | 키보드로 순서 변경 | 전체 흐름 띠와 중앙을 함께 갱신 |

사용 위치가 단순 A→B→C 안에 있으면 B 이동 시 A→C를 연결하고 새 위치에 B를 넣는 것을 제안한다. 전환이 붙어 있거나 여러 연결이 얽혀 있으면 drop 전 변경 목록을 표시하고 전환 처리 범위를 선택하게 한다. 연결을 삭제해 경로가 끊기면 자동으로 다른 섹션을 추측하지 않는다.

시작·끝 위치 이동도 preview에서 명시한다. `레이아웃 정리`는 좌표만 바꾸며 재생 계획을 바꾸지 않는다. 시간 비례 흐름 띠는 선택적으로 열어 탐색·순서를 확인하며 로컬 마디 위치를 함께 표시한다. 추후 drag 편집을 추가해도 같은 편곡 명령을 호출해야 한다.

## 반복과 같은 섹션의 재사용

`벌스 · 8마디 · 총 2회`는 같은 내용을 연속 16마디 재생한다. “두 번째만 다르게”가 필요하면 `반복을 사용 위치로 펼치기`로 두 개의 사용 위치를 만든 후 둘째만 변형한다. 이 동작은 음악 결과를 유지해야 한다.

곡 앞과 뒤에 나오는 후렴은 각각 다른 사용 위치로 표시한다. 두 원의 이름은 `후렴 1`, `후렴 2`여도 동일한 `후렴 A` 원본을 참조할 수 있다. 하나의 원에 여러 출구와 숨겨진 방문 횟수 조건을 달아 일반적인 송폼을 표현하도록 강요하지 않는다.

섹션 그룹의 반복은 내부 음악 배치를 함께 반복한다. 그룹을 접거나 이동하는 조작은 반복을 바꾸지 않는다. 섹션 안의 MIDI phrase 반복과 섹션 전체 반복을 구분한다. 여러 섹션을 다시 상위 섹션에 담아 반복하는 재귀 송폼은 별도 후속 설계다.

## 원본과 이번 사용의 편집

`원을 열기`는 이번 사용의 유효 내용을 보여주며 상단에 편집 범위를 고정 표시한다.

| 동작 | 원본과의 관계 | 영향 |
|---|---|---|
| `다시 사용` | 같은 원본 참조 | 공통 내용 변경은 따라감 |
| `이번 사용만 변형` | 원본 + 명시적 override | 이번 사용만 변화 |
| `원본 편집` | 공유 원본 변경 | 이를 참조하는 사용 위치에 전파 |
| `독립 섹션으로 분리` | 현재 유효 내용을 새 원본으로 생성 | 이후 기존 원본 편집을 따라가지 않음 |

기본 편집 범위는 `이번 사용`을 제안한다. 기존 clip을 편집하면 그 clip 단위 override를 만들고, 덮어쓰지 않은 다른 clip은 원본 변경을 계속 따라간다. 전체 원본을 편집할 때는 영향받는 사용 위치와 편곡안을 보여준다. 저장된 이전 revision과 undo를 통해 복구할 수 있어야 한다.

예: 마지막 후렴에 보컬 harmony를 추가하면 그 사용에만 새 clip이 생긴다. 원본 베이스 리프를 고치면 모든 후렴의 베이스가 갱신된다. 마지막 후렴에서 이미 따로 편집한 베이스 clip은 유지되며 원본과 차이가 있음을 표시한다. 정확한 충돌 규칙은 [음악 데이터 모델](03-playback-model.md)에 둔다.

## 전환을 붙이는 경험

연결선을 선택하면 `전환 추가`를 연다. 사용자가 정할 것은 효과 이름보다 먼저 **언제, 누구에게, 얼마나** 적용할지다.

| 선택 | UI 예 | 음악적 의미 |
|---|---|---|
| 대상 | `드럼`, `보컬 send`, `전체 mix` | 어떤 소리를 변경하는가 |
| 앞 구간 안에서 | `마지막 1마디 교체` | 앞 섹션 길이를 유지하며 필인 사용 |
| 마디 추가 | `1마디 삽입` | 별도 음악 구간이 생기고 곡 길이 증가 |
| 겹치기 | `1마디 겹침` | 다음 섹션이 먼저 시작하고 길이 감소 |
| 잔향 | `앞 구간 잔향 유지` | 종료한 음의 꼬리가 다음 섹션 위에 남음 |

필인은 사용자가 만든 연주 clip 또는 MIDI pattern을 지정한다. plugin을 하나 놓았다고 필인이 자동 생성되지는 않는다. 필터 sweep 등은 준비된 processing 경로의 parameter automation으로 표현한다. 앞 구간과 뒤 구간의 대상이 다르면 따로 선택한다.

전환 audition은 앞 섹션 끝 일부부터 다음 섹션 첫 부분까지 문맥을 포함한다. 곡 길이 변화, 필인 교체 범위, overlap 범위를 흐름 띠에 표시한다. 연결을 옮겼을 때 필인이 다른 드럼이나 박자에 그대로 맞는지 다시 검토할 수 있어야 한다.

## 섹션 경계를 넘어가는 연주

보컬 pickup이나 길게 이어지는 기타 녹음을 마디 경계에서 강제로 잘라야 한다면 이 제품의 장점이 줄어든다. 섹션 상세 편집기에서 앞뒤 섹션을 문맥으로 보여주고 경계를 넘는 clip 범위를 표시한다.

녹음 원본은 연속 파일로 보존한다. 기본안은 경계에 맞춘 비파괴 clip 참조를 만들고, pickup·잔향·유지 구간을 명시적으로 관리하는 것이다. 여러 섹션에 걸친 take를 재배치할 때 어느 범위까지 따라갈지는 [미결 사항 Q06](05-decisions-and-validation.md)에 기록한다.

## 사운드 그래프로 전환

섹션에서 트랙을 선택하고 `사운드`를 열면 instrument, effect, send, bus를 노드와 케이블로 연결한다. 기본 경로는 자동으로 마련하고 사용자가 필요한 연결을 편집한다. 직렬 effect와 병렬 send가 첫 검토 범위다.

`기타 → Amp → EQ → 기타 bus` 같은 오디오 케이블과 `벌스 → 후렴` 같은 진행 연결은 다른 port type을 사용한다. 동일한 프리폼 작업 공간에서 유형별 보기·접기·필터를 제공하는 안으로 수정한다. 서로 다른 연결 의미를 하나의 케이블 타입에 섞지 않는다. 섹션에서 보이는 effect 설정에는 `트랙 공통`과 `이 섹션에서만` 범위를 표시한다.

전환의 filter sweep을 선택하면 해당 사운드 노드와 parameter를 찾아갈 수 있다. 두 그래프의 연결 고리는 안정적인 track/device/parameter ID이며, 송폼 연결선이 오디오 케이블이 되는 것은 아니다.

## 상태와 오류 문구

| 상태 | 표시 및 행동 |
|---|---|
| 섹션 선택 | 속성 편집, 자동 재생 없음 |
| 글로벌 값 변경 | 상속 중인 서클만 갱신; 개별 값과 기존 절대 pitch 유지 |
| 패턴 사용 안 함 | 이 서클의 글로벌 패턴 재생도 끔 |
| 박자/강세 불일치 | `강세 설정 확인`; 원본 pattern과 note 보존 |
| 재생 중 | 현재 원, 로컬 마디/박, 반복 회차, 다음 원 강조 |
| 구조 변경 대기 | `다음 섹션부터 적용`과 적용 지점 표시 |
| 경로가 끊김 | `다음 섹션을 연결하거나 여기서 끝내세요` |
| 출력이 여러 개 | `이 편곡안에서 재생할 연결을 선택하세요` |
| 끝 없는 반복 | `곡 길이를 정하려면 반복 횟수나 끝 지점을 지정하세요` |
| missing media | 파일 경로와 `다시 연결`; 원본 clip 참조 보존 |
| 사용별 override 충돌 | 원본과 현재 사용 차이, 유지/원본 적용 선택 |
| plugin 준비 실패 | 해당 트랙과 원인, 재시도/명시적 bypass |
| 재생 준비 지연 | 준비되지 않은 구간과 상태; 준비 완료 전 시작 보류 |
| 저장 실패 | `저장하지 못했습니다`와 경로·재시도·다른 위치 저장 |

곡 구성 중심의 기본 재생에서는 unresolved graph로 새 실행을 시작하지 않는다. 이미 재생 중인 유효 계획은 편집 오류가 생겨도 보존한다. 상세 적용 규칙은 [재생 모델](03-playback-model.md)에 둔다.

## 접근성과 검토 항목

- drag 없이 원 선택, 생성, 연결, 앞뒤 이동, 반복 설정, 삭제와 undo가 가능해야 한다.
- 키보드 focus와 현재 재생은 다른 표시를 쓴다. graph 순서를 텍스트 목록으로도 탐색한다.
- 원의 포트는 확대 상태와 무관하게 선택 가능한 hit area를 확보하고 마디 링과 충돌하지 않게 배치한다.
