# 생성 위치와 드럼 첫 입력 — build77

2026-09-10, 기준9b9993c. 새 앨범→기본 곡→섹션→드럼 MIDI→스텝을 실제 UI로 진행해 두 마찰을 확인했다. 곡의 생성 메뉴에 비활성 MIDI/오디오와 전역 작업이 함께 나오고, 빈 Sound Bank 드럼 스텝에는 킥 한 행만 나타났다. before AX/드럼 화면은 qa/generated/creation-workflow에 보존한다. 메뉴 자체 screenshot은 도구가 제공하지 못해 AX로만 확인했다.

UX 계약: 현재 컨테이너의 생성 작업을 한 번 클릭해 고른다. 곡/악장에서는 섹션·악장, 섹션/음악에서는 MIDI·오디오·이펙트, 사운드에서는 bus·전역이펙트, 앨범에서는 곡을 먼저 표시한다. 다른 컨테이너 생성은 ‘다른 위치’ 아래에 목적지를 적어 유지한다. 불가능한 항목을 첫 화면에 나열하지 않는다. 우클릭/A의 생성 scope와 상단 메뉴가 nested group/music/signal을 같은 컨테이너로 해석한다.

기본 GM Sound Bank 드럼의 행은36/38/39/42/45/46/49/51이다. 노트를 추가/삭제해도 기본 행이 사라지지 않고 관측/매핑/사용자 추가 행과 합쳐진다. sample zone 악기와 일반 신스에는 이 기본 행을 넣지 않는다. 행 표시만으로 음악 노트나 Undo를 만들지 않는다. 개별 추가/검색은 유지한다.

검증 계약: 곡/섹션/사운드의 메뉴, 실제 생성 대상·Undo, 기본8행 표시, 킥/스네어 실제 입력과 Undo, 검색, 저장 재열기, 음악/원본/자산 보존. 출력·audition·마이크는 시작하지 않는다. 단일 슬롯에서 UX/native/review/QA 순차 역할이며 독립 agent 검토를 주장하지 않는다.

최종 결과: 관련 Swift7개와 release67.41초 통과. 실제10상태에서 음악 보존·검색·메뉴·저장 편집기 복원을 비교했다. 세부 한계와 재현은 [QA](../qa/creation-interface-review.md)를 따른다.
