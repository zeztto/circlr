# 1.3 미디어 확인과 복구 사용 안내

대상: **1.3.0/build259 검증 후보 · 미출고**. 기능 설명과 사용자가 확인할 항목을 구분한다. 전체 QA 상태는 [1.3 QA 계획](../qa/1.3-plan.md), 버전 범위는 [1.3 실행 계획](releases/1.3.0.md)을 따른다.

## 곡 미디어 화면 열기

곡을 연 다음 macOS 메뉴의 **파일 → 곡 미디어와 복구…**를 선택한다. 또는 **⇧⌘P**로 명령 검색을 열고 `곡 미디어와 복구`를 검색해 Return을 누른다. 시작 화면이나 다른 설정 화면을 먼저 닫아야 할 수 있다.

이 화면은 현재 곡에 등록된 미디어의 읽기 상태를 검사한다. 문제가 있으면 파일 이름과 이유가 나타나며 **원본 찾기…**로 다시 연결할 수 있다. **다시 검사**는 외장 디스크를 다시 연결하거나 파일 위치를 복구한 뒤 사용한다. “모든 미디어를 사용할 수 있습니다”는 파일 검사 결과이며 오디오 품질이나 실제 청취의 합격 판정은 아니다.

Tab·Shift+Tab으로 조작을 선택하고 Return 또는 Space로 실행한다. **닫기** 또는 Esc로 캔버스에 돌아간다. 진행 중에는 **작업 취소**를 사용할 수 있으며 파일 작업 정리를 기다리는 동안 추가 조작이 잠시 비활성화될 수 있다.

## 누락·변경된 파일 다시 연결하기

1. 목록에서 해당 미디어의 **원본 찾기…**를 누른다.
2. 파일 선택창에서 실제 원본 파일을 지정한다. 같은 이름의 파일이라는 이유만으로 연결되지는 않는다.
3. 검사 결과를 확인한다. 기존 checksum이 있으면 내용이 일치하지 않는 후보는 원본으로 연결되지 않는다. 다른 파일을 선택하거나 올바른 원본 위치를 다시 확인한다.
4. 연결되면 이 asset을 참조하는 **모든 서클**에 반영된다. 필요하면 ⌘Z로 취소하고, 결과를 확인한 뒤 곡을 저장한다.

오래된 곡에 checksum이 없으면 **“원본 확인 정보가 없는 미디어입니다”** 확인창이 나타난다. 이 경우 앱은 동일한 원본임을 증명할 수 없다. 형식을 검사한 뒤 사용자가 직접 지정한 대체 파일로 연결하는 절차다. 내용을 확인한 경우에만 **대체 파일로 연결**을 선택하고, 확신이 없으면 **취소**한다. 자동으로 checksum 일치라고 표시하는 경로가 아니다.

검사 도중 곡이 바뀌었다는 메시지가 나오면 현재 곡에서 **다시 검사**한다. 실패 메시지를 성공으로 간주하고 원본을 지우지 않는다.

## 미디어를 포함한 사본 저장하기

**미디어 포함 사본 저장…**을 누르고 현재 곡과 다른 위치에 **새 이름**을 지정한다. 이미 존재하는 목적지는 덮어쓰지 않으므로 다른 이름을 선택한다. 곡에 필요한 오디오 미디어를 함께 수집하며 누락·읽기 오류가 있으면 이를 먼저 해결해야 한다.

사본 저장은 현재 열린 문서를 바꾸지 않는다. 원래 문서의 미저장 변경 표시(`dirty`)도 그대로 남는다. 원래 곡에 변경을 확정하려면 별도로 **저장**을 실행한다. 반대로 **다른 이름으로 저장…**은 열린 문서의 저장 위치를 바꾸는 동작이므로 사본 수집과 구분한다.

완료 메시지를 확인한 뒤 사본을 실제로 열어 음악과 미디어를 확인한다. 취소·실패 시에는 이유를 읽고 접근 가능한 새 목적지에서 재시도한다. 공간 부족이나 권한 오류를 검수하려고 실제 작업 디스크를 채우거나 권한을 바꿀 필요는 없다.

## 진단 정보 저장하기

**진단 정보 저장…**으로 사용자가 선택한 위치에 JSON을 저장한다. 자동 업로드나 계정 연결은 하지 않는다.

포함되는 정보는 앱 버전/build, 프로젝트 schema·음악 revision, 트랙·섹션·미디어 등의 개수, 미디어 검사 집계와 제한된 오류 코드, 재생·녹음·작업 상태다. **프로젝트·트랙·파일 이름, 파일 경로, ID, 오디오 내용, 계정·credential, 대화/활동 로그, 원문 오류·작업 메시지는 포함하지 않는다.** 따라서 이 파일은 곡 백업이나 오디오 품질 보고서가 아니다.

저장이 실패하면 화면의 이유를 확인하고 다른 위치로 재시도한다. 지원 요청에 첨부할 때도 저장된 JSON을 직접 확인한 뒤 전달한다.

## 복구 경고가 나타났을 때

이전 작업의 복구 제안에서 **취소**하거나 앱을 종료하면 복구 자료를 남긴다. 복구와 새 작업 시작은 서로 다른 선택이므로 현재 안내를 읽고 결정한다. 실제 작업 파일을 이용해 강제 종료를 반복하는 방식으로 검수하지 않는다.

build258에서는 읽을 수 없는 복구 파일에 대해 **“복구 파일을 읽지 못해 원본을 보존했습니다”** 경고와 보존 위치를 표시한다. **보존 파일 보기**는 Finder에서 그 파일을 선택한다. **새 작업 계속**을 선택해도 안내한 보존 파일을 덮어쓰지 않는다. 파일이 보존됐다는 사실은 음악 복구에 성공했다는 뜻이 아니다. 경고가 반복되면 보존 파일과 경고 내용을 유지한 채 지원을 요청한다.

## 저장 장치 제한

기존 곡을 덮어쓰는 저장은 완전한 프로젝트를 원자적으로 교체할 수 있는 파일 시스템을 요구한다. 격리된 **HFS+** 검증에서는 덮어쓰기 교체가 **ENOTSUP(errno 45)**로 거절됐다. 이때 기존 곡은 보존되며 **“새 위치에 사본으로 저장하세요”** 안내가 나온다.

같은 기존 경로의 저장을 반복하기보다 새로운 이름·위치를 선택한다. 검사된 HFS+ 환경에서는 새 위치 저장 후 다시 열기가 통과했지만 모든 외장 디스크·파일 시스템의 지원을 의미하지 않는다. 저장 오류가 나면 기존 곡을 직접 삭제해 우회하지 않는다.

## 사용자 검수 · 약 5분

검수는 원본을 보존한 작업용 사본에서 진행한다. 아래 항목은 **실제 사용자 확인용**이며 자동 테스트 통과와 별개다. 이번 검수에서 확인하지 않은 항목은 미확인으로 남긴다.

- [ ] **0–1분 · 실제 한글 입력:** 이름 입력란에 한글을 직접 타이핑한다. 조합 중 Space·⌘C/⌘V·⌘Z가 의도한 텍스트 동작으로 처리되는지, 음악 재생·노트 편집으로 새지 않는지 확인한다. 붙여넣기만 해서는 IME 조합 검수가 되지 않는다.
- [ ] **1–2분 · 저장과 재열기:** 입력 확정 후 ⌘S로 저장하고 사본을 다시 열어 이름과 음악이 유지되는지 확인한다. 조합 중 ⌘S는 입력이 유실되거나 이중 확정되지 않는지 별도로 관찰한다.
- [ ] **2–3분 · 키보드 이동:** 곡 미디어 화면을 열고 Tab·Shift+Tab·Return·Esc를 사용한다. 세로 또는 약 700pt 너비에서도 선택 표시와 버튼이 보이고 캔버스 재생으로 키가 새지 않는지 확인한다.
- [ ] **3–4분 · 사본 저장:** 작은 작업용 곡을 새 이름으로 미디어 포함 사본 저장한다. 현재 열린 원본과 미저장 표시가 바뀌지 않는지 확인한다. 미저장 여부는 검사 시작 시 상태와 비교한다.
- [ ] **4–5분 · 진단:** 진단 JSON을 저장해 위 제외 정보가 없는지 확인한다. 누락 파일이나 복구 경고가 이미 있는 경우에만 안내 동선을 추가로 확인한다. 재현되지 않은 경고를 확인했다고 표시하지 않는다.

문제를 발견하면 **build 번호 / 창 크기 / 입력 위치 / 누른 키 / 기대한 결과 / 실제 결과**를 기록한다. 실제 녹음·물리 청취·장시간 영상·전체 VoiceOver 검수는 이 5분 확인에 포함되지 않는다. 자동·격리 native 결과와 남은 OPEN 항목은 [QA 기록](../qa/1.3-plan.md)을 확인한다.

## English quick guide

This guide describes the **unreleased 1.3.0/build258 candidate**. Open **File → 곡 미디어와 복구…**, or search for that command with **Shift–Command–P**.

Use **원본 찾기…** to relink missing media. A matching filename is insufficient; known checksums must match. Legacy media without a checksum requires explicit consent to use the selected replacement. Relinking affects every circle referencing that asset and supports Undo.

**미디어 포함 사본 저장…** creates a new portable copy without switching the open document or clearing its unsaved changes. Choose a new destination. Diagnostics are a local JSON export containing counts and bounded status only, not names, paths, audio, credentials or conversation logs.

Recovery warnings identify preserved files; preservation does not mean successful recovery. Existing-project overwrite may be rejected on HFS+ with ENOTSUP; keep the original and save to a new destination. Actual Korean IME, keyboard focus and device listening checks remain separate from automated test results.
