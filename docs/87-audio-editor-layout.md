# 오디오 편집의 직접 조작 — build 73

planning-gate-v1: development-lead. 기준18eeb4a, integration worktree. 실제 슬롯 제한에 따라 UX → native utility → review → QA 순차 수행. 사용자 앱과 원본 음악은 보존한다.

## 흐름

좌우 ScrollView에 나뉜 수치 폼을 제거한다. 파형은 전체 가로폭을 사용하고, 아래 두 줄에서 배치/원본 시작/원본 끝/분할 위치와 볼륨/페이드 인/페이드 아웃/원본 BPM을 직접 입력한다. 분할·복제·바운스·템포 추종·음소거·삭제는 상단, 전체/선택/커서 보기와 확대는 파형 아래에 둔다. 별도 창/패널/새 메뉴를 추가하지 않는다. 음악 편집 의미와 유효성·Undo·원본/이번 사용 계약은 유지한다.

## 검증

소유: AudioWorkspace.swift와 버전/문서/QA. 1019×768 창과 콘솔 펼침 상태에서 모든 필드/주요 버튼이 스크롤 없이 보여야 한다. 수치 trim/fade, 분할 cursor/분할/Undo, 원본 BPM/템포, 복제/Undo, 저장 재열기에서 실제 결과와 음악 보존을 검사한다. 파형의 넓어진 좌표와 키보드 포커스를 확인한다. 실제 장치 재생/녹음과 사용 앱 교체는 별도 출고 조건이다.

## 결과

관련14개 테스트, native11상태/작은 창과 큰 창을 확인했다. 트림·페이드·템포·분할·복제·Undo·재열기와 전체 음악/자산 보존은 [QA](../qa/audio-layout-review.md)에 기록했다. 후속은 파형에서 수치 필드로의 직접 키보드 이동과 복제 공간 부족 사전 안내다.
