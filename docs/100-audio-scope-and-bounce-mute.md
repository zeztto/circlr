# 오디오 편집 범위와 바운스 출력 음소거

상태: build86 Audio21개·최종 Release41.19초 및 아래 native 검증 확인. QA 최종 대조 통과. [QA](../qa/audio-scope-review.md).

## 확인한 문제

build85 실제 앱에서 이번 사용에만 있는 오디오 복제본→오토메이션→공유 원본 켜기→오디오 복귀 시 본문이 비었다. 공유 원본에 오디오가 있는 경우에도 현재 편집 범위를 알려주는 표시가 없었다.

오프라인 바운스 회귀는 최초 테스트1개에서 assertion4개 실패로 재현했다. 출력 서클 음소거를 pre-output 바운스에 적용하지 않도록 수정한 뒤 관련21개 테스트를 통과했다. 이 결과는 실제 장치 출력이나 최종 UI 검증과 구분한다.

## 사용자 동선과 데이터 계약

- 기존 편집 줄에서 공유 원본/이번 사용 범위를 표시한다. 추가 세로 행으로 파형 공간을 줄이지 않는다.
- 공유 원본에 오디오가 없는 이번 사용 전용 클립은 해당 클립 편집 범위로 복귀할 수 있게 한다. 빈 본문만 남겨 사용자가 경로를 추측하게 하지 않는다.
- 범위 전환 자체는 음악을 변경하지 않는다. 공유 원본 수정과 이번 사용 수정의 적용 범위를 구분하고 기존 Undo·저장 계약을 유지한다.
- pre-output 바운스는 출력 서클의 음소거를 제외한다. upstream 음소거와 정상 출력 경로의 음소거는 유지한다.
- 바운스 WAV 적용 시 출력 음소거 해제와 PCM 결과를 대조한다. 오프라인 렌더 결과를 청취·물리 I/O 성공으로 해석하지 않는다.

## 계획 gate와 검증 기준

1. 기준 동선에서 현재 범위를 확인하고 이번 사용 전용 클립으로 복귀한다.
2. 범위 전환 전후 음악 불변, 공유 원본/이번 사용 수정의 대상 분리, Undo와 저장/재열기를 확인한다.
3. 작은 창에서 파형 높이가 유지되고 기존 오디오·오토메이션 왕복을 방해하지 않는다.
4. 출력 음소거의 pre-output 제외, upstream/정상 출력 음소거 보존, WAV 적용·음소거 해제·PCM 일치를 테스트한다.
5. 최종 Release·native·QA 근거를 확보한 범위만 완료로 기록한다. 현재 테스트 통과를 이 기준 전체의 완료로 계산하지 않는다.

## 최종 후보의 확인 범위

- 최종 keyboard 후보 UUID `6902AC6C-552F-30C6-9B8F-C18DF5AC7B29`, Release41.19초.
- 공유 원본/이번 사용 트림0.1/0.2초와 각 Undo, 범위 표시·파형 높이 유지 확인.
- 첫 후보의 Return 무응답을 native에서 발견했다. `AlbumCanvas` dispatch 수정 후 Return 복귀와 도움말의 키 입력 차단을 재확인했다.
- 음소거 출력의 실제 UI 바운스 완료:34초·24bit·48kHz, asset peak0.079956·RMS0.030609. 공유 원본 범위에서 바운스 클립으로 Return 복귀→원본 복원→Undo3와 저장/재열기 확인.
- 실제 출력·audition0회이며 사용자 앱을 유지했다. QA checker28개 상태·자산2개·오프라인 바운스1개와 WAV 직접 PCM peak/RMS/checksum 대조를 통과했다. 원본 Bounces 파일과 같은 해시의 `keyboard/bounced.wav`를 새 렌더 없이 보존했다.

## 다음 우선과제 — tail 정책과 잘림

고정2초 tail의 효과 잘림을 compiled renderer로 재현했다.1초 body의 끝 직전 pulse와 delay1초·feedback0.8에서 tail2초/5초의 앞3초는 동일했다. 짧은 쪽에서 잘리는3–6초 구간에 peak0.1024(약−19.8dBFS)·RMS0.008464가 남았다. [Python 재현](../qa/probe-bounce-tail.py) · [Swift 재현](../qa/probe-bounce-tail.swift).

기본 명령 `python3 qa/probe-bounce-tail.py qa/generated/bounce-tail-build86`의 fresh build 분기도 exit0으로 같은 결과를 재현했다. UI 검증 앱 종료 후 기존 사용자 앱만 남은 것을 확인했다.

다음 계획은 tail 정책, 사용자가 선택할 길이, 잘림 가능성 안내, 렌더 시간·메모리·파일 크기 등 자원 상한을 함께 정의한다. 긴 효과를 보존하는 조건과 상한에 도달했을 때의 동작을 검증 기준에 포함한다. 이 오프라인 재현은 실제 장치 청취와 구분하며 이번 build86에서 tail 문제가 해결되었다고 기록하지 않는다.
