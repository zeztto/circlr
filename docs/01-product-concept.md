# 제품 개념

> 설계 기준 문서. 최종 제품 범위는 [아티스트 창작 세계](21-artist-universe.md), 현재 앱 0.10.0의 실행 범위는 [README](../README.md)와 [검증 기록](../qa/0.10-review.md)을 따른다. 장기 설계 전체가 구현됐다는 뜻은 아니다.

기초 버전: 0.3 · 개념 갱신: 2026-09-07 · 소유 역할: product-manager · 상태: 제안, 사용자 확인 사항 별도 표시

circlr의 최종 목표는 **아티스트를 선택하고 그 아티스트의 창작 세계를 관리하는 도구**다. 프로필 아래에 작품·자료·세계관·생성물을 연결하고, 음악 제작은 [궤도 타임라인](19-orbit-timeline.md)과 같은 캔버스 편집으로 이어진다. 세부 제품·저장 모델은 [아티스트 프로필 설계](21-artist-universe.md)를 따른다. 아래는 음악 제작이라는 출발점의 설명이다.

## 사용자가 확정한 출발점

- 기존 DAW를 폭넓게 사용했지만 원하는 제품을 찾지 못했다.
- verse, bridge, chorus 같은 송폼 단위를 원형 덩어리로 표현하고 싶다.
- 노드를 사용해 연결하고, 반복하고, 이펙팅하고 싶다.
- 송라이터와 편곡자가 섹션을 만들고 편하게 옮기면서 곡 전체의 구성을 설계하는 도구다.
- 오디오 녹음·샘플과 MIDI·가상악기를 함께 사용한다.
- 섹션 안의 음색 처리와 섹션 사이 전환 효과를 모두 다룬다.
- 제품명은 써클러(circlr)다. 영문 표기는 소문자 `circlr`를 사용한다.
- 사용자가 Mac을 사용하므로 첫 대상 플랫폼은 macOS 앱이다.
- ComfyUI 같은 자유 배치 노드 에디터를 지향하고 그리드·정렬·그룹을 지원한다.
- 섹션 길이와 마디·박은 원의 테두리에 표현한다.
- 글로벌 tempo·scale·박자와 서클별 개별 설정을 함께 지원한다.
- 글로벌 비트는 리듬 기준과 실제 드럼·리듬 패턴을 별도 설정으로 모두 지원한다.
- 초기 요청은 아이디어·문서·기본 아키텍처였으며 이후 실제 앱 제작과 개선 요청이 이어졌다.
- 모든 음악 요소를 서클로 표현한다. 각 섹션은 오디오·MIDI·이펙터 서클을 담고 연결하는 그룹이다.
- 기본은 단일 다크 캔버스이며, 최신 사용자 결정에 따라 확대하면 같은 캔버스에서 MIDI·오디오를 직접 편집한다.
- 최종 목적은 게임 캐릭터를 선택하듯 아티스트 프로필에 진입해 그 아티스트의 모든 창작물을 종합 관리하는 도구다.
- 음악뿐 아니라 텍스트·영상·이미지와 세계관을 통합한다.
- 연결은 서클 둘레의 8방향에 배치하고 IN·OUT을 명시하며 멀티 입력·출력을 지원한다. [연결 계약](22-eight-direction-ports.md)에서 방향·포트·신호의 의미를 구분한다.

어떤 기존 제품의 어떤 조작이 가장 불편했는지는 아직 확인하지 않았다. 아래 문제 정의는 사용자 발언에서 도출한 가설이다.

## 해결하려는 일

**음악적 생각의 단위를 유지하면서 곡의 구조를 바꿀 수 있어야 한다.** “브리지 뒤에 후렴을 한 번 더”, “두 번째 벌스는 절반만”, “마지막 후렴은 더 크게” 같은 의도를 섹션 수준에서 직접 표현한다.

| 음악적 의도 | 제안하는 조작 | 확인할 결과 |
|---|---|---|
| 후렴을 먼저 들려주는 곡으로 바꾸기 | 후렴의 사용 위치를 인트로 뒤 연결선에 삽입 | 전체 연주·automation이 함께 따라옴 |
| 벌스를 두 번 돌기 | 해당 원을 `총 2회`로 설정 | 원본 길이는 8마디, 이번 구간은 16마디 |
| 마지막 후렴을 크게 만들기 | `이번 사용만 변형` 후 연주·mix를 변경 | 앞의 후렴은 유지됨 |
| 브리지 유무 비교 | 편곡 A를 복제해 B에서 브리지 제거 | 두 안의 순서·길이·차이를 비교 |
| 후렴 직전에 한 박자 쉬기 | 연결점에 브레이크 설정 | 대상 악기와 시간 범위를 보고 audition |
| 기타 리프를 곡에 배치하기 | 녹음한 리프를 섹션으로 만들고 연결 | 섹션 안의 세부 편집과 전체 구성 왕복 |

이는 클립을 옮기는 속도뿐 아니라, 변경 결과를 예측하는 능력과 원본을 잃지 않는 신뢰의 문제다.

## 제품의 기본 단위

| 단위 | 음악가에게 보이는 의미 | 책임 |
|---|---|---|
| 곡 | 하나의 작업 프로젝트 | 악기, 미디어, 섹션, 편곡안 보관 |
| 트랙 | 드럼·베이스·기타·보컬 등 연주 파트 | 악기·입출력·기본 mix의 지속적인 정체성 |
| 섹션 원본 | 후렴 A와 같은 음악 그룹 | 내부 오디오·MIDI·악기·이펙터 서클과 연결, 로컬 시간 |
| 섹션 사용 | 이 곡의 첫 번째 후렴 | 원본 참조, 반복 수, 이번 사용의 변형 |
| 음악 서클 | 그룹 안의 연주 또는 처리 요소 | 종류별 내용·신호 포트·부모 설정 상속 |
| 연결 | 다음 구간 또는 신호의 처리 경로 | 진행과 audio/MIDI routing을 구분 |
| 편곡안 | 본편·짧은 버전 등 선택한 구성 | 시작부터 끝까지의 유한한 재생 경로 |

섹션 이름은 자유롭게 정한다. Verse와 Chorus는 음악적 메모이며 이름이 소리나 에너지를 자동으로 결정하지 않는다. 리프 A, 헤드, 솔로, 인터루드, 자유박 구간 같은 이름도 허용하는 방향이다. 자유박 재생의 구체적 시간 규칙은 후속 설계 사항이다.

## 프리폼 캔버스와 원형 표현

기본 작업 공간은 원형 노드를 자유롭게 배치·연결하는 캔버스다. 큰 섹션 서클 안에서 음악 서클을 만들고 연결한다. 그리드 snap, 중심 정렬, 간격 정돈, 다중 선택을 제공한다. 섹션 그룹은 길이·반복·상속 범위를 갖는 음악 구조다. 공간 배치와 접기만으로 시간이나 신호 합산은 바뀌지 않으며, 기존 정리용 CanvasGroup과 섹션 그룹을 구분한다.

원 테두리는 실제 음악 위치를 표시하는 마디 링이다. 한 바퀴 = 섹션 한 회를 제안하며, 같은 박자의 8마디는 링의 큰 구간 8개로 나뉜다. 박자·마디 길이에 따라 눈금을 계산하고 재생 위치가 이 눈금을 따라 돈다.

원의 크기 정책은 미정이다. 초기 제안은 읽기 가능한 일정 크기와 zoom에 따른 눈금 상세도다. 긴 섹션의 눈금 밀도와 서로 다른 tempo의 길이를 보완하도록 선택적으로 여는 **시간 비례 전체 흐름 띠**를 둔다. 마디 번호는 각 서클의 로컬 박자 기준으로 함께 표시한다.

축소 시 섹션 이름·길이·반복·내부 요약을 우선 표시하고, 확대하면 같은 캔버스에서 자식 서클과 연결을 읽고 waveform·note를 직접 편집한다. 사각 창 방식은 이후 사용자 결정으로 대체됐으며, 현재 시간 의미와 조작은 [궤도 타임라인](19-orbit-timeline.md)을 따른다.

## 세 가지 작업 깊이

| 깊이 | 사용자의 질문 | 주요 편집 |
|---|---|---|
| 송폼 | 다음에는 무엇이 나와야 하는가 | 순서, 반복, 편곡안, 전환 |
| 섹션 | 이 부분에서 악기들이 무엇을 연주하는가 | 녹음, clip, note, take, 구간 automation |
| 사운드 | 이 악기와 구간은 어떻게 들려야 하는가 | instrument, insert, send, bus, mix |

세 깊이는 같은 캔버스의 포함 관계와 연결로 이어진다. 섹션 안에 악기·이펙터를 서클로 표현하되, 화면의 서클과 실제 plugin 실행 instance는 구분한다. 여러 섹션의 악기 공유와 섹션별 독립 음색을 모두 표현할 수 있게 설계하며 동시 tempo·잔향·automation을 고려한 자원 공유 정책은 별도로 정한다.

## 기존 제품과의 관계

장면 단위 재생, 송폼 구간 이동, 노드 방식 음향 처리는 이미 여러 제품에서 제공된다. Ableton Live의 Scenes와 Follow Actions, Logic Pro의 Arrangement Markers, Bitwig의 The Grid, AudioNodes와 Nodal을 비교 대상으로 조사했다. 확인 범위와 공식 출처는 [비교 조사](06-references.md)에 기록했다.

차별성 가설은 **섹션을 원본으로 관리하고 여러 편곡안에서 재사용하며, 변형과 전환을 포함한 곡 전체 구성을 같은 작업 흐름에서 편집하는 것**이다. 원형 UI나 노드 자체의 독창성, 모든 경쟁 제품 대비 우월성을 주장하지 않는다.

## 첫 제품 후보의 범위

아래는 개발 승인이 아니라, 장차 사용자가 한 곡을 끝낼 수 있는 최소 범위에 대한 제안이다. 오디오·MIDI 병행과 두 종류의 이펙팅은 사용자 확인 사항이다.

| 우선도 | 범위 | 완료 의미 |
|---|---|---|
| 핵심 | 프리폼 캔버스·그리드·정렬·그룹·원형 마디 링 | 음악 구조를 자유롭게 배치하고 섹션 시간 확인 |
| 핵심 | 글로벌/서클별 tempo·scale·meter·BeatGrid·RhythmPattern | 기본 설정을 공유하며 특정 섹션만 독립적으로 작곡 |
| 핵심 | 섹션 생성·명명·길이·연결·재배치·유한 반복 | 한 곡의 구성을 처음부터 끝까지 결정 |
| 핵심 | 원본 재사용·사용별 변형·참조 분리 | 마지막 후렴만 변경해도 앞 후렴 보존 |
| 핵심 | 편곡 A/B·선택적 전체 흐름 띠·구간 audition | 후보를 듣고 최종 구조 선택 |
| 핵심 | 기본 오디오 녹음·import·MIDI 입력과 편집 | 자신의 음악 재료로 곡 작성 |
| 핵심 | 기본 instrument/effect/bus 노드 연결·트랙 mix·명시적 전환 범위 | 섹션을 넘어도 의도한 소리 유지 |
| 핵심 | undo/redo·저장/복구·stereo와 stem export | 작업 보존과 다른 도구로의 전달 |
| 핵심, 포맷 미정 | 외부 instrument/effect hosting | 필수 plugin과 포맷을 사용자와 선정 |
| 후속 검토 | 복잡한 signal graph, comping, 고급 warp | 첫 곡 제작 시 필요도에 따라 승격 |
| 후속 검토 | live triggering, 확률 분기, 섹션 안에 다시 섹션을 담는 재귀 송폼 | 필수인 섹션→음악 서클 포함 관계와 구분 |

반복 녹음의 take 보존은 기본 녹음에 포함한다. 여러 take를 조합하는 전문 comping UI는 별도 범위다. 가상악기 요구를 충족할 수 있도록 hosting을 핵심 후보에 포함했으며, 정확한 plugin·포맷·호환성 범위는 미정이다. 사용자 곡을 만들 수 없는 도구를 완성된 DAW로 취급하지 않는다.

첫 대상 플랫폼은 macOS로 확정했다. 일정, 팀 규모, 가격, 수익모델, 최소 지원 macOS 버전과 배포 방식은 미정이다. AI 자동 작곡이나 cloud 협업은 현재 요청에서 도출되지 않으므로 기본 아키텍처의 전제로 두지 않는다.

## 성공 기준과 실패 신호

첫 사용성 검토에서는 기존에 작업했던 한 곡을 기준으로 다음을 확인한다. 사용자 음원은 아직 받지 않았으므로 현재 문서에는 설명용 사례만 사용했다.

- 사용자가 시작점·순서·반복·총길이를 도움 없이 설명할 수 있다.
- 브리지 이동과 마지막 후렴 변형 후 영향받는 구간을 정확히 예측한다.
- 편곡 A/B를 만든 뒤 원래 안을 복구할 수 있다.
- 섹션 안팎으로 이동해도 지금 무엇을 수정하는지 잃지 않는다.
- 현재 쓰는 도구와 같은 편곡 과제를 수행하고 조작 수·수정 실수·완료 시간을 비교한다. 목표 수치는 관찰 후 정한다.

그래프의 선을 정리하는 시간이 작곡보다 길어지거나, 반복 원본을 실수로 바꾸거나, 전환에 매번 수동 audio bounce가 필요하면 설계를 다시 검토한다.
