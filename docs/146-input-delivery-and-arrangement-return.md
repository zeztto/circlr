# 한글 입력 전달 진단과 편곡별 작업 복귀

상태: build126에서 한글 입력 전달 경계를 비교 관측했다. build127 편곡별 마지막 작업 복귀의 소스 검토·Release와 아래 native 검증을 완료했다. 최종 재열기 r62와 production strict 서명/UUID도 확인했으며 독립 15개 capture 감사도 통과했다. 입력 전달 관측과 새 복귀 기능의 완료 근거를 구분한다.

## 한글 입력 전달 경계

앞선 편곡 이름 검증에서 한글 typeText가 축소된 원인을 분리하기 위해 새 빈 QA 콘솔에 `ABC 한글 가나다 123`을 전달했다. 결과는 `ABC   123`이었다. TextEdit의 새 문서에도 같은 문자열을 같은 도구로 전달했을 때 동일하게 한글 부분이 빠졌다.

실제 JPEG/AX는 `qa/generated/input-delivery/circlr-console`과 `textedit`에 보존한다. 서로 다른 앱에서 같은 도구 입력이 같은 방식으로 축소됐으므로 이 관측만으로 써클러 고유의 입력 버그라고 단정할 수 없다. 도구 전달 또는 공통 입력 환경 중 정확한 원인은 아직 확정하지 않았다. 실제 한국어 IME로 사용자가 조합 입력하는 경로를 검증한 것은 아니다.

TextEdit의 새 문서는 닫을 때 저장하지 않음을 선택해 폐기했다. 콘솔 문자열은 명령으로 실행하지 않았고 QA 앱을 종료했다. 사용자 문서·음악 내용을 바꾸는 진단이 아니다. 이 결과를 한국어 입력 전체 지원 완료 또는 미지원 판정으로 사용하지 않는다.

## 편곡별 마지막 작업 복귀 계약

편곡 대안을 비교할 때마다 작업 위치를 다시 찾는 비용을 줄이기 위해 세션 내 편곡별 마지막 주소와 workspace를 기억하는 경로를 구현한다. GUI와 MCP의 편곡 선택이 같은 복귀 동작을 사용해야 한다. 문서가 바뀌면 기억을 지워 다른 프로젝트의 주소를 재사용하지 않는다.

복귀 시 저장된 주소가 현재 편곡·프로젝트에서 유효한지 확인하고, 사라졌거나 적용할 수 없으면 해당 composition으로 돌아간다. 임의의 첫 MIDI를 원래 작업 위치라고 선택하지 않는다. 이 기억은 임시 UI 상태이며 음악 모델·프로젝트 schema를 바꾸는 기능이 아니다. 디스크에 편곡별 작업 위치를 영구 저장한다고 주장하지 않는다.

소스 검토는 PASS했다. 세션 기억은128개 상한과 정확한 주소·original/workspace mode를 사용하고 문서 reset에서 지운다. 이 상한 전체와 모든 주소 조합을 native로 검증한 것은 아니다.

## 검증 조건

- A의 실제 편집 주소/workspace에서 B로 이동해 다른 작업을 한 뒤 A/B 왕복 시 각각의 위치·편집 화면이 복귀하는지 확인한다.
- GUI 선택과 MCP 선택의 경로를 대조하고 현재 편곡 재선택은 작업 상태를 불필요하게 초기화하지 않아야 한다.
- 문서 전환/재열기에서 임시 기억을 지우고, 삭제되거나 무효한 대상은 composition으로 복귀하는지 검사한다.
- 음악 내용·Undo·사용자 파일을 보존하고, 실제 수정된 적용 편곡과 UI 기억의 변화를 구분한다.
- Release·서명/바이너리 식별·실제 화면/AX·저장 데이터 감사는 각각 수행한 결과만 기록한다. 소스 검토를 실제 실행 결과로 대체하지 않는다.

물리 오디오·한국어 IME·편곡별 영구 위치 저장은 이번 검증으로 완료되지 않는다. [현행 개발 계획](138-current-development-plan.md)의 한 곡 제작과 에이전트·아티스트 확장 목표를 유지한다.

## build127 검증 결과

baseline126에서는 A→B→A 후 composition으로 돌아가 기존 작업을 잃는 동선을 r46에서 관측했다. 최종 Release는 44.90초, UUID는 `46B2AAC2-3D40-3692-8D13-4392E69537DF`다.

final127에서 r46의 A 오디오 표시 범위 12–20초 → r47의 B automation 점 qa-use-gain·−12.04dB → r48의 A 복귀 → MCP로 r49의 B 복귀 순으로 작업 위치와 automation 점 복귀를 확인했다. GUI/MCP의 현재 편곡 재선택은49를 유지했고 stale 요청도49에서 거절됐다. r50의 A 스텝·topPitch 19 → r51의 B 피아노 → r52의 A 스텝·topPitch 19를 확인했다. 저장/재열기52는 정확히 일치했고 새 세션에서 B를 선택한53은 composition으로 복귀하여 임시 기억 reset을 확인했다. 빈 이름에서는 GUI 전환과 음악 변경을 차단했다.

B 오디오를 GUI에서 삭제한 r56·Undo한 r57 후 r58의 A에서 음악을 복원했다. arrangementID를 빠뜨린 첫 background 삭제 batch는58에서 거절되어 변경이 없었다. B arrangementID를 명시한 edit_audio로 삭제한 r59 뒤 B를 선택한 r60은 삭제된 대상 대신 composition으로 복귀했다. Undo 2회 후 r62의 final-saved에서 기준 음악·자산 4개를 복원했다. 이 실패 요청을 성공 삭제에 합산하지 않는다.

최종 15개 capture의 독립 감사는 PASS했다. 의도한 B 오디오 삭제 r60에서만 node·edge·빈 lane override·위치가 바뀌었고 나머지는 기준 음악과 일치했다. 자산 4개 SHA·noIO도 확인했다. 마지막 r62도 재열기했고 Undo 후 저장한 composition 화면으로 복귀했다. production strict 서명과 동일 UUID를 확인하고 QA 앱을 CmdQ로 종료했다. final-saved=final-reopened=disk는 r62에서 정확히 일치했고 독립 감사와 root 대조가 모두 통과했다. 물리 오디오·새 PCM 렌더 검사는 실행하지 않았다. 한국어 IME는 미검증이며 앞선 서로 다른 앱의 동일 축소 관측과 구분한다.
