# 프리폼 캔버스와 서클의 음악 설정

> 설계 기준 문서. 0.4.0에서 실행 가능한 범위는 [프로토타입 계약](08-prototype-contract.md)과 [검증 기록](09-prototype-verification.md)을 따른다. 이 문서의 장기 동작 전체가 구현됐다는 뜻은 아니다.

버전: 0.3 · 소유 역할: ui-ux-designer / architecture · 상태: 사용자 방향 반영, 세부 동작 Proposed

2026-09-07 갱신: 섹션 자체가 오디오·MIDI·이펙터 서클을 담는 음악 그룹으로 확정됐다. 부모/자식 탐색·설정·시간·연결의 최신 계약은 [중첩 서클 모델](13-nested-circle-model.md)을 따른다. 아래 시각 그룹 설명은 기존 정리용 `CanvasGroup`에만 해당한다. 필드별 설정 상속은 자식 음악 서클까지 확장하며, 정밀 note·파형 편집은 필요할 때 사각 창에서 연다.

## 사용자 지정 방향

써클러는 **자유롭게 배치한 원형 노드를 연결하는 macOS DAW**다. ComfyUI와 같은 노드 에디터의 작업 감각을 참고하며, 그리드·정렬·그룹을 지원한다. 각 섹션의 길이와 마디는 원의 테두리에 표현한다. 글로벌 tempo·scale·beat 기준을 두면서 각 서클이 독립적인 tempo·scale·박자를 가질 수 있다. 글로벌 비트는 사용자 답변에 따라 리듬 기준과 실제 드럼·리듬 패턴을 별도로 모두 지원한다.

ComfyUI는 노드를 배치하고 연결하는 canvas를 중심으로 workflow를 편집한다고 설명한다. 이 작업 공간의 감각을 참고하되, 써클러의 재생·시간·노드 형태는 음악 작업에 맞춰 설계한다. ComfyUI의 framework를 채택한 것은 아니다. [ComfyUI 공식 인터페이스 안내](https://support.comfy.org/articles/7675456845-the-comfyui-interface)

## 자유 배치 캔버스

| 기능 | 제안 동작 | 음악에 미치는 영향 |
|---|---|---|
| pan·zoom | 넓은 2D 공간에서 이동·확대·축소, 선택/전체 보기 | 없음 |
| 공간 그리드 | 표시와 snap을 각각 켜고 끔; 확대에 따라 표시 밀도 조절 | 없음 |
| 정렬 | 선택한 원의 중심을 수평·수직으로 정렬, 중심 간격 균등 배치 | 없음 |
| 다중 선택 | 영역 선택·선택 추가·여러 원 함께 이동 | 없음 |
| 정리용 그룹 만들기 | 기존 CanvasGroup으로 함께 이동; 최종 외형은 재검토 | 없음; 섹션 음악 그룹과 구분 |
| 그룹 접기 | 펼치기 전용 요약과 외부 연결 표시 | 내부 재생·음악 설정 유지 |
| 원 배치 잠금 | 실수로 원이나 그룹이 이동하는 것을 방지 | 재생·parameter 편집 가능 |
| 연결 | 명시적인 port와 선으로 진행 또는 신호 경로 지정 | 연결 유형에 따라 변경 |
| 순서에 삽입 | 삽입 모드에서 연결선에 drop, 변경할 선을 preview | SongGraph의 순서 변경 |

그리드는 위치를 맞추는 도구다. 캔버스 한 칸을 한 박으로 간주하지 않는다. 일반 drag는 선 위를 지나가도 화면 위치만 바꾼다. 순서를 바꾸는 삽입 조작은 명시적으로 시작하고 drop 전에 확인 가능한 preview를 제공한다.

그룹 이동은 내부 상대 위치를 보존한다. snap은 그룹 기준점에 적용하고 각 원을 따로 snap해 모양을 찌그러뜨리지 않는다. 그룹 해제는 내용이나 연결을 삭제하지 않는다. 그룹 삭제와 포함된 노드 삭제를 별도 동작으로 둔다.

### 시각 그룹과 음악 구조

**섹션 그룹**은 내부 음악 서클을 소유하고 길이·반복·음악 설정을 가진다. 아래의 ‘일반 그룹’은 기존 정리용 그룹이며 섹션을 의미하지 않는다. 음악 요소의 기본 외형은 모두 원형이고 섹션의 실제 포함 관계를 원형 경계로 표현한다.

일반 그룹은 캔버스 정리용이다. `1절 아이디어`, `후렴 후보`, `드럼 처리`처럼 사용자가 이름을 붙인다. 그룹 생성·이동·접기 때문에 재생 순서, tempo, scale, 박자, 오디오 합산이 바뀌지 않는다.

선택한 여러 섹션을 함께 반복하려면 별도의 `묶음 반복`을 사용한다. audio를 합치려면 bus 노드를 사용한다. 반복 묶음과 bus는 실제 음악 동작을 갖고, 단순 frame과 다른 표시를 사용한다. 접힌 frame은 새로운 재생 node가 아니므로 임의의 섹션 길이를 부여하지 않는다.

### 같은 작업 공간의 서로 다른 연결

송폼 진행과 audio/MIDI routing은 별도의 논리 graph로 유지한다. 화면에서는 **같은 프리폼 작업 공간에서 연결 유형과 보기를 선택**하는 안을 제안한다. 선택한 섹션의 사운드 연결을 펼치고 관련 없는 선을 숨길 수 있다. 별도 화면으로만 이동해야 한다는 이전 제안은 이 방식으로 수정한다.

진행·audio·MIDI·control 포트는 이름과 모양으로 구분하며 맞지 않는 포트끼리는 연결되지 않는다. port는 원둘레의 시간 눈금을 가리지 않는 별도 영역에 둔다. 연결선이 닿는 각도가 시작 마디나 재생 시점을 결정하지 않는다.

모든 실행 노드의 기본 외형은 원형이다. **시간이 있는 섹션 노드**에는 마디 링을 표시한다. 리듬 패턴 노드에도 자신의 패턴 길이를 표시하되 `패턴` 역할을 구분한다. instrument·effect·bus처럼 고유한 음악 길이가 없는 노드는 원형을 유지하면서 역할과 상태를 표시하고 가짜 마디 눈금을 만들지 않는다. 그룹 frame과 선택 영역은 캔버스의 보조 요소다.

## 원의 테두리 = 섹션의 음악 시간

**한 바퀴 = 섹션 한 회의 전체 길이**를 기본 제안으로 한다. 시작은 12시 방향, 진행은 시계 방향이다. 큰 눈금은 마디 경계, 작은 눈금은 박과 필요에 따른 박 분할을 나타낸다. 반복 회차는 `1/2회`처럼 따로 표시한다.

| 사례 | 링 표현 | 원 중앙의 보조 정보 |
|---|---|---|
| 8마디, 4/4 | 큰 구간 8개, 구간마다 quarter-note 박 4개 | `8마디 · 120 BPM · 4/4` |
| 4마디, 7/8 | 큰 구간 4개, 각 마디 안 8분음표 위치 7개 | `4마디 · 96 BPM · 7/8` |
| 8마디 총 2회 | 같은 링을 두 번 진행 | `8마디 · 총 2회 · 현재 2회` |
| 섹션 내부 변박 | 각 마디의 실제 음악 길이에 비례한 구간 | 현재 마디·박자와 전체 길이 |
| 긴 섹션·축소 화면 | 박 눈금을 생략하고 마디를 묶어 표시 | 전체 마디 수를 계속 표시 |

7/8의 `2+2+3` 같은 강세 묶음은 작은 눈금을 묶는 추가 표시다. 분모 단위의 눈금과 사람이 느끼는 강박을 동일한 의미로 취급하지 않는다. 강세 묶음은 사용자가 선택한다.

링의 각도는 **경과 초가 아닌 로컬 음악 위치**에 대응한다. local quarter-note 길이 `L`과 위치 `q`에 대해 시작점으로부터 진행각은 `360 × q/L`이다. 고정 박자에서는 마디가 같은 크기로 나뉘고, tempo가 바뀌면 playhead의 회전 속도가 달라진다. 한 섹션에 4/4 한 마디와 7/8 한 마디가 있으면 두 마디는 각각 192도와 168도를 차지한다.

원 반지름과 길이를 비례시킬지는 아직 확정하지 않았다. 기본 제안은 일정한 읽기 크기와 zoom에 따른 상세 표시이며, 어떤 시각 크기를 선택해도 실제 길이는 음악 데이터로 저장한다. 원 resize와 섹션 길이 편집을 혼동하지 않도록 한다.

### 테두리에서의 편집 제안

- 링의 마디를 가리키면 `3마디 2박`과 섹션 내 위치를 보여준다. 클릭하면 로컬 편집 위치를 선택한다.
- 위치 선택과 실제 transport seek를 구분한다. 선택만으로 재생 중인 곡이 갑자기 이동하지 않는다.
- 링 위 구간을 선택해 연주 확인·반복 audition·전환 범위 편집으로 이어갈 수 있다.
- 길이는 전용 `마디 수/길이 편집`에서 수정하고, 원 전체를 이동하거나 연결하는 동작과 분리한다.
- 길이를 줄여 clip을 자르게 되는 경우 영향 범위를 미리 보여주며 원본 bytes를 보존한다.
- pickup과 tail은 본문 링 바깥의 별도 표시를 사용한다. `8마디` 본문 길이에 잔향 시간을 섞지 않는다.

이 조작들은 아직 구현·사용성 검증하지 않은 제안이다.

## 글로벌 설정과 서클별 설정

각 설정은 독립적으로 상속하거나 직접 지정할 수 있다. tempo를 개별 지정했다고 scale까지 글로벌 연결에서 분리되지 않는다.

| 설정 | 글로벌 값의 역할 | 서클 개별 값의 역할 |
|---|---|---|
| Tempo | 곡의 기본 속도 | 특정 섹션의 BPM 또는 local tempo map |
| Scale | root와 scale/mode의 기본값 | 전조·mode 변경·해당 섹션의 pitch 기준 |
| Meter | 기본 박자표 | 4/4, 7/8, 6/8 등 개별 박자와 local meter map |
| BeatGrid | 박 분할·강세·swing 등 리듬 기준 | 섹션의 입력·눈금·리듬 기준 |
| RhythmPattern | 실제로 재생할 기본 드럼·리듬 패턴 | 이번 서클의 패턴 대체 또는 명시적 사용 안 함 |

상단에는 글로벌 값을, 선택한 원의 inspector에는 **실제 적용값과 출처**를 보여준다. 원에는 개별 설정된 항목을 우선 표시하되 필요한 경우 전체 값을 펼친다.

```text
글로벌     120 BPM · C minor · 4/4
벌스       글로벌 따르기 → 120 BPM · C minor · 4/4
브리지     개별 설정     → 96 BPM · D Dorian · 7/8
후렴       tempo 개별 / 나머지 글로벌 → 128 BPM · C minor · 4/4
```

글로벌 tempo를 132로 바꾸면 벌스만 132가 되고 브리지 96·후렴 128은 유지된다. 글로벌 scale만 바꾸면 scale을 상속하는 벌스·후렴이 새 기준을 따른다. 이것이 실제 note나 녹음 pitch를 자동 변경한다는 뜻은 아니다.

### 저장과 상속 정책 제안

`MusicalContext`는 tempo, scale, meter, beatGrid, rhythmAssignment 필드를 가진다. 각 필드는 출처를 명시적으로 저장한다. 반복마다 직전 노드에서 설정을 넘겨받는 숨겨진 상태를 만들지 않는다.

| 위치 | 정책 | 의미 |
|---|---|---|
| Project | 값 지정 | 글로벌 기본값 |
| SectionDefinition | `inherit` / `local` | 글로벌 따르기 / 원본 고유값 |
| SectionUse | `inherit` / `global` / `local` | 원본 따르기 / 원본 override를 건너뛰고 글로벌 따르기 / 이번 서클 직접 지정 |

기본 경로는 `글로벌 → 섹션 원본 → 이번 사용`이다. UI의 `글로벌 따르기`는 값의 복사가 아니라 연결이다. 다시 개별로 고정하면 현재 적용값을 명시적 local 값으로 저장한다. 화면 그룹은 이 상속 경로에 끼어들지 않는다.

scale의 root와 mode, meter의 분자와 분모처럼 하나의 의미를 이루는 값은 한 단위로 저장한다. meter를 바꿔 기존 강세 묶음이 맞지 않으면 `강세 설정 확인`을 표시하고 새로운 강세 패턴을 임의로 만들지 않는다. 잘못된 강세는 적용하지 않고 유효한 박자 눈금과 구분한다.

tempo/meter/scale map이 있다면 각 반복의 로컬 시작에서 같은 map을 다시 적용한다. `ResolvedMusicalContext`에는 유효 값·map·출처 revision을 담아 편집기·링·재생 계획이 같은 해석을 사용한다.

## 리듬 기준과 실제 리듬 패턴

`BeatGrid`는 눈금·입력 snap·강세·swing 기준이다. 이것만 설정해 드럼 연주를 생성하지 않는다. 메트로놈 click은 별도의 켜기/끄기로 이 기준을 사용할 수 있다. 기존 연주를 quantize하거나 swing하려면 적용 범위를 명시한다.

`RhythmPattern`은 길이를 가진 MIDI note/trigger와 선택적 audio clip 참조를 보관하는 실제 음악 재료다. 반복 구간, 원래 meter, drum map과 대상 Track/Instrument ID를 가진다. 사용자 입력·녹음·import로 만들며 근거 없는 기본 음원을 채우지 않는다. 실제 소리는 연결된 instrument/sample source가 낸다.

글로벌에는 기본 패턴 참조를 지정한다. 이를 상속한 서클에서 해당 패턴을 재생하고, 서클의 개별 패턴은 그 자리에서 기본 패턴을 대체한다. 패턴을 명시적으로 `사용 안 함`으로 지정하면 그 서클은 글로벌 패턴도 재생하지 않는다. 그룹은 패턴을 덧붙이거나 음소거하지 않는다.

패턴 재생기는 서클의 유효 tempo를 따른다. 별도 숨겨진 글로벌 재생기와 서클 재생기를 동시에 돌려 드럼이 중복되지 않게 한다. 두 패턴을 겹치려면 사용자가 명시적으로 추가 lane/source를 만든다. 기본 패턴 phase는 각 서클 진입·반복에서 시작으로 돌아가며, 여러 서클에 걸친 연속 phase는 후속 옵션으로 검토한다.

원본 패턴 길이는 보존한다. 4/4 한 마디 패턴을 7/8 서클에 넣어도 자동으로 note를 늘리거나 지우지 않는다. `원래 길이로 반복`이 기본 제안이며 패턴/서클 마디 경계 차이를 표시한다. `서클 박자에 맞게 편집`은 별도 명령이다. 섹션 끝에서 남는 event는 해당 occurrence의 종료 규칙을 적용한다. source가 audio이면 tempo 추종에는 명시적 stretch 설정과 준비가 필요하다.

예를 들어 글로벌 4/4 기본 groove를 벌스·후렴에서 상속하고, 브리지에는 직접 만든 7/8 패턴을 지정한다. 글로벌 groove를 수정해도 브리지의 개별 패턴은 바뀌지 않는다. pattern을 새 객체로 교체하거나 사용을 끄는 것과 원본 pattern 자체를 편집하는 것을 구분한다.

## scale과 실제 소리의 관계

scale 설정은 우선 작곡 기준이다. piano roll의 음 표시, 입력 보조, 코드/도수 표기의 기준을 바꾼다. scale 밖의 note도 입력·유지할 수 있어야 한다.

scale은 root와 음 집합으로 표현하고 익숙한 mode 선택과 사용자 지정 음 집합을 지원하는 방향이다. 조율 체계와 microtonal 지원 범위는 후속 설계 사항이다.

| 연주 데이터 | 기본 반응 | 명시적으로 선택할 수 있는 변환 |
|---|---|---|
| 절대 pitch MIDI | 기존 note pitch 유지 | 선택한 note의 transpose·scale 맞춤, preview와 undo |
| scale-relative MIDI | 사용자가 이 표현을 선택한 경우 해당 서클의 root·도수로 해석 | scale 변경을 따르는 pattern; 세부 도수/임시표 규칙 후속 설계 |
| drum MIDI | pitch mapping 유지 | 별도 drum map 편집 |
| 녹음·sample | 원본 pitch 유지 | 명시적 pitch-shift·warp 작업 |

scale 변경이 원본 recording이나 plugin preset을 자동으로 바꾸지 않는다. 따라서 사용자는 C minor 기준으로 표시하면서 의도한 경과음이나 다른 조의 sample도 사용할 수 있다. `scale 따르는 note`는 scale 설정의 필수 동작과 분리된 확장 제안이다.

## 서로 다른 tempo와 박자의 서클 연결

순차 연결에서는 다음 서클의 첫 박에 그 서클의 유효 설정을 적용한다. 브리지 96 BPM·7/8 다음에 글로벌을 따르는 후렴이 오면 후렴은 글로벌 설정으로 돌아온다. 브리지의 설정을 후렴에 전파하지 않는다.

각 occurrence는 자신의 음악 시간을 하나의 공통 sample clock으로 변환한다. 120 BPM·4/4의 8마디는 16초, 96 BPM·7/8의 4마디는 8.75초다. 링은 각각 자신의 마디 위치를 표시하고 전체 시간은 24.75초가 된다.

서로 다른 tempo/meter의 overlap을 같은 음악 beat 축에서 단순히 빼지 않는다. **출발/도착 중 어느 서클 기준의 길이인지 또는 초 단위인지**를 지정해 공통 sample 시간에 배치하는 방향이다. 예를 들어 출발 섹션의 마지막 1마디가 2초라면 도착 섹션을 출발 끝 2초 전에 시작한다. 두 서클의 링은 각자의 속도로 진행한다. 첫 구간 16초와 다음 구간 8.75초가 2초 겹치면 총 22.75초다.

공유 tempo-synced plugin에는 서로 다른 두 host tempo를 동시에 전달할 수 있다고 가정하지 않는다. 하나의 host transport는 도착 섹션 시작에서 도착 tempo로 전환하는 것을 기본 제안으로 한다. 앞 서클의 tempo에 묶인 delay나 instrument를 유지하려면 별도 processor instance 또는 준비된 audio render를 사용한다. 준비할 수 없는 경로는 이유와 대안을 표시한다. section별 설정 자유와 plugin 처리 제약을 구분한다.

이종 tempo/meter overlap은 지원을 목표로 한 설계 방향이며 아직 runtime 검증을 하지 않았다. 기존의 ‘같은 tempo/meter에서만 overlap’ 제안은 이 설계로 대체한다. tempo를 서서히 잇는 ramp와 박 위치를 맞추는 sync 방식은 별도 전환 옵션으로 후속 구체화한다.
