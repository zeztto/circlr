## 결과와 경계

1. **DAW MIDI take fidelity** — `AppStore.midi`의 활성 note는 pitch만으로 식별해 다른 채널의 같은 음과 같은 채널 재트리거의 첫 note를 잃을 수 있다. 채널+pitch별 note를 유지하고, 같은 key의 새 Note On은 기존 note를 그 시점에서 닫은 뒤 새 note를 시작한다. Note Off와 녹음 종료 flush, 반복 경계 분할, take 활성화·Undo를 합성 MIDI 이벤트로 검사한다. 원래 MIDI 채널을 `Note` 모델에 저장하는 기능은 별도 모델 변경이므로 이번에는 타이밍·음높이·속도·개수의 보존을 판정한다. 소유 파일: `Sources/CirclrApp/AppStore.swift`, 필요 시 `Sources/CirclrApp/RecordingWorkspace.swift`, 새 `Tests/CirclrAppTests/MIDIRecordingFidelityTests.swift`.
2. **compact 팔로우 가시성** — build232는 VoiceOver에서 대상이 보이지만, 실제 720×900pt/1440×900pt UI에서는 compact transport가 텍스트를 숨긴다. 곡·섹션·고정 대상과 일시 중지 상태를 짧은 가시 라벨로 보여 주되 Play/Stop·녹화·감상·서클 추가를 가리지 않는다. 상태 변경과 700/720/900/1440pt의 겹침을 실제 앱 화면·AX로 검사한다. 소유 파일: `Sources/CirclrApp/RootView.swift`, 필요 시 `Sources/CirclrApp/WorkspaceChromeLayout.swift`; UX 판단은 native QA.
3. **AI 문맥 크기** — 실제 외부 Codex→MCP QA에서 반복된 전체 `snapshot`/`inspect` 응답 때문에 높은 token 사용량을 기록했다. 기존 공개 MCP adapter에 `circlr_context` 읽기 도구를 추가해 **같은 native snapshot**에서 project/revision/layoutRevision, 현재 선택·arrangement/use/track ID와 이름, 지원 capability 및 간단한 실행 상태만 반환한다. 전체 원본 경로·asset·pattern·note 내용은 기본 응답에 넣지 않고, 목록이 길면 명시적 개수·잘림 표식을 제공한다. 전체 `circlr_snapshot`과 `circlr_inspect`는 그대로 두고, 실행 고정·read-only·오류 계약을 유지한다. QA 데모 기준 wire 응답 크기를 기록한다. 소유 파일: `mcp/server.py`, `mcp/test_server.py` 또는 새 `Tests/test_mcp_context.py`, `mcp/README.md`. 계정 로그인 UI나 API key 경로를 추가하지 않는다.

세 구현 담당은 같은 worktree를 공유하므로 소유 파일 밖을 수정하거나 다른 담당자의 변경을 되돌리지 않는다. 개발 리드는 통합·문서·패키지·native QA와 최종 commit/push를 맡는다. AI 작업은 사용자 계정의 제품 내 대화 기능이라는 1.0 목표를 유지하지만, [공식 Codex App Server](https://learn.chatgpt.com/docs/app-server)의 현재 production 미지원 문구 때문에 이번 build의 공개 기능으로 표기하지 않는다. 외부 MCP의 실제 작동을 개선하는 별도 진행이다.
