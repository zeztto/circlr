[UI/UX 감사](0.80-ui-ux-audit.md)에서 지적한 가로→세로 변경 때의 카메라 pan-only 이동을 수정했다. 곡·앨범 궤도의 context-fit을 사용 중이라면 `workspaceViewport`가 바뀔 때 새 크기로 다시 맞춘다. 하단 콘솔은 캔버스 위 overlay이므로 NSView 크기가 그대로여도 콘솔 높이·감상 모드 변화에 따라 보이는 영역을 다시 계산한다. 수동 wheel zoom/pan, 정밀 편집, 활성 재생 팔로우는 자동 맞춤과 분리했다. build222의 [격리 앱 첫 로드](0.80-build222-native.md)는 단일 곡의 일곱 섹션을 보여 주었지만 720×900에서 04 라벨이 숨었으므로 build223에서 다시 판정한다. [독립 코드 리뷰](0.80-build223-review.md)는 후속 소스에서 새 고확신 P1/P2를 찾지 못했다.

마지막 소스에서 `swift test`는 **1,189개 중 14 skip, 실패 0**, 종료 코드 0이었다. `./scripts/build-app.sh`로 0.80.0/build223 arm64 앱, 다섯 audio helper, 25파일 agent kit을 패키징하고 `codesign --verify --deep --strict`를 통과했다. 앱 실행 파일 SHA-256은 `17a6293add56acdcee8cfed6479dfa0ec75c52c7acfb4e50d18b5fc5c4a5e6a6`이다. 생성 앱과 테스트 로그는 Git에서 제외한다.

[DAW 오디오](0.80-daw-audio-audit.md)와 [AI/MCP](0.80-agent-journey-audit.md) 감사는 독립 경로의 결과다. Bach 70초 WAV 및 두 stem의 nonzero PCM은 확인했지만 이번 앱의 실제 녹음 take·청취는 증명하지 않는다. 앱 내 Codex 계정 대화와 trusted save/export/open도 미연결이다. 0.80 전체 출고 gate는 유지한다.

[build223 격리 native QA](0.80-build223-native.md)에서 1440×900 첫 로드는 일곱 섹션 라벨이 보였지만 720×900 resize와 큰 콘솔에서는 04·06·07 라벨이 생략됐다. 콘솔을 접으면 06·07은 돌아오고 04는 남는다. 원과 AX 노드는 모두 유지됐고 수동 카메라·감상 모드 왕복은 통과했다. build223은 세로 화면 사용성 **FAIL**이며 출고 후보가 아니다. 직접 섹션의 라벨 배치 공간을 넓히는 build224로 이어간다.
