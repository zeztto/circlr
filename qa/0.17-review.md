# 0.17 · MIDI 가져오기와 일괄 편집 검증

2026-09-08, macOS 26.5.1 / Apple Silicon. 전용 `com.circlr.hierarchyqa` 0.17.0 build 19와 `qa/generated/0.17/midi-QA.circlr`에서 확인했다. 원곡 v4와 사용자의 실행 중인 앱은 유지했다. 추가 agent slot이 없어 구현, 읽기 전용 코드·보안 검토, QA를 역할별로 순차 수행했다. 독립 에이전트가 검토했다고 주장하지 않는다.

## 자동 검사와 코드 검토

- `.build/midi-quality`에서 Swift **129개 통과**. 기존 Scarlett 장치 제약으로 `testArrangementRenderExportAndPlayback` 1개는 제외했다. 새로운 public struct layout을 사용하는 전체 검사는 독립 scratch 빌드로 시작했다.
- Python MCP **11개**, 음악 agent kit **9개** 통과. `.build/midi-release`의 최종 release 빌드는 warning 없이 통과했다.
- Note ID·길이·세기·비선택 노트/오디오 보존, partial quantize와 strength 0, 그룹 간격·경계 거부, duplicate fresh IDs, import atomic 적용·이번 use의 연장과 컴파일을 검사했다.
- AudioToolbox의 실제 SMF decoder로 format 0/1, 한국어 이름, 채널 분리·polyphony·quarter beats·tempo 표시를 검사했다. 빈/잘린 파일, SMPTE·format 2를 거부하고 CC 미지원 표시를 확인했다. API 계약은 설치된 macOS SDK `MusicPlayer.h`와 [Apple MusicSequence 파일 읽기 문서](https://developer.apple.com/documentation/audiotoolbox/musicsequencefileload(_:_:_:_:))를 참조했다.
- 파일 입력은 bounded read 16 MiB, 최대 100,000 notes / 1,000,000 열거 이벤트 / 131,072박을 검사한다. 파일 이름은 텍스트로만 사용하고 셸에 전달하지 않는다. MCP는 기존 revision·batch·socket·read-only 경계를 유지한다. 잘못된 ID/값을 포함한 batch가 음악을 부분 수정하지 않는 것을 Core와 실제 앱에서 확인했다. 이번 변경에서 미해결 critical/high 보안 항목은 발견하지 않았다. 외부 파일 decoder 전체에 대한 fuzzing이나 시스템 sandbox 검증을 의미하지 않는다.
- 녹음 권한 요청은 ID·project·revision·서클·track·lane을 고정한다. STOP 뒤 응답, 과거 요청이 새 요청보다 늦게 도착하는 경우, 프로젝트/음악/선택 변경, 중복 응답을 Core 테스트로 검사했다. 실제 TCC 창을 재설정하거나 하드웨어 마이크를 녹음한 검사는 아니다.

## 음악과 패키지

- Imported MIDI → 내장 신스 → native bounce: 48 kHz/24-bit/stereo **6초**, peak **0.13054192066192627**, non-zero sample **71,922개**. 오디오 파일과 그래프를 확인한 결과이며 직접 청취 평가는 아니다.
- QA에 새 MIDI와 트랙을 추가하되 재생 경로 밖의 섹션에만 배치한 전체 native export는 기존 v4와 바이트 동일: SHA256 `975a901aa9f4e01ac0d9e17ad85ba59a1c377a61f41577abd7aa4d0a6f887c6f`.
- 최종 source binary, native 검증 앱, `dist/써클러.app`의 UUID 일치: `03F2109C-A353-36DC-89C0-8EF66449CE35`.
- 앱 0.17.0 build 19, 번들 agent kit 0.17.0의 25파일 hash 검증 및 strict ad-hoc codesign 검사 통과. 기존 앱은 `dist/archive/써클러-0.16.0.app`에 보관했다. App Store/notarization 배포가 아니다.

## 남은 범위

실제 Scarlett 출력·마이크 녹음·녹음 동기와 장치 복구는 미검증이다. `AudioRecorder.start`의 동기 장치 시작도 후속 개선 대상이다. 권한 대기 guard만으로 장치 시작 지연을 해결했다고 보지 않는다. MIDI import는 note performance만 지원하며 파일 tempo/meter map·CC·페달·피치 벤드·SysEx를 재현하지 않는다. 다중 노트 드래그·마퀴 선택은 구현 전이다.

좁은 창에서 콘솔을 펼치면 궤도 MIDI의 24음 높이 행이 촘촘해진다. 정밀 편집의 확대·표시 음역 개선을 이어간다. 오디오 split/duplicate/fade, gain/pan automation, 연속 실시간 엔진 등 기본 DAW 전체는 [문서 31](../docs/31-daw-basics-plan.md)의 후속 구현이며 이 버전의 완료 주장에 포함하지 않는다.
