## 증거의 정확한 한계

초기 `step.png`, `import.png`, `cold-reopen.png`, `stems.png`는 `screencapture -x -o`가 **foreground Chrome 전체 화면**을 저장한 것으로 픽셀 검사에서 판명됐다. 이 네 파일은 앱 화면 증거로 사용하지 않는다. GUI 클릭 당시 AX와 MCP state/파일 hash는 별개로 유효하다. CUA가 앱 창에서 직접 반환한 JPEG byte를 `step-posthoc-app.jpg`, `import-posthoc-app.jpg`, `stems-app.jpg`로 다시 저장하고 눈으로 확인했다. 앞의 두 JPG는 **새 프로세스 재열기와 stems export 이후 사후 지속 상태**다. 최초 step 토글·import 클릭 그 순간의 픽셀 증거로 소급하지 않는다. GUI 앨범 WAV 저장 패널, 화면 song↔section live 전환, 700/720pt 세로·1440pt 가로 반응형, 실제 청취는 이번 여정에서 검사하지 않았다.

미디어 라이브러리의 `검색 폴더 선택`, `샘플 형식 선택` Menu는 각각 **마우스로 연 뒤** arrow/Return 또는 Space로 닫거나 형식을 고를 수 있었다. 검색 field에서 Tab으로 이동한 시도에서는 어느 Menu도 focused AX element가 되지 않아 **Tab→Space/Return 직접 접근은 UNVERIFIED**다. 이 접근성 항목을 audio import 성공과 묶어 PASS로 판정하지 않는다.

## 실패한 격리 시도

첫 `finaldaw239qa` 사본은 `author` 실행기의 `content.instrument._0` 가정이 실제 `content.instrument.trackID`와 달라 `StopIteration`으로 멈췄다. [`first-attempt-failure.json`](generated/r80-final-daw-journey-239/first-attempt-failure.json)과 부분 fixture/첫 WAV를 보존했다. 실패 직후 잘못 클릭한 `새 앨범`이 비동기로 열려 failure-time snapshot은 원래 fixture 상태가 아니라 새 unsaved album인 점을 그 파일에 드러냈다. 같은 fixture에서 `author`를 재실행하지 않았다.

둘째 `finaldaw239bqa` 사본은 effect automation Undo 뒤 `inspect`가 optional `automation` field를 생략했는데 실행기가 필수 key로 읽어 `KeyError`로 멈췄다. [`second-attempt-failure.json`](generated/r80-final-daw-journey-239b/second-attempt-failure.json), applied/after-Undo JSON과 부분 WAV를 보존했다. 세 번째 사본을 새 bundle ID/Support/fixture/evidence로 만들기 전 script shape와 asset staging/save 경계를 수정하고 fixture-free 검사 및 `py_compile`을 통과했다. **두 실패는 QA 실행기 가정 오류이며 제품 재현 결함으로 분류하지 않았다.**
