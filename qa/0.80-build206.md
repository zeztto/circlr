## 확인한 동선

- QA 폴더에만 닫힌 AF_UNIX `agent.sock`을 만들고 inode `24530182`를 기록했다. 시작 화면에서 데모 `f0r h3r`를 열자 앱은 **기존 연결 감지**를 표시했다. 콘솔의 **이 앱에 새 연결**을 누른 뒤 상태는 **MCP 연결 가능**으로 바뀌었고 `.r6f6b10ed` 경로가 표시됐다. 기존 inode는 그대로였다.
- `selected.json`은 같은 사용자 소유의 일반 파일·0600이었고, 격리 앱의 endpoint와 runID를 담았다. 기본 MCP resolver로 연속 snapshot 두 번이 성공했고 runtime의 build `206`·runID·endpoint가 선택 정보와 일치했다. 새 경로에 raw JSON 또는 잘못된 runID envelope를 보내면 모두 `agent_target_changed`로 거절했다.
- 앱 정상 종료 뒤 새 `.r` socket은 제거되고 기존 `agent.sock` inode는 보존됐다. 선택 정보는 남지만 사라진 새 socket으로만 가므로 MCP는 기존 경로로 fallback하지 않았다. QA가 만든 기존 socket을 inode 확인 뒤 `agent-build206-stale.sock`으로 보관하고 같은 앱을 다시 열자 표준 `agent.sock`과 새 선택 정보로 연결됐다. 두 번째 종료 뒤 표준 socket도 제거됐다.
- QA 앱 설정의 **Mac Studio 스피커**를 그대로 사용했다. 시스템 기본 출력은 Scarlett 6i6 USB였고 변경하지 않았다. 데모 재생에서 출력 큐 준비·장치 시작·재생 시계 진행 후 정지와 helper 정리를 UI 및 MCP snapshot으로 확인했다. **실제 스피커 청취·dropout·음질은 확인하지 않았다.** 연결된 Scarlett의 세대·호환성도 확인하지 않았다. [출력 조사](0.80-output-investigation.md)의 내장 출력 우선 정책을 따른다.
