## 실행 전 고정

최종 **동일 소스**로 만든 `dist/써클러.app`의 버전·build·arm64 본체/동봉 helper·`codesign --verify --deep --strict`·Resources/데모 hash를 기록한다. 기존 앱/QA 폴더를 덮어쓰지 않고 새 `qa/generated/r80-final-daw-journey-<build>/`에 `ditto`로 복사한다. QA 사본의 bundle ID를 `com.circlr.finaldaw<build>qa`처럼 새 값으로 바꾸고 문서 유형 등록을 제거한 뒤 ad-hoc 재서명한다. `qa/0.80-build237-native.md`의 격리·원본 대조 방법을 따른다. 앱의 전용 Support root와 socket을 확인하며 production `circlr` socket 및 사용자 프로젝트는 사용하지 않는다. 기존 `qa/prepare-integration-qa.py`는 **0.20.0의 기존 fixture와 바이너리 경로에 고정**되어 있어 그대로 실행하지 않는다.

전용 Support의 `fixtures/`와 evidence 폴더가 **존재하지 않음을 먼저 확인**하고 만들되, 전체 Support root를 삭제·초기화하지 않는다. QA 입력은 외부 라이선스에 의존하지 않는 **직접 생성한 2.000초/48 kHz/stereo/16-bit 330 Hz 사인 WAV** 한 개로 고정한다. 새 QA 폴더에서 아래 생성 코드를 한 번만 실행한다. 기존 대상 파일은 덮어쓰지 않는다.

```sh
: "${QA_BUILD:?set QA_BUILD to the candidate CFBundleVersion}"
python3 - "qa/generated/r80-final-daw-journey-${QA_BUILD}/authored-tone.wav" <<'PY'
import math, struct, sys, wave
from pathlib import Path
path = Path(sys.argv[1])
with path.open('xb') as file, wave.open(file, 'wb') as wav:
    wav.setparams((2, 2, 48000, 0, 'NONE', 'not compressed'))
    wav.writeframes(b''.join(struct.pack('<hh', sample, sample)
        for sample in (round(2000 * math.sin(2 * math.pi * 330 * i / 48000))
            for i in range(96000))))
PY
```

`QA_BUILD`는 실제 후보 build 숫자다. 입력 파일의 SHA-256·frame 수를 시작 시 기록한다. 시스템 기본 입력/출력 장치 이름과 UID hash를 읽기 전용으로 기록하고 변경하지 않는다. 앱의 출력 설정에서만 사용 가능한 내장 출력(현재 호스트에서는 `Mac Studio 스피커`)을 선택한다. 구형 Scarlett의 사용 가능 여부를 이 검사에서 가정하지 않는다.

격리 앱이 열리면 전용 `Agent/selected.json`의 bundle ID·run ID·socket 경로/owner/inode를 `circlr_snapshot.runtime`과 대조한 뒤 `mcp/server.py --socket <QA 전용 agent.sock>`에만 연결한다. MCP 편집은 매번 바로 앞 `circlr_snapshot`의 `projectID`·`expectedRevision`을 넣는다. 화면 작업마다 CUA의 **앱 창 자체** `getScreenshot()` byte와 AX 텍스트, 전후 snapshot, `circlr_inspect` 결과를 timestamp와 함께 evidence에 남긴다. desktop 전체 `screencapture`는 foreground가 다른 앱이면 앱 증거가 될 수 없다. 최종 앱용 실행기는 `qa/run-0.80-final-daw-journey.py`다.

## 현재 자동화 경계

build239 이상 최종 앱용 실행기는 [`run-0.80-final-daw-journey.py`](run-0.80-final-daw-journey.py)다. 이미 열린 **GUI step 한 개를 저장한 blank starter**와 고유 QA bundle/Support/socket을 인자로 받는다. 같은 `--qa-root`, `--fixture`, `--socket`, `--bundle-id`, `--build`, `--evidence`를 세 단계에서 유지한다. 실행 순서는 GUI blank 생성·beat 0/pitch 60 step·저장·PNG/AX → `author --step-png ... --step-ax ...` → 앱 GUI로 오디오 import와 전체 창 PNG/AX 저장 → `finish --audio-source ... --import-png ... --import-ax ...` → 앱 종료/새 프로세스 GUI 폴더 재열기·AX/픽셀/manifest 비교 → 앱 GUI로 stems export와 전체 창 PNG/AX 저장 → `stems --stems-dir ... --stems-png ... --stems-ax ...`이다. `finish`는 앱 전용 출력 이름을 `--expected-output`으로 검증하며, 기본값은 `Mac Studio 스피커`다. 세 phase 모두 기존 보고서를 덮어쓰지 않고, 중간 실패는 상태를 확인한 뒤 **새 QA app/fixture/evidence로 다시 시작**한다. GUI 증거는 존재 여부만 자동 확인하므로 실제 조작·픽셀은 별도 native 리뷰가 필요하다. `--help`는 앱 연결 없이 사용할 수 있다.

`author`는 section reorder의 실제 경로를 **중간 저장 manifest**에서 확인한 뒤 Undo하고, 세 MIDI 구간·gain FX·automation Undo/재적용의 독립 PCM hash를 비교한다. `finish`는 GUI import 1건의 파일 byte/hash, 같은 프로세스의 native save/open, master WAV, 섹션과 곡 각각 2주기 이상을 검사한다. 루프 판정은 `Playback.elapsedSeconds`가 hardware 경과 시간으로 단조 증가하고 음악 위치 `Playback.seconds`는 wrap한다는 코드 계약을 사용한다. `stems`는 GUI 결과 폴더의 metadata와 2개 stem+mix 파일의 format/frame/PCM, master와 mix PCM 동일성을 검사한다. 앱 시작 화면, 실제 step 에디터, 파일 패널, 새 프로세스 GUI 재열기, stems 조작, 물리 청취는 **자동 PASS에 포함되지 않는다.**

### build239 실제 실행

세 번의 서로 다른 bundle ID·Support·fixture·evidence에서 검증했다. 첫 두 번은 제품 결함이 아니라 QA 실행기의 `instrument` 및 optional `automation` JSON shape 가정 오류로 중단했고 부분 산출물을 보존했다. 세 번째 `com.circlr.finaldaw239cqa`/`circlr-finaldaw239c-qa` 사본이 `author`→GUI import→`finish`→새 프로세스 GUI 폴더 재열기→GUI stems→`stems`를 완료했다. 정확한 path·hash·PASS/미검증 경계와 세 번의 실패 기록은 [`0.80-build239-final-daw-native.md`](0.80-build239-final-daw-native.md)에 있다.

세 번째 결과의 `author.json`, `finish.json`, `stems.json`은 각각 MCP/파일 검사를 통과했다. `cold-reopen.json`은 별도 run ID에서 같은 project ID·revision·manifest hash와 음악을 확인했고 `clean-exit.json`은 QA 앱/helper/socket 0을 기록한다. **처음 단계의 `step.png`, `import.png` 및 재열기·stems의 `screencapture` PNG는 foreground Chrome 화면이므로 앱 픽셀 증거에서 제외한다.** CUA가 앱 창에서 직접 반환한 `step-posthoc-app.jpg`, `import-posthoc-app.jpg`, `stems-app.jpg`는 실제 앱 픽셀이다. 앞의 두 개는 클릭 순간이 아닌 저장 후 지속 상태만 증명한다. 실행기 자체는 PNG/AX 파일의 존재만 검사하므로 그 `*_GUI_PENDING` status를 화면 리뷰 없이 GUI PASS로 승격하지 않는다.

미디어 라이브러리의 **`검색 폴더 선택`**·**`샘플 형식 선택`** Menu는 마우스로 연 뒤 arrow/Return 또는 Space 조작이 작동했다. 검색 field에서 Tab으로 두 Menu에 직접 포커스되는지는 AX로 확인되지 않아 **Tab→Space/Return은 UNVERIFIED**다. 이 항목은 성공한 GUI audio import와 분리한다.

- `qa/verify-agent-journey.py`는 **이미 열린** disposable `.circlr`을 전제로 MIDI/Undo/save/open/WAV/bounce와 stdio MCP를 검사한다. 이번 시작 화면·오디오 Open 패널·GUI Stem Save 패널·루프 화면은 포함하지 않는다.
- `qa/0.80-build211-daw-journey.md`는 GUI import/편집/저장/WAV, `qa/0.80-build215-stems.md`는 기존 16트랙 곡의 GUI stems를 증명했다. 둘 다 **빈 곡에서 시작한 단일 최종 후보 여정**의 증거가 아니다.
- MCP의 `circlr_playback_loop`, `circlr_snapshot.view.loopIteration`/`loopTransition`은 반복 상태를 읽을 수 있다. 실제 경계 청취·compositor frame pacing은 상태 JSON으로 검증되지 않는다.
- 전용 실행기는 GUI 경계에서 단계별로 멈추며, GUI/AX 확인은 native QA가 수행한다. 각 단계는 새 revision/ID를 읽어 이어가고, 구형 fixture용 prepare script의 version assert를 지우고 성공으로 취급하지 않는다.
- 실제 마이크 take는 별도 [출고 gate](0.80-release-gates.md)의 D80-01이다. 오디오 import 결과를 녹음 성공으로 바꾸어 보고하지 않는다.
