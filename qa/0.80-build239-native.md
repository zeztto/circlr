CUA `typeText('클럽 킥')`는 이 환경의 검색 필드에 공백만 남겼다. 이어 같은 필드에 한국어 문자열을 **붙여넣기**하자 `Value: 클럽 킥`와 정확한 검색 결과가 표시됐다. 따라서 한국어 검색·결과 이동은 확인했지만 실제 macOS 한글 IME 조합 이벤트의 성공·실패로 해석하지 않는다. 사용자가 이전에 남은 IME QA를 우선 패스하기로 한 범위와도 구분한다.

[가로 PNG](../docs/images/circlr-song-build239.png)는 1440×900pt/2880×1800px, [세로 PNG](../docs/images/circlr-song-portrait-build239.png)는 720×900pt/1440×1800px의 **전체 창**이다. 모두 번들 데모를 00:00.0에 정지하고 네 overlay를 닫은 화면이다. 원본 CUA JPEG와 AX는 [가로](generated/r80-build239-native/width1440x900-overview.source.jpg)·[세로](generated/r80-build239-native/width720x900-overview.source.jpg)에 보존했고, RGB PNG 변환의 decoded pixel 동등성, 해시, 무크롭·무합성 여부를 [provenance](generated/r80-build239-native/screenshot-provenance.json)로 확인했다. 이 캡처는 실제 compositor FPS나 재생·녹음 품질의 증거가 아니다.

종료 시 ⌘Q에서 QA 곡 변경을 버렸다. 격리 앱·관련 helper process 및 QA `agent.sock`은 0개, 시스템 오디오 목록의 [전](generated/r80-build239-native/audio-before.txt)·[후](generated/r80-build239-native/audio-after.txt)는 byte-exact로 같으며 기본 입·출력·시스템 출력은 Scarlett 6i6 USB다. 원본/복제본 strict 서명은 모두 유효하고 원본 실행 파일 SHA는 시작 때와 같았다. Resources 57/57과 실행 helper 7/7은 원본과 byte-identical이다. 이 실행에서 장치를 전환하거나 재녹음하지 않았다. CalDigit 선택과 실제 nonzero CAF 검증은 [build238 native QA](0.80-build238-native.md)의 32초 데이터 경로 증거로만 남기고 build239 오디오 재검으로 주장하지 않는다.
