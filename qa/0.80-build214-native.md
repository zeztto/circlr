## 앱 전용 내장 출력과 GUI WAV

앱 출력 설정은 시작 시 `시스템 기본값: Scarlett 6i6 USB`를 보여 주었다. **앱 내부 선택만** `Mac Studio 스피커`로 바꿨다. Play 준비 후 AX 시계가 **00:03.2 → 00:12.1 → 00:18.1 → 00:24.4**로 진행했고 `마지막 재생 확인 장치: Mac Studio 스피커`와 재생 정지 버튼이 나타났다. Stop 후 **00:00.0**, `이전 출력 정리가 끝났습니다`, `출력 장치 시작 완료(시작 후 0.1초)`가 표시되었다. 격리 bundle UserDefaults의 `circlr.playback.outputDeviceUID`는 종료 후 `BuiltInSpeakerDevice`다. 이는 앱 UI/출력 시작 상태와 시계 진전의 증거이며 실제 스피커 소리를 물리적으로 들었다는 주장이 아니다.

Stop 상태에서 GUI `File → WAV 내보내기…`를 한 번 실행해 `build214-f0r-h3r-export.wav`를 QA 폴더에 저장했다. GUI 상태 줄은 `내보내기 완료`를 표시했다. 별도 `wave`/NumPy 판독과 `afinfo`는 **48,000 Hz, stereo, signed little-endian 24-bit PCM, 9,456,096 frames, 197.002 s**를 확인했다. 곡 구성 192초 뒤 5.002초 export tail이며 마지막 6개 1초 구간 RMS는 0이다. PCM 전체 18,912,192개 sample 중 **18,048,371개가 0이 아니고**, normalized peak `0.808287`, RMS `0.105937`이다. 0·32·64·80·112·128·160초 섹션 시작의 1초 RMS도 모두 0보다 크다. WAV SHA-256은 `09f811ca84f2e9da640bfa9c599b6af73a9f0e0c29aa0485f005faf6f093f683`; 원자료와 계산은 `wav-analysis.json`에 있다. 이 수치는 export가 무음 파일이 아니고 길이가 맞는다는 확인이며 청감 품질 평가는 아니다.

종료 후 격리 QA 앱과 관련 helper 프로세스는 **0개**다. 읽기 전용 CoreAudio 조회의 시스템 기본 출력은 검사 전·후 `AppleUSBAudioEngine:Focusrite:Scarlett 6i6 USB:10000B65:1,2`로 같았다. Scarlett은 테스트하지 않았고, 이 장치의 오래된 하드웨어/최신 macOS 호환성은 앱 결함 판단에 사용하지 않는다. 프로젝트를 열 때 CUA native pipe가 한 번 응답을 닫았지만 다음 상태 조회에서 앱이 실행 중이고 QA 프로젝트가 정상 로드된 것을 확인해 계속 진행했다. 앱 crash나 지속적인 사용자 흐름 실패로 관측하지 않았다. 세부 파일 해시·서명·프로세스·장치 결과는 `baseline.json`과 `final-check.json`에 있다.
