# 0.18 · 오디오 편집 검증

2026-09-08, macOS 26.5.1 / Apple Silicon. 전용 `com.circlr.hierarchyqa` 0.18.0 build 20, 정확한 사본 `qa/generated/0.18/audio-QA.circlr`에서 확인했다. 기존 v4 음악과 실행 중인 사용자 앱·시스템 장치 설정을 유지했다.

사용자가 추가 슬롯을 알린 뒤에도 읽기 전용 검토 dispatch가 `agent thread limit reached`로 거부됐다. 구현, 코드·입력 검토, QA를 같은 에이전트가 역할별로 순차 수행했다. 독립 검토 에이전트의 승인을 받은 릴리스가 아니다.

## 자동 검사와 코드 검토

- `.build/audio-edit-quality`에서 Swift **138개 통과**. 기존 하드웨어 `testArrangementRenderExportAndPlayback` 한 개는 제외했다. Python MCP **12개**, 음악 agent kit **9개** 통과. 최종 release 빌드는 warning 없이 통과했다.
- split/duplicate/fade/delete, 공유 clip 선택 격리, 공유 섹션 use 보존, fresh ID·출력/sidechain gain 보존, bounce family, JSON 복원, MCP atomic batch·stale revision을 검사했다.
- 양쪽 PCM 채널을 비교했다. 48 kHz·44.1 kHz source, 기존 명시 fade, 개별 tempo·명시 loop length, 부모 tempo map·repeat, 144 BPM tempo follow의 다섯 변형과 재분할에서 최대 Float 오차가 **2e-7 이하**다. 페이드가 구간 신호를 줄이고 이후 0으로 제거할 때 원래 PCM으로 돌아온다.
- 잘못된 rate와 frame count를 정수로 바꾸기 전에 거부한다. source bounds, envelope 범위·개수, cycle beat와 유효한 ID를 검사한다. 기존 socket/UID·revision·읽기 전용 MCP·경로 처리 경계를 유지한다. 원본 오디오를 덮어쓰는 작업과 새로운 shell/network 실행 경로는 없다.
- 검토에서 키보드 메뉴의 활성 상태가 텍스트 first responder 변경을 즉시 반영하지 않는 문제를 native로 재현했다. 실행 시점 검사로 수정하고 이름 필드 ⌘A/D/T와 실제 파형 ⌘T를 각각 다시 검사했다. invalid frame conversion도 별도 테스트로 고정했다. 이번 diff에서 남은 high/critical 입력 문제는 발견하지 않았으며, 전체 파일 포맷 fuzzing이나 하드웨어 검증을 의미하지 않는다.

## Native 동작

| 시나리오 | 확인 결과 |
|---|---|
| 시작 자료 | 앞선 MIDI import QA의 실제 신스 바운스 6초를 사용. QA 섹션만 4마디/8초로 늘리고 원곡 재생 경로 밖에 유지 |
| GUI 분할 | 0.5초 위치 입력 → 앞 source 0/길이 0.5, 뒤 source 0.5/길이 5.5/beat 1. 실제 두 오디오 서클과 같은 원본 asset 생성 |

| 기존 곡 | 최종 빌드의 v4 전체 WAV가 제작본과 byte 동일, SHA256 `975a901aa9f4e01ac0d9e17ad85ba59a1c377a61f41577abd7aa4d0a6f887c6f` |

Native 검증에서 발견해 수정한 항목은 작은 창의 지나치게 작은 파형, 분할 뒤 이어지는 단축키의 대상 소실, 분할 조각 복제의 불필요한 간격, fade 수정 후 커서 초기화, 텍스트 입력 중 Cmd+T 개입이다. 최초 빌드의 Swift exclusivity와 테스트 await 문법 오류, 재분할 fixture의 loop 밖 컷도 수정했다. 중간 실패 증거를 최종 성공 증거로 사용하지 않는다.

레이아웃 검사는 canvas **1080×673**에서 콘솔을 펼친 파형·분할·fade 필드와 하단 스크롤을 확인했고, 이후 **1080×1255**에서 최종 궤도/선형 파형을 확인했다. 작은 크기의 아래쪽 템포·음소거·삭제는 스크롤이 필요하다. 장치에서 실제 소리를 청취하거나 녹음한 검사가 아니다.

## 남은 개발

분할 window 밖으로 trim을 다시 확장하거나 분할 이전 fade를 개별 조각에서 제거하는 명령은 없다. fade보다 구간을 짧게 trim하려면 fade를 먼저 줄여야 한다. 각 조각의 같은 source window 반복 처리는 cache 개선 대상이다. 자유 배치의 접근성 파형 설명도 모드에 맞춰 더 구체화할 수 있다.

실제 마이크/Scarlett 장치 시작·녹음 동기·영상 재생 녹화는 아직 미검증이고 `AudioRecorder.start`의 동기 장치 시작은 후속 개선 대상이다. gain/pan automation, 고급 MIDI CC·다중 드래그, crossfade/comping, 연속 실시간 엔진·PDC·8방향 포트도 남는다. [다음 실행 계획](../docs/31-daw-basics-plan.md)을 유지하며 이 버전으로 전체 목표를 완료 처리하지 않는다.
