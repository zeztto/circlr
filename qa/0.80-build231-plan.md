## 목적과 범위

구형 Scarlett가 최신 macOS에서 제대로 동작하지 않을 수 있다는 사용자 정보를 반영해, 물리 오디오 장치 호환성과 앱의 영상 writer 안정성을 분리한다. 기존 build211의 37.980초 실제 앱 MP4는 1080p·10분 지속성의 증거가 아니다. opt-in 1920×1080·10분 synthetic writer soak을 만들고 실제로 실행해 출력 파일·디코드·오디오·메모리·임시 파일 정리를 검사한다. 시스템 기본 장치·실제 녹음 입력·사용자 프로젝트는 건드리지 않는다. 이번 작업은 테스트와 문서만 바꾸므로 제품 바이너리는 여전히 build230이다.

## 완료 조건

1. 장치 없이 실행되는 opt-in 테스트가 일반 전체 회귀 시간을 늘리지 않는다. 기한과 디스크 여유·출력 경로를 명시한다.
2. 18,000개 프레임과 nonzero stereo 반복 PCM을 30 Hz 목표 시각에 넣고, 종료 후 실제 MP4의 해상도·PTS·프레임 수·오디오 끝부분과 메모리/queue 계측을 기록한다. 최초 17,997-frame 실패와 수정본 18,000-frame 통과를 모두 보존한다. 실제 앱 캡처 스케줄은 이 writer 테스트와 분리해 OPEN으로 둔다.
3. 검증 산출물은 ignored QA 경로에 저장하고, 요약·실행 환경·미검증 범위를 문서화한다. 이 테스트만으로 실제 AppKit 화면 FPS·청취·Scarlett 호환성이나 0.80 릴리스 전체를 PASS로 바꾸지 않는다.
4. `git diff --check`, 관련 focused 테스트, 독립 변경 검토 뒤 문서 commit/push한다. 제품 바이너리가 바뀌지 않으므로 build 번호와 README 화면을 올리지 않는다.

## 분리된 후속 게이트

현재 실제 앱 후보의 내장 출력 Play/Stop 및 짧은 영상·UI 상태는 최종 소스 후보에서 재확인한다. Scarlett의 정상 재생 자체를 출고 조건으로 삼지 않고, 장치 열기 timeout·분리/복구 시 문서·파일 보존을 별도 확인한다. AI 계정 연결은 공식 production 경로 G0가 확인되기 전까지 출고 범위에서 제외하며 내부 테스트를 사용자 대화 기능으로 홍보하지 않는다.
