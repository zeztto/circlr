`./scripts/build-app.sh`로 0.80.0/build200 앱과 다섯 helper를 빌드·ad-hoc 서명했다. 빌드 로그 `qa/generated/r80-build200-build.log` SHA-256은 `370cddfa2c714809a77cf5070ba3f40e105a9189dd7ff8baca133b3d3a8e389c`다. `com.circlr.portfocusqa` 전용 앱·데모 사본의 [패키지 기록](generated/r80-build200-package.json)에는 원본 앱 tree SHA-256 `b386977483cdc1b63ad33955a489ecc7597d28b90d0921c840dd8dee3ba34b13`과 원본 데모 SHA-256 `b15252dbe5d4d4f79b6935449fa7238cf30fe90d783af20544b71ba83fcdf085`가 있다.

QA 전용 Application Support의 `recovery.json`에 보존해 둔 build198 복구 사본을 다시 놓았다. 실제 앱은 **구버전의 저장되지 않은 곡을 복구할까요?** 창을 표시했다. 이 창이 열려 있는 동안 `Agent/agent.sock` 접속은 `ECONNREFUSED`였고, 새 `recovery-v2.json`도 없었다. **새로 시작**을 선택한 후에만 agent socket 연결이 가능해졌으며, `legacy-recovery-ack.json`에는 검토한 legacy 파일의 SHA-256이 기록됐다. legacy 파일 SHA-256 `0c7507e9686665d048b82c5b5780d86e36dfda94fc1b91759c0f35702d8380e7`은 변하지 않았다.

같은 앱에서 `f0r h3r` 데모를 열자 새 `recovery-v2.json`이 생성됐다. ⌘Q → **변경 버리기** 후 새 복구본은 제거됐고 legacy 파일과 사용자의 기본 `circlr/recovery.json` SHA-256 `688558b00e4160106065114e7a6305ffa1a24ea8f57636408f408e38e5148c38`은 그대로였다. 재실행 시 이미 확인한 legacy 복구 창은 다시 나타나지 않고 시작 화면으로 진입했다. 테스트 앱은 정상 종료했다.

이는 **읽기 전용 legacy → 별도 v2 autosave**와 시작 복구 선택 전 agent socket 차단에 대한 native 증거다. 후속 리뷰에서 데모 사본 회수 시점 결함을 찾아 build201에서 수정하므로 build200을 최종 후보로 보지 않는다. 기존 앱과의 동시 실행, old writer의 새 legacy 변경 시 UI, 유효 JSON migration 실패, `--open` 우선순위는 native 미검증이다. 실제 청취·마이크·장시간 녹화와 전체 제작 QA도 여전히 열려 있다. `v0.80.0` 태그·Release는 만들지 않는다.
