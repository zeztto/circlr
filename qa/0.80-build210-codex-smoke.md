# 0.80 build210 · Codex 계정 런타임 개발 smoke

2026-09-24 KST. 대상은 이 Mac에 설치된 `codex-cli 0.149.1`의 `codex app-server --listen stdio://`다. 이 검증은 **circlr 앱 밖의 독립 Python JSONL 클라이언트**로 수행했다. 앱의 계정 콘솔, 음악 도구, 인증 격리, 배포 패키지의 성공 증거가 아니다. 공식 [App Server 문서](https://learn.chatgpt.com/docs/app-server)는 명령을 experimental이며 production workload 미지원으로 명시한다.

| 단계 | 관찰 |
|---|---|
| `initialize` → `initialized` → `account/read(refreshToken:false)` | 응답 성공, `account.type=chatgpt`. 이메일·토큰은 출력하거나 QA 파일에 저장하지 않았다. |
| `model/list(limit:50,includeHidden:false)` | `gpt-5.6-sol` 기본, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`가 표시됐다. 이 목록은 해당 런타임·계정의 당시 결과다. |
| `thread/start` sandbox 값 | 공식 페이지의 예시 `readOnly`는 설치 0.149.1에서 `unknown variant`로 거절됐다. 설치 런타임이 받아들인 값은 `read-only`였다. |
| 모델을 지정하지 않은 `turn/start` | 응답은 수락됐지만 `turn/completed.status=failed`. 오류는 HTTP 400 `invalid_request_error`: 설정된 `gpt-6-astra`에 더 새로운 Codex가 필요했다. |
| `thread/start`와 `turn/start` 양쪽에 `model=gpt-5.6-sol` 지정 | `turn/start`가 수락됐고 `turn/completed.status=completed`를 확인했다. 읽기 전용 임시 작업 디렉터리에서 도구 사용을 요청하지 않은 한 문장 smoke다. 답변 내용의 정확성이나 음악 도구 실행은 이 검사에서 수집·판정하지 않았다. |
| 정리 | 생성한 QA thread에 `thread/delete`를 호출해 성공 응답을 확인했고 자식 App Server 프로세스를 종료했다. 기존 Codex 대화와 circlr 사용자 프로젝트는 변경하지 않았다. |

**결론:** 로그인 상태 조회와 하나의 실제 모델 turn은 이 Mac에서 동작했다. 하지만 런타임의 `model/list` 기본값만 믿거나 Codex 앱의 전역 기본 모델을 그대로 전달하면 서로 다른 호환 결과가 나온다. 제품은 고정한 런타임의 실제 schema·모델 목록을 검사하고, 선택한 모델을 thread와 turn에 일관되게 명시해야 한다. 이후 앱 내부 연결에서는 동일한 계정·모델·문서 범위·중단·도구 권한을 각각 검증한다. 이 개발 smoke는 1.0 출고 G0를 통과시키지 않는다.
