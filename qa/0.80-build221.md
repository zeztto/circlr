[build220 Documents QA](0.80-build220-native.md)의 manifest 한 파일 선택 저장은 kernel `open`에서 30초 넘게 멈췄다. [동일 앱·곡 통제](0.80-build220-temp-native.md)는 `/tmp`의 manifest 선택과 Documents의 `.circlr` 폴더 선택을 각각 0.7초·0.6초에 저장하고 media hash를 유지했다. build221은 GUI에서 manifest를 고른 경우 같은 곡 폴더를 한 번 더 선택해야 로드하도록 바꿨다. 두 번째 선택을 취소하거나 다른 폴더를 고르면 현재 문서를 바꾸지 않는다. `NSDocumentsFolderUsageDescription`은 macOS 권한 안내의 이유를 설명한다.

build221 최종 `swift test`는 **1,187개 중 14개 skip, 실패 0, 종료 코드 0**이었다. `./scripts/build-app.sh`는 arm64 앱·오디오 helper 5개·25파일 agent kit을 패키징했고 `codesign --verify --deep --strict`를 통과했다. 실행 파일 SHA-256은 `19d7a61907905c5c635136e0d8a77a1d107cbb42e4c50e5ebeecd5237be8d032`다. 기존 `PlaybackFollowCameraCurve` Sendable 경고는 남아 있다. Python MCP/agent kit 소스는 변경되지 않아 과거 검증을 build221의 새 실행으로 표현하지 않는다.

읽기 전용 코드 리뷰에서 두 번째 폴더 선택 취소·다른 경로 선택이 현재 곡을 바꾸지 않는 것을 확인했고 새 고확신 P1/P2는 없었다. [실제 앱](0.80-build221-native.md)의 Documents manifest→동일 폴더 확인은 첫 `⌘S`가 약 0.5초에 끝났고 media 6/6 hash·staging/backup 0, 저장된 곡 재열기를 확인했다. Scarlett의 세대/입출력 성공은 이 Open/Save 검증에서 추론하지 않는다.

native Open 패널이 확장자 없는 일반 폴더를 곡으로 선택하지 못해, 같은 8개 파일을 가진 격리 `with-note.circlr` 패키지로 보존 시험을 수행했다. 폴더를 열어 `⌘S`하자 “곡 폴더에 프로젝트 외 파일이 있어 덮어쓸 수 없습니다”라고 거절했고, note·manifest를 포함한 **8/8 파일 hash**는 불변, 새 staging/backup은 0이었다. 이 앱 화면의 최종 캡처와 종료 후 process 정리는 [native 기록](0.80-build221-native.md)에 분리한다.

실제 앱의 정지한 **f0r h3r** 곡 궤도를 1440×900·720×900 전체 창으로 촬영하고 한영 README에 반영했다. 원본 JPEG와 PNG의 픽셀·SHA-256은 [화면 출처](../docs/images/README.md)에 기록했다. 가로·세로 화면에서 섹션 순번과 상단 조작이 보이지만 세로 오른쪽 위성 원 일부는 화면 밖으로 이어진다. 원본 demo 7/7·패키지 Resources 57/57·QA 미디어 6/6 hash, 시스템 기본 출력은 전후 불변이고 앱/helper PID는 종료 후 0이다. 이 화면이나 저장 시험을 재생·물리 청취의 증거로 사용하지 않는다.
