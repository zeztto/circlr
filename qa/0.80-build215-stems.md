## 독립 파일·메모리 검사

`wave`와 NumPy가 WAV의 **전체 PCM 샘플**을 읽었다. 17개 모두 48,000 Hz, stereo, signed 24-bit, **9,456,096 frames / 197.002초 / 각 56,740,672 bytes**이며 각 파일의 nonzero sample 수가 0보다 크다. 16 stem의 nonzero sample 수 범위는 **163,132–15,661,032**, 전체 mix는 **18,068,177 / 18,912,192 samples**다. 전체 mix의 normalized peak는 **0.808287**, RMS는 **0.106217**이다. 전체 mix SHA-256 `a8cb08237df6e4ce03600acd5728be519b3e921b429322dcc390e5a2aae38173`는 동일 revision의 [build211 GUI 앨범 WAV](0.80-build211-daw-journey.md)와 실제 보존 파일을 다시 해시한 값에 정확히 일치한다. 개별 17개 WAV의 SHA-256·RMS·peak·nonzero 수는 `wav-analysis.json`에 있다. 출력 총량은 **964,591,424 bytes**다.

렌더 전부터 종료 상태까지 약 0.55초 간격으로 앱 PID의 RSS를 88회 샘플링했다. 시작 **201,248 KB**, 최고 **2,061,904 KB(약 1.97 GiB)**, 모니터 종료 시 **800,736 KB**였다. 최고점은 모니터 시작 뒤 14.146초였으며 관측 구간은 47.868초다. 이 실행에서 앱의 child process 수는 샘플마다 0이었다. `rss-samples.csv`와 `final-check.json`에 원자료와 집계를 남겼다. RSS는 한 호스트의 한 번 실행값이므로 일반 기기 한도나 장시간 누수의 증거는 아니다.

프로젝트 파일별 SHA-256은 원본과 QA 사본 모두 검사 전후 일치했고, 9개 파일 목록의 안정적 tree digest는 전후 **`d6935f03a718a3fc1456c2eb5f1231b3807a020bf24de879c7b4973cdf457f92`**다. read-only CoreAudio 조회의 시스템 기본 출력은 전후 ID **111**, UID SHA-256 **`d4bc96d8fc82c68ec973b2af8dca79a5f5ceb89e121c740e29c661043c3e5eed`**로 같았다. 격리 앱 설정의 선택 UID는 `BuiltInSpeakerDevice`다. `⌘Q` 뒤 앱 PID와 해당 bundle의 helper 잔류는 0개였다. CUA는 종료 직후 상태 조회에서 `procNotFound`를 반환했으나, OS 프로세스 목록과 서명·파일 해시 검사로 실제 앱 종료를 확인했다.
