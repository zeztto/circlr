## 실제 세로 GUI의 순서 변경

시작 궤도는 01 DJ Intro `0:00.0–0:32.0`, 02 Groove `0:32.0–1:04.0`, 03 Lift `1:04.0–1:20.0`, 04 Club Chorus `1:20.0–1:52.0`, 05 Breakdown, 06 Final Chorus, 07 DJ Outro였다. 720×900 창의 전체 곡 궤도에서 Lift를 선택하고 **실제 키보드 `⇧⌥→`**를 입력했다. 앱 상태는 `섹션 순서 이동 완료`였고, 상위 곡 화면의 AX·화면에서 **Club Chorus 03 `1:04.0–1:36.0` → Lift 04 `1:36.0–1:52.0`**로 바뀌었다. 케이블도 Groove → Club Chorus → Lift 순서로 갱신되었다. **`⌘Z`**는 `섹션 순서 이동 실행 취소`를 보이고 Lift 03/Club Chorus 04 및 기존 시간·케이블을 복원했다.

이어 전체 곡 궤도에서 Lift를 다시 선택하고 **실제 `⇧⌥←`**를 입력했다. 앱 상태는 이동 완료였고, **Lift 02 `0:32.0–0:48.0` → Groove 03 `0:48.0–1:20.0`**로 순번·시간·케이블이 재계산되었다. `⌘S` 뒤 앱은 `저장 완료 · f0r-h3r-reorder-qa.circlr`를 표시했다. QA 경로를 새로 선택해 재열었을 때 같은 02 Lift/03 Groove와 시간이 AX에 남았다. 디스크 manifest의 연결 경로를 독립 판독한 `saved-route.json`도 원본의 Intro → Groove → Lift와 QA 저장본의 **Intro → Lift → Groove**를 구분한다. 이 검사는 한 일자형 7섹션 곡의 양방향 한 칸 이동이며 분기/반복 편곡은 다루지 않았다.

## 우클릭 경계 메뉴 결함과 열기 alert

Lift(중간 섹션)의 우클릭 메뉴에는 `순서 앞으로 한 칸 · ⇧⌥←`와 `순서 뒤로 한 칸 · ⇧⌥→`가 모두 노출되었다. 첫 **Intro 01** 및 마지막 **Outro 07**의 메뉴에서는 이동 불가 방향까지 AX에서 `(disabled)` 표시 없이 활성 항목처럼 노출되었다. Intro의 `순서 앞으로` 항목을 클릭해도 순서/상태는 바뀌지 않았고 메뉴만 닫혔다. 따라서 데이터 이동 방어는 동작했으나 사용자가 실행 불가 상태를 메뉴에서 구분할 수 없다. development lead가 별도로 같은 build215의 `NSMenu.update()` 재현을 **RED**로 확인했고 AppKit 자동 menu validation이 명시적 `isEnabled`와 충돌하는 결함으로 소스 수정 중이라고 보고했다. 이 원인 확인은 별도 개발 검사이며, 이 문서의 직접 native 증거는 메뉴 화면·AX와 무효 클릭이다. `build215-intro-context-menu-720x900.png`가 원본 메뉴 화면이다.

저장 후 첫 `⌘O`에서 Open panel의 QA 곡 행(`f0r-h3r-reorder-qa.circlr`, 같은 폴더)을 클릭했지만 AX 선택 상태 변화는 확인되지 않았다. 이어 Open을 눌렀을 때 **`The file “manifest.json” couldn’t be opened because there is no such file.`** alert가 한 번 나왔다. 그 시점 디스크에는 해당 QA 폴더의 `manifest.json`이 실제 존재했다. Alert를 닫고 `⌘O → ⌘⇧G`로 **절대 경로를 지정**하자 패널에서 QA 곡 행이 `(selected)`로 보였고, Open 후 `f0r h3r 열기 완료` 및 저장된 02 Lift/03 Groove가 확인됐다. 최초 alert의 원인은 확정하지 않으며, 열기 흐름의 잔여 위험으로 남긴다. Alert 원본은 `build215-reopen-alert-260x155.png`다.
