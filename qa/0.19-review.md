# 0.19 · 볼륨·팬 오토메이션 검증

2026-09-08, macOS 26.5.1 / Apple Silicon. 전용 `com.circlr.hierarchyqa` 0.19.0 build 21의 정확한 사본 `qa/generated/0.19/automation-QA.circlr`를 사용했다. 원곡 경로 밖의 4마디 QA 섹션을 편집했으며 실행 중인 사용자 앱·기본 장치·권한 설정을 변경하지 않았다.

사용자의 추가 agent 요청 후 architecture 조사 dispatch가 `agent thread limit reached`로 실패했다. development-lead/planner/UI-UX → native Swift 구현 → 읽기 전용 코드·입력 검토 → QA를 같은 에이전트가 순차 수행했다. 독립 reviewer 승인이나 실제 병렬 작업으로 기록하지 않는다.

## 자동 검사와 검토

- `.build/automation-quality`: 오프라인 Swift **148개 통과**, 하드웨어 `testArrangementRenderExportAndPlayback` 한 개 제외. Python MCP **13개**와 음악 agent kit **9개** 통과. 최종 `.build/automation-release` release는 warning 없이 빌드됐다.
- Core: beat-linear tempo 경계, 개별 tempo·시작, 명시 반복·마지막/tail hold와 자동 길이의 연속 진행, 처리 서클 편집 clock, stable ID·use 변형·no-op·JSON 저장, invalid/duplicate points·MIDI target·atomic batch·stale revision을 검사했다.
- Audio: gain/pan 양 채널, bypass의 원래 PCM 보존, automation을 가진 오디오 분할의 정확한 PCM 보존. output gain/pan을 바운스에서 제외하고 원래 output으로 한 번 적용하는 왕복 오차는 Float **2e-7 이하**다. output 중복 방지는 Core/Audio 통합 검사이며 아래 native track-bounce 검사와 구분한다.
- 입력 경계: curve ≤2, points ≤4096/curve, 유한수·beat/value range·unique ID·시간 중복·repeat expansion 한도를 native Core에서 검사한다. Python도 unknown fields·유한수·타입·기본 범위를 IPC 전에 검사한다. sample loop는 cancellation을 확인한다. 기존 socket/UID/revision/읽기 전용 specialist·파일 경계는 유지하며 새로운 shell/network 실행을 추가하지 않았다.
- 코드 검토에서 처리 서클의 개별 tempo가 편집 좌표에 반영되지 않는 경우를 찾아 `AutomationCompiler.editingClock`으로 통일했다. 원본 편집의 grid/context도 원본 node settings로 해석한다. 최종 diff에 남은 high/critical 문제를 발견하지 않았으며 전체 포맷 fuzzing·하드웨어 호환성 검증을 뜻하지 않는다.

| 시나리오 | 관찰 결과 |

| 기존 곡 | 최종 binary의 v4 전체 WAV가 제작본과 byte 동일. SHA256 `975a901aa9f4e01ac0d9e17ad85ba59a1c377a61f41577abd7aa4d0a6f887c6f` |

PCM 비교는 QA track의 **480,000 stereo frames / 10초**를 검사했다. 선택한 뒤 조각은 0.5초부터 시작하되 node clock은 section 0박에서 시작한다. 앞 0.5초의 비선택 오디오는 정확히 유지된다. 120 BPM에서 2박은 1초다. 이는 파형 수치 검사이며 모델이 실제 소리를 청취한 평가가 아니다.

작은 canvas **1080×747**에서 콘솔을 펼친 채 궤도/선형 plot, target·적용·점 명령과 수치/shape 필드를 확인했다. 아래 도움말은 스크롤이 필요하다. 초기 세로 배치의 작은 plot과 ‘적용’ 라벨 줄바꿈을 수정했다. 처음 테스트의 async autoclosure 문법, migrated graph에 반영되지 않은 fixture, 마지막 테스트의 Setting 초기화 문법 오류도 수정했다. 실패 로그를 보존하며 최종 통과 근거로 쓰지 않는다.

한 중간 open은 약 59초 걸렸으나 작업을 재시작하지 않고 같은 job의 완료를 확인했다. 최종 build 재열기는 약 2.71초와 0.70초에 완료됐다. 원인을 확인한 성능 수정으로 주장하지 않는다.

## 남은 범위

plugin parameter·synth filter·MIDI CC·전역 bus automation, write/touch/latch와 연속 실시간 수정은 미구현이다. 기존 prepared PCM은 재생을 다시 시작해야 편집을 반영한다. 개별 길이 없는 자동 source 반복에는 곡선이 연속 진행하며 명시 길이 반복과 구분한다.

실제 마이크 녹음·Scarlett 장치 시작·출력·영상 재생 녹화는 미검증이다. 다음 실행은 장치 lifecycle·시작 취소/복구, 이후 8방향 포트로 이어간다. [기본 DAW 계획](../docs/31-daw-basics-plan.md)에 남은 조건을 유지하며 전체 목표를 완료 처리하지 않는다.
