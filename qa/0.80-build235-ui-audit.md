## 한 건의 사용성 결함

송폼을 보는 기본 [가로](../docs/images/circlr-song-build234.png)·[세로](../docs/images/circlr-song-portrait-build234.png) 화면에는 섹션 01–07과 곡의 중앙 궤도가 모두 보인다. 이 화면에서 섹션을 선택한 뒤 **원 자체를 끌면 재생 순서가 아닌 공간 배치만 바뀐다.** 이는 의도한 계약이다: `AlbumCanvas.mouseUp`은 일반 drag를 `moveHierarchySelection`으로 보내고, 이 명령은 `musical:false`인 layout mutation이다. 음악상의 순서 이동은 부모 궤도의 별도 손잡이를 끌거나 `⇧⌥←/→`/우클릭 메뉴로 실행한다.

그러나 `CanvasPortLabels.visibleTimeHandle`은 부모 궤도의 **화면 반지름이 100pt를 초과할 때만** `순서 이동` 손잡이를 보인다. build234의 전체 곡을 맞춘 세로 이미지에서 중앙 곡 궤도의 반지름은 이미지상 약 125px, 2× 화면 기준 약 **63pt**로 보인다. 이 크기에서는 선택해도 손잡이 경로가 `nil`이 된다. 직접적인 마우스 조작을 찾으려면 송폼 전체 구도를 잃을 정도로 확대하거나, 발견하기 어려운 우클릭 메뉴를 열어야 한다. 가로/세로 상단의 선택 조작에는 `선택 섹션 듣기`와 `섹션 재사용`만 있으며 순서 조작은 없다. 스크린샷은 정지·미선택 상태이므로 **선택 후 실제 손잡이 부재는 소스와 픽셀 크기에서 추론한 것**이다. 이 감사에서 앱을 새로 조작하지 않았다.

이 결함은 기존 키보드·메뉴 순서 이동 자체의 실패가 아니다. [build215 native QA](0.80-build215-native.md)는 `⇧⌥→`로 Lift의 03→04 이동과 Undo를 검증했다. 문제는 써클러의 중심 작업인 **곡 전체를 보며 섹션을 옮기는** 화면에서 기본 마우스 경로가 가려진 점이다. 서클 drag를 음악 명령으로 재해석하면 [캔버스·음악 시간 분리 계약](../docs/07-canvas-and-musical-context.md)을 깨므로 피해야 한다.

## 재현 및 인수 기준

1. 격리 build235 앱에서 번들 `f0r h3r`을 열고 720×900pt와 1440×900pt 각각에서 전체 곡 01–07을 맞춘다. `03 수평선 · Lift`를 **한 번 클릭**해 곡 구도와 선택을 유지한다. 현재 코드에서는 중앙 궤도가 100pt 이하라면 `순서 이동` 손잡이가 보이지 않아야 한다. 섹션 원을 일반 drag하면 화면 위치만, 우클릭/`⇧⌥→`는 음악 순서만 바뀌는지 `musicRevision`·order badge·Undo로 대조한다.
2. 고정 패널을 추가하지 않고, **선택한 섹션의 재생 순서를 한 칸 앞/뒤로 이동하는 명시적 조작**을 곡 개요에서 제공한다. 가로 선택 도구에는 명확한 이름 또는 도움말을 가진 컨트롤, 세로 `서클 도구`에는 동일한 메뉴 명령을 둔다. `순서 앞으로 한 칸`/`순서 뒤로 한 칸`처럼 위치가 아니라 재생 순서임을 나타낸다. 두 조작은 기존 `AppStore.moveSectionOccurrence`를 호출한다.
3. 첫/끝 섹션, 분기 경로, 전환 효과로 이동 불가, 녹음·영상 등 편집 잠금에서는 해당 방향이 disabled이고 이유를 알아볼 수 있어야 한다. 빈 조작이 새 Undo를 만들거나 카메라·공간 좌표를 바꾸지 않는다. 이동 후 order badge·연결·재생 경로가 즉시 갱신되고 `⌘Z`가 복구된다. 일반 원 drag는 여전히 layout 전용이다.
4. 자동 검사는 기존 `CanvasSectionReorderTests`의 양 방향·끝·분기 fixture를 재사용하고 신규 UI의 enabled/disabled 및 한 번의 command dispatch만 좁게 확인한다. native QA는 같은 최종 빌드의 가로·세로 선택 전/후 픽셀·AX, 03→04→Undo의 badge와 최종 카메라를 기록한다. 실제 출력 PCM이나 Scarlett 호환성은 이 UX 감사의 판정 대상이 아니다.

구현 소유 범위 제안: `RootView.swift`의 선택 도구와 필요 시 작은 presentation helper/UI test. `CanvasCommands.swift`·`OrbitEditing.swift`의 음악 명령을 다시 구현하지 않는다. 작은 궤도에 시간 손잡이를 무조건 노출하면 순번 마커·케이블·포트 hit와 충돌할 수 있으므로 이번 수정의 첫 선택지는 아니다.
