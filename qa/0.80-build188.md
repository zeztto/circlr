# 0.80 build188 · 명시 출력 장치와 실제 앱 루프/영상 QA

상태: **개발 빌드 부분 통과 · 정식 0.80 출고 차단 유지** · 2026-09-23. 검증 대상은 `release/0.80.0`의 0.80.0/build188을 `com.circlr.integrationqa`로 복사·ad-hoc 재서명한 앱이다. 출고 앱의 `codesign --verify --deep --strict`와 QA 앱의 동일 검사가 통과했다. [공개 QA 요약](evidence/r80-build188-qa-summary.json)의 원본 앱 tree SHA-256은 `9b77aa5cc2e41647dba7e55920842e3a15df3289c05c82d875404771270c5312`, QA 앱은 `a369f4de4ced822b89b1f6efbd09c9304c7d4e55c93aa5abff1cdbab3f51bdfd`이다. QA용 데모 작업 사본과 `qa/generated` 출력만 사용했다. 사용자 설치 앱·프로젝트와 시스템 기본 출력은 변경하지 않았다. 최종 QA 앱과 출력 helper는 종료했다.

## 검증 결과

- 최종 소스의 전체 Swift 테스트 **1,036개 실행·11개 skip·실패 0**: 로컬 로그 `qa/generated/r80-build188-full-suite.log`. skip에는 실장치·환경을 요구하는 별도 opt-in 테스트가 포함된다. 실제 build188 worker/host의 명시 내장 스피커 opt-in 테스트 **5개 실패 0**: 60초 실행 제한과 중단 후 최대 5초 process-group 정리를 둔 로컬 로그 `qa/generated/r80-build188-native-host-bounded-v3.log`. 0.1초 자연 종료, 3초 prefill 초과 스트리밍, 시작·clock·정지, 루프 교체·종료의 예약 프레임/잔향 완료를 검사했다. 공개 QA 요약에는 두 로컬 로그의 SHA-256을 남겼다.
- build187 격리 앱에서 `f0r h3r`의 `접속 · DJ Intro` 섹션 루프는 2회차와 해제 후 잔향까지 진행했지만 마지막에 `오디오 출력 상태가 올바르지 않습니다`가 나타났다. build188은 마지막 buffer 완료와 timer 장치 재검사 사이를 완료 표식으로 구분한다. 독립 리뷰가 해당 경합과 실제 오류 전달을 재검토해 추가 결함을 찾지 못했다.
- build188 격리 앱은 시스템 기본 출력이 `Scarlett 6i6 USB`인 상태에서 **앱 안의 `Mac Studio 스피커`를 명시적으로 선택**했다. 같은 DJ Intro를 재생해 2회차 진입, 재생 중 루프 해제 예약, 다음 경계에서 잔향 재생, 오류 없는 자연 정지를 UI/AX로 확인했다. 이어서 출력 helper 잔류 0을 확인했다. 별도의 유한 섹션 재생은 시작·시계 진행·수동 정지를 확인했다. 실제 스피커 청취는 확인하지 않았다.
- 동일 build188 worker의 명시적 내장 스피커 native 테스트를 [5회 연속 반복](evidence/r80-build188-native-repeat.json)해 **총 25개 통과·timeout 0·잔류 worker 0**을 원시 로그와 해시로 대조했다. 시작/끝 시스템 기본 출력 UID hash가 같다. 이 테스트 입력은 무음 PCM이므로 실제 청취·음질이나 앱 GUI의 반복 cold start를 입증하지 않는다.
- 같은 앱에서 영상 녹화를 시작하고 약 15초 후 저장했다. [기계 판독 증거](evidence/r80-build188-short-movie.json)의 MP4 SHA-256은 `51e2cae3c59c6412f87a2416094a250542f4b24500010a07654bb443be0cf487`이다. AVFoundation decoder 기준 **14.859초, 1426×1080, 441 decoded frames, 평균 29.696fps, 2프레임 초과 간격 0, 최대 간격 63.33ms, 연속 동일 화면 0**이었다. AAC 오디오의 첫 PTS는 영상과 함께 0, 마지막 PTS는 14.859초다. `afconvert`로 읽은 48kHz stereo PCM은 peak 0.608, RMS 0.0746이며 시작·중간·끝 1초 구간 모두 nonzero다. 이는 파일과 프레임/오디오 신호 검사이며 물리 청취나 정확한 1920×1080·장시간 품질 검사는 아니다.
- 키보드 방향키로 선택을 옮겼을 때 선택된 앨범 사운드 궤도는 화면에 남았다. 그러나 자식 출력 서클 일부는 아래 가장자리에서 잘려 보였다. 새 reveal 동작의 계약은 **선택 궤도 자체**이며 하위 그래프까지 한 번에 맞추는 동작은 아니다. 이 화면의 여백과 자식 가시성은 R80-01의 추가 UX 확인 항목이다.

재현 명령: `./scripts/swift-local.sh test --scratch-path .build/r80-build188-worker-qa`; opt-in 실제 출력은 worker를 빌드한 뒤 `python3 qa/run-audioqueue-native-tests.py --worker .build/r80-build188-worker-qa/debug/circlr-output-worker --scratch .build/r80-build188-worker-qa --output qa/generated/native-host.log --timeout 60`으로 실행한다. MP4 검사는 `xcrun swiftc -parse-as-library qa/inspect-movie-timing.swift -o qa/generated/inspect-movie-timing-build188`과 `python3 qa/inspect-movie-audio.py <mp4>`를 사용했다. `qa/generated/r80-build188-short.mp4`와 원시 로그는 Git 제외 QA 산출물이다.

## 열린 출고 gate

시스템 기본 Scarlett 출력의 `AVAudioEngine.outputNode` 대기와 명시적 Scarlett의 AudioQueue 시작 대기는 해결되지 않았다. Scarlett의 세대/드라이버/macOS 원인은 미확정이다. 동일 최종 앱에서 장치별 반복 cold start·Play/Stop·복구, 실제 청취, 장치 분리, 재생 중 편집, 정확한 1080p·10분 영상과 중간/끝 AV 동기, 오디오 녹음 take·전체 제작 동선도 남아 있다. 따라서 build188은 사용자 설치 앱이나 `v0.80.0` Release로 게시하지 않는다. [출력 조사](0.80-output-investigation.md)와 [버전 계획](../docs/releases/0.80.0.md)을 따른다.
