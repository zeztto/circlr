## 이유와 작업 경계

build229의 궤도 가독성·CoreMIDI 재진입 개선은 검증됐지만 0.80의 실제 take·AI 작업 완료 gate는 열려 있다. 구형 Scarlett의 최신 macOS 물리 호환성은 기기 세대와 실제 입출력 확인이 필요한 별도 조건이다. 앱 소스에서 재현 가능한 녹음/프로젝트 교체 경합과, 이미 앱이 소유한 trusted AI turn의 안전한 저장·내보내기 계약을 우선 처리한다. 공식 Codex 계정 콘솔 G0 NO-GO는 유지하고 비동작 로그인 UI를 공개하지 않는다.

## 검증·출고 경계

작은 계약 테스트 → 관련 App/저장 통합 테스트 → 전체 Swift/Python → 최종 arm64 패키지·서명 → 변경 영향의 격리 native QA 순서다. 소스 수정 이후 기존 build229 화면 증거를 새 빌드에 전용하지 않는다. 물리 녹음 take·Scarlett 호환성, 독립 청취와 긴 MP4는 실제 장치/사람의 별도 QA로 남긴다. 리뷰는 기능/보안 경계를 독립적으로 한 번 검사한다. 필수 gate가 열려 있는 한 `v0.80.0` tag·GitHub Release는 만들지 않는다.
