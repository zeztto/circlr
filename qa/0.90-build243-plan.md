## 계획 점검 결과

0.80의 출고와 0.90의 신뢰성 목표를 분리했다. 현재 마일스톤은 녹음·편집·저장·출력·반복 재생을 강화하는 방향과 일치하지만, 기존 문서의 1.0 기준 버전은 0.70으로 오래돼 0.80으로 정정했다. 실패한 70ms 영상 항목은 유지하며, 이 작은 차이만 반복 측정하느라 실제 DAW 결함을 뒤로 미루지 않는다.

소스 감사에서 두 가지 구체적인 사용 방해를 확인했다. `MIDIInput`은 생성 당시 source만 연결해 나중에 꽂은 MIDI 키보드와 재연결 장치를 받지 못한다. MIDI plot의 Tab은 노트 이동을 우선 소비하고 수치 inspector로 들어가는 명시적인 키 경로가 없다. 둘은 파일 소유가 겹치지 않아 병렬 수정한다.

## 뒤따를 핵심 작업

- **R90-04 live expression:** MIDI 녹음은 현재 note on/off만 저장해 CC64 sustain과 pitch bend가 누락된다. 이미 저장/렌더되는 표현 모델에 맞춰 입력 channel 정책, 반복 경계의 상태 carry, Stop/cutoff·Undo·저장/재열기·오디오 결과를 별도 slice로 구현한다. 본 hotplug patch에 섞지 않는다.
- **R90-05 긴 MIDI 반응성:** piano roll은 시간축 밖 노트에도 draw/AX 작업을 수행한다. viewport culling과 AX 접근성의 영향을 먼저 측정한 뒤 수정하며, 사용자가 선택한 offscreen note의 keyboard 이동을 보존한다.
- R90-01/02/07의 실제 입력·출력·청취와 R90-03 긴 영상은 최종 후보의 독립 QA로 남긴다. 과거 버전의 PASS나 사용자 이월을 새 버전의 합격으로 재사용하지 않는다.

이 build는 개발 checkpoint이며 0.90 마일스톤 전체 완료나 Release 승인이 아니다.

## take 데이터 의미 재검토

`ProjectEditing.activateTake`가 notes와 함께 nil pitchBend/sustain을 대입하는 것은 새 연주로 교체하는 정상 의미다. 이전 연주의 표현을 무조건 유지하면 새 연주가 변한다. `AppStore.mutate`는 활성화 직전 프로젝트를 Undo에 저장하고 기존 `project.takes`를 삭제하지 않는다. 따라서 nil 대체 자체를 신규 데이터 손실 결함 또는 release blocker로 분류하지 않는다. 이는 소스 검토 결과이며 새 런타임 테스트 PASS는 아니다.

수동 편집된 override/added lane의 녹음 전 상태는 별도 take로 영구 저장되지 않으며 Undo는 세션에 한정된다. 후속 개선은 오디오의 baseline take 방식에 맞춰 성공한 비어 있지 않은 MIDI 녹음에만 `녹음 전` take를 보존하는 것이다. 이 항목도 현재 마감의 필수 gate로 추가하지 않는다.

0.90 후속 빌드에 필요한 환경 확인: 기본 `swift --version`은 여전히 Xcode license 미동의로 exit 69다. 사용자에게 `sudo xcodebuild -license`로 약관을 직접 확인·동의하도록 요청했다. 시스템 설정 변경·대리 동의·추가 CLT 우회 재시도는 하지 않았다. 실제 XCTest 0건과 소스 검토는 릴리스 회귀 검증을 대체하지 않는다.
