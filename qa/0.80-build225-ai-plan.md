## 현재 계약과 첫 경계

`Package.swift:12–13`에서 `CirclrCodex`는 별도 target이고 `CirclrApp`의 의존성이 아니다. `CodexOfflineSessionCoordinator.swift`도 스스로 credential-free 가짜 JSONL 자식 시험용이며 앱 target에서 의도적으로 제외됐다고 명시한다. [계정 콘솔 계획](../docs/20-codex-account-console-plan.md)은 공식 App Server의 production 지원·인증·런타임 재배포 G0를 **NO-GO**로 남긴다. 이 slice는 해당 coordinator를 앱에 연결하거나 로그인 UI를 흉내 내지 않는다. `Package.swift`와 `Sources/CirclrCodex/**`는 첫 slice에서 **변경하지 않는다**. 후속 실제 런타임 통합은 G0가 바뀐 뒤에만 진행한다.

현재 가능한 실제 음악 집행 경로는 `AgentRunLease` → `TrustedAgentIngress` → `AgentSessionGateway.executeTrustedAgent` → `AgentWorkspace.executeAgent` → `AppStore`/Audio다. `AgentRunLease.swift:61–66`은 `snapshot/inspect/job/apply/bounce`만 허용하고, `apply`는 대상 section/use/lane/node를 정확히 묶는다. `AgentSessionGateway`는 문서 binding·revision·request replay를 검사하고 읽기 결과를 경로 없는 작은 projection으로 만든다. bounce worker는 stage WAV를 만든 뒤 MainActor commit 직전에 job generation·trusted lease·문서 snapshot을 재검사한다(`AgentWorkspace.swift:493–545`). 기존 `TrustedAgentIngressTests`는 socket capability·queued STOP을, `TrustedAgentGatewayIntegrationTests`는 MIDI/Undo 및 bounce 수락/STOP을 각각 증명했다. 그러나 테스트가 ingress를 직접 만들고 있어 **실제 앱의 세션 소유·수명 관리**는 아직 연결되지 않았다.

콘솔 `AgentConsole.swift:128–175`는 명령어 파서이며 자연어/모델 세션이 아니다. `RootView.swift:378`의 overlay와 실제 activity/job 표시는 재사용 가능하지만 이 slice에서 `Codex 연결`, 로그인, 모델명, 자연어 답변 버튼을 노출하지 않는다. 외부 `agent.sock`은 같은 UID 자동화용이며 trusted capability를 발급할 권한이 없다.

## 실행 순서와 파일 책임

1. **앱 소유 수명 관리 — `Sources/CirclrApp/AppStore.swift`, `AgentSessionGateway.swift`, `TrustedAgentIngress.swift`.** `AppStore`가 활성 trusted ingress 하나를 강하게 보유한다. 앱 내부 시작 함수는 현재 문서와 명시적으로 선택한 arrangement/use/lane/track에서 `AgentRunTarget`을 고정하고, 앱이 만든 sessionID/turnID와 짧은 TTL로 `beginTrustedAgentTurn`을 호출한 뒤 별도 `.t…` socket을 연다. 모델 문자열이나 외부 MCP 요청은 target, method, TTL, socket 경로 또는 capability를 정하지 못한다. 시작 중 socket 생성 실패는 발급 lease까지 철회한다. 기존 `beginTrustedAgentTurn`을 다른 내부 호출자가 쓸 때도 이전 ingress를 먼저 닫는다.
2. **완료/STOP의 다른 의미 — 같은 세 파일과 `AppStore.stop()`.** `completeTrustedAgentTurn`은 새 요청을 즉시 막고 **ingress socket을 바로 닫되**, 이미 수락한 bounce의 제한된 commit lease는 유지한다. AI STOP은 먼저 `trustedRun.revoke()`로 쓰기를 차단하고 자신이 소유한 running job만 취소한 다음 socket을 닫는다. `TrustedAgentIngress.stop()`과 store cleanup의 재귀·새 turn 철회를 피하도록 socket-only `close`와 lease revoke를 한 방향으로 분리한다. 앱 종료, 새 곡/열기, 같은 projectID의 Save As 또는 mediaRoot 교체, 복구/`resetSession`도 활성 ingress를 닫는다. 전역 `AppStore.stop()`은 DAW 재생까지 멈추므로 AI STOP 버튼이 이를 호출해서는 안 된다.
3. **QA 전용 typed client — `Tests/CirclrAppTests/AppOwnedAgentTurnIntegrationTests.swift` 신규, 필요 시 `TrustedAgentIngressTests.swift` 추가.** 앱이 고른 대상과 활성 문서로만 시작하고, QA client가 turn 전용 socket에 capability envelope를 보내는 test harness를 사용한다. capability는 test process 내부에만 있고 로그·MCP tool argument·project file에 기록하지 않는다. production 사용자 UI에는 이 QA 진입점을 노출하지 않는다. `AgentConsole.swift`는 이번 slice에서 변경하지 않고 실제 `recordActivity`/`agentJob`이 기존 overlay에 나타나는지만 native QA에서 관찰한다.
4. **Core 계약 변경은 원칙적으로 없음 — `Sources/CirclrCore/AgentRunLease.swift`와 `Tests/CirclrCoreTests/AgentRunLeaseTests.swift`는 security review 대상으로 둔다.** 테스트가 명확한 계약 결함을 드러낼 때만 좁게 수정한다. `save/export/open/record/play/stop`, 공유 원본 편집, 임의 경로, 일반 `undo`는 allowlist에 추가하지 않는다. 사용자의 Undo는 기존 `AppStore.undo()`가 AI의 한 `apply` batch를 한 history 항목으로 되돌리는지 검증한다. 모델이 일반 `undo`를 호출하면 그 사이에 들어온 사용자의 작업까지 취소할 수 있으므로 AI 전용 Undo는 transaction 소유권을 설계한 다음 slice다.
5. **빌드와 문서 — `Package.swift`, `Sources/CirclrCodex/**`, `mcp/server.py`, `AgentConsole.swift`는 첫 slice 무변경.** 테스트가 통과하면 `qa/0.80-build225-ai.md`, `docs/releases/0.80.0.md`, `CHANGELOG.md`에 범위와 남은 G0를 기록한다. README의 사용자 기능 문구는 실제 native QA 전에 승격하지 않는다.

## 보안·복구 규칙

- capability는 `TrustedAgentIngress`가 생성한 32-byte 난수이며 모델 입력, JSON activity, stdout/stderr, `.circlr`에 남지 않는다. test client에게만 직접 전달한다. socket directory의 0700, socket 0600, peer UID, 큰 패킷 사전 거부는 기존 `AgentSocket` 계약을 유지한다. 같은 UID 공격자를 이 경계만으로 완전 격리했다고 주장하지 않는다.
- `AppStore`의 `project` ID, `projectURL`, `mediaRoot`와 회복 흐름이 변하면 lease뿐 아니라 **실제 turn socket도 닫혀야 한다**. 특히 현재 `stopTrustedAgentTurn()`은 lease/job을 정리하지만 자신이 소유한 ingress 참조가 없고, `AppStore.stop()`은 lease를 직접 철회한다. 새 owner 도입 시 두 경로를 합치지 않으면 stale socket이 남는다.
- bounce publish는 stage→lease/revision/document 검사→asset 등록 순서를 유지한다. STOP 후 `job=cancelled`만 보고 성공이라 하지 않고 실제 파일·manifest hash와 작업 종료 후 지연 관찰로 늦은 commit을 검사한다. 이미 사용자 Undo로 바뀐 문서에는 이전 bounce를 적용하지 않는다.
- 실패 시 turn-owned socket/capability/job만 정리한다. 기존 외부 MCP `agent.sock`, 음악 재생, 다른 QA 앱, 사용자의 프로젝트와 Codex 계정 상태는 그대로 둔다. 테스트 fixture의 임시 곡·asset은 해시 기록 뒤 폐기할 수 있으나 원본 데모는 수정하지 않는다. 코드 rollback은 앱 owner/ingress 추가만 되돌리면 기존 외부 MCP/DAW 경로가 남는 구조로 한정한다.

## G0 이후 별도 단계

공식 runtime 지원, 앱 단독 설치·서명/재배포, 계정/Keychain 격리, tool policy와 실제 모델 tool 목록을 검증한 후에만 `CirclrApp`의 `CirclrCodex` 의존성과 session manager를 검토한다. 그때도 Codex process가 같은 UID라는 사실을 곧바로 trusted 세션으로 간주하지 않는다. 앱이 검증한 thread/turn과 선택 문서에서 method·target을 발급하고, helper가 turn 전용 ingress에만 접근하도록 제한한 실제 계정 E2E가 필요하다. 별도 `save/export/open`과 사용자 경로 승인은 그 작업의 staged commit 설계와 함께 추가한다.
