## 실행 명령·build 슬롯

아래는 초기 검증용 명령 목록이며 실제 완료 여부는 현재 상태표와 로그를 따른다. 이미 통과한 검사는 source 변경·실패 근거 없이 반복하지 않는다. 신규 실행은 lead가 shared build 슬롯을 배정한다. filter가 빈 suite이면 그 실행은 PASS 수에 넣지 않는다. 신규 relink/복구 class 이름은 구현 owner가 확정한 뒤 이 revision을 갱신한다.

```sh
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter 'RecoveryFileStoreTests|StagedProjectSaveTests|SavedWorkspaceTests'
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter 'RecoveryProcessTests|ProjectPublicationProcessTests'
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter 'MIDIClipboardWorkspaceTests|SectionReuseWorkspaceTests|RecordingDocumentBoundaryTests|CaptureMutualExclusionTests'
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter 'LiveLoopUpdateTests|PlaybackLoopDrainTests|AppOwnedAgentTurnIntegrationTests|TrustedMCPHelperProcessTests'
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter 'PlaybackSpaceShortcutTests|OverlayKeyboardTraversalTests'
```

trusted helper process 검사는 해당 테스트가 요구하는 helper 경로와 opt-in 환경을 먼저 확인한다. unavailable/skip을 실제 IPC PASS로 세지 않는다. 파일 권한·공간 fixture는 같은 사용자로 수행하고 root로 permission 오류를 무력화하지 않는다.

추가한 `RecoveryProcessTests.swift`와 `ProjectPublicationProcessTests.swift`는 focused/Core regression에서 부모 시나리오가 통과했다. child-only harness method의 일반 실행 skip2개는 의도적이며, recovery 부모1개와 publication 부모2개의 child 실행·assertion 성공과 구분해 센다. recovery는 owner/contender 별도 child, publication은 pre-publish와 atomic swap 직후의 child SIGKILL이다. output은 파일로 redirect해 PIPE deadlock을 피하고 marker/exit 대기는 상한을 둔다.

최종 버전 계획이 요구하는 Core/MCP와 package 확인은 영향 회귀가 닫힌 뒤 lead가 1회 수행한다.

```sh
./scripts/swift-local.sh test --scratch-path .build/r130-tests --filter CirclrCoreTests
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s Tests -p 'test_mcp_*.py'
./scripts/build-app.sh
codesign --verify --deep --strict 'dist/써클러.app'
```

### release 판정 근거와 남겨둘 미실행 한계

- **S09:** 원래 release 계약은 crash 후 이전 또는 새 완전본 재열기와 타 자료 보존이다. atomic publication 전후 SIGKILL, 새 process 후속 save의 이전 manifest·foreign marker 보존이 이를 충족한다. 계획표의 cleanup 재시도 문구를 이유로 없는 startup orphan cleanup API를 새로 구현하도록 요구하는 것은 범위 확대다. cleanup 기능의 부재·재시도 미실행 사실은 계속 남기되 신규 구현을 출고 필수로 추가하지 않는다.
- **S10/S11:** 원계약의 공간/권한 실패 보존·재시도는 APFS actual copy/manifest ENOSPC, 실제 chmod publication 실패·retry, native missing/foreign 오류에서 dirty/Undo/Redo·원본·retry로 계층별 확인했다. publication syscall의 **ENOSPC 자체**는 미실행이며 PASS라 하지 않는다. 원 release matrix가 특정 errno×모든 저장 단계를 전수 요구하지 않으므로 같은 보존 분기의 errno 조합을 새 출고 gate로 확대하지 않는다. 계층 연결로 증명되지 않은 실제 오류나 branch 차이가 발견되면 그 지점만 재검한다.
- **M08/D02:** native 목적지 충돌/재시도·save-panel 취소, Core/App 실제 파일시스템 실패·bounded/private projection·dirty/Undo/stale 보호는 함께 판정한다. 자동검사 자체를 native PASS라 명명하지 않으며 동일 UI를 errno마다 다시 실행하지 않는다.
- **U02:**700pt 정상 keyboard 흐름과 실제 오류/복구 UI evidence는 재사용한다. ‘모든 오류×모든 크기×IME’ 전수조합을 원계약에 추가하지 않는다. 실제 IME 사용자 검수는 별도로 유지하며 이미 확인한 가로·700pt 동선은 재사용한다.
- **M04/M06 새 근거:** `qa/evidence/r130-build258-legacy-relink.json`은 명시 identity 경고·Replace와 변경범위 표시 native 결과다. `qa/evidence/r130-relink-stale.json`은 후보준비 중 selection/revision/document 변경의 자동 lifecycle 결과다. selection 자체는 authority가 아니며 captured assetID가 대상이라는 계약을 검증했으므로 selection 변경을 무조건 취소시키는 새 동작을 요구하지 않는다.
