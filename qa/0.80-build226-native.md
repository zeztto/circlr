2026-09-24 KST. `dist/써클러.app` build **226**을 격리 폴더에 복사하고 bundle ID를 `com.circlr.build226nativeqa`로 변경해 ad-hoc 재서명했다. QA용 복구 폴더는 `~/Library/Application Support/circlr-build226native-qa`이며, 번들 `f0r h3r`은 `~/Library/Application Support/com.circlr.build226nativeqa/Demo Projects`의 새 편집 사본으로 로드했다. 사용자 곡·시스템 오디오 설정·물리 Scarlett 장치는 건드리지 않았다. 재생·녹음·영화 녹화도 시작하지 않았다.

**결함 재현:** 1440×900 최초 화면은 01–07의 전체 이름과 원 둘레·마디 눈금을 보여준다. 창을 정확히 720×900pt로 줄이고 기본 122pt 콘솔을 유지하면 **06 이름표의 뒷부분이 우하단 navigation 위젯 밑에 들어간다**. `demo-default-exact720x900.png`는 자르지 않은 전체 창 1440×1800px Retina 캡처다. 720pt에서 `circlr_snapshot.playback.canvasSize=[720,751]`, `workspaceViewport=[24,78,672,427.5]`, 06 `rect=[409.812,469.5,192,36]`, `anchor=[505.812,102.203]`, 원 `radius≈44.286`이다. 라벨의 아래 변은 viewport의 아래 변 `505.5`와 일치한다. 화면의 navigation은 대략 canvas `x=540–704`, `y=475–511`을 덮어 이 라벨과 교차한다. 이는 픽셀에서 확인한 근삿값이며 navigation의 별도 앱 진단 좌표는 없다. `CanvasPresentation.readableLabelObstacles`가 navigation을 장애물에 넣지 않는 것도 코드에서 확인된다. 723×900pt 중간 폭에서도 같은 가림을 재현했다.

큰 180pt 콘솔, 작은 40pt 콘솔, 접힌 콘솔의 **723×900pt** 캡처에서는 7개 전체 이름과 각 시간 링·눈금을 볼 수 있었다. 특히 이전 build224에서 자기 링을 가린 04/06/07은 이 상태들에서 링 밖에 배치된다. 감상 모드에서는 텍스트가 사라지고 7개 링·연결은 남으며, 종료 후 이름이 복원됐다. 04·06·07 각각의 이름표를 직접 클릭하고, 노출된 링 둘레를 클릭했을 때 해당 섹션이 AX `selected`가 되는 것을 확인했다. AX에는 01–07 이름·시간 범위가 유지됐다. 직접 키보드 순회, hover 전체 조합, 재생 중 song/section follow, 수동 줌·팬 후 폭 왕복, 편집·저장·Undo는 이번 결함 검증에서 실행하지 않았다.
