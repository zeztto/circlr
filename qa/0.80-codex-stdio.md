# 0.80 Codex stdio 초기화 조사

상태: **내부 프로토콜 확인 / 계정 기능·출시 검증 아님** · 2026-09-24.

설치된 `codex-cli 0.149.1`에 `python3 qa/probe-codex-stdio.py`를 실행했다. 이 도구는 별도 `codex app-server --stdio` 프로세스에 `initialize` 한 건만 보내고, 응답의 성공 여부와 **키 이름만** 출력한 뒤 자식 프로세스를 종료한다. 실제 결과:

```json
{"errorCode": null, "initializeSucceeded": true, "resultKeys": ["codexHome", "platformFamily", "platformOs", "userAgent"]}
```

모델 turn, 계정 조회·로그인, 프로젝트 데이터 전송, 음악 편집, MCP 호출은 수행하지 않았다. 응답 값이나 stderr 원문은 기록하지 않는다. 이 검사는 로컬 CLI의 stdio wire가 현재 초기화 요청에 응답한다는 것만 입증한다. 로그인 상태, 앱 단독 설치, 사용자 계정으로 대화, 재배포 권리, 실제 DAW 도구 호출의 증거가 아니다.

[OpenAI App Server 문서](https://learn.chatgpt.com/docs/app-server)는 `codex app-server` 명령을 experimental·production 미지원으로 표시한다. 따라서 이 검사를 1.0의 계정 런타임 G0 통과나 공개 UI 활성화의 근거로 사용하지 않는다. 다음 내부 구현 단위는 계정·thread·turn 상태기계와 별도 세션 전용 MCP helper이다. [1.0 인수 기준](../docs/releases/1.0.0.md)의 실제 계정/음악 작업 검증은 그대로 남는다.

내부 `CirclrCodex`에 자식 프로세스의 시작·JSONL 쓰기·출력 수신·유한 시간 종료를 관리하는 `CodexProcessHost`를 추가했다. `/bin/cat`·`/bin/echo`·`/bin/sleep`을 이용한 6개 host 테스트와 기존 프로토콜 테스트를 합해 `CirclrCodexTests` **36/36 통과**했다. 쓰기 timeout 뒤 이전 세대가 새 세대를 종료하지 못하도록 하는 경합과 호스트 해제 뒤 idle 자식 종료도 재현한다. 독립 코드 검토에서 세대·수명 경합과 부분 쓰기·EINTR timeout 수정을 확인했다. 실제 연결부는 콜백에서 host를 약하게 참조하고 teardown에서 명시적으로 `stop()`해야 한다. 이 테스트는 실제 Codex 계정·모델 turn·앱 UI·MCP 승인 흐름을 검증하지 않는다. Host는 아직 `CirclrApp` 실행 파일에 연결하지 않았다.
