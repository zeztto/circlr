# 0.80 build195 정상 정지 문구·실제 앱 재검증

상태: **부분 통과 / 0.80 출시 보류** · 2026-09-24. build194 native QA에서 정상 Stop 뒤에도 장치 변경을 권한 표현을 수정한 개발 후보이다. 사용자 설치 앱, 원본 데모, 시스템 기본 출력은 변경하지 않았다.

## 확인한 결과

- `./scripts/build-app.sh`로 **0.80.0/build195 arm64 앱·다섯 helper**를 패키징했고 `codesign --verify --deep --strict`를 통과했다. 빌드 로그 `qa/generated/r80-build195-build.log` SHA-256 `89bfb20ebe0c4ccf173974c5c2d826ce3648ce61ac15478b5baee7dcd1bb7900`; 별도 `com.circlr.portfocusqa` 패키지 inventory SHA-256 `46d6dac173aabc02b9f5e98dddc261ff1e33b37866124aa62bc05d9c0df76ee7`.
- 격리 앱의 출력 설정은 **Mac Studio 스피커**, macOS 시스템 기본 출력은 **Scarlett 6i6 USB**로 표시됐다. 동봉 `f0r h3r`를 두 번 재생해 각각 00:02.6, 00:03.2까지 시계가 진행했고 앱은 실제 출력 확인 장치를 Mac Studio 스피커로 표시했다. 각 정상 Stop 뒤 상태 설명은 `이전 출력 정리가 끝났습니다. Space로 다시 재생하세요.`였으며 부정확한 장치 변경 안내가 없었다. build194의 timeout→감상 모드 복귀→앱 전용 내장 출력 재시도 검증은 [별도 기록](0.80-build194.md)에 있다.
- 실제 앱에서 9.363초·702×750 MP4를 저장했다. SHA-256 `79d97776b078420d9b1ca46b14528305af046b15413b0167b6e8693013f6130c`. 파일 판독은 **282 디코드 프레임**, 평균 30.12fps, P95 간격 40ms·최대 51.67ms, 중복 PTS·인접 동일 화면0, 시작 video/audio PTS0을 보였다. stereo 48kHz AAC 전체 peak 0.608/RMS 0.0741, 시작·중간·끝의 RMS가 모두 0보다 컸다. 판독 JSON SHA-256은 영상 `b9acf9cc0d0c6f5b2086ff81a015231eaff0af96529a473ce971b3465728aa61`, 오디오 `08eb8b732d4c5c7bcb52f5ff9385090aa370d6fc222fe0590ce26289bfd359fd`다.

- QA 앱 종료 후 build194/195 앱·출력 helper 잔류 프로세스는 없었다. 격리 앱의 출력 선호는 `BuiltInSpeakerDevice`, macOS 기본 출력은 계속 `Scarlett 6i6 USB`였다.

전체 Swift **1090개·11개 skip·실패0**, MCP Python **39/39**, agent kit **9/9**은 build194의 동일 기능 소스에서 통과했다. 이후 build195에서는 `PlaybackOutputStatus`의 정상 Stop 상태 문구만 분리해 위 release 앱 빌드와 실제 앱 Stop 2회로 재검사했다. 전체 Swift 테스트를 다시 실행한 결과로 표현하지 않는다. 내부 trusted `inspect`의 독립 보안 재검토에서 P1/P2 추가 발견은 없었지만 실제 계정 대화 gateway의 통합 replay와 큰 MCP 요청 성능은 미검증이다.

## 남은 출고 gate

물리 청취, 실제 세로 디스플레이·고밀도 연결/줌 장시간 사용성, 정확한 1920×1080·10분 녹화, 중간/끝 A/V 박자 동기, 플러그인·오디오 입력/편집·stem을 포함한 전체 GUI 제작 동선은 아직 완료되지 않았다. Scarlett 정상 출력이나 HAL timeout의 원인은 확정하지 않았고 그 기기의 성공을 필수 조건으로 삼지 않는다. `v0.80.0` 태그와 GitHub Release는 만들지 않는다.
