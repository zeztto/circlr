# 0.80 build207 · 살아 있는 앱의 기본 MCP 연결 재선택

상태: **해당 격리 native 동선 PASS / 0.80 출고 승인 아님** · 2026-09-24. build206 리뷰에서, 앱 B가 마지막으로 `selected.json`을 게시하고 종료하면 살아 있는 앱 A의 socket이 열려 있어도 기본 MCP 연결은 B의 사라진 경로를 가리키는 가용성 결함을 찾았다. 무조건 A로 자동 전환하면 다른 프로젝트로 쓰기가 갈 수 있어 명시적 재선택 UI로 처리했다.

`release/0.80.0`의 build207을 `com.circlr.portfocusqa` 격리 앱으로 실행했다. 로컬 `qa/generated/r80-build207-package.json`의 원본 앱 SHA-256은 `8bc11be6609f7b40a093dedcbcfac2b58a0fa4927d6a849af90573b89343234e`, QA 앱은 `77f911dfc11cd4a5d97febc5d5fc3b0e2c8768cc9d4adcc22297293e640bdc44`다. 사용자 앱·프로젝트·시스템 출력 설정은 변경하지 않았다.

- 데모 `f0r h3r`를 열자 UI는 **0.80.0 · 빌드 207**, **MCP 연결 가능 · 기본 선택**을 표시했고 기본 MCP snapshot은 이 실행의 runID와 `agent.sock`을 반환했다.
- QA 전용 `Agent/selected.json`만 원자적으로 바꾸어, 이미 종료한 다른 앱이 `.rdeadbeef`를 마지막으로 선택한 상황을 재현했다. 실제 두 앱을 동시에 실행한 검증은 아니다. 기존 `agent.sock` inode `24542316`은 유지됐다. UI는 1초 이내 **기본 미선택**과 **이 앱을 기본 연결로 선택** 버튼을 표시했다. 새 기본 MCP 요청은 사라진 `.rdeadbeef`에서 실패하며 살아 있는 socket으로 fallback하지 않았다.
- UI 버튼을 누르자 상태가 **기본 선택**으로 바뀌고 동일 socket inode를 유지한 채 현재 앱의 선택 정보만 다시 게시했다. 새 MCP snapshot은 build `207`·선택 정보와 일치하는 runID를 반환했다. 기존 MCP 세션은 재시작하도록 UI와 문서가 안내한다.
- 정상 종료 뒤 소유한 `agent.sock`은 제거됐고 `selected.json`만 남아 기본 MCP가 실패로 닫혔다. 사용자 `circlr/recovery.json` SHA-256 `688558b00e4160106065114e7a6305ffa1a24ea8f57636408f408e38e5148c38`와 QA legacy 복구본 SHA-256 `0c7507e9686665d048b82c5b5780d86e36dfda94fc1b91759c0f35702d8380e7`는 동일했다. QA 앱 프로세스는 종료했다.

검증: endpoint Swift standalone smoke는 선택 정보의 소유·권한·현재 선택 판독과 FIFO/symlink 거절을 통과했다. 전체 Swift **1113 실행·11 skip·실패 0** (`generated/r80-build207-swift-tests.log`), MCP·agent kit Python **50/50** (`generated/r80-build207-python-tests.log`), release arm64 앱·다섯 helper 빌드와 strict deep ad-hoc 서명이 통과했다. 독립 보안 리뷰에서 새 P1/P2는 없었다.
