앱이 현재 선택한 섹션의 MIDI lane과 track을 한 turn의 대상으로 고정하고, 앱이 만든 session/turn ID와 300초 만료를 사용한다. `AppStore`가 전용 `.t…` Unix socket을 보유한다. 새 turn·완료·AI STOP·문서/미디어 루트 교체·앱 종료·만료에는 새 요청을 막고 socket을 닫는다. 완료는 **이미 수락된 bounce**의 제한된 commit 권한을 만료 전까지 남기고, STOP은 그 권한을 철회한다. 일반 MCP `agent.sock`과 DAW transport는 별개다. 실제 Codex 로그인·모델·자연어 UI는 연결하지 않았다.

새 `AppOwnedAgentTurnIntegrationTests` 5개와 관련 기존 테스트 합계 **27/27 통과**. 전용 socket으로 `snapshot → inspect → MIDI apply → 사용자 Undo → 재적용 → bounce`를 실행하고, 완성 asset의 nonzero PCM을 디코드해 확인했다. 결정적 worker 대기 지점에서 STOP한 뒤 늦은 socket 쓰기와 asset/stage WAV가 없음을 확인했다. 이전 capability는 preflight에서 연결이 응답 없이 끊겼다. socket 생성 실패 rollback, turn 교체, project URL/media root 변경, 종료, 일반 Stop, 짧은 TTL 정리도 확인했다. 독립 코드·보안 리뷰에서 확정적인 P1/P2는 없었고, 빠른 bounce가 STOP보다 먼저 끝날 수 있던 **테스트 경쟁 조건**을 수정해 다시 27개를 통과했다. 재생 중 AI STOP이 실제 transport를 유지하는지, WAV 게시 직전 경합과 같은 프로세스의 실제 계정 turn은 별도 통합 QA다. 보안 경계의 세부 계획은 [slice 계획](0.80-build225-ai-plan.md)에 기록한다.

전체 Swift 회귀는 서로 다른 scratch 경로에서 두 번 실행했다. **각각 1,194개·14 skip·같은 실패 1건**이다. `AudioTests.testVirtualMIDIReceivesMultiplePackets`가 `MIDIClientCreateWithBlock`에서 `MIDI client 생성 실패: -2`로 끝났다. 그 테스트 단독과 `AudioTests` 묶음은 통과했다. 독립 진단에서는 `AppOwnedAgentTurnIntegrationTests` 5개 → `AudioClipEditingTests` 8개 → `AudioTests` 7개 순서에서도 재현됐고, 각 묶음만 실행하면 통과했다. 이 관찰은 순서/프로세스 상태 의존성을 좁히지만 정확한 CoreMIDI 원인은 확정하지 않는다. 테스트를 skip하거나 제품에 근거 없는 retry를 넣지 않았다. 로그는 `/tmp/circlr-build225-{full,final}-swift.log`에 있으며 로컬 임시 자료다.

Python 전체 `python3 -m unittest discover -s Tests -p 'test_*.py' -q` **50/50**, MCP 부분집합 **39/39**. `qa/verify-agent-journey.py`는 이제 명시한 격리 QA bundle ID와 전용 Application Support root를 허용하되 생산 앱 경로를 거부한다. 이 옵션의 help·비 QA root·비 fixture 거절과 `git diff --check`를 확인했다. 이 변경 뒤 build225의 전체 MCP 제작 동선을 다시 실행했다고 주장하지 않는다. [build224 실제 앱 MCP QA](0.80-build224-mcp-native.md)는 MIDI·FX/automation·WAV·bounce·저장/재열기와 원본 보존을 별도로 검증했다.

`dist/써클러.app`의 `CFBundleVersion=225`, arm64 주 실행 파일 SHA-256 `f8a0d8dc4d71b2b9ab325437713e8611e8a8afa675017f77f5852b232a1f7cd0`, 다섯 helper, agent kit 25파일, `codesign --verify --deep --strict`를 확인했다. 리소스 57파일을 패키징했고 동봉 `f0r h3r`와 Bach Invention 8 manifest는 각각 저장소 원본과 SHA-256이 일치한다. [격리 native smoke](0.80-build225-native.md)는 실제 설치형 앱의 시작, 27개 MCP 도구와 build225 snapshot, 정상 종료·socket/helper 정리를 확인했다. `Resources/Assets.car`는 아이콘 생성의 비결정적 재생성만 발생해 이전 추적 파일로 돌려두었고, 화면 변경이 없어 한영 README 화면은 검증된 build224 그대로다.

구형 Scarlett 6i6의 세대와 이 Mac의 HAL timeout 원인은 미확정이다. 이번 build225 AI/오프라인 QA는 **물리 오디오 출력·녹음 입력 장치를 시작하지 않았고**, Scarlett의 정상 동작을 입증하지 않는다. 출시 QA는 앱 전용 내장 출력을 기준으로 하고 Scarlett timeout 뒤 UI/worker 정리와 안전한 재시도를 별도로 판정한다. 실제 take·청취, CoreMIDI 전체 회귀, 장시간 영상과 전체 AI 계정 경로가 열려 있으므로 `v0.80.0` tag/GitHub Release를 만들지 않는다.

다음 검증은 CoreMIDI client의 test-process 수명과 앞선 두 테스트 묶음의 누적 상태를 관찰해 `-2`를 설명하고, 동일 최종 소스의 전체 Swift를 다시 통과시키는 것이다. 실패를 임의로 건너뛰지 않는다. 실제 Scarlett 세대 확인은 장치 이름이 아닌 기기 정보와 지원표를 대조할 수 있을 때 별도 수행한다.
