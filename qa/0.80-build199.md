# 0.80 build199 · 복구·세로형 케이블 도구 QA

상태: **해당 결함 수정 확인 / 0.80 출시 gate는 계속 열림** · 2026-09-24.

`./scripts/build-app.sh`로 0.80.0/build199 arm64 앱과 다섯 helper를 패키징하고 `codesign --verify --deep --strict`를 통과했다. 빌드 로그 `qa/generated/r80-build199-build.log` SHA-256은 `57de5f2ea1726fa89b61650dc0966d946c4d738de7d779a1cece217613059f4a`다. 별도 `com.circlr.portfocusqa` 앱과 동봉 데모 동일 음악·별도 시각 배치 사본을 [QA 준비 도구](prepare-port-focus-qa.py)로 만들었다. 패키지 기록은 `qa/generated/r80-build199-package.json`, 원본 앱 tree SHA-256은 `02f32faa486cfc188fe2032210a5130cf5e5b73666181b85732d32805c70e72f`다.

실제 격리 앱에서 `f0r h3r`와 버전 **0.80.0 · 빌드 199**를 확인했다. 데모 로드 후 QA 전용 `recovery.json`이 생겼고, ⌘Q → **변경 버리기**로 종료하자 파일이 없어졌다. 새 프로세스로 다시 열어도 복구 안내 없이 시작 화면이 열렸다. 빌드198에서 버린 QA 복구본은 테스트 전 `recovery-build198-discarded.json`으로 이름만 옮겨 보존했다.

별도 손상 파일 실험에서는 QA 폴더에 일부러 넣은 읽을 수 없는 복구 파일이 `recovery-unreadable-<UUID>.json`으로 보존됐고 SHA-256 `539fbedaba46810e197d90d5a5355005ed6d74e18e5a81cecb7d45b3e9d24256`이 유지됐다. 이후 데모를 열자 새 `recovery.json`이 생성됐으며, 종료 시 다시 제거됐다. 기본 사용자 `circlr/recovery.json` SHA-256 `688558b00e4160106065114e7a6305ffa1a24ea8f57636408f408e38e5148c38`은 전후 동일했다. 동일 번들 중복 실행의 복구 잠금과 복구 파일 교체는 `RecoveryFileStoreTests` 5개로 검사했으며 native 두 인스턴스·migration 실패 UI는 별도 확인이 남는다.

약 702×900pt 실제 창에서 곡 궤도의 `수평선 · Lift → f0r h3r · Club Chorus` 케이블을 선택했다. 도구는 두 줄로 표시되고 AX 트리에 재연결·위치 이동·편집·해제·OUT·IN이 모두 남았다. **IN**을 누르자 해당 끝점 강조가 바뀌었고 **편집**은 Club Chorus의 IN 연결 편집 화면을 열어 기존 연결 2개·검색 대상 6개를 표시했다. [build198 최초 관찰](0.80-build198.md)을 최종 소스의 build199에서 재확인한 범위다. 실제 340/375pt 창은 RootView 최소 폭 700pt 때문에 확인하지 못했다.

기본 `.build`의 첫 전체 Swift 테스트는 `AgentArguments.init`에서 SIGSEGV로 중단됐다. 동일 테스트를 반복해도 충돌했으나, 독립 조사에서 이전 구조체 배치의 낡은 `MIDISustainEditingRenderTests.swift.o`가 새 `laneID` 필드와 섞여 링크된 증분 산출물 불일치를 확인했다. 새 `.build/test199-clean`에서 `AgentPortTests` **8/8**, 전체 Swift **1100개 실행·11개 skip·실패0**을 통과했다. 깨끗한 전체 로그 `qa/generated/r80-build199-tests-clean.log` SHA-256은 `9225c29b81cb0d9cc2cdf36c76a0eae0da594bc9eff07e2396ba895c37e12a61`이다. 기본 `.build` 테스트 실행은 PASS로 세지 않는다. Python MCP server **28/28**, MCP 통합 **39/39**, agent kit **9/9**, 취소 fixture **8/8**도 통과했다. 후속 독립 리뷰가 startup MCP gate, 구버전 복구 writer와의 경쟁, Codex host의 수명 경합을 지적했으므로 build199를 최종 후보로 판정하지 않는다.
