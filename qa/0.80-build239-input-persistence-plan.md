실행 결과는 [build239 입력 지속성 native QA](0.80-build239-input-persistence-native.md)에 기록했다. 아래는 실행 전 계획이며 실제 녹음 길이와 증거는 결과 문서가 우선한다.

TEMPLATE_VERSION: qa-response-v1
REPLY_TO_TEST_REVISION: 0.80-build239-input-persistence
STATUS: prepared; not executed
COVERAGE: 앱 전용 CalDigit 입력 선택 → 4마디 빈 곡 take → .circlr 저장 → 완전 종료·재실행 → WAV export
BLOCKERS: 다른 DAW QA 앱이 실행 중이다. 그 앱의 종료 통보 및 development lead의 별도 실행 지시 전에는 clone·실행·장치 조회를 하지 않는다.
RISK_CALLS: macOS 마이크 TCC가 막거나 물리 입력 신호가 완전 무음이면 해당 단계는 BLOCKED; 우회 또는 청취 성공 주장 금지

## 격리·사전 조건

1. DAW QA 앱 종료와 실행 지시를 받은 뒤에만 시작한다. `dist/써클러.app`의 `0.80.0/build239`, 실행 파일 SHA-256 `f87136cef6f5453bcfd7aa034cb75bf4d49873efea267a6aad8d0b166ace9314`, 원본 `codesign --verify --deep --strict`를 다시 확인한다. 새 폴더 `qa/generated/r80-build239-input-persistence/`와 `.build/build239-input-persistence/`만 증거·앱 복제에 사용한다. 대상이 이미 존재하면 덮어쓰지 않고 중단한다.
2. `system_profiler SPAudioDataType` 원본 전체를 `audio-before.txt`로 기록한다. 기본 입력·출력·시스템 출력 기기 이름과 UID를 별도로 적는다. 그 후 저장소 루트에서 `python3 qa/prepare-0.80-input-persistence.py`를 실행한다. 이 추적 스크립트는 원본을 복제해 고유 bundle ID `com.circlr.build239inputqa`를 넣고 문서·URL 형식 등록을 제거한 뒤 ad-hoc 재서명한다. Resources·helper의 원본 대비 byte 일치와 원본 불변을 `qa/generated/r80-build239-input-persistence/bundle-integrity.json`에 기록한다. **원본 앱이나 시스템 오디오 기본 장치를 실행·변경하지 않는다.**

## 실제 조작 순서

3. 복제 앱만 열고 시작 화면에서 이름이 식별되는 **새 곡**을 만든다. 기본 120 BPM/4⁄4/4마디/건반 1트랙을 유지한다. 캔버스에서 `섹션 1`과 `건반` 트랙/서클을 선택하고 녹음 메뉴의 target AX가 이를 가리키는지 확인한다. MIDI 노트를 추가하지 않아 녹음 전 프로젝트의 오디오는 무음이어야 한다.
4. 녹음 메뉴의 입력 목록에 `CalDigit Thunderbolt 3 Audio`와 `Scarlett 6i6 USB`가 보이는지 기록하고, **QA 앱 내부에서만** CalDigit를 선택한다. 재연 메뉴의 checkmark와 bundle preference `circlr.recording.inputDeviceUID`를 확인한다. 그 직후 시스템 기본 입력·출력을 재조회해 변경이 없음을 확인한다.
5. `⌥⌘R` 또는 `오디오 테이크 녹음`으로 시작한다. `오디오 녹음 중` 및 입력 레벨/형식을 확인하고 2–4초 후 정지한다. `파일 마무리 중`이 끝나 `오디오 take 저장 완료`와 take 1개가 나타날 때까지 기다린다. 시스템 TCC 권한 창이 도구 접근을 막으면 사용자 대신 선택하거나 `tccutil`·설정 조작으로 우회하지 않는다. 해당 gate를 BLOCKED로 기록한다.
6. QA 앱의 Application Support `takes/*.caf` 중 이번 take를 확정해 원본 SHA-256, `afinfo` 형식·sample rate·channels·frames·duration, Float32 PCM nonzero/peak/RMS를 기록한다. build238의 CalDigit peak가 약 0.00061이었으므로 매우 낮은 nonzero는 **입력 데이터 경로**만 입증한다. 실제 음악/청취 품질은 판정하지 않는다.
7. `⇧⌘S`로 새로운 `qa/generated/r80-build239-input-persistence/qa-input-take.circlr` 패키지에 저장한다. `저장 완료`와 `manifest.json`을 확인한다. `assets`에서 새 CAF의 asset ID, `path=media/<asset-id>.caf`, checksum, 해당 `takes`/lane의 audio clip assetID를 검사한다. 패키지 media의 SHA-256이 6번 CAF와 같고 상대 경로가 패키지 내부에 머무르는지 확인한다. 기존 프로젝트·사용자 파일을 덮어쓰지 않는다.
8. `⌘Q`로 앱을 완전히 종료하고 QA bundle process·helper·socket 0을 확인한다. **같은 QA 앱**을 다시 실행해 `⌘O`로 `.circlr` 폴더를 연다. 곡 ID, take 수, asset ID, clip 참조와 패키지 media SHA가 저장 전과 같고 오디오 clip이 활성화되어 있는지 UI/manifest로 교차 확인한다.
9. 재열기 후 아무 MIDI도 추가하지 않은 상태에서 `⌘E`로 새 `qa-input-take-after-reopen.wav`를 export한다. `내보내기 완료`를 확인하고 `afinfo`·PCM 분석으로 4마디 길이의 유효한 WAV와 nonzero 프레임을 검사한다. 빈 곡의 다른 신호가 없으므로 WAV의 nonzero는 보존된 take의 render 증거다. 더 엄격한 귀속 확인이 필요하면 녹음 전 동일 빈 곡의 baseline WAV와 비교하되, baseline export는 별도 UI/시간 비용이므로 필요한 경우에만 수행한다. CAF nonzero인데 WAV가 무음이면 **FAIL**, CAF 자체가 무음이면 take 저장 지속성은 확인하되 WAV 신호 귀속은 INCONCLUSIVE로 둔다.

## 종료·판정

10. 복제 앱을 종료하고 QA 관련 process/helper/socket 0, `audio-after.txt`의 기본 입력·출력·시스템 출력이 시작 값과 정확히 같은지, 원본 실행 파일·데모 manifest SHA와 strict 서명이 그대로인지 확인한다. 확인된 전 과정의 AX, 전체 창 스크린샷, 기기 목록, manifest/CAF/WAV 분석 JSON만 이 문서의 실행 결과표에 추가한다. 실행되지 않은 항목은 PASS로 표시하지 않는다.

**합격선:** 앱 전용 CalDigit 선택, nonzero take 확정, 패키지 byte 보존, 종료 후 재열기, 해당 take가 살아 있는 빈 곡의 nonzero WAV export, 환경 원복이 모두 관찰되어야 한다. TCC나 실제 입력 무음은 판정 범위를 분리한다.
