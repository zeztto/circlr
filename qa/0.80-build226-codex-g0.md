# 0.80 build226 · Codex 계정 콘솔 G0 재평가

조사일: 2026-09-24 · 범위: 공식 OpenAI 문서, 저장소의 설계·소스 정적 대조. 계정 로그인, 모델 호출, API 호출, credential 조회, 실제 배포 테스트는 하지 않았다.

```text
DECISION: NO-GO — 공개·서명된 macOS 앱의 자체 ChatGPT/Codex 계정 대화 콘솔
REASON: 공식 App Server 문서가 codex app-server 명령의 production 미지원을 명시한다.
READY: 음악 명령과 앱 소유 turn/socket의 오프라인 보안·DAW 검증을 계속 진행
NOT READY: 앱 내부 실제 로그인·모델 대화·Codex MCP helper·런타임 동봉/재배포
```

## 공식 근거와 해석 경계

| 현재 문서에서 확인한 내용 | G0에 적용한 판단 |
|---|---|
| [Codex App Server](https://learn.chatgpt.com/docs/app-server)는 자체 제품의 인증·대화 이력·승인·스트리밍 이벤트를 위한 프로토콜로 소개한다. 기본 `stdio`와 JSONL, `initialize`→`initialized`, `thread/start`, `turn/start`, `turn/interrupt` 등의 계약을 문서화한다. 같은 페이지는 **“The app-server command and WebSocket transport are experimental and aren’t supported for production workloads.”**라고 명시한다. | 제품 통합이 기술적으로 가능하다는 설명과 현재 production 지원 상태를 함께 적용한다. `stdio`를 택하거나 `experimentalApi`를 끄는 것만으로 **명령 자체**의 production 미지원 문구가 해소되었다고 판단하지 않는다. |
| [2026-08-19 OpenAI의 플랫폼 통합 안내](https://developers.openai.com/blog/codex-as-a-platform)는 agent가 제품 자체에 들어가는 경우 App Server를 사용해 지속 대화, 이벤트, 중단, 도구, 승인을 다룰 수 있다고 권한다. | 방향을 지지하는 공식 자료지만 App Server 페이지의 명시적인 현재 production 제한을 철회한 문서는 아니다. 두 자료가 함께 있으므로 제품 출시는 보수적으로 NO-GO다. 이는 OpenAI가 미래에도 사용을 허용하지 않는다는 뜻이 아니다. |
| [App Server 인증 계약](https://learn.chatgpt.com/docs/app-server)은 `account/read`, `account/login/start`, `account/login/completed`, `account/logout`과 Codex 관리형 ChatGPT 브라우저·device-code 로그인을 설명한다. 앱이 직접 공급하는 `chatgptAuthTokens` 모드는 experimental이다. | 별도의 비밀번호 입력이나 자체 OAuth/token 교환을 발명하지 않는다. 실제 출시 경로에서는 Codex 관리형 로그인을 검증하고 외부 토큰 주입은 배제한다. 이 프로토콜이 있다고 circlr 계정 연동이 이미 구현된 것은 아니다. |
| [Codex Authentication](https://learn.chatgpt.com/docs/auth)은 ChatGPT 로그인과 사용량 기반 API key 로그인을 별개로 설명한다. CLI와 IDE 확장은 캐시를 공유하며, `cli_auth_credentials_store=keyring`은 OS credential store가 없으면 실패하고 `auto`는 `auth.json`으로 fallback할 수 있다. | 기존 데스크톱 Codex 로그인·캐시를 circlr 전용 격리 계정으로 간주하지 않는다. 전용 `CODEX_HOME`/Keychain 항목/로그아웃의 실제 격리 효과를 깨끗한 macOS 사용자에서 검증해야 한다. API key 또는 Agents API 과금으로 조용히 전환하지 않는다. |
| [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)는 앱 통합을 언급하며 Python SDK stable 배포본이 pinned CLI runtime을 포함한다고 설명한다. 같은 문서는 Python SDK가 로컬 App Server를 제어하고, 인증·이력·승인·스트리밍을 직접 다루는 custom client에는 App Server를 사용하라고 한다. [Non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)는 `codex exec --json`을 사전 설정된 sandbox/승인 하의 스크립트·CI 작업으로 설명한다. | SDK의 stable **패키지**와 `codex exec`의 자동화 가능성을 native interactive App Server의 production 지원으로 전이하지 않는다. 둘은 제한된 백그라운드 작업의 후보이나 사용자의 앱 안 실시간 대화·중단·승인 요구를 대신 충족했다고 주장하지 않는다. |
| [Open Source](https://learn.chatgpt.com/docs/open-source)는 Codex CLI·SDK·App Server 소스의 공개 위치를 열거한다. 페이지에는 circlr가 특정 macOS 바이너리를 앱에 동봉할 때의 버전별 NOTICE/라이선스, 서명·notarization, 지원 약속이 적혀 있지 않다. | **재배포 금지라는 결론도, 동봉 배포 승인이라는 결론도 내리지 않는다.** 실제 선택한 릴리스의 라이선스·의존 파일·출처·hash·서명·깨끗한 Mac 실행을 별도로 검증할 때까지 G0의 배포 항목은 미완료다. |
| [Feature Maturity](https://learn.chatgpt.com/docs/feature-maturity)는 Experimental을 변경·제거 가능 상태로, Stable을 production 사용에 적합한 상태로 구별한다. | 문서의 명시적인 experimental/unsupported 문구를 단순 문서 지연으로 무시하지 않는다. |

## 현 저장소 대조

- [계정 콘솔 계획](../docs/20-codex-account-console-plan.md)은 이미 G0를 NO-GO로 두고 `stdio`, Codex 관리형 로그인, Keychain 실패 시 fail-closed, 앱 단독 설치, 보안 경계와 clean Mac QA를 요구한다. 이번 재확인은 그 판단을 뒤집을 근거를 찾지 못했다. 위 공식 블로그가 제시하는 **제품 통합 방향**과 문서의 **현재 출고 제한**을 둘 다 유지한다.
- `Package.swift`의 `CirclrCodex`는 별도 target이고 `CirclrApp` 의존성이 아니다. `Sources/CirclrCodex/CodexOfflineSessionCoordinator.swift`는 credential-free 고정 JSONL child fixture용이며 실제 App Server 세션이라고 명시하지 않는다. `Sources/CirclrApp/**`에서 `CirclrCodex` 참조도 발견되지 않았다.
- [build225 AI QA](0.80-build225-ai.md)는 앱 소유 turn의 Unix socket, MIDI apply/Undo/PCM bounce 및 STOP을 검증했지만 Codex 계정·모델·MCP helper는 연결하지 않았다. 앱 내 AI 콘솔과 공개 릴리스의 G0를 통과했다는 근거가 아니다.

## 다음 안전한 구현 단위

1. **G0와 무관하게 DAW 작업 권한을 완성한다.** 앱이 먼저 선택한 문서와 내보내기 목적지에 한정해 trusted `save`/`export`의 typed grant, staged write, revision/STOP/만료 직전 검사, 실패 복구를 구현한다. 모델이 넘긴 임의 파일 경로를 권한으로 사용하지 않는다. 격리된 fixture에서 편집→Undo→bounce→저장·재열기·export와 STOP 경합을 실제 파일로 검증한다. 이것은 AI 실행기가 선택되기 전에도 필요한 음악 작업 계약이다.
2. **런타임 연결은 별도 실험으로 유지한다.** 지원 상태가 바뀌거나 명시적 production 지원 근거가 생긴 뒤, 정확한 CLI 릴리스와 schema를 고정하고 signed arm64/x86_64 앱에서 자식 실행, App Server managed 로그인, 독립 `CODEX_HOME`/Keychain, MCP helper 신원과 turn별 capability, 조직 정책, CLI 변경 호환성을 검증한다. 실제 사용자 계정으로 한 turn의 음악 편집·STOP·승인·재시작을 확인하기 전에는 `CirclrApp`에 `CirclrCodex`를 의존시켜 계정 UI를 공개하지 않는다.
3. **G0 재개 조건을 명시한다.** 공식 App Server production 지원 문구 또는 OpenAI의 해당 통합에 대한 명시적 지원 확인, 선택 릴리스의 재배포 조건 검증, clean Mac에서 앱 단독 로그인·이탈·오프라인·업데이트 복구, trusted MCP 경계와 제한된 모델 도구 목록, 실제 계정 E2E 및 전체 DAW 회귀가 모두 필요하다. 어느 한 항목의 통과를 전체 GO로 승격하지 않는다.

이 문서는 공식 공개 자료와 로컬 정적 상태의 재평가다. 공식 자료에서 서명된 circlr 배포에 대한 개별 승인이나 모든 ChatGPT 플랜의 이용 자격을 확인하지 못했다. 그래서 현재 상태는 **불가능 판정**이 아니라 **출고 근거 부족에 따른 NO-GO**다.
