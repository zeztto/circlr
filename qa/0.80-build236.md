[계획](0.80-build236-plan.md)의 네 독립 slice를 같은 최종 소스에서 통합했다. 시스템 기본 입출력과 사용자의 프로젝트·설치 앱은 바꾸지 않는다. 구형 Scarlett은 정상 동작을 합격 조건으로 삼지 않고, 격리 QA 앱의 재생에는 앱 전용 Mac 내장 출력을 선택한다.

- **AI 파일 작업:** 앱 소유 `circlr-trusted-mcp-helper`가 turn lease의 메서드 목록에 따라 `save`와 `export`를 노출한다. 현재 선택된 문서와 앱이 고른 WAV 목적지만 허용하고 모델이 보낸 파일 경로·socket·capability를 거절한다. 실제 child 11/11과 인접 trusted 테스트 35/35가 통과했다. [독립 보안 재검토](0.80-build236-security-review.md)는 이 변경의 구체적인 P0–P3를 찾지 못했다. 앱 안의 사용자 Codex 계정 대화나 실제 모델 turn은 검증하지 않았다.
- **MIDI 연주 시점:** CoreMIDI host ticks를 입력 callback 시 단조 시각으로 바꾸고, MainActor 지연과 녹음 종료 전에 받은 이벤트를 순서대로 회수한다. 파서 지연의 유한 fallback은 누락 가능성을 상태에 표시한다. 입력 source별 running status를 분리하고 분할 메시지의 첫 byte 시각을 보존한다. 실제 가상 MIDI packet과 deterministic 교차 source parser·Undo·재열기를 포함한 집중 테스트 25/25가 통과했다. CoreMIDI가 불완전한 가상 source packet을 callback 전에 걸러내므로 교차 분할 자체는 parser 단위에서 검증했다. 독립 DAW 재검토의 초기 P2/P3는 수정됐으나, 앱 실행 뒤 새로 연결한 물리 MIDI 장치의 자동 인식은 기존 P2로 남는다.
- **콘솔:** 사용자가 과거 로그를 읽으면 표시 목록을 고정하고 미확인 수와 `최신 로그` 복귀를 제공한다. 500행 절단 시 유지된 행의 좌표로 스크롤을 판단하고, 좁은 40pt 로그 높이와 휠·키보드 범위의 집중 상태 테스트 11/11이 통과했다. 독립 UI 재검토의 새 P0–P3는 없었다. 실제 VoiceOver·500행의 레이아웃 비용과 재생 중 FPS는 native 결과를 따로 판정한다.
- **Stem STOP:** 원자적 폴더 교체의 직전 검증·게이트를 `WAVExportCommitGate`에 넣고 `AppStore.stop()`과 연결했다. 게이트가 먼저 취소되면 기존 폴더 바이트가 남고, 게시가 먼저 시작되면 STOP이 교체 완료까지 기다린다. Stem 10 PASS/선택 fixture 1 skip, WAV gate 4 PASS이며 독립 DAW 리뷰에서 새 결함은 없었다. 저장 패널을 포함한 전체 GUI 경합 동선은 native 미검증이다.

최종 동일 소스의 `./scripts/swift-local.sh test --scratch-path .build/build236-integration-final`은 **1,296개 실행·15 skip·실패 0**으로 끝났다. 실제 trusted helper child 11개가 skip 없이 포함됐다. skip은 물리 CoreAudio·선택 입력·10분 영상·대형 stem·별도 helper 실행 경로 등의 opt-in fixture이고 통과로 계산하지 않는다. 로그 `/tmp/circlr-build236-swift-final.log` SHA-256은 `1609a8c18c7184e8514fd8f9850f2a4e05886cd631c722bc1958665dadb4307f`이다. Python MCP 서버 **47/47**, Python 프로젝트 MCP **39/39**, agent kit **9/9**도 통과했다. 각각의 로그는 `/tmp/circlr-build236-python-server.log` (`ed47ac19e66433ebfd3af87a37494c60e88cea90d17c88eedcd34aaba0a3a1a3`), `/tmp/circlr-build236-python-mcp.log` (`95098ce7a572c71cae46bb7db5b5314e0037ffe936fbea33b612418765f0e7fc`), `/tmp/circlr-build236-python-kit.log` (`707fdb8570e19490bd80197a4bfd18d632a0913bb67eb1330928b652a87f4b94`)에 남겼다.

`./scripts/build-app.sh`는 **0.80.0/build236** arm64 앱과 **7개 arm64 helper**를 만들었다. 앱과 helper 모두 `codesign --verify --deep --strict`를 통과했다. 주 실행 파일 SHA-256은 `1d584821bc6ebe296449f850b73a4bce3271d6e76f75483444e8d7d757b43e74`, 패키지 로그 `/tmp/circlr-build236-package.log` SHA-256은 `076f1248f4f1c01470c60b708f027ab7f10d3b3877a0be0f679c7b3f1435110c`다. 동봉 Demos **27/27파일·manifest 26/26**, Codex kit **26/26파일·manifest 25/25**, 권리 고지 2/2가 소스와 byte 일치한다. 패키지 후 icon builder가 생성한 tracked `Resources/Assets.car`는 HEAD 원본으로 되돌렸고, 최종 패키지 내부 카탈로그는 빌드 시 생성본을 유지한다.

격리된 build236 앱의 700×900pt/40pt 콘솔·500행 조건에서 Play 중 read-only MCP 로그 **100건/15.28초**를 보낼 때 `playback.frameCount`는 **2170→2336(+166, 약 10.9 count/s)**이었다. 같은 조건에서 로그 입력이 없는 **8.03초**에는 **+415(약 51.7 count/s)**였다. 시계는 로그 유입 중에도 15.279초 진행했다. 이는 실제 compositor FPS 측정이 아니지만, 동일 앱 내부 프레임 카운트의 큰 하락이므로 native 성능 gate는 **FAIL**이다. 상세 화면·원시 자료·원본 정리는 [build236 native QA](0.80-build236-native.md)에 남긴다. 한영 README의 build236 화면은 이 실패 후보의 실제 미리보기이며 합격 증거가 아니다.

같은 QA 앱을 다시 실행해 500행을 채운 뒤 동일한 100건을 각각 약 **6.498건/s**로 보낸 A/B에서는 콘솔 펼침 **+164/15.388초≈10.66 count/s**, 접힘 **+812/15.390초≈52.76 count/s**였다. 재생 시계·출력 상태·프로젝트 revision은 양쪽 모두 유지됐다. 이는 펼친 로그 화면 갱신의 기여를 강하게 시사하지만, 특정 SwiftUI 코드만 원인으로 확정하거나 실제 화면 FPS로 해석하지 않는다. 원시 A/B와 두 번째 격리 앱 종료 기록도 [native QA](0.80-build236-native.md)에 있다.

실제 마이크 PCM/TCC·물리 청취, 긴 MP4와 한 곡 제작 동선, 사용자 Codex 계정 G0는 아직 열린다. 콘솔 프레임 회귀를 고친 새 빌드에서 같은 native 조건을 다시 검사한다. `v0.80.0` tag/GitHub Release는 만들지 않는다.
