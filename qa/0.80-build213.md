# 0.80.0 build213 · 앨범 stems와 렌더 경합 보강

상태: **개발 빌드, 정식 0.80 출고 승인 아님** · 2026-09-24. 기준 브랜치는 `release/0.80.0`이다. 구형 Scarlett의 정상 출력은 합격 조건이 아니다. 앱 전용 Mac 내장 출력의 재생·안전 복구를 별도 판정하고 시스템 기본 출력은 변경하지 않는다.

## build212 검토 결과와 수정

- [build212](0.80-build212.md)의 순차 stems는 한 composition의 16트랙 오프라인 렌더와 실제 앱의 2트랙 렌더를 완료했지만, 통합 리뷰에서 다중 곡 앨범은 첫 편곡안만 출력하는 P1을 발견했다. stems 계획을 일반 WAV와 같은 `AlbumCompiler.executionPlan`으로 통일했다. 두 composition fixture에서 첫 곡은 무음, 둘째 곡은 MIDI가 있는 조건으로 전체 mix·stem·일반 WAV의 동일한 전체 frame 수와 후반 nonzero 신호를 비교했다. 기존 16트랙 장시간 렌더는 수정 전 한 곡 증거이며 재실행하지 않았다.
- 목록 없는 legacy stem manifest는 어떤 `-6hex.wav`가 사용자 추가 파일인지 판별할 수 없었다. 이런 폴더의 교체를 거부하고 새 폴더를 사용하도록 했으며, `personal-ABCDEF.wav` 보존을 회귀 검사했다. 새 형식은 명시된 `stemFiles` 목록으로 대상 파일을 검증한다.
- 재생 준비 PCM 및 완료된 agent worker 결과를 새 stem 렌더 전에 해제한다. 일반 재생 준비, stems, loop 전환, agent render/open의 소유 작업을 분리해 취소된 worker가 실제 종료하기 전 새 대형 PCM을 할당하지 않게 했다. GUI stems는 Save 패널 전후에 재생·준비·agent 작업 상태를 확인하며 busy일 때 시작하지 않는다. 데모 QA 복사본의 정리도 loop worker 종료를 기다린다. synthetic gate 테스트는 Stop 뒤 loop worker 추적과 다음 prepare의 loop·production 대기를 검사한다. 일반 재생 준비가 정지된 기존 mix를 새 결과 할당 때까지 보유하는 기존 메모리 정책은 별도 잔여 위험이다.
- 축소 원형의 IN/OUT 표시·hit·AX와 내부 Codex offline coordinator 변경은 [build212 실제 앱 QA](0.80-build212-native.md)와 소스/집중 테스트에 근거한다. build212 화면 결과를 build213 native PASS로 소급하지 않는다. 계정 로그인·앱 안 AI 대화는 공식 production 경로 G0가 열려 있어 공개 기능이 아니다.
