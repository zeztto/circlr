# 0.80.0 build210 · 영상 프레임 수와 내부 Codex 연결 준비

상태: **개발 빌드, 정식 0.80 출고 승인 아님** · 2026-09-24. 대상은 `release/0.80.0`의 0.80.0/build210이다. 구형 Scarlett의 정상 출력은 합격 조건이 아니며, 앱 전용 내장 출력과 실패 후 안전한 복구를 기준으로 한다.

## 변경과 검증

- 유한 PCM 또는 예약된 loop exit의 오디오 종료 시각에 도착한 영상 프레임은 `AVAssetWriter.endSession` 경계에서 실제 MP4에 기록되지 않는다. 이제 이 프레임을 저장 프레임 수에 넣지 않고, 중간 프레임 누락으로도 세지 않는다. 두 경계의 독립 decode 회귀를 포함한 `CanvasMovieWriterTests` 9개가 통과했다. [원인·테스트](0.80-build210-movie-count.md).
- 앱 실행 파일과 분리된 `CirclrCodex`에서 `account/read`, `model/list`, 읽기 전용 `thread/start`, 명시적 `turn/start` 모델을 같은 RPC ID 공간에 넣었다. 선택적 자식 환경 설정은 허용 목록만 전달하고 canonical 작업 디렉터리를 요구한다. `OPENAI_API_KEY`는 자식 환경에 전달하지 않는다. 독립 검토에서 실제 CLI schema의 optional `account`·`nextCursor`를 필수로 읽는 P2를 찾아 수정했다. 최종 `CodexProtocolTests` **37/37** 통과. 앱의 계정 콘솔이나 음악 도구는 아직 연결하지 않았다. [앱 밖 계정 smoke](0.80-build210-codex-smoke.md).
- 전체 Swift **1131 tests, 11 skipped, 0 failures**. 이 실행은 위 optional schema 최종 수정 전에 시작했으므로 Codex 파서는 별도 최종 집중 테스트로 재컴파일했다. 전체 로그 SHA-256 `0b35dff3d988566e27dc59120c79437d9f0345f0105f8b3adb7e5145c9fddf56`, 최종 Codex 로그 SHA-256 `580485562d821731ac13c1b579798f532b12eda472d197d4a88465743cac307e`. MCP Python **39/39**, agent kit Python **9/9**, `git diff --check` 통과.
- 동일 화면 코드의 build209 격리 앱에서 700/900/1280pt toolbar, 선택 케이블/포트 AX, 재생 중 선택 끝점 라벨과 Stop 복원을 관찰했다. hover 단독과 같은 섹션에서의 통제된 zoom 복원은 미검증이다. 이는 build210 실행 화면의 증거가 아니다. [UI 매트릭스](0.80-build210-ui-matrix.md).

## 패키지와 남은 경계

`scripts/build-app.sh`로 arm64 앱과 다섯 helper를 패키징했고 `codesign --verify --deep --strict`가 통과했다. 앱 버전은 0.80.0/build**210**, 실행 파일 SHA-256 `2172559a9e4725cddbba5ca7721d25305e6b5e8ed99b1b0990fa64998613b5f2`. 동봉 데모 `manifest.json` SHA-256은 소스와 동일한 `928cc86b1f451f51878235ffecccb079d956593155743159e91315df4999c393`. 패키지 로그 SHA-256 `ee17f1ef09183a74c1fc5bcfec76823a68a5bcd716080f2c1fb8dc368027e056`.

격리된 **build210 실제 앱**에서 `f0r h3r`를 앱 전용 Mac Studio 스피커로 재생·녹화했다. 7.438초 MP4의 저장 알림 **223프레임**과 독립 AVFoundation decoder의 **223프레임**이 일치했다. 중복 PTS·2프레임 초과 공백은 없었고 AAC 별도 해독은 48kHz stereo PCM의 시작·중간·끝 신호를 확인했다. 같은 앱에서 가로 1440×900·세로 720×900 전체 창 화면을 촬영해 당시 한영 README에 넣었다. 시스템 기본 Scarlett은 전후 동일하고 QA 앱/helper는 종료했다. [native 영상·화면 QA](0.80-build210-native-movie.md) · [스크린샷 출처](../docs/images/README.md).

단, 먼저 저장된 **37.299초 MP4**에서는 UI **1118프레임**과 독립 decoder **1117프레임**으로 불일치가 남았다. 따라서 build210의 프레임 수 수정은 **짧은 실앱 시나리오만 통과**했고 일반 종료 문제는 미해결이다. [첫 녹화의 분리된 증거](0.80-build210-native-movie.md).

물리 청취, hover와 동일 섹션 통제 zoom 복원, 완전한 GUI 제작 동선, 1080p·장시간 영상, 앱 안의 실제 Codex 계정 대화와 AI 음악 편집은 별도 gate다. 공식 [App Server 문서](https://learn.chatgpt.com/docs/app-server)의 production 지원 경계도 유지한다. `v0.80.0` tag·GitHub Release는 만들지 않는다.
