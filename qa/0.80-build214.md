## 수정과 독립 리뷰

- 곡 궤도 원호와 위성 라벨에 실행 순번을 연결하고, 선택·hover·키보드 선택·VoiceOver에 구간 시작·끝을 표시한다. 반복 `A→B→A`에서는 곡의 로컬 재생 시각이 속한 한 구간만 강조한다. 짧은 제목의 시간 배지는 subtitle 폭을 측정해 잘림을 줄이고 감상 모드에서는 순번·라벨을 숨긴다. 독립 UI 리뷰에서 처음 발견한 반복 구간 동시 강조와 시간 끝 잘림 P2를 수정 후 다시 확인해 코드 수준 새 P1/P2가 없었다. 실제 작은 창의 충돌·판독성은 native QA에서 판단한다.
- 일반 WAV 저장을 MainActor에서 분리해 16,384-frame 단위로 기록하고, 숨겨진 형제 파일이 완성된 뒤에만 게시한다. `WAVExportCommitGate`가 Stop과 게시를 직렬화하므로 Stop 후 늦은 파일 교체를 막는다. 중복 GUI 내보내기는 시작 전·Save 패널 후·내부 helper에서 차단한다.
- Stop→음악 수정→Play의 cache miss는 이전 렌더·loop·production 작업을 기다리고 store/playback PCM 참조를 해제한다. 출력 helper가 CAF 준비 중 이전 PCM을 잡은 경우에는 직렬 queue barrier까지 기다린 뒤 새 렌더를 시작한다. 독립 오디오 리뷰가 최초 P2 두 건과 후속 race P2 두 건을 지적했고, 최종 수정분에서 새 고신뢰 P1/P2는 찾지 못했다. 대형 곡 RSS 실측과 실제 GUI 반복은 별도 QA다.
- UI·오디오를 합친 최종 diff의 별도 읽기 전용 통합 리뷰에서도 새로운 고신뢰 P1/P2는 발견되지 않았다. 이 판정은 실제 앱 조작·청취·대형 곡 성능의 합격을 뜻하지 않는다.

## 남은 출고 gate

격리된 최종 서명 앱의 [native QA](0.80-build214-native.md)는 1440×900·720×900 창에서 일곱 섹션의 순번·라벨, 짧은 Lift 선택 시 `03 · 1:04.0–1:20.0 · 길이 0:16.0`, 감상 모드의 텍스트 숨김과 복귀를 확인했다. 앱에서만 Mac Studio 스피커를 선택해 재생 시계가 00:24.4까지 진행하고 Stop 후 00:00.0으로 돌아오는 것을 확인했다. GUI WAV는 48 kHz·stereo·24-bit, 197.002초로 게시되었고 독립 PCM 분석에서 신호가 0이 아니었다. 원본 앱·데모 해시와 macOS 기본 Scarlett UID는 불변이며 QA 앱·helper 잔류 프로세스는 없었다. 이는 출력 시작 상태와 파일 형식의 증거이지 물리 청취나 음질 판정은 아니다.

CUA가 포인터 이동만 하는 동작을 제공하지 않아 순수 hover 전환은 **PARTIAL**이다. GUI WAV 중 Stop 경합은 deterministic 테스트로 확인했으나 실제 장시간 GUI 조작 중의 체감 응답성은 미확인이다. 물리 청취, 빈 곡부터 제작·저장·재열기 전수, 다중 곡·대형 stems의 최종 앱 반복, 큰 곡의 메모리 사용량, 1080p/10분 녹화, AI 계정 대화의 공식 production 경로는 여전히 열린 상태다. `v0.80.0` tag·GitHub Release는 만들지 않는다.
