# 0.80.0 build212 · 순차 stem 출력과 축소 포트 검증본

상태: **수정 전 개발 검증본, 정식 0.80 출고 승인 아님** · 2026-09-24. 기준 브랜치는 `release/0.80.0`이다. 통합 리뷰에서 stems의 다중 곡 누락(P1), 재생 후 PCM 잔류(P2), 목록 없는 기존 stem 폴더의 사용자 WAV 손실 가능성(P2)을 찾았다. 이 문서의 통과 항목은 해당 결함의 수정이나 최종 제품 판정을 뜻하지 않는다. 후속 수정은 [build213](0.80-build213.md)에 분리해 기록한다. 구형 Scarlett의 정상 출력은 합격 조건이 아니며 앱 전용 Mac 내장 출력과 실패 후 안전 복구를 기준으로 한다. 시스템 기본 출력은 변경하지 않는다.

## 변경과 검토

- 16트랙 곡의 전체 stems가 `PreparedAudio.stems` 메모리 사전 한도에서 막힌 build211 GUI 결함을 재현했다. 새 export는 원래 mix와 sidechain 참조를 유지하면서 stem 하나씩 숨김 sibling 폴더에 WAV로 기록한 뒤 완전한 세트만 원자적으로 게시한다. 취소·clipping·파일 쓰기 실패는 기존 대상 폴더를 보존한다. 새 형식 대상의 symlink·일부 추가 파일 및 트랙 이름·ID의 경로 문자와 대소문자·Unicode 충돌은 제한했다. 다만 목록 없는 legacy 폴더에 stem 파일명 형식의 개인 WAV를 추가한 경우 교체 시 삭제될 수 있어 수정 중이다.
- 일반 재생 준비/WAV와 stems가 서로 교체되거나 Stop 직후 재시작할 때 이전 render task·worker의 종료를 기다린 뒤 새 PCM을 할당한다. 그러나 재생용으로 보유한 준비 PCM은 정지 뒤에도 남아 새 stem 렌더와 겹칠 수 있다. 실제 GUI의 취소·재시작 경합과 이 메모리 경계는 미통과다.
- 45pt 이하 축소 서클에서 hover·선택한 IN/OUT 포트를 다시 표시·hit·AX 공통 목록에 올린다. 읽기 라벨이 기본 anchor를 덮으면 같은 측면의 대각 anchor로 옮기고, 선택 뒤 기존 정밀 배율로 확대한다. 원래 연결 anchor와 큰 반경의 8방향 포트는 유지한다. 독립 검토에서 발견한 라벨 충돌을 수정한 뒤 새 P1/P2는 발견되지 않았다.
- 앱에 연결하지 않은 내부 `CirclrCodex`에는 가짜 JSONL 자식과 host/reducer를 잇는 offline coordinator를 추가했다. 승인 요청은 거절하고 모델 목록 완료 전 thread를 열지 않으며, 취소 뒤 늦은 텍스트·출력 폭주·재시작 뒤 이전 이벤트를 제한한다. 두 차례 독립 검토의 큐 한도/취소/종료 알림 결함을 수정했다. 실제 계정 로그인·앱 안의 AI 대화·배포 runtime 지원은 **미구현/NO-GO**다.
