사용자는 버전 번호보다 실제 작동과 UI 품질을 우선한다. "버그 0개"를 증명할 수는 없으므로 재현 가능한 핵심 작업의 성공, 실패/취소 경계, 미검증 위험을 각각 기록한다. 시스템 기본 `Scarlett 6i6 USB`는 구형·세대/호환성 미확인이다. QA 앱에서만 사용 가능한 입출력을 선택하며 사용자 프로젝트·설치 앱·시스템 기본 장치를 변경하지 않는다. 현재 debug 격리 조회는 약 0.5초에 `CalDigit Thunderbolt 3 Audio`와 Scarlett 입력을 열거했고 Mac Studio 내장 마이크는 없었다. 한 드라이버가 목록 조회에서 멈추는 환경은 미검증이다. 5초 격리 timeout 후 재조회할 수 있지만 정상 장치만 부분 표시하는 기능은 이번 범위에 포함하지 않는다. 사용자 부재 중에는 물리 청취를 성공으로 표시하지 않는다.

**2026-09-25 출고 결정:** 사용자는 남은 작업이 핵심 DAW·AI 동선의 필수 결함이 아니라면 0.80을 닫고 다음 버전으로 넘기라고 지시했다. build242의 10분 MP4 한 지점 70.0ms는 사전 상한 66.67ms보다 3.33ms 길지만, 전체 평균29.983fps·AAC 연속·앱의 dropped/skipped 카운터 0·메모리 기준은 통과했다. 앱 제출 17,990프레임과 독립 decoded 17,989프레임의 종료 경계 차이는 [원본 QA](0.80-build242-performance.md)에 남긴다. 이를 낮은 우선순위의 영상 품질 결함으로 수용한다. **U80-02와 Q80-07의 원 판정 FAIL, 물리 청취·compositor FPS·IME 등 OPEN은 유지**하고 0.90의 별도 gate로 이월한다. 테스트 결과를 PASS로 바꾸거나 기기 호환성을 보증하지 않는다. 외부 Codex→MCP 실제 편집과 핵심 DAW 제작 동선의 제한된 native 증거는 위 표와 원본 QA에 남긴다.

## 구현 순서와 병렬 계약

1. build237은 UI 성능 수정의 원격 개발 체크포인트로 고정했다. 각 후속 build는 `CFBundleVersion`을 올리고 같은 소스의 테스트/QA를 닫은 뒤 커밋한다.
2. 입력 worker와 세로 UI는 파일 소유가 겹치지 않아 병렬 구현한다. 앱 입력 선택 UI는 worker의 선택/오류 계약이 확정된 뒤 별도 slice로 연결한다. QA/리뷰 에이전트는 소스에 쓰지 않는다.
3. AI 실제 모델 E2E는 격리 앱·전용 socket·임시 프로젝트에서 수행하고 권한/토큰을 문서·로그·모델 입력에 복사하지 않는다. 앱 내 계정 대화는 0.80 출고 계약 밖의 후속 범위다.
4. DAW end-to-end와 장시간 영상은 소스가 고정된 최종 후보에서 재측정한다. 물리 입력·청취에 사용자 조작이 꼭 필요하면 그때 하나의 검수 요청으로 모은다. 그 전까지 자동·native 독립 작업을 계속한다.

개발은 `release/0.80.0`에서 진행했고 사용자 설치 앱은 건드리지 않았다. 정식 tag·Release는 위의 사용자 이월 결정과 [build242 검증](0.80-build242.md)에 근거해 발행한다. 구현 소유자는 공유 worktree의 다른 변경을 되돌리지 않는다. [build237 통합 QA](0.80-build237.md)는 준비된 기준선이며 최종 후보의 검증을 대체하지 않는다.
