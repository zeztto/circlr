# 0.10 궤도 타임라인 검증

날짜: 2026-09-07. 결과: 로컬 release 0.10.0/build11. 순차 owner는 native integration → QA → code/security review → development-lead였다. 동시 agent 슬롯이 없어 별도 검토 agent를 실행하지 않았다. untracked workspace의 변경 파일 전체와 실제 실행 증거를 대조했으며 commit/외부 배포는 하지 않았다.

## 목표와 수용 결과

| 요구 | 구현 및 증거 |

## 자동 검증

- Swift **80/80**: `generated/0.10-tests-final.log`. Core·Audio·graph·album·geometry·agent 회귀를 포함한다.
- Python **3/3**: `generated/0.10-python-tests.log`. 실제 stdio 초기화·도구 목록·입력 거부를 포함한다.
- 최종 바이너리의 native 제작: `generated/0.10-final/0.9-mcp-native.json`. 파일명은 기존 smoke runner의 이름을 유지하며 내부 runtime.version은 0.10.0이다. MIDI 생성, stale revision, 원자적 batch, 동일 요청 재전송, 취소/중간 편집 후 파일 미생성, 바운스·WAV·save를 검증했다.
- 최종 바이너리의 새 명령: `generated/0.10-final/orbit-mcp.json`. `set_clip`, `reorder_section`, 소스 `startBeat`와 실제 orbit.anchor, 정확한 Undo를 최소화 상태에서 확인했다.
- 101.310354초의 9,725,794개 interleaved sample 비교: 최대 차이 **24-bit PCM 1단계**, RMS 2.15626e−8. `generated/0.10-final/bounce-audio-comparison.json`. 실제 렌더와 수치 분석이며 주관적 청음 평가를 완료했다는 주장은 하지 않는다.

## 실제 화면 조작

최종 실행 파일에서 MIDI를 64→65개로 늘리고, 입력 노트를 5박/0.25박에서 길이 3박으로 조절했다. 원호 몸체를 끌어 9.75박으로 이동하고 pitch 60→58로 바꿨다. 한 번의 Undo 후 전체 lane이 길이 조절 직후 데이터와 정확히 같았다. `generated/0.10-final/midi-before.json`, `midi-resized.json`, `midi-moved.json`, `midi-undo.json`에 있다.

최종 오디오 끝 손잡이로 18.552초를 약 13.879초로 trim하고 Undo했다. `generated/0.10-final/audio-trim.json`에 실제 clip이 기록됐다. 앞선 동일 편집 구현 검증에서는 시작 손잡이도 4.633초로 옮겨 길이와 함께 갱신됐으며, 한 번의 Undo로 모든 lane을 정확히 복원했다 (`generated/0.10-audio-start-trim.json`, `0.10-audio-undo.json`). 파형 표시 ×23은 실제 조용한 소스의 화면 배율이며 오디오 gain을 바꾸지 않는다.

섹션 전체 보기에서 작은 MIDI 소스를 선택하고 시작 손잡이를 3시 방향으로 옮겼다. 실제 `startBeat=8`, `anchor=4.137931034482759`초가 됐으며 Undo가 원본 그래프를 정확히 복원했다. `generated/0.10-source-before.json`, `0.10-source-shifted.json`, `0.10-source-undo.json`에 있다.

최종 휠 줌은 215.648148→306.019289→215.648148로 왕복했고 음악 revision은 유지됐다. 실제 저장 파일과 native 재열기의 전체 MIDI lane이 정확히 같았다. 닫기 버튼을 눌러도 socket이 응답했고 창은 `minimized=true, visible=false`였다. `generated/0.10-final/wheel-*.json`, `reopened.json`, `closed-window.json`으로 확인한다.

## 검토에서 수정한 문제

- 균등한 마디 tick을 실제 초 기준으로 바꾸고 소스의 부분 마디와 부모 변박도 보존했다.
- 그룹 외곽 여백 때문에 상위 궤도가 이동하던 문제를 음악 배치 반경과 시각적 외곽의 분리로 수정했다.
- 작은 서클에서 보이지 않는 연결 포트가 선택을 가로채던 문제를 표시 배율과 hit-test의 일치로 수정했다.
- 작은 자식 선택이 다른 곡·섹션까지 다시 표시하던 문제를 충분히 확대된 가장 가까운 부모 기준으로 수정했다.
- 조용한 파형의 표시 배율과 상세 편집 공간을 개선했고 editor 위의 부모 궤도선을 제거했다.
- 마지막 섹션 이동으로 들리는 전환이 사라지는 경우는 거부하며, 분기 경로도 조용히 변경하지 않는다.
- MCP trim이 원본 파일 범위를 넘으면 전체 batch를 거부한다. 기존 socket 권한·peer UID·8 MiB 경계, revision·Undo·job 취소 경계와 shell/TCP 미노출은 유지한다.

## 보존과 배포

사용자가 QA 앱에 남긴 미저장 r8은 `generated/0.10-preserved-user-r8.circlr`에 별도로 보존했다. 원본 `music/f0r-h3r/v1`과 production 복구 데이터는 덮어쓰지 않았다. 실험은 QA 사본에서 수행했다. Splice 추가 구매는 없었다.

Release/QA/배포 앱의 Mach-O UUID 일치, 서명, source hash, 테스트 결과는 `generated/0.10-release-evidence.json`에 기록했다. `dist/써클러.app`을 0.10.0/build11로 구성했고 이전 0.9.0을 `dist/archive/써클러-0.9.0.app`에 보관했다.

## 남은 제품 경계

현재 engine은 prepared PCM이다. 연속 realtime graph 변경, plugin PDC·crash isolation, 모든 외부 MIDI/오디오 장치 및 AU 호환성을 완료했다고 주장하지 않는다. text/image/video 세계관 참조는 후속 제품 범위다. 현재 목표였던 앨범 계층·음악 서클·같은 캔버스의 상세 편집과 궤도 시간은 구현·검증했다. 외부 LLM 연결은 사용자가 선택하며 앱 자체에 모델이나 계정을 자동 설치하지 않는다.
