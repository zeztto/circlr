독립 리뷰는 첫 10분 MP4의 SHA `aa8804f92d73a5be6428d22135001ea06ff81374871dc60035324edd243bc0f1`와 수정본의 SHA `edee62c4648ad049b58d764258093120b8bd7dfddf0c4a1c52855013f6d2d0f1`, 두 `inspection.json`의 주요 수치를 원본 파일과 대조했다. 장시간 실행을 중복하지 않았고 제품 소스는 수정하지 않았다.

| 발견 | 조치·검증 |
| --- | --- |
| 인접 프레임이 서로 다른지만 확인하면 영상 내용이 PTS 사이에서 교환된 경우를 놓친다. | opt-in 테스트에 15-bit 카운터와 `PTS×30` 대조를 넣었다. 2초 전체 60/60 mismatch0 통과. 별도 `qa/inspect-movie-soak-counter.swift`로 보존된 10분 PASS MP4 전체 18,000개 mismatch0, 첫 FAIL MP4의 존재하는 17,997개 mismatch0을 확인했다. 새 검사를 포함한 XCTest 10분 재실행은 하지 않았다. |
| AI 경로 감사가 같은 작업에서 이미 수정한 계획 문서를 여전히 낡았다고 서술했다. | `qa/0.80-build231-ai-audit.md`를 감사 시작 시점과 최종 수정 상태로 구분했다. 내부 trusted save/export 구현과 앱 사용자 대화 미연결 경계는 유지했다. |
| 영상 감사가 timing JSON에도 SHA가 있다고 읽히게 했다. | timing JSON에는 해시가 없음을 명시했다. audio JSON과 별도 `shasum -a 256`, 새 counter JSON의 실제 파일 SHA만 일치한다고 기록했다. |

변경 후 `CanvasMovieWriterTests` **12건 중 11 pass·opt-in 1 skip·실패0**, opt-in **2초 60/60·counter mismatch0**, 120ms 강제 지연 2초의 **writer pass/scheduler fail·counter mismatch0**, 독립 10분 counter 판독 **18,000/18,000 mismatch0**, Markdown 로컬 링크 **누락0**, `git diff --check` 통과. 테스트와 문서만 바꿔 앱 build230 및 기존 스크린샷은 그대로다. 장치 없는 writer의 10분 결과는 통과했지만 실제 AppKit 캡처·청취·Scarlett 호환성·0.80 릴리스는 여전히 열린다.

최종 read-only 재검토에서 위 세 발견은 해결됐고 새 차단 결함은 찾지 못했다. 카운터 검사를 추가한 **10분 XCTest 자체는 재실행하지 않았으며**, 보존된 동일 SHA의 10분 MP4를 독립 판독한 증거를 사용했다.
