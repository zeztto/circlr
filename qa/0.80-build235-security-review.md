# 0.80 build235 · AgentSocket 독립 보안 검토

```text
TEMPLATE_VERSION: security-review-v1
SCOPE: AgentSocket.swift, AgentSocketFairnessTests.swift, TrustedAgentIngress 계약
VERDICT: 수정 후 새 P0–P3 미발견; 계정 콘솔 G0 NO-GO는 별개
```

첫 리뷰는 느린 연결을 비차단 처리한 뒤 **완료 요청의 FD·Data가 32개 미완료 연결 상한에서 빠지는 P1**을 찾았다. 같은 UID 클라이언트가 정상 형식의 요청을 계속 보내면 MainActor 대기 응답이 무한정 늘 수 있었다. 해당 구현은 최종 변경으로 대체했고, 미완료+완료 요청 합계 32개, 집계 버퍼 32MiB, 응답 8MiB, 수락 요청 15초 기한을 적용했다.

독립 재검토는 UID·trusted capability/lease, STOP 직후 socket path 해제, 이미 수락된 요청의 stale 응답, writer 중 기한 만료 시 단일 FD close, 요청/응답 budget 회수를 소스에서 확인했다. 실제 Unix socket 전용 회귀 7/7은 단일 느린 연결, 64개 완료 요청 flood의 32개 수락, STOP·기한·oversized reply·집계 buffer를 검사했다. 최종 재검토에서 구체적인 새 P0–P3은 발견되지 않았다.

남은 위험은 동일 UID가 32개 idle 연결을 3초 간격으로 반복 점유하면 정상 요청을 거절시킬 수 있다는 제한된 로컬 DoS다. 8MiB 응답을 받지 않는 peer에게 쓰는 동안 15초 기한이 만료되는 조합은 소스상 shutdown/단일 close로 설계했지만 직접적인 socket 테스트가 없다. 공개 사용자 계정 대화는 [공식 G0](../docs/20-codex-account-console-plan.md)가 여전히 NO-GO이며, 이번 오프라인 경계 검증으로 출시 상태가 바뀌지 않는다.
