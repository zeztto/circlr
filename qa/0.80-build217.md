build216 격리 앱의 [Open 패널 재현](0.80-open-panel-repro.md)에서 행 선택이 성립하지 않은 채 Open을 누르면 `manifest.json` 누락 오류가 발생했다. `manifest.json` 파일 자체를 선택해도 별도 generic 오류가 났다. build217은 `ProjectStore.rootURL(for:)`에서 디렉터리와 해당 파일을 구분하고, GUI와 agent open이 정규화된 프로젝트 루트를 사용하도록 했다. 없는 manifest·관계없는 파일은 무엇을 선택해야 하는지 설명한다. `DemoCopyLease.retainIfManaged`에도 정규화된 루트를 전달한다.

`swift test --filter 'CoreTests/testPackageRoundtripPreservesAssetBytesAndRejectsEscape'`의 첫 실행은 test URL에 붙는 디렉터리 `/` 표현 때문에 assertion이 실패했다. path 동등성으로 고쳐 같은 focused test가 통과했다. 최종 `swift test`는 **1,184개 중 14개 skip, 실패 0, 종료 코드 0**이었다. skip에는 환경변수/실기기 helper가 필요한 테스트가 포함된다. 첫 독립 읽기 전용 코드 리뷰에서 Open diff의 고신뢰 회귀 발견은 없었고 `git diff --check`도 통과했다. **후속 저장 보안 리뷰에서는 일반 폴더에 유효한 manifest와 개인 파일이 함께 있을 때 덮어쓰기가 개인 파일을 삭제할 위험, FIFO manifest 읽기가 멈출 위험을 발견했다.** 따라서 build217은 출고 후보에서 제외하며 build218에서 수정·재검증한다. Python MCP/agent kit 계약은 바꾸지 않았으므로 build216의 이전 검증을 새 실행 결과로 재기록하지 않는다.

`./scripts/build-app.sh`가 0.80.0/build217 arm64 앱과 오디오 helper 5개 및 25파일 agent kit을 패키징했다. 원본 `dist/써클러.app`에 대한 `codesign --verify --deep --strict`는 통과했고 `CFBundleVersion=217`을 확인했다. 빌드 중 기존 `PlaybackFollowCameraCurve` Sendable 경고가 출력됐지만 컴파일·패키징은 성공했다. 이 경고는 이번 수정의 실행 실패 근거가 아니며 후속 Swift 동시성 정리에서 다룬다.

[실제 build217 앱 QA](0.80-build217-native.md)에서는 무선택 Open이 구체적인 앱 안내로 끝났고, `manifest.json` 파일 선택→저장→`.circlr` 폴더 재열기가 성공했다. 저장 후 QA 사본의 미디어 6/6개 hash는 불변, 저장/재열기 7/7개 파일 hash는 일치하고 manifest의 asset checksum도 실제 파일과 같다. 동봉 원본 데모 7/7개와 시스템 기본 출력은 불변, 앱/helper 잔류 프로세스는 없었다. 가로 1440×900·세로 720×900 전체 창은 원본 JPEG를 크롭·크기 변경 없이 PNG로 변환해 [화면 출처](../docs/images/README.md)에 기록하고 한영 README에 반영했다. 세로 화면의 우측 위성 원 일부는 창 밖으로 이어지므로 전체 곡이 항상 완전히 들어오는 UX로 판정하지 않는다.

[별도 입력 조사](0.80-selected-input-investigation.md)는 CalDigit을 명시적으로 선택해 `AVCaptureSession.startRunning()`과 `AudioDeviceCreateIOProcID`를 10초 제한으로 시험했지만 둘 다 반환되지 않았다. callback/PCM/실제 take는 없고, 시스템 기본 Scarlett 입력·출력은 변하지 않았다. Focusrite 세대 지원표가 말하는 class-compliant 가능성과 이 Mac에서의 circlr 입력 성공은 서로 다른 사실이다. 선택 입력 녹음은 fail-closed 상태를 유지하고 [R90-07](../docs/releases/0.90.0.md)의 별도 native gate에 둔다.

이 결과는 지정된 Open 회귀가 수정됐다는 증거이며, 곡 전체 제작·물리 청취·녹음·장시간 영상·앱 내 Codex 계정 대화와 정식 0.80 출시를 증명하지 않는다. `v0.80.0` tag와 GitHub Release는 만들지 않는다.
