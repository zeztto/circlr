2026-09-24 KST. [build237 계획](0.80-build237-plan.md)의 조건으로 [build236 원시 native QA](0.80-build236-native.md)를 재현했다. 아래는 실행한 절차와 사전에 정한 판정 기준이다.

1. **후보 고정과 격리.** `dist/써클러.app`의 `CFBundleShortVersionString=0.80.0`, `CFBundleVersion=237`, arm64 본체·7개 보조 실행 파일, `codesign --verify --deep --strict`를 확인하고 본체·Resources·번들 데모 SHA-256을 기록한다. 새 경로 `.build/build237-native/써클러 build237 네이티브 검증.app`에만 복사하고 bundle ID를 `com.circlr.build237nativeqa`로 바꾸며 문서 유형/URL 등록을 제거한 뒤 ad-hoc 재서명한다. 원본/QA 서명과 Resources·helper·데모 byte equality를 다시 검사한다. 기존 QA 경로가 있으면 덮어쓰지 않는다. 설치 앱과 사용자 프로젝트는 실행·수정하지 않는다.
2. **앱·소켓 신원.** 격리 앱만 열어 번들 `f0r h3r` 데모를 로드한다. 요청 전에 `~/Library/Application Support/circlr-build237native-qa/Agent/selected.json`의 bundleID/runID/endpoint, 해당 socket type·owner·inode와 MCP `circlr_snapshot.runtime`의 bundleID/version/build/runID를 대조한다. `mcp/server.py`의 `EndpointResolver`를 **QA socket의 고정 경로**로 새로 만들고 한 측정 세션 동안 inode와 runID 고정을 검증한다. production `~/Library/Application Support/circlr/Agent/agent.sock`은 사용하지 않는다. projectID/revision/path/dirty·번들 데모 manifest 해시를 전후 비교한다.
3. **화면/콘솔 계약.** 실제 창을 **700×900pt**, 콘솔 로그를 **40pt**로 만들고 AX·전체 창 원본 캡처로 확인한다. `circlr_events.sequence`를 읽어 정확히 500이 되도록 미존재 jobID `00000000-0000-0000-0000-000000000000`의 **read-only `circlr_job` 실패 조회**를 순차 실행한다. 각 응답이 `jobID를 찾을 수 없습니다`이고 같은 projectID/revision인지 확인한다. 500→501 보관 경계에서 oldest ID만 앞으로 가고 자동 팔로우가 유지되는지, 휠 위 입력 중 새 로그가 쌓여 읽기 위치와 unread가 유지되는지, 700pt 폭·40pt 로그에서 `최신 로그` 버튼이 보이고 클릭/Return으로 최신 행 복귀하는지 AX·픽셀로 검사한다. 키보드 PageUp/Home과 VoiceOver는 실제 포커스/음성 조작을 검증한 경우에만 PASS로 적는다.
4. **출력 경계와 재생.** 시스템 기본 출력/입력을 변경하지 않는다. 현재 기본값이 `Scarlett 6i6 USB`인지 UI/`system_profiler`로 시작·종료에 읽어 기록한다. 외부 요인으로 기본값이 달라졌다면 변경하지 않고 환경 차이를 기록한다. QA 앱의 `출력 설정…`에서만 `Mac Studio 스피커`를 선택한다. Play 중 `snapshot.output.actualOutputDeviceName`, `output.phase=ready`, `output.transport.phase=playing`, UI 시계 진행과 앱 장치 라벨을 확인한다. 물리 청취·Scarlett 호환성은 판정하지 않는다. Stop 후 출력·transport `idle`, 시계 `00:00.0`을 확인한다.
5. **성능 동등 조건.** 동일 700×900pt·40pt·500행·QA 내장 출력에서 펼친 콘솔의 무입력 기준을 **8초 이상** 측정한다. 이후 콘솔 **펼침**과 **접힘** 조건마다 Stop→Play로 `접속 · DJ Intro` 시작점에 맞춘다. 출력 `ready/playing`에서 시작해 같은 미존재 jobID read-only 실패 조회 **각 100건**, 목표 **6.5건/초**로 단조 시계 기준 pacing한다. 각 구간의 실제 wall time/요청률, activity sequence 전후(+100), `view.elapsedSeconds`, `playback.frameCount`, `view.consoleOpen`, `snapshot.output`, section caption, projectID/revision/path/dirty를 원시 JSON으로 저장한다. **실제 처리율 6건/초 미만 또는 다른 섹션·장치/재생 상태가 끼면 해당 비교는 무효**로 재측정한다. 성능 PASS의 기본 수치 기준은 펼침 구간 `frameCount` 증가율 **40 count/s 이상**이면서 같은 세션 접힘 구간의 **80% 이상**, 시계 증가와 wall time 차이 **1초 이내**다. 이는 앱 내부 animation counter의 gate이며 실제 compositor FPS/영상 frame pacing 판정이 아니다. 값이 경계에 근접하면 1회 재현하고 두 측정 모두 보고한다.
6. **대표 이미지.** 최종 build237 QA 앱에서 데모 전체 곡 7섹션이 보이는 정지 화면을 **1440×900pt/2880×1800px**와 **720×900pt/1440×1800px** 전체 창으로 CUA 캡처한다. 원본 JPEG·동시 AX를 Git-ignored `qa/generated/r80-build237-native/`에 저장한다. crop·resize·합성 없이 decoded RGB를 PNG로 바꿔 `docs/images/circlr-song-build237.png`, `docs/images/circlr-song-portrait-build237.png`에 넣고 픽셀 동등성·원본/PNG SHA-256을 기록한다. **패키지 이전 캡처나 build236 이미지를 build237로 표시하지 않는다.**
7. **종료/불변.** QA 앱의 `⌘Q → 변경 버리기`로 종료하고 QA 앱/helper PID와 전용 socket이 0인지 확인한다. 원본·QA deep strict 서명, 원본 실행 파일·Resources·데모 SHA, 시스템 기본 Scarlett 출력/입력, QA 프로젝트 비저장 여부를 다시 확인한다. 원시 JSON/AX/원본 이미지와 SHA 목록을 Git-ignored evidence 폴더에 남긴다. 발견한 실패는 코드 수정 없이 개발 담당자에게 전달한다.
