현재 소스에서 확인한 독립 결함을 파일 소유권별로 나눈다. 사용자 프로젝트, 설치 앱, macOS 기본 입출력, 로그인 상태는 변경하지 않는다. 회귀는 격리 QA 경로만 사용한다.

| 소유 slice | 파일 경계 | 사용자 결과와 인수 증거 |
| --- | --- | --- |
| AI trusted file tools | `Tools/CirclrTrustedMCPHelper/main.swift`, `AgentSessionGateway.swift`, `TrustedMCPHelperSession.swift`, `TrustedAgentIngress.swift`, 전용 child 테스트 | app-owned helper가 lease가 허용한 `save`/`export`만 노출한다. 모델이 경로를 지정할 수 없고 앱이 고른 현재 문서·WAV 목적지만 쓴다. 실제 child의 MIDI 편집→저장·재열기→nonzero WAV, 미허가 도구 부재, STOP·문서 교체 뒤 게시 0건 |
| MIDI event time | `Sources/CirclrAudio/Playback.swift`의 MIDIInput, `Sources/CirclrApp/AppStore.swift`의 MIDI 수신·정지 순서, 전용 테스트 | CoreMIDI host timestamp를 연주 시점으로 보존하고 파서 지연으로 beat가 밀리지 않는다. 반복 경계 전 수신 이벤트를 정지 처리 전에 회수하고 경계 뒤 이벤트는 버린다. 0/future timestamp, 가상 MIDI, Undo·재열기를 검증 |
| 콘솔 로그 팔로우 | `AgentConsole.swift`, 전용 상태 테스트 | 사용자가 과거 로그를 읽는 동안 새 이벤트가 와도 화면이 점프하지 않는다. 바닥에서만 자동 팔로우하고 `최신 로그`·미확인 수·VoiceOver 경로로 복귀한다. 500건 절단과 좁은 창을 확인 |
| Stem STOP 게시 경계 | `AudioExport.swift`, `AppStore.swift`의 stem export/STOP 범위, 전용 테스트 | stage가 완성된 뒤에도 STOP이 먼저면 기존 stem 폴더를 보존한다. 게시가 먼저 시작되면 STOP은 원자 교체가 끝날 때까지 기다린다. WAV gate와 같은 cancellation/rename 계약을 실제 파일 hash로 검증 |

먼저 각 slice의 재현 테스트를 실패시키고 최소 코드를 수정한다. AppStore는 MIDI slice와 Stem slice가 겹치므로 MIDI 변경을 합친 뒤 Stem을 연결한다. 마지막에는 관련 Swift 필터→전체 Swift·Python MCP 회귀→`./scripts/build-app.sh`→arm64/helper·서명·kit/데모 hash→격리 native UI/재생 확인을 실행한다. 문서·한영 README·스크린샷은 같은 빌드 결과와 범위를 맞춘다. 독립 코드·보안·QA 검토 후 개발 브랜치에 커밋·푸시한다. 실제 입력 PCM·물리 청취·1080p 장시간 영상·앱 안의 Codex 계정 대화는 이 단위의 자동 PASS로 승격하지 않는다.

[공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)와 [명령 성숙도 표](https://learn.chatgpt.com/docs/developer-commands)는 현재 `codex app-server`를 실험 단계로 표시한다. 따라서 이번 AI 작업은 이미 앱이 소유하는 오프라인 helper의 음악 파일 경계를 완성하는 것이며 사용자 계정 대화의 출고 승인은 아니다.
