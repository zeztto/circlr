## G0와 문서 정합성

[공식 Developer commands](https://learn.chatgpt.com/docs/developer-commands)는 현재 `codex app-server`를 **Experimental**, `codex exec`를 **Stable 비대화형 명령**으로 분류한다. [공식 MCP server removal](https://learn.chatgpt.com/docs/mcp-server)은 App Server가 production workload에 지원되지 않는다고 재확인하면서 Codex의 외부 MCP client 지원은 유지한다고 설명한다. 따라서 [build226 G0 판단](0.80-build226-codex-g0.md)의 공개 앱 내 계정 대화 **NO-GO**는 뒤집을 근거가 없다. `codex exec`가 stable인 사실도 앱 단독 설치·사용자 계정 격리·대화 승인 UI·서명된 런타임 재배포를 증명하지 않는다. API key/Agents API 과금으로 무언중 전환하지 않는다.

감사 시작 당시 `docs/20-codex-account-console-plan.md`의 서두와 구현 표에는 trusted `save/export`가 아직 미구현이라고 적혀 있었다. build230의 `AgentRunFileGrant`, `ProjectStore` stage, `TrustedExportPublisher` 및 통합 테스트를 확인하고, 같은 QA 작업에서 **내부 계약은 구현, 사용자 호출자는 미연결**로 해당 계획 문서를 고쳤다. 이 수정은 사용자 앱의 native 파일 선택→trusted save/export UI가 시험됐다는 뜻은 아니다.

## 가장 가치 있는 다음 안전한 slice: 실제 모델이 쓰는 외부 MCP 수직 QA + 연결 UX

내부 계약 테스트를 더 늘리기 전에 **현재 사용자가 접근할 수 있는 유일한 모델 경로**를 build231 서명 QA 앱에서 검증한다. `circlr-studio`가 들어간 격리 Codex 프로젝트와 새 QA `.circlr` 사본을 쓰고, 실제 로그인된 모델에게 구체적인 음악 과업 하나를 준다. 예: 기존 Verse의 한 MIDI lane에 2마디 신스 응답구를 만들고, 원본 노트/섹션을 보존하며, 한 batch Undo 검토 뒤 재적용하고, 짧은 bounce·WAV·저장/재열기로 결과를 제출한다. 모델은 `snapshot → inspect → apply(expectedRevision) → inspect → bounce/job → export/job → save` 순서의 실제 MCP tool을 호출해야 한다. 성공 답변이나 tool-call 수만으로 합격시키지 않는다. 작성된 노트의 위치·pitch·역할, 변화한 대상과 불변 대상, 원본/최종 manifest, WAV 헤더·nonzero PCM, 앱 activity의 tool/job, 저장·재열기를 독립적으로 대조한다.

이 경로에 필요한 작업 파일은 `qa/verify-agent-journey.py`를 재사용하거나 **새** `qa/verify-codex-model-journey.py`로 모델 호출과 native 관측을 분리한 harness, `mcp/server.py` 및 `Resources/Codex/skills/circlr-studio/`의 작업 지침, `qa/0.80-build231-model-native.md`다. 실패가 UI 연결 혼동이나 작업 피드백 부족으로 드러날 때만 `Sources/CirclrApp/AgentConsole.swift`·`AgentWorkspace.swift`를 수정한다. 예를 들어 socket이 열렸다는 상태를 실제 MCP client 활동과 명확히 구별하고, 실제 request/job의 시작·실패·완료를 읽기 쉬운 로그로 표시한다. `Resources/Codex` 원본을 바꾸면 `scripts/build-agent-kit.py`로 manifest를 재생성하고 패키지 25개 파일의 hash와 서명을 검증한다. 원본 데모·사용자 프로젝트·시스템 오디오 기본 장치·현재 Codex 설정은 변경하지 않는다.

**인수 조건:** (1) 실제 모델 식별·로그인 경로와 사용한 Codex/MCP runtime 버전을 비밀 없이 기록한다. (2) 격리 QA 앱의 bundle ID/build/runID와 MCP 세션의 pinned endpoint가 일치한다. (3) 모델이 실제 tool을 호출하고 MIDI/효과 작업이 의도와 일치하는지 사람이 읽을 수 있는 전후 diff와 음악 데이터로 평가한다. (4) Undo 후 원복, 재적용 후 저장·재열기, 완료 job과 nonzero WAV를 확인한다. (5) stale revision·다른 run/socket·STOP/취소 뒤 늦은 쓰기 0건을 재현한다. 외부 MCP `cancel_job`은 **job만** 취소하고 이후 쓰기 권한은 남으므로, 이를 trusted AI STOP 성공이라고 주장하지 않는다. (6) 같은 최종 소스로 Swift/Python 전체 회귀, 실제 app/package signature, QA 원본 hash를 확인한다. 실제 스피커 청취와 음악적 발매 품질은 별도 QA다.

이 slice의 결과를 **"외부 Codex+MCP로 DAW 제작 가능"**이라는 범위에만 적용한다. 앱 안의 자연어 대화 완성을 표시하지 않는다. 사용자의 기존 로그인으로 무인 QA가 가능하면 바로 격리 검증하고, 새 로그인·승인 UI가 필요하면 그 단계만 남겨 코드·패키지·fixture 검증을 계속한다.

## 그다음 앱 내부 연결의 필수 기술 gate

제품의 최종 AI 경험에는 `CirclrApp`이 소유한 실제 Codex turn과 trusted ingress 사이에 **신원 확인된 helper**가 필요하다. `Tools/CirclrMCPTool/`(신규), `Package.swift`, `scripts/package-app.py`, `AgentSessionGateway.swift`, `TrustedAgentIngress.swift`, `Tests/CirclrAppTests/`가 소유 파일 후보이다. 앱은 선택 문서에서 turn을 발급하고 helper에게만 비밀 capability를 전달해야 한다. 모델의 prompt·tool argument·프로젝트 파일·명령줄·모델이 볼 수 있는 shell 환경으로 capability를 전달하면 안 된다. 실제 runtime이 private handoff를 지원하는지 확인하기 전에는 IPC 방식을 가정해 제품 연결을 발표하지 않는다. fake MCP client→동봉 helper→trusted socket→MIDI/Undo/bounce/save/export와 STOP/TTL/문서 교체를 먼저 통과시키고, G0가 풀린 뒤 실제 계정/승인/중단 E2E를 별도 통과시킨다.

이번 감사는 정적 코드·기존 QA 기록·공식 현재 문서 검토다. build231 실제 모델 호출이나 native 앱 조작을 실행했다는 기록이 아니다.
