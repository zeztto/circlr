## 현재까지 확인한 결과

- **AI socket:** 동일 UID의 느린 미완료 연결이 정상 요청을 직렬로 약 2.897초 지연시킨 RED 시험 뒤 이벤트 기반 수신에서 약 0.109초를 측정했다. 독립 보안 리뷰가 완료 요청의 FD·요청 데이터가 무한히 쌓이는 P1을 발견했고, 완료/미완료 합계 32개, 버퍼 32MiB, 응답 8MiB, 완료 응답 15초 기한으로 수정했다. 최종 실제 Unix socket 전용 회귀 7/7은 64개 완료 요청에서 32개만 수락, STOP 즉시 경로 해제와 수락된 stale 응답, 제한·기한을 확인했다. [보안 재검토](0.80-build235-security-review.md)는 별도 기록한다. 같은 UID의 반복적인 32-slot 점유는 제한된 로컬 DoS 위험으로 남는다.
- **입력 캡처:** [선행 감사](0.80-build235-input-audit.md)의 부모 HAL 시작 무기한 대기를 앱 소유 입력 자식으로 격리했다. 첫 구현의 Foundation `Process.waitUntilExit()` 무기한 대기와 PID 재사용 가능성을 발견해 `posix_spawn` 및 host 단독 `waitpid` 소유로 변경했다. 실제 자식 fixture **10/10**은 시작/종료 hang, crash, 늦은 응답, malformed/oversized 응답, 0-frame/손상 CAF 미게시, CAF readback, 진행값/peak/limit/interruption, 동일 recorder 재시도와 background reap, 기존 파일 보호·게시 직전 취소를 검사했다. 입력 UID 직접 선택은 부모 HAL 조회 없이 미지원으로 실패하고, 최종 take는 자식 종료·형식/길이 검증 뒤 대상 볼륨의 private stage에서 `RENAME_EXCL`로 게시한다. 실기기 선택 입력 1개는 환경 의존으로 skip이며 실제 마이크 PCM·TCC 귀속은 **미검증**이다. 앱이 private stage로 CAF를 복사하던 중 crash하면 일부 복사본이 남을 수 있는 P3 정리 항목은 후속으로 남긴다.
- **송폼 UI:** [선행 감사](0.80-build235-ui-audit.md)에서 전체 곡 축소 시 순서 손잡이가 숨는 문제를 확인했다. 선택 섹션의 앞/뒤 순서 이동을 넓은/좁은 도구 모음에 노출하고 세로 `서클 도구` 메뉴에도 넣었다. 기존 `moveSectionOccurrence`/Undo·분기/경계·녹음/영상 잠금 계약을 재사용한다. 독립 리뷰에서 자유 배치의 공간 이동 키를 순서 이동으로 잘못 안내한 문제와 세로 메뉴 누락을 고친 뒤 신규 UI 모델 테스트 3/3이 통과했다. 700/720/900/1440pt 픽셀/AX와 실제 순서 변경은 최종 앱에서 재검증한다.
- **공식 Codex G0:** [App Server 문서](https://learn.chatgpt.com/docs/app-server)가 현재 명령과 WebSocket transport를 experimental·production 미지원으로 명시한다. [계정 콘솔 계획](../docs/20-codex-account-console-plan.md)을 갱신했고 공개 앱 내 계정 대화는 NO-GO를 유지한다. build234의 오프라인 앱 소유 helper 검증을 계정 기능 완성으로 간주하지 않는다.

최종 소스의 전체 Swift 회귀는 **1,273개 실행·15 skip·실패 0**이었다(`/tmp/circlr-build235-swift-final.log`, SHA-256 `944bdfd18878592536b2a2268ecaeda1f8ebedc97bd11fdded822a63e8aa0553`, 264.4초). 앱 소유 실제 MCP helper 8개와 입력 프로세스 10개가 포함된다. Python MCP 회귀 `mcp` **47개**와 `Tests` **39개**도 각각 통과했다. 독립 입력 코드 재검토의 초기 PID 재사용·late meter·무조건 catch 지적은 수정했고, callback-before-completion 지적은 강제 순서 테스트와 completion의 `reaped` 재확인을 대조한 뒤 리뷰어가 철회했다. 최종 재검토는 구체적 새 P0–P2를 확인하지 못했다.

`./scripts/build-app.sh`는 **0.80.0/build235** Apple Silicon 앱과 **7개 helper**를 패키징했다. 패키지 로그 `/tmp/circlr-build235-package.log` SHA-256은 `b1bb5f7255e6f45075614b36546b7afdeef93642a28cc1c62ec7703a4bc441ca`이고 주 실행 파일 SHA-256은 `f2ba2325305f23b554d37836fa185d0aad2e9b87a234d7683401a33563a2b5f6`다. 앱과 helper 전부 arm64 Mach-O이고 각각의 서명 및 `codesign --verify --deep --strict`가 통과했다. 패키지에서 버전/build를 직접 읽었으며, Demos source/package **27/27파일**과 manifest **26/26**, Codex kit **26/26파일**과 manifest **25/25**, 권리 고지 2/2가 byte 일치했다. icon builder가 생성한 tracked `Resources/Assets.car`는 패키지 검증 후 HEAD의 원본으로 돌렸다.

격리된 실제 build235 앱에서 700/720/900/1440pt 창의 조작과 AX를 확인했다. 720pt의 `서클 도구`에서 중간 03 섹션을 02로 옮기고 Undo로 03에 복귀했으며, 700pt에서 첫/마지막 방향 비활성화와 자유 배치 단축키 설명을 확인했다. 앱에서만 Mac Studio 스피커를 선택한 Play/Stop에서는 시계가 **00:25.4→00:30.4→00:00.0**으로 움직였다. 이는 실제 청취나 Scarlett 정상 동작의 증거가 아니다. 정지한 f0r h3r 7섹션의 전체 창 가로·세로 PNG를 [한영 README](../README.ko.md)와 [이미지 출처](../docs/images/README.md)에 반영했다. 자세한 동작·화면·프로세스 정리는 [native QA](0.80-build235-native.md)에 기록한다.
