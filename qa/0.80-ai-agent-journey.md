## 현재 확인한 사실

2026-09-25 KST, [build239 최종 후보의 실제 모델 QA](0.80-build239-model-native.md)가 로그인된 외부 Codex→동봉 MCP→격리 앱의 MIDI 한 step 편집을 **모델 turn 1회**로 확인했다. 앱 콘솔의 같은 작업 행은 AX·화면에서 확인했다. 독립 QA가 정확한 note diff와 Undo·재적용·저장·재열기·70초 nonzero WAV를 확인했다. 사용량은 input 151,569(cached 92,416), output 1,123 tokens다. `codex exec`는 사용자 환경·인증을 상속하고 사전 pin 확인과 모델 write는 별도 MCP 프로세스였으므로 프로세스 전면 격리나 write 직전 runID/path 강제 pin은 미검증이다. 이 실행의 전후 runtime·문서 경로·revision은 일치했다. 앱 내 계정 대화·trusted AI STOP·물리 청취는 별도 범위다.

2026-09-24 KST, `release/0.80.0`의 build237 체크포인트 `5d69566`에서 `codex-cli 0.149.1`의 `codex login status`는 `Logged in using ChatGPT`였다. 인증정보나 계정 식별자는 읽거나 기록하지 않았다. 이 상태 조회 자체는 모델 호출·MCP 연결·음악 편집의 성공 증거가 아니다. 사용자 프로젝트, 설치 앱, 시스템 오디오 기본값을 건드리지 않았다.

[build230의 실제 모델 QA](0.80-qa232-model-native.md)는 로그인된 외부 Codex CLI가 서명된 고유 bundle ID의 앱에 동봉 MCP adapter로 연결해 4개 MIDI note를 추가하고 Undo로 원복한 뒤 재적용, 저장·재열기, nonzero 48 kHz/stereo/24-bit WAV까지 만든 **제한된 PASS**다. 두 번째 trace의 MCP 순서는 `snapshot → inspect → apply → inspect → undo → inspect → apply → save → open → job → snapshot → inspect → export → job`이다. 원시 JSONL SHA-256은 첫 시도 `c9af59fc1ab407a0683daaa8a916b13c4a33466cf61160bc46d82a2d266a3372`, 쓰기 시도 `24e4bcb461ea46b6179c439b2fe16975ee5d88333af80cda7e85de892f49c265`이며 Git-ignored `qa/generated/r80-qa232-model-native/`에 있다. 모델의 최종 답변만이 아니라 실제 note/revision, 재열린 manifest와 WAV PCM을 독립 검사한 기록이다. 첫 `-s read-only` 시도는 MCP write 승인이 거절되어 **실패**했고, 승인된 두 번째 시도만 편집 PASS다.

기존 두 시도의 입력은 각각 **232,974**(cached 181,504), **926,302**(cached 850,944) tokens였다. 두 번째 trace는 큰 `snapshot`/`inspect`/`apply` 결과를 반복해서 모델 문맥에 누적했다. `item.completed` 기준 29–67 KB짜리 MCP 결과가 여러 번 반복된다. 따라서 최종 후보에서 동일한 긴 모델 시나리오를 다시 실행하지 않는다.

build230 이후 `mcp/server.py`에는 bounded read-only `circlr_context`가 추가됐다. 반면 `AgentSocket.swift`의 수신·응답·timeout 경로는 크게 바뀌었고, 별도의 app-owned trusted helper/lease와 콘솔 follow가 추가됐다. build237의 MCP Python 회귀 **47/47**, 프로젝트 MCP **39/39**, agent kit **9/9**, [격리 native QA](0.80-build237-native.md)의 read-only socket 질의는 해당 범위의 증거다. 이것만으로 build230의 **모델 write 성공을 최종 바이너리로 승계할 수 없다.** app-owned trusted helper는 외부 CLI의 일반 MCP socket과 다른 경로이며, 내부 trusted STOP/lease 결과를 외부 MCP STOP의 권한 철회 증거로 취급하지 않는다.

## 최종 후보에서 한 번만 실행하는 bounded E2E 계약

1. 최종 소스와 패키지가 고정되고 자동 회귀·서명·bundle kit hash가 통과한 뒤, `dist/써클러.app`을 Git-ignored QA 위치에 복제해 고유 bundle ID로 재서명한다. QA Support와 `.circlr` fixture를 새로 만들고 production Agent socket·사용자 곡·설치 앱은 열지 않는다. `selected.json` 권한, bundle ID/build/runID, QA socket inode와 `circlr_context`/`circlr_snapshot.runtime`을 요청 전 대조한다. 기본 `Scarlett 6i6 USB`는 변경하지 않으며 Play/Record·물리 청취를 이 시나리오에 넣지 않는다.
2. 동봉 `circlr-studio` kit를 QA client에만 설치한다. MCP **자식에만** 짧은 private HOME의 QA `Agent` symlink를 설정해 기본 `EndpointResolver`의 v2 runID/socket pin을 사용한다. `--socket`/`CIRCLR_SOCKET` 직결을 pinned 연결의 증거로 사용하지 않는다. Codex 본체의 로그인·전역 config는 바꾸지 않는다. 실제 endpoint와 QA snapshot이 달라지면 모델을 시작하지 않는다.
3. **모델 turn은 최대 1회**다. 프롬프트에는 QA projectID/revision과 실제 대상 use/lane, 기존 MIDI를 보존하면서 빈 2–4 step에 짧은 응답구를 만드는 범위만 준다. `circlr_context → 대상 circlr_inspect → revision-checked circlr_apply`를 요구하고, 그 외 shell write·다른 곡 열기·장치 변경·구매를 금한다. 자격증명·socket 경로·capability/lease secret은 프롬프트나 수동으로 추가하는 모델 context에 넣지 않는다. 이전과 같이 `--ignore-user-config --ephemeral` 및 QA 디렉터리만 허용하는 승인 설정을 사용하고, 승인 거절·target_changed·문서 불일치·timeout이면 **재호출하지 않고** snapshot으로 불확실한 쓰기 상태를 먼저 확인한다.
4. 모델 turn 종료 후 **독립 QA client**가 앱 `circlr_events`와 모델 trace의 요청을 대조하고, 실제 콘솔의 해당 활동 행을 AX/화면 증거로 확인한다. inspect로 정확한 note diff, 기존 lane·다른 use/track 불변, revision 증가를 검사한다. 이어 같은 QA 문서 `save → open/job → snapshot/inspect → export/job`을 결정적으로 진행하고 manifest 지속성과 nonzero 48 kHz/stereo/24-bit WAV를 확인한다. Undo는 저장 전 같은 프로젝트에서 exact restoration을 검사할 수 있으나 다시 적용할 경우 **새 revision으로 정확히 같은 범위**만 재적용한다. `save/open/export`가 모델이 직접 수행한 단계인지 독립 QA 단계인지 결과에 명확히 구분한다.
5. 앱 종료 후 QA bundle/helper/socket 잔류 0, 원본 앱·kit·fixture 원본 hash, 기본 오디오 입력·출력 불변을 확인한다. Git-ignored JSONL·snapshot·manifest·PCM 검사값과 각 SHA-256을 기록한다. 모델 응답의 자기보고, 도구 호출 수락, WAV 파일 존재만으로 PASS하지 않는다.

이 bounded 재검증의 핵심 합격점은 **최종 서명 앱에서 모델이 실제 MCP write를 한 번 수행했고 음악 data·콘솔 activity가 일치한다는 것**이다. 저장·재열기·WAV는 독립 QA가 같은 변경을 끝까지 이어서 검증한다. 모델 비용/시간을 제한하면서 전체 DAW 결과를 확인하는 범위이며, 앱 내 계정 채팅·trusted AI STOP·물리 청취·음악적 발매 품질의 합격 판정은 포함하지 않는다. 최종 후보가 바뀌면 새 후보에서 다시 판단한다.
