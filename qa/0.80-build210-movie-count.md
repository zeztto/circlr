# 0.80.0 build 210 — MP4 저장 프레임 수 경계

2026-09-24 KST. build 209의 `qa/generated/r80-build209-native/build209-native-8s.mp4` (SHA-256 `301e53ad00598cce9b3b19857d40838e6272831badfeb1d19e9ebdff5aa137ff`)에서 UI 저장 문구는 235프레임, AVFoundation 독립 decoder는 234프레임이었다. 원본 파일을 다시 읽으면 영상 길이는 7.805초, 마지막 decoded PTS는 7.771667초다. 마지막 PTS와 종료 시각의 차이는 정확히 1/30초다.

1초 PCM과 0~1초의 31개 캡처를 사용한 회귀 테스트에서 수정 전 writer는 31프레임을 저장했다고 세었지만 MP4에는 30프레임만 남았다. `AVAssetWriter.endSession(atSourceTime:)`와 같은 시각의 영상 sample이 파일에서 제외되는 경계를 재현했다. 캡처 지연이나 실제 중간 프레임 손실을 의미하지 않는다.

유한한 오디오의 종료 시각 이상에 도착한 캡처는 AVAssetWriter에 제출하지 않는다. `frameCount`는 이 경계 프레임을 세지 않고 `droppedFrames`에도 추가하지 않는다. 그 외 프레임 제출 실패의 기존 누락 집계는 유지한다. 일반 종료와 scheduled loop exit의 회귀 테스트는 각각 큐 수용 31개 / AVAssetWriter 인코딩 대상 30개, 독립 decode 30개, 누락 0개를 확인한다.

검증: `swift test --filter CanvasMovieWriterTests` — 9개 통과. 기존 build 209 MP4 자체는 변경하지 않았다. build 210 패키지 앱의 실제 녹화와 UI 저장 문구는 별도 native QA가 필요하다.
