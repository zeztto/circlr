# build222 시작 화면·카메라 복원 코드 리뷰

범위: `Sources/CirclrCore/StudioWorkspace.swift`, `Sources/CirclrApp/AlbumCanvas.swift`, `Tests/CirclrCoreTests/SavedWorkspaceTests.swift`의 미커밋 diff. 제품 소스는 변경하지 않았다.

## 판정

확정할 수 있는 P1/P2 회귀는 찾지 못했다. `openingSelection`은 저장된 viewport가 없는 단일 leaf 곡에만 적용되며, 다중 곡과 저장된 앨범 선택은 기존 경로를 유지한다. `layout()`의 pending command 처리도 `update()`가 실행 전 `commandID`를 설정하므로 같은 명령이 즉시 재귀 실행되지는 않는다. 저장된 유효 카메라는 `.restore`의 기존 분기에서 그대로 적용된다.

## 초기 배치 경로 재검토

초기 `scene == nil`인 layout에서 카메라 초기화를 건너뛰고 `update()`가 focus 명령을 소비하면, 다음 layout이 앨범 카메라로 포커스를 덮을 가능성을 제기했다. 후속 diff의 `AlbumCanvas.swift:376-379`가 첫 유효 bounds에서 `setCamera`를 호출할 때 `initialized = true`로 설정하므로 이 경로의 재설정 문제는 해소된다. 이는 저장된 카메라의 즉시 적용과 새 곡의 focus 애니메이션 모두에 적용된다.

잔여 점검: `AlbumCanvas.swift:245`의 `update()`는 `layout()` 안에서 `@Published` 선택을 바꿀 수 있다. 명령 ID로 재실행은 방지하지만, 실제 AppKit/SwiftUI 초기 배치 중 layout warning, 첫 화면 흔들림, 반복 배치 여부를 native QA에서 관찰한다. 코드만으로 확인된 회귀로 분류하지 않는다.
