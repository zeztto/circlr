## 사용자 결과와 범위

1. **MIDI 반복 녹음 종료 경계** — 선택한 반복 횟수보다 `tick` 호출이 늦으면 녹음 종료 시각과 활성 note flush가 다음 반복으로 넘어가는 문제를 고친다. 마지막 반복 끝에 note를 자르고 늦은 Note On을 무시하되 실제 입력 audition을 해제한다. 합성 timestamp로 정확한 take 개수·마지막 노트·Undo를 검증한다. 소유: `Sources/CirclrApp/AppStore.swift`, `Tests/CirclrAppTests/MIDIRecordingFidelityTests.swift`.
2. **녹음 작업 진입** — 현재 상단 `녹화`가 영상 MP4만 뜻하는데 MIDI/오디오 take 녹음과 혼동된다. 같은 캔버스 상단에서 녹음 종류·대상·상태를 분명히 구별하고, 기존 감상 버튼과 반응형 우선순위를 유지한다. 녹음할 대상이 없거나 입력 조건이 맞지 않을 때 실패 원인을 설명한다. 실제 take 동작이 기존 정밀 편집기와 일치해야 한다. 소유: `Sources/CirclrApp/RootView.swift`, 필요 시 `Sources/CirclrApp/RecordingWorkspace.swift` 및 UI 전용 테스트. DAW 담당의 `AppStore.swift`는 수정하지 않는다.
3. **앱 소유 AI helper** — build233의 외부 MCP 문맥 도구는 계정 대화도 앱 소유 turn도 아니다. 읽기 전용 설계 감사에서 Foundation `Process`의 임의 FD3 상속을 신뢰할 수 없음을 확인했다. 앱이 helper의 stdin/stdout을 독점하고, 첫 제한된 stdin frame으로만 private socket·capability를 건넨 뒤 MCP JSONL을 처리하는 **내부 오프라인 경계**를 구현한다. `initialize`/`tools/list`/`tools/call`과 선택 MIDI 범위의 snapshot·inspect·apply·bounce·job, STOP·문서 교체·만료의 child/socket 정리를 검증한다. 모델 도구 인수·argv/env·로그·프로젝트에 비밀을 싣지 않고, 공개 로그인 UI와 Codex 계정 연결은 만들지 않는다. 소유: 새 helper tool/host·통합 테스트, `AgentSessionGateway.swift`, `TrustedAgentIngress.swift`, `Package.swift`, 패키징 스크립트. DAW/UI 담당 파일은 수정하지 않는다.
4. **오디오 QA 기준** — 사용자가 지적한 구형 Scarlett의 최신 macOS 호환성은 미확인이다. 그 장치의 실패를 circlr 결함이나 정상 동작으로 단정하지 않는다. 격리 QA 앱에서 앱 전용 Mac 내장 출력을 우선 사용하고 시스템 기본 장치는 바꾸지 않는다. 실제 청취·입력 take가 없는 자동 출력 시계와 파일 검사는 별도로 표시한다. Scarlett 호환성은 정확한 기기 세대·드라이버와 독립 검증 전까지 OPEN으로 유지한다.

## 실행 순서와 판정

DAW와 UI 구현은 서로 다른 소유 파일에서 병렬로 수행한다. 개발 리드는 겹치지 않는 AI helper 경계 검토, 통합 테스트, 격리 앱·픽셀/AX 검증, 문서와 최종 commit/push를 맡는다. 모든 담당자는 같은 worktree를 공유하므로 타 담당자 변경을 되돌리지 않는다. `0.80.0`과 `1.0`의 출시 gate는 이 작은 build의 통과로 닫히지 않는다.

각 구현에서 실패를 드러내는 targeted 검증을 먼저 만들고 수정 뒤 재실행한다. 통합 Swift/MCP 회귀, 앱 패키지·서명·bundle hash, 700/720/900/1440pt의 녹음/영상 버튼과 상태·AX, 실제 파일 결과를 영향 범위에 맞춰 확인한다. 독립 코드 리뷰와 보안 관련 변경의 보안 리뷰를 받는다. README·CHANGELOG·QA·필요한 최종 앱 스크린샷을 갱신한 뒤 checkpoint commit/push한다. 물리 입력·청취나 계정 turn을 실제로 시험하지 못하면 PASS로 적지 않고 정식 tag/Release를 보류한다.
