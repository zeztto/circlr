# 0.80 build204 · Agent socket 원자 게시 QA

상태: **socket 소유권·재연결 회귀 통과 / 0.80 출고 후보 아님** · 2026-09-24.

build203 최종 리뷰에서 발견한 bind 직후 공개 경로 inode 오인 경합을 수정했다. 앱은 임시 socket을 listen 상태로 준비하고 그 inode를 캡처한 뒤 macOS `renamex_np(RENAME_EXCL)`로 `agent.sock`에 게시한다. 공개 경로가 이미 있거나 다른 앱이 먼저 게시하면 교체하지 않는다. 게시 뒤에도 같은 inode인지 확인하고, 종료 시에는 자기 inode인 경로만 정리한다. 기존 구버전의 임의 unlink/rebind까지 제어하는 계약은 아니며 crash-stale socket 자동 삭제는 계속 금지한다.

최신 `AgentSocket.swift`와 smoke를 단독 컴파일·실행했다. active listener·bind-only·stale 경로의 보존, 다른 socket으로 교체된 뒤 늦은 deinit의 보존, `RENAME_EXCL` 경쟁 경로의 no-replace 및 임시 경로 제거가 PASS였다. 로그 `qa/generated/r80-build204-agent-socket-safety.log` SHA-256은 `55e5fff3ecb21d62692c5b69bec77b8562ee12ba159ff6734ab4aa3a49f9dc8e`다. 최종 독립 코드 리뷰에서 이 변경의 새 P1/P2는 없었다.

0.80.0/build204 arm64 앱과 다섯 helper를 빌드·서명했다. `qa/generated/r80-build204-build.log` SHA-256은 `ca5738365069de8d40e749b37b7dc1cc83370bf28a2e8c6f92d5f7c327b1e45d`다. 격리 QA 패키지 `qa/generated/port-focus/build204/package.json`의 원본 앱 tree SHA-256은 `e335f4570bf86729738b09ece41121222b8d2073270ca3ac9df133be0f239dc4`; 원본·QA 앱은 strict deep codesign 검증을 통과했다. `f0r h3r` 원본 데모 tree SHA-256은 이전 패키지와 같은 `b15252dbe5d4d4f79b6935449fa7238cf30fe90d783af20544b71ba83fcdf085`다.

실제 격리 앱을 열자 QA socket `snapshot`이 `ok=true`, `runtime.build=204`, `bundleID=com.circlr.portfocusqa`로 응답했다. 데모를 연 화면의 접근성 버전은 **0.80.0 · 빌드 204**였고, 임시 `.a*` socket 경로는 남지 않았다. ⌘Q → **변경 버리기** 후 앱 프로세스·공개 socket·v2 복구본이 모두 사라졌다.

QA 폴더에서 별도 test listener가 공개 `agent.sock`을 먼저 bind/listen한 뒤 build204 앱을 다시 열었다. 앱 시작 중 test listener의 `(dev,inode)`는 `(16777230,24515292)`로 유지됐다. test listener가 정상 종료해 자기 경로를 제거하자 앱의 10초 주기 재시도로 `snapshot`이 다시 `ok=true`, `build=204`에 응답했다. 재연결 뒤 앱을 정상 종료하자 공개 socket·v2 복구본은 남지 않았다. 이는 **별도 test listener로 모사한 정상 점유 해제**이고 실제 구버전 앱 두 프로세스 간 경쟁 검증은 아니다.

QA legacy `recovery.json` SHA-256 `0c7507e9686665d048b82c5b5780d86e36dfda94fc1b91759c0f35702d8380e7`과 사용자 기본 `circlr/recovery.json` SHA-256 `688558b00e4160106065114e7a6305ffa1a24ea8f57636408f408e38e5148c38`은 그대로다. Core clean scratch Swift 1,112개·11개 skip·실패0 및 MCP 회귀는 [build201](0.80-build201.md)의 소스 검증이고, 이후 socket 변경은 이번 smoke·앱 빌드·native QA로 검증했다.
