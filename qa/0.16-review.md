# 0.16 · 스텝 편집 검증

2026-09-08, macOS 26.5.1 / Apple Silicon. 전용 `com.circlr.hierarchyqa` 0.16.0 build 18, `qa/generated/0.16/step-QA.circlr`에서 확인했다. 원곡 v4는 변경하지 않았다. Sub-agent dispatch는 실제 실행 한도(`agent thread limit reached`)로 거절되어 역할별 구현·읽기 전용 검토·QA를 순차 수행했다.

## 자동 검사

- 새 `.build/step-quality` 환경에서 Swift **119개 통과**, Scarlett 실제 장치 재생 테스트 `testArrangementRenderExportAndPlayback` 1개는 기존 제약으로 제외했다.
- Python MCP **10개**, 음악 agent kit **9개** 통과. release는 `.build/step-release`에서 새로 빌드했다.
- 드럼/화음, idempotency, off-grid/held note 보존, triplet/odd length, page 복제의 fresh IDs/끝 경계/오디오 보존, invalid input/batch, viewport의 구버전 decode를 검사했다.
- `HierarchyViewport`의 저장 필드 추가 직후 기존 incremental debug 경로에서 equality 실패와 signal 11이 발생했다. 실패 로그는 `swift-tests-incremental-failure.log`에 보관했다. 동일 소스의 독립 scratch 전체 빌드는 119개를 통과했다. 캐시 내부 원인을 확정한 것은 아니며 새 scratch 결과를 출고 기준으로 사용했다.

## 음악 출력

- 편집 Undo 뒤 native 전체 WAV가 v4와 **바이트 동일**: SHA256 `975a901aa9f4e01ac0d9e17ad85ba59a1c377a61f41577abd7aa4d0a6f887c6f`.
- 새 신스 스텝을 입력한 전체 WAV는 기존 음악과 실제로 달라졌다(최대 806347 LSB).
- 새 스텝 → 신스 → 킥 sidechain 이펙트 → 바운스 → 전체 WAV 비교: **24-bit 최대 2 LSB 차이**, 두 편집 Undo 후 lane 데이터 복원.
- 최초 smoke의 1 LSB 기준은 이 15트랙 remix에서 실패했다. 바운스는 24-bit 중간 파일을 Float32로 읽어 재합산하므로 bit-exact 계약이 아니다. 검증 스크립트에 4 LSB(-126 dBFS) 상한을 명시하고 실제 2 LSB를 보고한다. 실패 로그/오디오를 보관했다. DSP와 바운스 구현을 이 테스트에 맞춰 바꾸지는 않았다.

## 남은 경계

실제 Scarlett 출력·하드웨어 마이크 녹음·재생 중 step playhead는 이 검증에서 실행하지 않았다. 저장된 PCM export, 이전 sample-time 경로, 실제 출력 장치 검사는 서로 구분한다. 새 스텝 입력은 기존 prepared PCM 재생 경로를 사용하며 재생 중 편집은 다시 준비/재생해야 들린다. 기본 MIDI/audio 녹음 경로는 기존 구현이며 일괄 MIDI 편집·audio split/fade·automation은 문서 31의 후속 구현이다.
