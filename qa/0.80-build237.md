[계획](0.80-build237-plan.md)은 build236 [native 성능 실패](0.80-build236-native.md)의 동일 조건을 재현하도록 정했다. 이번 소스는 최근 로그의 즉시 레이아웃을 최대 64행으로 제한하고, 이전 로그는 지연 배치한다. 행 identity와 스크롤 요청도 묶는다. 500행 보관, 과거 로그 위치, 미확인 수, `최신 로그`, 휠·키보드·접근성 동작은 유지한다. 재열기 때 이전 뷰가 남긴 스크롤 예약을 무효화한 뒤의 집중 테스트는 **13/13** 통과했다. 독립 UI 정적 재검토에서는 새 P0–P3 결함을 찾지 못했다. 실제 성능은 [build237 native QA](0.80-build237-native.md)에서 판정한다.

최종 동일 소스의 `./scripts/swift-local.sh test --scratch-path .build/build237-integration-final --skip-build` 전체 회귀는 **1,298개 실행·15 skip·실패 0**으로 통과했다. 로그 `/tmp/circlr-build237-swift-retry.log` SHA-256은 `6d5166b820b5dcacbe9b4e1367145bb4008964d47fd73ea571aa14d33ad6cea8`이다. 첫 전체 시도는 `AgentSocketFairnessTests.testCompletedRequestFloodIsCappedAndStopDrainsAcceptedStaleReplies` 시작 직후 테스트 프로세스가 signal 13(SIGPIPE)으로 종료됐다. 해당 소켓·테스트 소스는 build235 대비 변경이 없고 양쪽 소켓에는 `SO_NOSIGPIPE`가 설정되어 있다. 같은 build237 바이너리의 단독 **20/20**, 클래스 5회×7 **35/35**, 별도 Swift runner 필터 **7/7**에서는 재현되지 않았다. crash backtrace가 없어 최초 FD 원인은 미확정이다. 이 첫 시도를 통과로 계산하지 않고 위의 최종 전체 재실행만 합격 근거로 쓴다. Python MCP 서버 **47/47**, 프로젝트 MCP **39/39**, agent kit **9/9**도 통과했다.

`./scripts/build-app.sh`는 **0.80.0/build237** arm64 앱과 **7개 arm64 helper**를 패키징했다. `codesign --verify --deep --strict`가 통과했고, 주 실행 파일 SHA-256은 `c5f85c5fb5a7fe5f4f405cc00a1d0af5c8a34d0a97b03b842a273df210a5542d`다. 패키지 로그 `/tmp/circlr-build237-package.log` SHA-256은 `1773b8ac778fa651cf614ad51756abaf5978ec7dcd364137a3fc199bdc29fac5`다. Demos **27/27파일**(manifest 26/26), Codex kit **26/26파일**(manifest 25/25), `LICENSE`·`THIRD_PARTY_NOTICES.md` **2/2**가 소스와 byte 일치한다. 빌드 후 생성된 tracked `Resources/Assets.car`는 HEAD 원본으로 복원했고 앱 내부의 아이콘 카탈로그는 생성본을 보존했다.

격리 [native QA](0.80-build237-native.md)는 700×900pt·40pt·500행에서 정확한 500→501 절단, 과거 로그 위치와 새 로그 30건 알림·최신 복귀를 실제 앱에서 확인했다. 앱 내장 출력 `Mac Studio 스피커`로 Play/Stop 상태와 시계도 진행·정지했다. 같은 100건/약 6.5건/s의 로그 유입에서 펼친 콘솔의 내부 `playback.frameCount` 증가율은 **43.67 count/s**, 접힘은 **53.22 count/s**(82.05%)였다. 합격선에 가까워 반복한 두 번째는 **42.96/53.16 count/s**(원시 값 비율 **80.80%**, 80% 기준의 여유 **0.80%p**)였다. 무입력 펼침 기준은 **57.49 count/s**였다. 두 번 모두 사전의 펼침 ≥40, 접힘 대비 ≥80%, 시계와 wall time 오차 ≤1초 기준을 통과했다. 이는 build236의 같은 유입 조건 펼침 **10.66 count/s**보다 개선됐다는 앱 내부 계수의 증거이며 실제 compositor FPS나 물리 청취를 측정한 수치는 아니다.

QA 앱은 `⌘Q → 변경 버리기`로 종료했고 helper와 전용 socket은 남지 않았다. 원본·QA deep strict 서명, 원본 실행 파일·57개 Resources·7개 helper·번들 데모 해시, 시스템 기본 `Scarlett 6i6 USB` 입력·출력은 전후 불변이었다. 가로·세로 전체 창 [스크린샷 출처](../docs/images/README.md)는 최종 build237 격리 앱에서 확인했다. 원본 프로젝트·설치 앱은 실행·수정하지 않았다. 실제 물리 MIDI/마이크 입력과 청취, 구형 Scarlett 세대별 호환성, 실제 프레임 pacing·긴 MP4, 사용자 Codex 계정 G0는 별도 출고 gate로 남는다. `v0.80.0` tag/GitHub Release는 만들지 않는다.
