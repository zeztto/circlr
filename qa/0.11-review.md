# 0.11.0 재생 비주얼라이저 검증

환경: 2026-09-07 · Apple Silicon · macOS 26.5.1. QA는 승인된 `com.circlr.hierarchyqa`와 `qa/generated/0.11-visualizer/f0r-h3r.circlr` 사본에서 수행했다. production 앱은 실행하지 않았으며 사용자 곡·production 복구 데이터는 수정하지 않았다.

## 자동 검증

- Swift 92개 테스트, 실패 0. [전체 로그](generated/0.11-visualizer/tests-final.log). 테스트 실행에 필요한 Audio Unit 서비스는 sandbox 밖에서 검증했다. sandbox 안의 기존 sampler 초기화 실패를 제품 테스트 통과로 취급하지 않았다.
- Python MCP 4개 테스트, 실패 0. 기존 stdio handshake·14개 도구·입력 검증과 follow의 boolean 타입 계약을 확인했다.
- 시각화 옵션을 끄고 켠 렌더의 PCM left/right 배열이 정확히 일치했다. 단일 샘플 transient·마지막 envelope bucket·MIDI 시간 경계·effect tail·음소거·분리·gain 0 경로를 검증했다.
- overlap 동시 playhead와 incoming follow, insert·최종 tail 유지, 섹션·곡 반복, local tempo, 선택 섹션 재생과 follow 상태 전이를 검증했다.

## 실제 앱 검증

[재현 스크립트](verify-playback-native.py)와 [최종 상태 증거](generated/0.11-visualizer/native-scenarios.json)를 사용한다. 실제 sample time, 신호 값, camera, selection, revision, 최소화 상태를 QA socket에서 읽었다.

최종 실행 결과: 5개 시나리오 통과. 시작 대기는 이미 오디오 출력이 연결된 상태에서 0.121초였고, 약 1초 간격의 표본 사이에 표시 타이머 60프레임을 관찰했다. 이동 중 최소화 전후의 섹션이 동일했으며 복원한 zoom·pan도 기준값과 0.000001 이내로 일치했다.

1. 재생 시간이 진행하며 node/edge 신호와 phase가 변한다. 음악 revision과 편집 선택은 그대로다.
2. 수동 focus는 follow를 suspended로 바꾸고 follow=true가 현재 섹션 추종을 재개한다.
3. 최소화 중 실제 재생 시간은 증가하고 표시 frameCount는 멈춘다. 이동 중 최소화한 카메라도 복원 후 목표 위치에 다시 맞춘다.
4. 실제 섹션 경계에서 focusedSection이 currentSection으로 바뀌고 카메라가 이동한다.
5. 음악을 수정하면 stale=true와 함께 node/edge/phase를 지운다. 정지하면 표시 타이머도 멈추며 Undo·저장 후 트랙과 dirty 상태를 복원한다.

별도 GUI 검증에서 실제 휠 확대가 `팔로우 재개` 상태로 전환되고 해당 버튼이 팔로우를 재개하는 것을 확인했다. [휠 조작 상태](generated/0.11-visualizer/wheel-suspended.json). 상단 버튼은 폭 1080 환경에서 한 줄로 보이고 BPM·박자·스케일과 겹치지 않는다. 캔버스 1080×845와 2560×1255에서 확인했다.

콘솔을 접으면 followViewport 높이가 527.5에서 675로 증가하고, 다시 펼치면 527.5로 돌아간다. ## 소스 검토와 패키지

렌더 관찰 callback은 준비 단계에서만 실행한다. 기존 PCM 처리 순서와 gain 적용을 변경하지 않는다. 프레임 루프는 실제 재생 중인 PreparedAudio를 읽고 musicRevision이 다르면 표시·카메라를 중단한다. 사용자 카메라 조작과 자동 팔로우를 분리하고 편집 선택·Undo를 건드리지 않는다. 창 복원 시 중간에 끊긴 카메라 이동을 다시 시작한다. 접근성 트리는 재생 중 최대 5 Hz로 갱신하며 표시 타이머는 60 Hz 목표다.

0.11.0/build 13 release 빌드와 strict ad hoc 서명 검증을 완료했다. QA와 배포본의 Mach-O UUID가 일치하며 AppIcon.icns·Assets.car와 Info.plist 아이콘 연결을 유지한다. [패키지 검증](generated/0.11-visualizer/package-check.json) · [빌드 로그](generated/0.11-visualizer/package-build-final.log). 직전 배포본은 `dist/archive/써클러-0.10.1-de768f2a.app`에 보관했다.

## 관찰된 한계

- 재생 중 표시가 시작되지 않은 추가 검증에서는 `windowVisible=true`, `windowOccluded=true`, `meterPlaying=true`였다. 창 메뉴의 Bring All to Front 후 `windowOccluded=false`로 바뀌며 정상 재개됐다. [가려짐 진단](generated/0.11-visualizer/display-diagnostics.json) · [창 표시 후 신호](generated/0.11-visualizer/display-after-front.json). 최종 runner는 보이는 화면을 검증하기 전에 occlusion 조건을 확인한다.

- 새로 서명한 QA 앱의 파일 읽기가 OS open 호출에서 대기한 사례가 있었다. 해당 작업을 취소하고 표준 파일 선택기로 같은 QA 사본을 열어 완료했다. 시스템 권한을 변경하거나 TCC를 초기화하지 않았다.
- 첫 재생 요청이 60초 제한을 초과한 사례가 있었다. 이후 정상 재생이 시작됐고 같은 실행 파일의 반복 재생 시나리오는 통과했다. [첫 시작 timeout 기록](generated/0.11-visualizer/native-first-start-timeout.json). 최초 오디오 출력 준비 지연의 원인은 이번 작업에서 해결했다고 주장하지 않는다.
- frameCount 표본은 표시 타이머 실행 횟수이며 GPU가 실제 화면에 출력한 프레임 수나 모든 프로젝트의 60 FPS를 보증하는 지표가 아니다.
- macOS 동작 줄이기 분기는 코드 검토했으나 사용자 시스템 설정을 바꿔 native 검증하지 않았다. 1024×740 정확한 최소 크기·다른 디스플레이 배율·외부 오디오 장치 전환도 이번 native 범위에 포함하지 않았다.
- 연결선 입자의 속도와 처리 노드의 회전은 신호 방향을 보여주는 표현이며 플러그인 처리 지연 측정이 아니다. 기존 prepared PCM 재생 구조를 유지한다.
