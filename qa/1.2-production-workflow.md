# 1.2 실제 제작 흐름 검증

상태: RELEASED_WITH_KNOWN_LIMITS · 핵심 제작 흐름 native/집중 회귀 및 배포/원격 검증 PASS. 실제 청취·광범위 IME·영상 제한은 아래와 같이 유지한다.

## 개선 전 기준

기준9b20765/build251: MIDI 선택·퀀타이즈·현재 lane 복제는 있지만 서클 간 clipboard가 없다. 편집 커서는 재생 시작 인자와 연결되지 않고 Play는 처음부터 시작한다. AppStore 음악 변경은 재생 중 다음 재생에 반영한다고 안내한다. 일반 섹션 재사용은 freeform use를 만들지만 재생 경로에 삽입하지 않는다. 이는 소스에서 확인한 기능 경계이며 실제 청취 결과가 아니다.

## 측정과 보고 경계

PCM/output worker clock 검증은 실제 스피커 청취를 대신하지 않는다. AX 문자열 입력은 IME 조합 검증이 아니다. 화면에 상태가 떴다는 사실만으로 음악 파일 변경을 판정하지 않는다. 바운스와 저장 결과를 직접 검사한다. 보호 거절은 변경 전·후 음악 데이터를 비교해 무변경을 확인한다.

OpenAI 모델 요청은 사용자 보류 상태이며 실행하지 않는다. 기존70ms video FAIL 및 물리 I/O/청취 제한은 유지한다. 별도의 미검증 기능을 제작 작업 합격에 섞지 않는다.

## Native 진행 기록 (build252–253)

- 격리 앱 `com.circlr.build252nativeqa`에서 새 곡을 만들고 실제 키보드 Cmd+C/X/Z, Shift+Cmd+Z/V로 복사·잘라내기·Undo·Redo·원래 박 붙여넣기를 확인했다.
- 다른 섹션의 플럭 트랙에 붙여넣고 로컬 RPC inspect로 박·길이·음높이·세기의 정확한 일치와 source/target ID 비중복을 검사했다. 증거: `qa/generated/1.2-build252/clipboard-native.json`.
- 실제 섹션 우클릭 메뉴의 ‘이 섹션 뒤에 재사용’을 실행했다. 새로운 useID와 동일 sectionID를 확인하고 저장했다. build253에서 cold open 완료, revision10과 세 section use/공유 sectionID가 보존됐다. 증거: `qa/generated/1.2-build252/reuse-native.json`, `production-flow.circlr`.
- build253에서 10박 위치 노트를 선택해 도움말 5.00초를 확인하고 ⌥⌘Return을 실행했다. 화면은 00:05.4에서 재생 중을 표시하고 실제 출력 worker는 Mac Studio 스피커에서 시작했다. 시스템 기본 Scarlett는 변경하지 않았다. 연속 snapshot: `qa/generated/1.2-build253/cursor-native.json`. 실제 청취는 미검증이다.
- 독립 검토에서 CAF staging 중 Undo가 아직 제출되지 않은 구 revision을 예약하는 경합을 발견했다. PlaybackLoopCommitGate로 동기 무효화와 실제 전송을 직렬화해 수정했다. 실제 AppStore staging gate 회귀 포함38 PASS (`.build/r120-loop-staging.log`). build253 빌드 및 격리 사본의 strict code signature 검사 PASS. 재검토/루프 native 검증은 진행 중이다.
- build253 실제 section loop의 revision12 적용 전후 output session이 동일하고 elapsed clock이 0.26–27.60초 구간에서 단조 증가했다. 3회 이상 루프 동안 출력 재시작 없이 반영됐다 (`loop-native.json`, `loop-continuity-assertions.json`).
- 별도 노트 추가(revision13)에서 output worker의 초기/교체 CAF 두 파일을 확보했다. 각각 48kHz stereo float32, 10초, PCM 3,840,000 bytes이며 data chunk SHA256이 달랐다. 적용 후 appliedRevision=currentRevision=13 확인 (`loop-pcm-after.json`, `loop-pcm-assertions.json`). 최초 capture는 process 경로 검색 실패로 파일0개였고, 두 번째는 copy2의 원본 metadata 조회 전에 worker가 원본을 지워 collector가 종료됐다. 이미 복사된 두 파일은 afinfo/CAF chunk 길이 검증을 통과했다. 이 collector 오류를 제품 실패 또는 전체 연속 로그 PASS로 분류하지 않는다.
- 실제 바운스 버튼으로 플럭 트랙의 오디오 서클과 ‘원본 복원’ UI를 생성했다. 10초 바운스 완료 및 프로젝트 저장 후 master WAV export 완료. WAV 직접 검사: 48kHz stereo24-bit,26초,peak0.18897,RMS0.01389 (`production-flow.verification.json`).
- 경합 수정에 대한 독립 재검토: 기존 P2 해결, 신규 P1/P2 없음. native 검증 결과와는 별도 소스 검토다.

## 최종 후보 검증

- build253 Core 전체736개 PASS (`.build/r120-core-final.log`), Python MCP39개 PASS (`.build/r120-python-mcp.log`). 기존 집중 테스트와 중복 합산하지 않는다.
- 700×900pt MIDI 화면에서 새 커서 재생·노트 작업 메뉴가 보이고 메뉴의 copy/cut/paste/original-paste 항목에 접근했다. 1440×900pt/700×900pt 실제 MIDI·오디오·동봉 데모 스크린샷을 보존했다. 전체 확대율·IME matrix는 아니다.
- 바운스 후 저장한 revision14 프로젝트를 앱 종료/재실행 후 열었다. projectID·세 use와 공유sectionID·오디오 asset이 보존됐다. 전체 곡 실제 재생 snapshot 순서가 A→B→B′와 정확 일치했다.
- 영속 요약: [native 증거](evidence/r120-build253-native.json), [패키지 증거](evidence/r120-build253-package.json). 원시 snapshot·CAF·프로젝트·WAV는 ignored `qa/generated/1.2-build252`와 `1.2-build253`에 보관한다.

- 최종 리뷰 문서 정정: native 곡 순서는 A→B→B′이며 C 전환 보존은 Core 테스트 증거로 구분한다. 이미 제출한 revision은 최신 렌더 준비·후속 경계까지 여러 주기 유지될 수 있으므로 한 번만 재생된다고 보장하지 않는다.
- 배포 ZIP의68파일 복원 byte 일치·strict deep signature PASS. 압축 복원 사본을 별도 bundle ID로 실행해 시작 화면의 새 곡·3템플릿·4데모를 확인하고 종료했다. 설치된 사용자 앱은 변경하지 않았다.

## 로컬 출고 승인

최종 독립 검토는 `LOCAL_EVIDENCE_PASS_WITH_DOC_CORRECTIONS`였다. native 송폼/C 전환 검증 경계, 이미 제출된 revision의 재생 횟수 비보장, 과거 OPEN 문구의 시간순 기록 표시를 정정했다. 코드 차단 결함은 없으며 ZIP 시작 확인과 종료까지 마쳤다. 이 승인은 원격 Release 성공을 뜻하지 않는다.

- 종료 후 build252/253/ZIP 검증 앱의 process와 socket은0이다. CUA가 반환한 스크린샷 실제 형식은 JPEG여서 내용 변환 없이 `.jpg`로 저장·참조했다.
