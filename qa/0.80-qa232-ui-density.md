## 선정한 한 건: 팔로우 재개 후 선택 케이블의 전면 강조가 사라짐

**재현 계약:** 격리 build230의 `f0r h3r` QA 사본에서 `도시의 기억 · Groove`처럼 연결이 겹치는 섹션으로 들어가 720×900pt와 1440×900pt를 각각 맞춘다. 재생 중 가시 케이블 하나를 `K` 또는 클릭으로 선택한다. 이 조작은 팔로우를 일시 중지하므로 선택 케이블의 밝은 선과 양 끝점을 기록한다. 상단 팔로우를 다시 켠 직후, 그 케이블이 계속 화면에 있는 동안 같은 선택 ID, 케이블/포트 AX, 전체 창 픽셀을 비교한다. 선택 해제·Stop·감상 모드 복귀도 이어서 확인한다. 이 단계는 **이번 감사에서 실행하지 않았다**.

**소스상 결과:** `selectCable()`은 `selectedCable`을 보존하며 재생 팔로우를 일시 중지한다(`CanvasCableEditing.swift:73–79`). 사용자가 팔로우를 다시 켜면 `placeEditor()`가 `refreshCableTools()`를 부르지만, 재생+following 조건에서는 `CableToolsView`만 제거하고 `selectedCable`은 지우지 않는다(`AlbumCanvas.swift:426–431`, `CanvasCableEditing.swift:81–87`). 같은 프레임의 모든 케이블은 장면 순서로 그려진다(`AlbumCanvas.swift:553–569`). `drawEdge()`는 선택 ID에 대해 fade 0을 주지만 선 굵기는 다른 케이블과 같은 1.5pt이며 edge 종류 색으로 그린다(`AlbumCanvas.swift:670–685, 719–735`). 선택 케이블을 맨 앞에 accent로 다시 그리는 유일한 경로는 `cableTools != nil` 조건이라 팔로우 재개 시 실행되지 않는다(`CanvasCableEditing.swift:188–193`). 이 때문에 **선택 상태와 포트·레이블 예외는 유지되나 전면 선택선만 빠지는 것**은 소스로 확정된다. 교차선 위에서 실제 시각 인지가 얼마나 나빠지는지는 build230 native 재현으로 판정해야 한다.

**영향과 소유:** 송폼에서 곡→섹션 시간 순서를 보며 같은 캔버스의 MIDI/오디오/flow 경로를 따라갈 때, 팔로우 재개 후에는 겹치는 활성 선·pulse가 선택 경로 위에 그려질 수 있다. 연결 도구막대를 숨기는 정책은 유지하면서 선택 케이블의 화면 표현을 도구막대 생존 여부와 분리하는 App UI 표현 결함 후보(P2)다. 음악 그래프·라우팅이나 실제 재생 실패를 발견한 것은 아니다.

## 수정 인수·focused QA

1. 선택 ID가 현재 보이는 유효 케이블이면 재생 팔로우가 `.following`이어도 선택선이 다른 케이블·신호 pulse보다 앞에서 연속적으로 구별되어야 한다. 선택이 없는 경우는 기존 고밀도 LOD를 유지하고, 선택 해제 후 기본 우선순위로 돌아간다. 팔로우 중 `CableToolsView`와 재연결 핸들은 열리지 않는다.
2. 같은 `f0r h3r` QA 사본에서 정지/재생, 팔로우 일시 중지→재개, 축소 개요(`zoom≤0.64` 부근)/중간/확대, 720×900·1440×900 전체 창을 비교한다. 선택선이 교차점에서 사라지지 않는지, 선택 케이블 양 끝 섹션·포트 이름이 가능한 공간에서 읽히는지, 송폼 01–07·현재 재생 섹션을 계속 식별할 수 있는지 확인한다. native 판정에는 **같은 최종 build·같은 곡/카메라/선택**의 전후 전체 창과 `snapshot.playback.ports.selected`·AX를 함께 보존한다.
3. 표시 우선순위만 바뀌어야 한다. MIDI/오디오/flow/sidechain 방향, 포트와 케이블 hit, 선택/Undo/저장·재열기, 음악 revision·재생 clock·출력 PCM은 같은 fixture에서 불변이어야 한다. VoiceOver 편집 화면의 케이블/포트 이름·선택 상태를 비교하고, 감상 모드와 MP4에는 이름표·케이블 도구막대·편집 핸들이 새로 나타나지 않게 한다. 감상 모드의 기존 AX 정책은 별도 변경 없이 유지한다.
4. focused 자동 검사에서는 `playing=true`, `follow=.following`, `selectedCable` 유효·무효, `cableTools=nil` 조합에서 그리기 우선순위를 검증한다. `CanvasPlaybackLabelLODTests`와 관련 포트/케이블 선택·AX 테스트를 돌린 뒤 격리 native 픽셀을 최종 판정으로 삼는다. App 실행과 테스트는 이 읽기 전용 감사에서 하지 않았다.
