## 2트랙 클래식 데모의 GUI export

앱 GUI에서 `bach-invention-08-qa.circlr`을 열고 프로젝트 메뉴의 **트랙별 stems 내보내기…**를 `build212-bach-invention-08-stems`로 실행했다. UI는 `내보내기 완료 · build212-bach-invention-08-stems`를 표시했다. 결과는 정확히 **2 stem + `전체 mix.wav` + `circlr-export.json` + `내보내기 정보.txt`**이며 `.circlr-export-*` stage 잔류는 없다. manifest SHA-256은 `91deb2353dd3b7f74f711b6037eb532d53b139796ae3f5b55dc7afc0de04ad0f`; `circlr-stems-v1`, arrangement `C74E18FE-FFA3-5C9A-B1CE-7B7014F5209B`, 68초 본편+2초 tail, 48kHz/24-bit, track stem 2개를 명시한다.

| 실제 WAV | SHA-256 | 독립 PCM 검사 |
| --- | --- | --- |
| `빛의 플럭-E980B1.wav` | `e00319c774b799aa4614cecb96daa1630b2f08c8b544300fb99241ea74a5763c` | stereo 48kHz/24-bit, 3,360,000 frames, 70.0초 |
| `유리 건반-384344.wav` | `59a9c98ebb83a859cfc4c7b8ae8c79f9d8ae33e52444a9e7896b4ae158b5a5c4` | 위와 동일 |
| `전체 mix.wav` | `bee5082440b740282b4c33718aa2058b48c736bde213ecb7ff6acf25d122e9d0` | 위와 동일 |

각 파일은 20,164,096 bytes다. 독립 PCM 창 분석에서 34.5초 1초 창 RMS는 순서대로 **0.020177 / 0.048616 / 0.052835**로 nonzero이고 69초 tail 1초 창은 모두 0이다. 첫 1초의 유리 건반 stem은 0인데 휴지 구간이며 중간에는 신호가 있다. 이는 파일 내용·길이의 계측 증거이고 물리 청취 판정은 아니다. 전체 수치는 `stems-check.json`에 남겼다.

stems가 UI 관찰 한 번 사이에 완료되어 진행 중 Stop을 누를 수 있는 상태를 확인하지 못했다. 대신 후속 GUI **앨범 WAV 내보내기…**를 한 번 실행해 `build212-bach-after-stems.wav`를 만들었다. 이 파일의 SHA-256은 위 `전체 mix.wav`와 완전히 동일하고 이후 stage 잔류도 없다. 따라서 stems→일반 WAV 전환 완료는 확인했지만 **실제 cancel/drain은 미검증**이다. Stop을 시험했다고 주장하지 않는다.

## f0r h3r 고밀도 Groove의 포트와 화면

`f0r-h3r-ports-qa.circlr`(15트랙·7섹션)을 GUI로 열고 `도시의 기억 · Groove` 섹션에서 `네온 브라스 · 악기`를 선택했다. 기본 축소 상태의 작은 서클에서 OUT AX가 나타났다. 포인터를 서클과 핸들 사이의 공백으로 이동한 뒤 OUT을 클릭하면 AX에서 `(selected) 네온 브라스 · OUT 오디오 메인 · 스테레오` 및 연결 편집 안내가 나타났다. 이후 창의 확대/축소를 조절해 PNG상 링 반경이 약 **44pt**, **45pt**, **46pt**인 장면을 별도로 보존했다. 이 값은 화면 픽셀 추정이며 내부 `camera.zoom`의 정확한 실수값은 읽지 않았다.

약 44pt 장면에서 선택한 서클의 **IN MIDI 연주**와 **OUT 오디오 메인 · 스테레오**가 AX 버튼으로 둘 다 노출되었다. 각 방향에서 링과 앵커 사이 공백을 클릭한 뒤에도 AX 버튼이 남았고, 앵커를 클릭하면 해당 포트가 `(selected)`로 바뀌고 연결 편집 안내가 표시되었다. 포트 클릭은 화면을 해당 서클 쪽으로 자동 확대했다. 45/46pt 부근은 별도 PNG와 IN/OUT AX 노출을 확인했다. 마우스의 순수 hover만 분리한 실험이나 내부 반경 45.000pt 양쪽의 분기 판정은 하지 않았으므로 해당 경계의 수학적 정확성은 PARTIAL이다. 연결선을 새로 만들거나 프로젝트 데이터를 편집하지 않았다.

**감상 모드 시작**을 누르면 노드/케이블은 남고 캔버스 텍스트·일반 상단 도구가 숨겨지며 AX는 **감상 모드 종료** 버튼을 제공했다. 종료 버튼으로 일반 편집 화면으로 복귀했다. 실제 앱 창을 CUA로 가로 **1440×900**에서 세로 **720×900**으로 크기 변경했다. 세로에서는 상단이 2행으로 재배치되어 버전/프로젝트/앨범 설정/서클 추가와 재생/팔로우/녹화/감상 모드가 창 안에 보이고, breadcrumb·서클 도구가 다음 줄에 남았다. 캡처는 CUA가 실제 최종 build212 창에서 반환한 원본 PNG bytes를 그대로 저장한 것이며 합성·이전 빌드 화면이 아니다.

## 출력 경계와 종료

앱 설정에서만 `Mac Studio 스피커`를 선택했다. 종료 후 격리 bundle UserDefaults의 `circlr.playback.outputDeviceUID`는 **`BuiltInSpeakerDevice`**다. 읽기 전용 CoreAudio 기본 출력 조회는 검사 전·후 모두 **`AppleUSBAudioEngine:Focusrite:Scarlett 6i6 USB:10000B65:1,2`** (`Scarlett 6i6 USB`)였다. 시스템 기본 출력은 바꾸지 않았다. 이 시험은 앱의 선택 상태와 오프라인 PCM export를 확인한 것이며 내장 스피커의 물리 청취나 구형 Scarlett의 최신 macOS 호환성 판단은 하지 않았다.

⌘Q로 격리 QA 앱을 종료했다. 종료 후 해당 앱/helper 프로세스는 **0개**이고 QA 앱의 strict deep 서명도 유효하다. 원본 dist 실행 파일 SHA는 위 시작값과 동일하며 QA 사본 manifest·미디어는 검사 전후 불변이다. 정확한 개별 증거와 전체 PNG 해시는 `qa/generated/r80-build212-native/baseline.json`, `stems-check.json`, `final-check.json`에 있다. 이번 build212 증거는 변경 전 한정 검사이며 이후 수정 패키지의 동작을 대신하지 않는다.
