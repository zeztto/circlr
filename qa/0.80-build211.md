# 0.80.0 build211 · 녹화 종료 프레임 복구

상태: **개발 빌드, 정식 0.80 출고 승인 아님** · 2026-09-24. 기준 브랜치는 `release/0.80.0`이다. 구형 Scarlett의 정상 출력은 합격 조건이 아니며, 앱 전용 내장 출력과 실패 후 안전 복구를 기준으로 한다.

## 변경과 검증

build210의 실제 37.299초 MP4에서 UI 1,118프레임과 독립 decoder 1,117프레임이 어긋났다. MP4 session 종료 시각에 닿는 마지막 영상 sample이 decoder에서 제외되는 경계가 있었다. build211은 유한 PCM 종료 뒤 **최대 1/30초만 영상 session을 연장**해 마지막 수용 프레임을 표시할 수 있게 한다. PCM 제출은 원래 오디오 종료점에 멈춘다. 유효한 0.98초 프레임까지 버리던 첫 후보는 독립 리뷰에서 P2로 기각했다. 정확한 종료점·근접 종료점·예약된 loop exit·0.98초 유효 프레임의 독립 MP4 decode 회귀를 통과했고 최종 diff의 새 P1/P2는 발견되지 않았다. [원인·테스트](0.80-build211-movie-count.md).

내부 Codex 보안 리뷰의 세 P2 통합 위험도 같은 후보에서 수정했다. `CodexProcessHost`는 allowlisted 자식 환경·canonical cwd 설정 없이는 생성할 수 없고, 부모에만 둔 합성 secret이 자식에 전달되지 않음을 검사한다. `CodexEventReducer`의 관리형 경로는 승인 canonical cwd에서만 읽기 전용 thread를 열고, 그 서버 응답 ID가 없거나 다른 thread ID를 지정한 turn을 거절한다. 비관리형 turn-only 경로는 앱에 연결되지 않았으며 G0가 풀려도 그대로 공개하지 않는다. Host와 reducer에 같은 승인 workspace를 주입하는 통합은 후속 앱 연결의 필수 조건이다.

최종 소스에서 전체 Swift **1,137 tests, 11 skipped, 0 failures**. 로그 SHA-256 `2e6bac736d932104c7786be9b82a5c81870af84c9501649b0fc017d29aeb9fe8`. MCP 계약 Python **39/39**, MCP 서버 Python **41/41**, agent kit Python **9/9**, `git diff --check` 통과. 같은 최종 소스의 arm64 앱과 다섯 helper를 패키징했고 `codesign --verify --deep --strict` 통과. 앱 버전은 **0.80.0/build211**, 실행 파일 SHA-256 `78ef7cae624439f34076abde3a2d11ac340b900df06477d1dcc6d29c84bb0865`. 동봉 데모 manifest의 소스/앱 SHA-256은 `928cc86b1f451f51878235ffecccb079d956593155743159e91315df4999c393`로 일치한다. 패키지 로그 SHA-256 `fc4f571ed990069b2ba25e9ebe840f8769c083707247ef9260b9459f1c41e1a7`.

## 실제 앱 판정과 남은 범위

격리된 **첫 build211 패키지**(실행 파일 SHA-256 `c58a4d80d33e1fe22397eaf25700b597313c34d3cb6aa190cb33ef92174089f2)의 실제 앱에서 동봉 `f0r h3r`를 앱 전용 Mac Studio 스피커로 재생·녹화했다. 38.006667초 MP4의 저장 알림 **1,138프레임**과 독립 pixel decoder **1,138프레임**이 일치해 build210의 장시간 1프레임 불일치를 이번 조건에서 해소했다. 중복 PTS·인접 동일 화면은 0, 영상 평균 29.94fps, 간격 P95 40ms다. 단, 5.99초 부근 최대 68.33ms의 두 프레임 초과 gap이 **1곳** 있어 움직임 품질은 미완료다. AAC를 따로 해독한 48kHz stereo PCM 1,824,320프레임은 시작·중간·끝 nonzero였다. 이는 실제 스피커 청취 판정이 아니다. 시스템 기본 Scarlett은 전후 동일하고 격리 앱과 helper는 종료했다. [native 영상·화면 QA](0.80-build211-native-movie.md).

보안 경계 수정 뒤 같은 버전/build를 다시 패키징해 실행 파일 SHA-256이 `78ef7cae624439f34076abde3a2d11ac340b900df06477d1dcc6d29c84bb0865`로 바뀌었다. 이 **최종 패키지**를 새로운 bundle ID·저장소로 다시 검증했다. 37.980초 MP4는 UI/독립 pixel decoder **1,138/1,138프레임**, 중복 PTS·인접 동일 화면 0, 영상 간격 P95 **38.33ms**, 최대 **60ms**, 두 프레임 초과 gap **0**이었다. 독립 해독한 48kHz stereo PCM은 1,823,027프레임이며 시작·중간·끝 nonzero였다. 최종 패키지의 가로·세로 화면을 README에 반영했다. 첫 패키지의 68.33ms gap은 역사적 관찰로 유지하며, 두 실행의 차이를 소스 수정에 따른 성능 효과로 단정하지 않는다.
