## 목표 길이 녹화

앱의 저장 패널을 통해 `qa/generated/r80-build210-native-movie/build210-native-short.mp4`를 지정하고, `영상 녹화 중 · 캔버스 + 음악`에서 약 7.6초 뒤 ⇧⌘R로 마쳤다. UI는 `영상 저장 완료 · 223프레임 · build210-native-short.mp4`를 표시했다. 파일은 **1,017,057 bytes**, SHA-256 **`405bc64a9e0b5670894b33bc8db8c4070ef81bb8805b99227b5adede6c0e9ce0`**. 저장 문구의 원본 화면 `build210-short-save-notice.png` SHA-256은 **`dd35ce0c0727f0aaf5efc23dc0a0538c97cdb4ccc019a8d9608e6e72a4f8bb57`**이다.

`swiftc -parse-as-library qa/inspect-movie-timing.swift`로 만든 별도 AVFoundation decoder가 **223개**의 영상 프레임을 실제 픽셀로 해독했다. 1440×800 H.264, container duration **7.438270833초**, 첫/마지막 video PTS **0 / 7.400초**, 평균 30.00fps, p50/p95/p99 간격 **33.33/38.33/48.33ms**, 최대 **58.33ms**였다. 중복 PTS·인접 픽셀 완전 동일·2프레임(66.67ms) 초과 gap은 모두 0. 첫 audio/video PTS는 모두 0이다. `decoded-frames/frame-start.png`(0.0983초), `frame-middle.png`(3.900초), `frame-end.png`(7.400초)를 별도 추출해 실제 곡 궤도와 진행 표시를 확인했다. **이 짧은 파일에서는 UI 223 = decoded 223으로 일치한다.**

`afinfo`는 stereo 48kHz AAC와 유효 audio **357,037 PCM frames**를 보고했다. `qa/inspect-movie-audio.py`가 `afconvert`로 별도 해독한 PCM 길이도 **7.438270833초**, peak **0.60773**, RMS **0.07367**이었다. 시작 0초, 중간 3.719초, 끝쪽 6.694초의 1초 창 RMS는 각각 **0.07368 / 0.07368 / 0.06003**으로 모두 nonzero다. PCM nonzero는 청취·주관적 음질·중간/끝의 지각 동기 검증을 뜻하지 않는다.

## 추가 관측: 긴 첫 시도에서 불일치

첫 녹화는 조작 사이 재생 시간이 길어져 목표 길이를 벗어났다. UI 저장 문구는 **1118프레임**이었으나, `build210-native-37s.mp4`를 같은 독립 decoder로 해독하면 **1117프레임**이다. 파일 SHA-256 **`7a81a82facda9e1a0090fa2f4d15b1a581feba036efb3cac7b327f0bb4b50504`**, container duration **37.29875초**, 마지막 decoded video PTS **37.265초**이며 마지막 PTS에서 파일 끝까지 **33.75ms**다. 중복 PTS·완전 동일 인접 프레임·2프레임 초과 gap은 0, 최대 간격은 60ms였다. 별도 UI 문구의 1118을 찍은 파일 캡처는 없고 CUA AX 결과에 관측값이 남아 있다. 파일의 마지막 프레임이 `endSession` 경계에서 제외됐는지는 이 관측만으로 확정하지 않는다. **저장 프레임 수 불일치는 build210에도 재현되므로 수정의 일반 종료 PASS는 보류한다.**
