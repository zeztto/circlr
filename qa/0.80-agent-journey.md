상태: **부분 통과 / 릴리스 승인 아님** · 2026-09-23. 격리된 `com.circlr.integrationqa` 0.80.0/build184 앱에서 번들 Bach Invention 8의 작업 사본만 사용했다. 앱 SHA-256은 `df43e4604eb50680e574f2e3a03accd66bc836d6e884054fade157037e26483f`다. 실제 사용자 앱·프로젝트·시스템 출력 설정은 변경하지 않았다.

## 재현과 결과

`qa/verify-agent-journey.py`는 QA 앱이 실행된 상태에서 `--project`로 지정한 **QA Application Support/fixtures 경로의 `.circlr` 프로젝트**를 연다. 실행자는 번들 데모에서 새 QA 작업 사본을 먼저 준비해야 한다. 현재 `mcp/server.py`와 stdio로 통신하며 현재 앱 bundle ID/build, 26개 tool catalog, 저장되지 않은 변경이 없음을 먼저 검사한다. 매 RPC는 30초 응답 제한을 두고, 비동기 job은 결과를 기다린다. 증거 경로와 WAV가 이미 있으면 덮어쓰지 않는다.

```sh
python3 qa/verify-agent-journey.py \
  --project "$HOME/Library/Application Support/circlr-integration-qa/fixtures/r80-agent-e2e-build184-c.circlr" \
  --evidence qa/generated/r80-agent-journey-build184-c --build 184
```

실행 결과는 `qa/generated/r80-agent-journey-build184-c/report.json`에 보존했다. 이 경로와 QA 작업 사본은 Git에 포함되지 않는다. 번들 원본 `Resources/Demos/classical/bach-invention-08/bach-invention-08.circlr/manifest.json`의 SHA-256은 실행 전후 `a0350b4802b192bf3d7ba207a9a031f166c0c5092e60faf0f82f766da3257c34`로 같았다.

한 번은 Documents 경로의 QA 작업 사본을 `open` job으로 요청했을 때 60초 넘게 완료되지 않았다. QA 앱 `stop`으로 취소한 뒤 같은 데모의 새 사본을 QA Application Support에 놓고 `open`을 다시 실행하자 약 2초에 완료됐다. macOS 접근/TCC가 원인인지는 확인되지 않았다. 임의 사용자 경로의 에이전트 파일 접근과 취소·권한 UI는 별도 gate다.

이 검증은 **typed MCP를 통한 앱의 결정적 작업**이다. 실제 모델 호출, 사용자 Codex 계정 로그인·앱 내 대화, 역할별 agent 협업, AI 전용 STOP/늦은 쓰기 차단을 검증하지 않았다. WAV 헤더와 nonzero PCM은 실제 독립 청취·믹스 품질을 증명하지 않는다. GUI에서 전체 섹션 이동·FX/automation·오디오 take 편집·stems도 아직 재현하지 않았다. 따라서 [0.80 계획](../docs/releases/0.80.0.md)의 Q80-08은 PARTIAL이며, 출력 준비와 짧은 MP4 gate도 열린다.

## 출력 timeout 회귀 범위

`OutputWorkerProcessTests.testOutputNodeAcquisitionTimeoutCleansUpAndRetryStarts`는 build184에서 관찰된 `outputNodeAcquisition/entered` 이후 helper 무응답을 fixture로 만든다. 제한 시간 뒤 `didStart=false`, timedOut, helper 작업 디렉터리 삭제, 마지막 trace 보존을 확인하고 같은 host의 다음 재생 성공까지 검사한다. 이는 HAL 중단의 **복구 계약 테스트**이며 실제 CoreAudio 지연을 해결했다는 뜻이 아니다. 첫 fixture는 구형 hello에 새로운 trace stage를 섞어 실패했고, 실제 helper와 같은 capability 응답으로 수정한 뒤 타깃 테스트가 통과했다. 최종 전체 `OutputWorkerProcessTests`는 **26개 통과·실패 0**이며 로그는 `qa/generated/r80-build184-output-process-tests.log`에 보존한다.
