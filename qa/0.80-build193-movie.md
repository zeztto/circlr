- 영상 캡처는 20ms 간격의 출력 helper 시계가 새 값을 보고할 때만 프레임을 만들며, 그 시점에서 최대 20ms 보간한 동일한 시각으로 PTS와 시각화 픽셀을 계산한다. helper 시계가 멈추면 wall clock만으로 영상을 진행시키지 않는다. 일반 캔버스의 60Hz 화면 갱신·팔로우와 녹화 시각은 분리한다.
- 루프가 교체되거나 종료될 예정인 경계에서는 캡처 위치와 그 위치를 그리는 음악 계획을 함께 선택한다. 준비되지 않은 새 오디오를 이전 섹션의 시각화에 섞지 않도록 한다.
- `qa/test-movie-frame-clock.swift`의 30Hz/20ms 합성 시계 시험은 원본 시계 gap P95 40ms, 보간 P95 33.33ms로 통과했다. 관련 Swift 테스트 48/48, 전체 Swift **1085개 실행·11개 skip·실패0**, MCP Python **39/39**, agent kit **9/9**을 통과했다. 전체 Swift 로그 `qa/generated/r80-build193-full-suite.log` SHA-256 `301ed8354f4c0ded26e60b7699dc684db550937fce10df2b1373c23925d9f199`.
- `./scripts/build-app.sh`의 arm64 앱·다섯 helper 빌드와 `codesign --verify --deep --strict`가 통과했다. 빌드 로그 `qa/generated/r80-build193-build.log` SHA-256 `1308c48caf632e6079484374d579690f580bc31b6e6443ceae191c8ba8cea7d4`. 격리 QA 패키지의 inventory `qa/generated/port-focus/build193/package.json` SHA-256 `1a2034f4bccd790db9fc6dc0c55912f872b930a7598b4f1ca3d219aa653f5fa0`.

## 열린 gate

동일 장면·동일 길이의 A/B 녹화, 1920×1080·10분·고밀도/감상 모드, 독립 플레이어 시청과 실제 청취, 중간/끝 AV offset의 정량 검사, 실제 세로 디스플레이의 UI 가독성이 남아 있다. 구형 Scarlett의 정확한 세대와 HAL timeout 원인은 확인되지 않았다. Scarlett 정상 출력은 필수 출시 조건이 아니지만 timeout 뒤 앱·worker의 안전한 복구는 검증해야 한다. QA 앱과 output worker는 종료했으며 시스템 기본 출력은 그대로다. **0.80 출시 판정은 보류한다.**
