## 실제 앱 동작

- 저장된 Bach QA 사본에서 70초 `export`를 시작하고, **14,602,240바이트가 기록된 전용 `.circlr-agent-<jobID>.wav`가 존재하며 해당 job이 running**인 순간 `cancel_job`을 보냈다. 결과는 cancelled였고 반복 취소도 cancelled였다. 정리와 2초 경과 후 임시·최종 WAV 없음, manifest SHA·music/layout revision·dirty·transport 보존을 확인했다. 새 job으로 재시도한 WAV는 70초·48kHz/stereo/24-bit·nonzero PCM이며 SHA-256 `bee5082440b740282b4c33718aa2058b48c736bde213ecb7ff6acf25d122e9d0`다. [기계 판독 증거](evidence/r80-build186-stage-cancel.json). 이 검증은 export stage에 한정되며 bounce stage·MIDI import 동시 편집은 아직 native로 재현하지 않았다.
- 접힌 `응답과 전개`·`색채의 전환` 그룹을 가진 별도 Bach 사본을 실제 앱에서 열었다. AX 선택과 키 입력으로 `주제의 출발` → Tab → `QA 중간 섹션 그룹` → Return → 펼친 그룹의 첫 섹션 `응답과 전개` → Esc → 그룹 → Tab → `주제의 귀환` 순서를 관찰했다. 비시간 노드/다중 그룹의 모든 탐색 경로와 VoiceOver 발화는 검증하지 않았다. 그룹 펼침은 QA 사본에 저장했고 동봉 원본 manifest SHA-256 `a0350b4802b192bf3d7ba207a9a031f166c0c5092e60faf0f82f766da3257c34`는 유지됐다.
- 마지막 섹션으로 Tab 이동한 화면에서 선택 궤도의 왼쪽 가장자리가 일부 잘렸다. 현재 자동 카메라 이동은 다음 서클의 중심점이 화면 안에 있으면 동작하지 않는다. 키보드 탐색 순서의 성공과 별도로, 선택된 원 전체가 보이도록 하는 구도 조정은 R80-01 후속 UX 항목이다.
- QA 앱을 종료한 뒤 전용 `Bounces` 폴더에 정확한 UUID stage 이름과 비일치 이름의 테스트 파일을 만들었다. 새 QA 앱에서 MCP 연결이 준비되자 UUID stage만 삭제되고 비일치 파일은 남았다. 테스트 파일은 검사 후 정리하고 QA 앱을 종료했다. 임의 export 폴더는 이 시작 정리 대상이 아니다.
