# Splice 정책·CC0 데모 교체 검증

2026-09-08 · macOS 26.5.1 / Apple Silicon. 앱은 기존 0.13.0, 변경 대상은 제작 CLI·샘플 준비/감사 도구·데모 v3·문서다. 단일 슬롯에서 제작, 코드/입력 검토와 QA를 순차 수행했다.

## 확인한 결과

- 공식 Splice 약관과 FAQ의 완성 음원 사용 범위와 독립 샘플 재배포 제한을 대조했다. 누구나 샘플을 추출할 수 있는 앱 튜토리얼 배포에 Splice 원본을 포함하지 않기로 결정했다. [근거·통합 설계](../docs/27-splice-licensing-and-integration.md).
- FreePats 공식 archive와 동봉 readme/LICENSE의 CC0 선언을 확인했다. 공개 archive SHA-256 `dbb2e5bb8268022fffa6dcc3d11a93368316038bf3ae81a965c58e9d490ed23b`를 고정하고 선별 WAV 6개를 준비했다.
- 20Hz DC 제거·100ms settling tail·peak trim을 거친 결과 manifest SHA-256은 `11275cbfd9d933bb293dc266faf373ea65efa918ca2f6136c2f69ce88e5b804b`다. 제작 CLI가 이 manifest와 각 파일의 hash를 요구한다.
- 초기 후보의 킥에서 DC offset이 발견돼 DC 처리와 더 짧은 Kick04로 조정했다. 중간 후보는 `generated/0.13-license/first-render-v3`에 보존했다. 최종 v3의 DC는 채널별 약 0.000033이다.
- 최종 프로젝트의 모든 미디어가 허용 목록과 일치한다. 외부 경로·추가 미디어·이전 Splice hash는 0개다. 3,119개 노트의 beat/length/pitch/velocity, 글로벌 음악 설정, 68마디 섹션 길이는 v2와 같다. [감사 JSON](../music/f0r-h3r/v3/license-audit.json).
- 실제 QA 앱에서 파일 선택창으로 v3를 열고 11섹션과 9트랙·6에셋을 확인했다. 전체 native WAV export는 제작 CLI WAV와 **파일 전체가 동일**하다. SHA-256 `d5980956759921bb0e8f362b3482d592a01298e920d075b5fbda3ba18e68b9d3`.
- 최종 WAV 142.689667초, 48kHz/24-bit stereo, peak −1.20dBFS, clipping 0, integrated −18.30LUFS. 기존 자체 측정기를 사용했으며 실제 청취·발매 품질 인증을 뜻하지 않는다.

## 산출물 검사

`dist/f0r-h3r-v3-portable.zip`에 프로젝트+내부 CC0 미디어, WAV, MIDI, 구성/튜토리얼, 원본 LICENSE와 출처/가공/측정/감사 기록을 넣었다. 17파일 / 39,913,701 bytes. 별도 임시 폴더에 풀어 CRC, 원본과 모든 파일 hash 일치, 추출된 프로젝트의 라이선스 감사를 재검증했다.

ZIP SHA-256: `a1cea067909345e11fa4db1e0e38aa151716b7ba97ec4b5589ae50b4da5476a6`.

이 ZIP은 별도 로컬 데모 패키지이며 앱 번들에 자동 탑재한 것은 아니다. Git에는 소스·직접 작성 MIDI·출처/CC0 허가·측정 기록을 보관하고 오디오·곡 프로젝트·ZIP은 제외한다. 원격 소스만으로 공식 CC0 archive를 받아 다시 생성할 수 있다. Splice 사용 v1/v2와 사용자 샘플 라이브러리는 보존했으며 추가 지출은 없다.

## 도구·회귀 검사

- 최종 `circlr-studio` release 빌드 성공. 앱/오디오 엔진 코드 변경은 없다.
- 같은 archive의 샘플 재생성에서 manifest와 각 파일 hash가 일치한다.
- Git처럼 provenance만 있고 WAV가 없는 폴더에서도 누락된 6개 파일을 복구한다. 이미 있는 정상 파일과 출처 기록은 덮어쓰지 않는다.
- 수정된 기존 샘플은 재사용을 거부한다. 제작 CLI도 출력 파일을 쓰기 전에 거부한다.
- 잘못된 archive를 Python `-O`로 실행해도 거부한다. 필수 준비 검사에 assert 제거 영향을 받지 않는다.
- 출력 폴더에 기존 WAV가 있으면 곡 생성은 실패하고 원래 bytes를 유지한다.
- 프로젝트에 허용 목록 밖의 파일을 추가하면 미디어 감사가 실패한다. 감사 도구는 `-O` 실행을 명시적으로 거부한다.
- Python 구문 검사 및 `git diff --check` 통과. 이번 변화와 무관한 102개 오디오/Core 회귀를 다시 실행한 것으로 기록하지 않는다.

증거: `generated/0.13-license/build.log`, `sample-tests.json`, `native-v3-snapshot.json`, `native-v3-job.json`, `native-comparison.json`, `portable-package.json`.

## Splice AU 탐색 검사

현재 Mac의 설치된 공식 bundle metadata를 읽어 Splice Sounds AU 0.12.1과 Listener, INSTRUMENT를 확인했다. 코드가 조회하는 `aumu` 종류와 Sounds의 종류가 일치하며, 실제 검증용 프로젝트에서 해당 악기와 Plugin 화면을 열었다. **Splice의 공식 로그인 화면 표시까지 확인**했다. 증거: `generated/0.13-license/splice-au.png`.

데스크톱 앱의 기존 로그인은 플러그인에 자동 반영되지 않았다. 별도 로그인·device authorization, 카탈로그 검색, 크레딧 구매, preview/transport 동기, drag/import를 완료했다고 주장하지 않는다. 플러그인 화면의 오른쪽이 고정 편집 영역에 잘리는 현상도 있어 companion AU 화면 크기 처리가 필요하다.

MCP로 새 QA 프로젝트를 열 때 파일 read가 지연되어 취소한 뒤, 사용자가 이미 허용한 검증 앱의 일반 파일 선택창에서 해당 프로젝트를 선택해 열었다. 기존 QA 사본은 `generated/0.13-license/previous-QA-preserved.circlr`에 보존했다. 시스템 접근 권한·인증정보·Splice 계정 설정은 변경하지 않았다. 실제 오디오 출력과 화면 녹화의 이전 Scarlett 검증 경계는 이번 샘플 교체 작업에서 다시 검증하지 않았다.
