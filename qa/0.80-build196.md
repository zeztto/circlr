# 0.80 build196 · 케이블 도구 QA 중 발견한 격리 결함

상태: **실패 / build197에서 수정·재검사** · 2026-09-24.

좁은 작업 영역의 케이블 도구를 두 줄로 배치하고 0.80.0/build196 arm64 앱·helper를 패키징했다. `codesign --verify --deep --strict`는 통과했고 빌드 로그 `qa/generated/r80-build196-build.log`의 SHA-256은 `1c1b164b9e68cc3c4a7b9b099a5cdcfc2c3e7151a0ce01c4a6aa1936157c3b1e`다. [격리 QA 준비 도구](prepare-port-focus-qa.py)는 `com.circlr.portfocusqa` 앱과 음악 내용이 동일한 별도 사본을 만들었다.

실제 QA 앱을 열자 케이블 도구 전에 **“저장되지 않은 곡을 복구할까요? f0r h3r”** 창이 나타났다. `AppStore.storageRoot`가 `integrationqa`·`portsqa`·`hierarchyqa`만 분기하고 `portfocusqa`는 기본 `circlr` 폴더로 보냈기 때문이다. 앱이 복구 파일을 읽었지만 복구·새로 시작 어느 버튼도 누르지 않고 정확히 build196 QA 프로세스만 종료했다. 기본 폴더의 `recovery.json` mtime은 QA 시작 전 00:37:28 그대로였다. QA 앱이 만든 연결되지 않은 `Agent/agent.sock`은 연결 거절을 확인한 뒤 해당 socket만 제거했다. 이 상태에서 UI 버튼의 표시·클릭·AX를 PASS로 판정하지 않는다.

build197은 QA 번들별 Application Support namespace를 사용하도록 수정한다. 새 앱의 저장·socket 경로가 `circlr-portfocus-qa` 아래인 것, 기존 기본 폴더의 복구 창이 뜨지 않는 것, 좁은 도구의 실제 동작을 다시 확인한다. 이 실패는 0.80 릴리스 보류 gate다.
