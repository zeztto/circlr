이번 변경은 녹음용 입력을 **앱에서만** 선택해 격리된 `circlr-input-worker`의 AUHAL에 전달한다. CoreAudio 장치 조회도 child에서 실행하고 5초 timeout·취소·PID 회수로 막힌 드라이버가 앱을 멈추지 못하게 한다. 선택 UID가 worker의 실제 바인딩 응답과 다르면 녹음을 시작하지 않는다. 녹음 중 장치가 끊기거나 쓰기에 실패했을 때는 검증 가능한 nonzero CAF만 복구 파일로 게시하고 프로젝트 take에는 자동 첨부하지 않는다. 시스템 기본 입력·출력은 변경하지 않는다. 실제 마이크 권한 귀속과 nonzero PCM은 [격리 native QA](0.80-build238-native.md)에서 별도로 판정한다.

700–720pt 세로 창에서는 네 작업 선택창의 외곽·검색·확인·닫기를 두 줄 상단바 아래와 16pt 창 여백 안에 배치한다. 가로 창에서 콘솔 오른쪽의 빈 캔버스는 곡·섹션 fit, 라벨, 포트·케이블, MIDI/오디오 파일 드롭과 키보드 reveal에 사용한다. 콘솔 자체는 hit와 라벨 배치에서 피한다. `f0r h3r`의 1440×900pt/180pt 콘솔 Core 계산에서는 전체 곡 fit zoom이 0.30256→0.32531(**+7.5%**)이고 모든 송 원 경계가 콘솔을 피했다. 80개를 넘는 원은 계산량을 제한하기 위해 상단 안전 사각형 fit을 사용한다. 이 수치와 layout 테스트는 **실제 화면 FPS나 조작감의 증거가 아니다**.

최종 동일 소스의 `./scripts/swift-local.sh test --scratch-path .build/build238-integration-final`은 **1,325개 실행·15 skip·실패 0**으로 통과했다. 로그 SHA-256: `17f8bd4a02ac1fc6db7c20151de2868261cf156141d31d485e0ccb4c980ce071` (`/tmp/circlr-build238-swift-final-after-cable.log`). 첫 전체 실행은 마지막 케이블 곡선 수정 전 바이너리였으므로 중단했고 합격으로 계산하지 않았다. Python `mcp.test_server mcp.test_endpoint` **47/47**, `Tests/test_mcp_*.py` **39/39**, agent kit **9/9**도 통과했다. 독립 코드 검토는 입력 복구 손실·고장 장치 하나의 전체 목록 차단·캔버스 포트/드롭/키보드·케이블 가림·고밀도 O(n²) 경계를 찾아 수정 후 재검토했고, 최종 diff에서 새 P0/P1을 찾지 못했다.

`./scripts/build-app.sh`가 만든 `dist/써클러.app`은 **0.80.0/build238**, arm64 본체와 **7개 arm64 helper**다. `codesign --verify --deep --strict` 통과, 주 실행 파일 SHA-256 `188509986a08d0e37fc01e159a841d409da75998661dbcd0d88b307696881fd1`, 패키지 로그 SHA-256 `8576c91656b9db7f1c80dc33fdae09692feecc0f90fa081787051948dc63afa1` (`/tmp/circlr-build238-package.log`). Demos **27/27**, Codex kit **26/26**, `LICENSE`와 `THIRD_PARTY_NOTICES.md` **2/2**가 소스와 byte-identical이다. 앱 내부 generated icon은 보존하고 작업 트리의 build-generated `Resources/Assets.car`는 커밋 전에 원본으로 되돌린다.

현재 debug helper의 격리 장치 조회는 약 0.5초에 `CalDigit Thunderbolt 3 Audio`와 시스템 기본 `Scarlett 6i6 USB`를 반환했다. Mac Studio 내장 마이크는 열거되지 않았다. 고장 난 장치가 **오류를 반환**하면 해당 장치만 건너뛰지만, 드라이버의 동기 호출 자체가 멈추면 전체 child를 5초 뒤 종료하므로 건강한 장치의 부분 목록은 아직 표시하지 못한다. 현재 호스트에서 그 hard hang은 재현되지 않았다. [build238 격리 native QA](0.80-build238-native.md)는 네 overlay의 700×600pt 배치, 가로·세로 곡 화면, CalDigit 앱 전용 입력 선택과 32초 nonzero CAF를 확인했다. 동시에 media/sound/arrangement 검색 필드의 **Tab 포커스가 캔버스로 빠지는 P1 결함**을 재현해 build238을 출고 불가로 판정했다. 녹음 신호 레벨은 매우 낮아 음악 입력 품질 증거가 아니다. Scarlett의 물리 입출력 호환성, 실제 compositor FPS, 긴 MP4, 빈 곡 DAW 여정과 최종 외부 Codex 모델 write는 미검증이다. [출고 gate](0.80-release-gates.md)를 모두 채우기 전에는 `v0.80.0` tag/Release를 만들지 않는다.
