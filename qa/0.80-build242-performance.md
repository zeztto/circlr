## 표시 성능 경계와 정리

이번 20개 녹화 중 표본은 전부 가시·비가림이었지만 **앱 PID에 매칭된 compositor-present timestamp는 확보되지 않았다**. 앞선 [build241 계측](0.80-build241-performance.md)에서 이 macOS 26의 `Core Animation FPS`가 OS metric 부재로 disabled이고, `Frame Lifetimes` surface swap에는 앱 PID가 없음을 확인했다. build242에서는 해당 Instruments export를 재실행하지 않았다. 따라서 앱 내부 callback `frameCount`, MP4 FPS, 20개 가시 표본을 compositor FPS로 부르지 않는다. 60초/20초 콘솔 A/B는 app-present 계측 수단 부재와 MP4 strict FAIL 후 앱 정리 우선순위 때문에 실행하지 않아 **OPEN**이다.

정상 `⌘Q` 후 QA 데모의 미저장 변경만 버렸다. 최종 QA 앱/helper PID **0**, 전용 `agent.sock` **없음**, socket listener **0**이었다([종료 전](generated/r80-build242-performance/endpoint-before-quit.json)·[종료 후](generated/r80-build242-performance/endpoint-after-final-quit.json)). 선택 기록 `selected.json`은 비활성 파일로 남았으며 다른 실행의 socket은 건드리지 않았다. `.circlr-movie-*` stage **0**([목록](generated/r80-build242-performance/stages-after-stop.txt)); 원본 app tree·실행 파일 해시/서명 및 시스템 기본 오디오·디스플레이는 불변이다. release lead가 PTS gap 원인을 별도 조사해 새 frozen build에서 동일 실제 앱 1080p·600초 기준으로 재판정해야 한다.
