기존 콘솔의 `취소`는 모든 실행 중 job을 `cancelAgentJob`으로 보냈다. 내부 trusted turn의 job에는 이 호출이 job만 취소하고 lease를 철회하지 않으므로, 늦은 AI `apply`가 허용될 수 있었다. build232의 `AI 중단`은 현재 활성 lease가 소유한 job을 확인한 뒤 `stopTrustedAgentTurn()`으로 turn을 철회하고 전용 socket과 소유 job을 닫는다. 일반 MCP job의 `취소`는 기존 job 전용 취소이며 DAW transport를 멈추지 않는다. 내부 계정 대화 UI가 연결됐다는 뜻은 아니다. [계획](0.80-build232-plan.md).

기본 곡 팔로우에서 섹션 내부 케이블이 재개 후 화면 밖으로 이동한 build231 관찰은 선택 강조선의 회귀가 아니라 **설정된 곡 팔로우 대상**의 결과다. 일시 중지 버튼은 이제 `곡·섹션·고정 팔로우 재개`처럼 복귀 대상을 명시한다. 카메라/음악 시간 정책은 바꾸지 않았다. 섹션 팔로우와 실제 고밀도 선택선은 [native QA](0.80-build232-native.md)에서 별도 PASS 판정했다.

테스트는 소유 bounce가 다른 worker를 기다리는 동안 콘솔에서 중단해 old socket/lease를 닫고 늦은 apply·commit·파일 게시가 없으며 새 turn이 다른 endpoint를 받는 것을 확인했다. 일반 공개 bounce job도 실제로 시작·취소하고 내부 trusted turn의 snapshot 권한이 남는 것을 확인했다. 이 두 테스트의 재생 상태는 정지 상태였으므로 **재생 중 AI 중단 시 transport 보존은 코드 경계의 리뷰 결과이며 실제 오디오 QA는 남아 있다**. native 팔로우·10초 영상 PASS는 물리 청취·Scarlett 호환성·앱 내부 Codex 계정 대화·장시간 MP4 및 0.80의 다른 출고 gate를 닫지 않는다. 이 build만으로 tag/GitHub Release를 만들지 않는다.
