# 0.15 · 작업 이동과 가독성 검증

2026-09-08. 실제 검증 대상은 전용 bundle `com.circlr.hierarchyqa`의 0.15.0 build 17과 `qa/generated/0.15/navigation-QA.circlr`다. 원본 v4는 수정하지 않았다. 단일 agent 슬롯에서 구현 → 읽기 전용 코드 검토 → QA를 순차 수행했다.

## 통과한 동작

- ⌘J로 작업 이동 열기, 한국어·영문을 함께 사용한 `Club Chorus 빛의 코드` 검색, Return으로 해당 사용의 MIDI 진입. ⌘2 음색, ⌘3 실제 킥 sidechain compressor 전환에서도 `빛의 코드` 트랙 문맥이 유지됐다.
- 검색 0건 안내와 Esc 취소 후 캔버스 포커스 복귀. 메뉴·버튼 이름을 Accessibility tree로 확인했다.
- 신스 배음 0.6 → 0.55 입력, Tab 확정, ⌘Z로 0.6 복원, ⌘S 저장. MCP snapshot에서도 같은 값을 확인했다.
- 실제 파일 선택창과 MCP 비동기 open으로 QA 사본을 다시 열어 마지막 선택·카메라 복원을 확인했다.
- 전체 곡에서 제목 8개(곡 1, 섹션 7), 섹션에서 우선순위 라벨 17개의 화면 좌표 충돌 검사를 통과했다. 작은 `Club Chorus` 라벨을 좌표로 더블클릭해 해당 섹션에 진입했다.
- Native 캔버스 1024×673, 1080×673, 1080×803/845에서 UI를 확인했다. title/header를 합친 최소 창은 1024×772다. 1440 폭은 Core geometry에서 검증했으며 해당 폭의 native screenshot을 확보했다고 주장하지 않는다.
- 콘솔 열림/닫힘에서 editor frame이 workspace viewport를 벗어나거나 콘솔과 겹치지 않았다. 두 열 신스는 공간이 부족하면 파라미터 영역만 스크롤한다. 경로·편집 전환 버튼은 유지한다.
- Swift 113 tests, Python 18 tests(kit 9/MCP 9) 통과. 테스트 중 발견한 잘못된 단일-member 그룹 fixture를 2-member 계약에 맞췄다. macOS CoreGraphics import를 명시했다.

## 실제 음악 보존

최종 QA 앱에서 UI 편집/Undo 후 전체 194초 WAV를 내보냈다. v4 제작 WAV와 파일 bytes가 정확히 같았다.

SHA-256: `975a901aa9f4e01ac0d9e17ad85ba59a1c377a61f41577abd7aa4d0a6f887c6f`.

Core 검사는 반복 use ID·공유 FX·sidechain 제외·미연결 원본·그룹 reveal의 atomic 실패/음악 보존, 밀집 라벨 충돌 회피와 작은/큰 viewport를 포함한다. 0.15에서 DSP·노트·미디어 형식은 바꾸지 않았다.

## 검토 중 수정한 문제

- effect/mix를 선택하면 이전 트랙 ID가 남던 문제: 실제 출력 reachability로 문맥을 결정한다. 공유 FX는 유효한 이전 트랙을 유지하고 단일 owner만 자동 선택한다.
- 축소 창의 표시 범위가 전체 창 기준이라 곡의 섹션 이름이 숨던 문제: 실제 workspace viewport를 기준으로 한다.
- 고밀도 섹션이 빈 원처럼 보이던 문제: 직속 자식을 최소 크기의 점으로 표시하며 MIDI/audio 라벨을 우선한다.
- label과 가려진 포트/time handle의 입력 충돌: label 선택을 우선한다. hover 강조가 라벨 정렬 우선순위를 바꾸지 않도록 했다.
- console bounds가 비관찰 값이라 재배치가 늦을 수 있던 문제: 값이 바뀔 때 canvas를 갱신한다.

## 남은 범위

고밀도 궤도에서는 모든 label을 동시에 표시하지 않는다. 음악의 시간·배치를 바꾸지 않고 충돌하는 label을 줄이며, 전체 서클은 작업 이동/명령 검색으로 접근한다. 연결선·8방향 포트 정리는 후속 E 범위다. 전체 DAW 기능이나 UI 개선이 모두 완료된 상태가 아니다.

Scarlett 실시간 출력/MP4 동기·외부 장치 녹음은 이번 오프라인/UI 검사의 대상이 아니다. `testArrangementRenderExportAndPlayback`을 제외했으며 오디오 장치 제한을 해소했다고 주장하지 않는다. 0.14의 실제 청취 경계도 그대로다.
