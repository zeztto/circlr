# 0.80 build194 출력 복구·고밀도 궤도·내부 AI 읽기 QA

상태: **부분 통과 / 출시 gate 유지** · 2026-09-24. 범위는 `release/0.80.0`의 0.80.0/build194 개발 후보와 별도 QA 앱이다. 사용자 설치 앱·원본 데모·시스템 기본 출력은 변경하지 않는다.

## 변경 계약

- 고밀도 **재생 중**에는 비선택 연결의 화살표와 중복된 전체 길이 강조선만 줄인다. 기본 연결선, 활성 signal pulse, 선택·hover 경로, IN/OUT hit 영역과 음악 그래프는 유지한다. 실제 좁은 화면의 전후 프레임·선택 경로·줌 복원은 native 화면으로 따로 판정한다.
- 출력 timeout/실패가 감상 모드에서 발생하면 편집 화면으로 돌아와 상태와 `⌘,` 장치 선택을 보인다. 사용자가 내장 출력을 명시할 수 있으며 시스템 기본 출력이나 스피커로 자동 전환하지 않는다. 취소된 재생의 늦은 성공은 새 상태를 덮어쓰지 않는다.
- 내부 trusted `inspect`는 선택된 arrangement/use와 선택적 MIDI lane만 읽고 revision·lease·대상 권한을 확인한다. 응답은 음악 context, lane 요약 또는 유효 MIDI 노트의 1–256개 페이지로 한정한다. 원본 오디오, 경로, asset과 plugin state는 응답하지 않는다. 이 코드는 실제 Codex 계정 로그인·대화·승인 화면과 연결되지 않았다.

## 자동 검증과 리뷰

- 최종 소스의 새 scratch 전체 Swift 테스트 **1090개 실행·11개 skip·실패0**. 로그 `qa/generated/r80-build194-final-suite.log` SHA-256 `b2a8fed1f96ee8ade1bf022fef322befeae69077c65ae685a3204b80d18226f3`.
- MCP Python **39/39**, agent kit **9/9** 통과. 로그 SHA-256은 각각 `2b6678655f96d4545a860d32fb9ea12a4bf528f7bb2027975abf5915ee2a14dc`, `00f16caf3d63273fbaede03eae062732a3f9e888818b1a27634b031a22faa67c`이다.
- 독립 보안 재검토에서 trusted 요청의 unknown/null 필드와 중첩 편집 작업의 allowlist 우회 두 건을 수정·재검토했다. 같은 request ID의 변형 요청은 replay 충돌로 거부하고 동일한 정상 `apply` 요청은 revision이 증가한 뒤에도 기존 receipt를 반환하는 회귀 테스트가 통과했다. 실제 앱 gateway를 통과하는 계정 세션 및 큰 MCP payload의 성능은 검증하지 않았다.
- 현재 시스템 기본 `Scarlett 6i6 USB`와 명시적 `BuiltInSpeakerDevice`를 시스템 설정 변경 없이 무음 최소 AudioQueue에서 구분했다. 기본 경로는 `Start`에서 10.015초 timeout, 명시 내장 출력은 start/stop/dispose OSStatus0·0.391초다. [출력 조사](0.80-output-investigation.md)에 독립 결과와 제한을 적었다. 연결 기기의 세대·HAL 원인·실제 청취는 미확정이다.

- 702×900pt QA 창의 동봉 `f0r h3r`를 DJ Intro 섹션까지 열어 Mac Studio 스피커를 앱 전용으로 사용했다. Play 후 `00:07.5`까지 시계가 진행했고 출력 확인 장치가 `Mac Studio 스피커`로 표시됐다. 정지·다시 재생도 동작했다. 연결 케이블을 선택하자 포트 위치·편집 조작이 접근성 트리에 남고 선택된 경로가 화면에서 강조됐다. 고밀도 재생 프레임의 비선택 화살표·중복선은 줄었으나 **섹션의 많은 노드와 연결 자체는 여전히 조밀**하다.
- 같은 앱에서 23.671초·702×750 MP4를 저장했다. 파일 SHA-256 `4bdf6a236b3279ede924ca6d65af45994f69ab57a70eb3186f141e2cb112be44`. 디코드 프레임 **709개**, 평균 29.95fps, P95 간격 38.33ms, 최대 56.67ms, 중복 PTS·인접 동일 화면0, 시작 video/audio PTS0이다. stereo 48kHz AAC는 전체 peak 0.732/RMS 0.0888, 시작·중간·끝 RMS가 모두 0보다 컸다. 판독 JSON SHA-256은 영상 `9bcbc86eac05bf4c2f22862904b0782f90dd33a1ea732fbca7a737f9ec42c5b1`, 오디오 `e4bd239a39719ae2d16aa748822c3b138d1856e71febae914b88ae2312e6cc48`이다. 이 수치는 파일의 프레임·PCM 검증이며 실제 compositor FPS나 물리 청취가 아니다. build193과 녹화 길이·화면 구도가 달라 성능 개선량의 통제 비교가 아니다.
- **발견한 결함:** 정상 Stop 뒤에도 상태 설명에 `⌘,에서 다른 출력 장치를 선택`하라는 문구가 나타났다. timeout과 사용자의 정상 정지를 함께 취급한 표현 문제다. build194는 이 QA 기록으로 남기고, 다음 빌드에서 timeout에만 장치 변경 문구를 보이도록 수정·재검사한다.

## 열린 출고 gate

단일 timeout 뒤 앱 전용 내장 출력 재시도는 이번 앱에서 확인했다. **반복 cold start·장치 분리/재연결**, 좁은 창의 다른 밀도·줌과 선택/hover 전체 조합, 감상 모드의 긴 재생·녹화 화면, 물리 청취, 정확한 1080p·10분·고밀도/루프·최소화 장시간, 중간/끝 A/V 박자 동기, 전체 GUI 제작 경로는 남아 있다. 따라서 이 빌드만으로 `v0.80.0` 태그나 GitHub Release를 만들지 않는다.
