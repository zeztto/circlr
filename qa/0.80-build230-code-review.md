## 발견사항

### [P2] AI 저장 STOP 이후에도 큰 미디어 stage 복사가 끝날 때까지 계속됨

`beginTrustedAgentSave`는 detached worker에서 `ProjectStore.prepareSessionSave`를 실행하고, STOP 시 `worker.cancel()`을 호출한다 (`Sources/CirclrApp/AgentWorkspace.swift:422-434`). 그러나 `prepareSave`의 asset 루프와 `copyAssetBytes`의 1 MiB 복사 루프에는 cancellation 확인이 없다 (`Sources/CirclrCore/ProjectStore.swift:236-254,363-373`). 따라서 GB 단위 녹음 파일을 저장 준비하는 중 사용자가 AI STOP을 누르면, 작업 상태는 취소되어도 stage 파일 쓰기와 디스크 I/O가 복사 완료까지 지속된다. 새 production 작업도 이전 task drain을 기다리므로 반응이 늦어질 수 있다. 최종 문서 publish는 뒤의 취소 검사로 막히지만, DAW에서 STOP이 무거운 파일 작업을 즉시 멈춘다는 계약은 충족하지 않는다.

재현: 미디어가 큰 저장된 `.circlr` 곡에서 trusted `save`를 수락하고 미디어 복사가 시작된 직후 `stopTrustedAgentTurn()`을 호출한다. stage 크기 증가와 새 작업 대기 시간을 관찰한다. 복사 chunk 또는 asset 경계마다 `Task.checkCancellation()`을 실행하고, 취소 시 stage를 정리하는 결정적 테스트를 추가해야 한다. 사용자 문서와 기존 미디어는 STOP 전후 바이트가 같아야 한다.

## 확인한 범위

- UI의 새 곡·열기·starter·demo 적용 및 저장 경로는 녹음 pending/recording/finishing 동안 교체를 거절하고, modal 또는 비동기 대기 뒤 다시 검사한다. `RecordingDocumentBoundaryTests`는 상태 경계를 검증하지만 실제 오디오 장치에서 take writer가 마무리되는 경로를 증명하지는 않는다.
- 외부 agent `open`은 공통 `executeAgent`의 녹음 busy guard 뒤로 들어가므로 이번 diff에서 별도 누락으로 분류하지 않았다.
- MIDI 녹음 시간은 `systemUptime`을 표시하고 정지 시 playback meter로 복원한다. 자동 정지 경로가 테스트에 포함된다.
- staged save는 준비 후 target 지문을 재검사하고 stage를 검증한 뒤 교체한다. 기존 `.circlr`의 manifest/media 보존 및 변경 target 거부 테스트가 있다. 다만 위 STOP 중 복사 자체의 취소 검증은 없다.

물리 Scarlett 호환성, 실제 입력 take, 긴 WAV/영상, native UI는 이 코드 리뷰의 검증 범위 밖이다.

## 수정 후 재검토

앞의 P2는 현재 diff에서 **해결**됐다. detached AI save worker는 `Task.checkCancellation()`을 `ProjectStore.prepareSessionSave`에 전달한다 (`Sources/CirclrApp/AgentWorkspace.swift:425-434`). 준비 시작·asset 경계·미디어 1 MiB 복사 chunk·checksum chunk마다 취소를 확인하고, 취소 시 소유 stage만 폐기한다 (`Sources/CirclrCore/ProjectStore.swift:350-360,365-400,499-559`). `StagedProjectSaveTests.testCancellationDuringMediaCopyLeavesTargetAndSourceUntouched`는 복사 도중 결정적으로 취소하고 기존 manifest·원본 오디오와 stage 정리를 검사한다 (`Tests/CirclrCoreTests/StagedProjectSaveTests.swift:116-138`). 따라서 위의 최초 발견사항과 재현 절차는 수정 전 기록이며 현재 열린 결함이 아니다.

새 trusted WAV 경로도 검토했다. turn 시작 때 앱이 선택한 parent의 device/inode를 캡처하고 (`Sources/CirclrApp/AgentSessionGateway.swift:84-95`, `Sources/CirclrApp/TrustedExportPublisher.swift:19-34`), 렌더 후 별도 worker가 고정한 디렉터리 descriptor에 전용 임시 파일을 복사한다. 게시 시 parent identity와 lease·문서·revision을 다시 검사하고 `linkat`으로 기존 파일을 덮어쓰지 않는다 (`Sources/CirclrApp/AgentWorkspace.swift:649-679`, `Sources/CirclrApp/TrustedExportPublisher.swift:117-143`). 선택 폴더 교체·symlink·동일 이름 충돌·복사 중 취소를 검증하는 테스트가 추가됐다. `ProjectStore.discardStage`는 stage root와 각 파일의 inode를 검사한 뒤 소유 파일만 폐기하므로, 대체 stage 경로의 데이터를 재귀 삭제하던 이전 위험도 완화됐다 (`Sources/CirclrCore/ProjectStore.swift:91-154`; `StagedProjectSaveTests.swift:140-173`).

현재 diff에서 추가 고확신 회귀는 발견하지 못했다. 통합팀이 보고한 관련 집중 테스트 49/49 통과는 이 리뷰에서 독립 재실행하지 않았으며, 실제 파일시스템 경합·물리 장치·native QA 성공을 뜻하지 않는다.
