# 0.80 build231 · 선택 케이블 표시 독립 코드 리뷰

```text
TEMPLATE_VERSION: code-review-v1
REVIEWED: CanvasCableEditing.swift, CanvasCableAccentTests.swift
VERDICT: 수정본에서 새 차단 결함 없음; 재생·팔로우 native 픽셀/AX는 별도 QA
```

읽기 전용 리뷰어는 최초 diff에서 두 가지를 지적했다. 첫째, `MovieRecording.swift`는 `movieWriter`를 대입하기 전에 opening frame을 캡처하므로 `movieWriter == nil`만으로 영상에서 편집 accent를 제외하면 첫 프레임에 선이 섞인다. 수정본은 `movieCaptureDepth`를 사용해 capture closure가 `placeEditor()`/`draw()`에 들어가기 전에 도구막대·끝점 핸들·accent를 모두 숨긴다. 첫 프레임과 같은 `movieWriter=nil, movieCaptureDepth=1` 상태의 focused 회귀가 통과했다. 리뷰어가 해당 순서를 재검토해 해소로 판정했다.

둘째, 단위 fixture는 실제 `Playback.playing=true`를 안전하게 주입하지 못한다. 새 테스트는 follow 상태에서 도구막대 없이 선택 accent curve가 존재하는 계약을 확인하지만, `playing+following`의 실제 픽셀과 겹친 케이블 위 최종 그리기 순서는 native 앱 관찰이 필요하다. 이 제한을 테스트 PASS로 덮지 않고 [native QA](0.80-build231-native.md)에 남긴다. 리뷰어는 stale project, 숨은 끝점, 감상/영상 상태와 선택 해제 경로에서 수정본의 다른 고확신 차단 결함을 찾지 못했다. 리뷰는 코드 읽기 전용이었고 테스트·앱 실행 결과는 [build231 QA](0.80-build231.md)와 분리한다.
