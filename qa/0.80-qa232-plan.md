```text
TEMPLATE_VERSION: development-plan-v1

```

사용자가 알려 준 구형 Scarlett의 macOS 호환성 불확실성을 앱 회귀와 분리한다. 시스템 기본 장치나 Scarlett 설정을 바꾸지 않는다. 실제 앱의 재생 안정성은 앱에서 명시적으로 고른 Mac 내장 출력으로 확인하고, 물리 청취는 사용자가 돌아와 확인할 때까지 미검증으로 기록한다. 오프라인 WAV/PCM·MP4 검증은 장치 독립 결과로만 취급한다. Scarlett의 정상 출력은 출고 조건으로 삼지 않으며, 사용 불가·준비 timeout에서 앱이 멈추거나 문서/파일을 훼손하지 않는지가 앱의 조건이다.

AI 경로는 현재 서명된 build230의 고유 QA bundle·Support·곡 사본만 대상으로 한다. 현재 Codex CLI의 기존 ChatGPT 로그인을 사용할 수 있는지 먼저 읽기 전용으로 확인한다. Codex 프로젝트의 MCP subprocess에만 별도 QA `HOME`을 주어 `selected.json`의 실행 ID와 socket identity를 고정한다. 전역 Codex 설정·인증 캐시·사용자 곡은 변경하지 않는다. 실제 모델이 MCP `snapshot → inspect → apply → inspect → Undo → 재적용 → save/open → render`를 실행하면 음악 내용·revision·원본 hash·WAV PCM을 독립 검사한다. 모델의 텍스트 보고만으로 PASS로 쓰지 않는다. 이 외부 Codex/MCP QA를 앱 내부의 계정 대화 기능으로 표현하지 않는다.

실행 전에는 QA bundle/Support의 고유성, 앱 서명과 원본 hash, fixture의 원본 hash, `selected.json`의 권한·runID를 확인한다. 실패하거나 로그인/프로젝트 MCP 설정이 막히면 앱/사용자 상태를 보존한 채 실패 조건을 기록하고, 임의의 인증 우회·API 과금 경로로 전환하지 않는다. 실제 UI 고밀도 수리는 별도 UX 감사의 한 가지 재현 사례와 인수 기준이 확정된 뒤에만 착수한다. 코드 변경 시 영향 테스트·최종 앱/스크린샷·README/CHANGELOG·독립 리뷰를 갱신한다. 문서/QA만 변경하면 build를 올리지 않고 링크와 diff를 검사해 checkpoint commit/push한다. 열린 native/청취 gate가 있는 동안 `v0.80.0` tag·Release는 만들지 않는다.
