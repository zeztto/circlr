# build226 궤도 가독성 UX 감사 · 2026-09-24

`ux-brief-v1` · 대상: 0.80.0/build225 소스, build224의 공개 가로·세로 스크린샷. 읽기 전용 감사이며 build226 실행 결과가 아니다.

## 확인된 결함: 섹션 이름표가 자기 시간 궤도를 가림

720×900 [세로 캡처](../docs/images/circlr-song-portrait-build224.png)에서 **04 Club Chorus, 06 Final Chorus, 07 DJ Outro**의 불투명 이름표가 각 섹션 원의 중앙을 가로지른다. 원의 좌우 테두리와 그 부근 마디 눈금이 이름표 아래로 사라져, 원을 타임라인으로 읽기보다 이름표 뒤의 장식으로 보게 된다. 1440×900 [가로 캡처](../docs/images/circlr-song-build224.png)에서도 긴 이름표가 자기 원과 겹친다. 이는 라벨끼리 겹치거나 잘리는 결함과 다르다. build224의 [native QA](0.80-build224-native.md)는 720px에서 7/7 이름이 읽힌다고 확인하면서, 이름표가 원·연결선 위에 놓이는 위험을 기록했다.

현재 [배치기](../Sources/CirclrCore/CanvasLabelLayout.swift)는 `expanded == false`이고 화면 반지름 `r >= 45`인 원에 `p.x-w/2, p.y-h/2` 중앙 후보를 첫 번째로 넣는다. 다른 원과 장애물은 피하지만 **요청한 원의 테두리**는 피하지 않는다 (`circles` 검사에서 `$0.id != request.id`). [CanvasPresentation](../Sources/CirclrApp/CanvasPresentation.swift)의 섹션 요청은 720px에서도 긴 전체 제목을 유지하고, 같은 원을 `labelCircles`에 넘긴다. [AlbumCanvas](../Sources/CirclrApp/AlbumCanvas.swift)는 섹션 원을 `isTimelineRing`으로 그리고 마디 눈금을 그린 뒤 불투명 이름표를 나중에 그린다. 따라서 이름표가 시간 정보를 덮는 것은 스크린샷과 그리기 순서가 모두 뒷받침한다.

**사용자 결과:** 축소된 송폼에서도 각 원의 둘레가 길이·마디·현재 위치를 뜻한다는 사실이 드러나고, 섹션 이름은 계속 읽힌다. 이름표가 넓거나 높은 경우에는 자기 시간 궤도와 실제 눈금을 덮지 않도록 바깥 후보와 leader를 우선 검토한다. 중심 배치가 궤도 안에 완전히 들어가면 유지할 수 있다. 장소가 부족하면 라벨·원·카메라의 전체 구도를 함께 다뤄야 하며, 무작정 원을 더 작게 만들거나 7개 이름을 지워서는 안 된다.

## 인수 기준

1. 기본 `f0r h3r`의 720×900 세로 화면에서 기본 콘솔, 확장 콘솔, 접힌 콘솔 모두 7/7 섹션의 **원형 둘레와 전체 이름**을 식별한다. 이름표는 자기 시간 궤도·눈금·재생 위치를 불투명하게 가리지 않고, 다른 이름표·원·포트·시간 핸들·상단 조작과 겹치지 않는다. 한국어와 `f0r h3r · Club Chorus` 혼합 제목이 잘리지 않는다.
2. 1440×900과 720×900에서 정지·재생/팔로우·선택·hover·감상 모드 왕복 시 라벨의 위치 우선순위가 안정적이다. 감상 모드에는 기존처럼 텍스트가 없고 원·신호는 남는다. 작은 카메라 이동/창 resize 때문에 라벨이 매 프레임 반대편으로 튀지 않는다.
3. 라벨을 클릭하면 해당 서클을 선택하고, 드러난 원 둘레를 클릭/드래그하면 기존 ring/time/port 조작이 우선된다. 접근성의 섹션 이름·시간 범위와 키보드 섹션 이동은 유지된다. 편집·저장·Undo와 음악 시간/연결 데이터는 바뀌지 않는다.
4. `CanvasLabelLayout`의 좁은 viewport 테스트는 자기 **타임라인 ring**과 다른 원, 도구 장애물을 동시에 피하는 경우와, 공간이 없는 경우의 명시적 fallback을 다룬다. 현재 다른 원과 도구를 피하는 테스트를 약화하지 않는다.

## 격리 native QA 시나리오

build226 격리 앱에서 번들 데모 사본만 열고, 1440×900 최초 fit → 720×900 → 콘솔 기본/확장/접힘으로 전환한다. 각 상태에서 전체 캡처와 AX tree를 기록하고 7개 라벨·원·마디 눈금·IN/OUT을 육안 확인한다. 04·06·07은 각각 이름표 클릭, 원의 이전에 가려진 좌우 둘레 클릭, hover, 선택 해제를 반복해 hit target을 확인한다. 재생 중 song/section follow와 감상 모드를 왕복한 뒤, 수동 줌·팬→창 너비 왕복에서 카메라가 임의로 리셋되지 않는지 확인한다. 실제 오디오 장치와 물리 청취는 이 UI 감사의 범위 밖이다.

**구현 위험:** 라벨을 외부로 내보내면 이웃 원·케이블과 720px viewport 경계에 닿을 수 있다. fit 계산이 라벨만 따라 매 프레임 변하면 팔로우 카메라가 흔들릴 수 있다. `AlbumCanvas.hit(_:)`는 이름표를 원보다 먼저 처리하고 `mouseDown`은 이름표 위에서 시간 핸들/포트 조작을 시작하지 않으므로, 위치 변경 후 hit area를 픽셀과 실제 입력으로 확인해야 한다. 현재 스크린샷만으로 시간 핸들 클릭이 실패했다고 단정하지 않는다.
